<measured_facts>
Established by direct measurement on THIS host. Do not re-derive; do not
contradict without measuring again.

**Package.** zellij 0.44.3-1 from the official `extra` repo (NOT the AUR).
Depends only on curl/glibc/libgcc/zlib. No plugin manager, no git clone.

**Live reload — the finding that dictates the architecture.** Measured three
ways, with a non-empty byte capture asserted on every branch:
- Theme defined INLINE in config.kdl → applies at start AND live-reloads a
  running session (fg changed mid-session; the new SGR appeared and the old one
  vanished entirely, 14001 bytes captured, no restart).
- Theme in a separate themes/<name>.kdl → applies at start, does NOT live-reload
  (4901 bytes captured, so a real negative, not a silent probe).
- Touching config.kdl does not make zellij re-read a separate themes dir
  (7694 bytes, still absent).
KDL has no include/source mechanism, so the "app sources a matugen fragment"
pattern used by fish, fzf and tmux is UNAVAILABLE here.

**Symlink + rsync live-reload (measured THIS session, new).** With
~/.config/zellij/config.kdl a SYMLINK to a state-dir file:
`zellij setup --check` reports "[CONFIG FILE]: Well defined." and exits 0. After
`rsync -a --delete` replaced the symlink's target inode — exactly commit.sh's
promotion mechanism — a RUNNING session live-reloaded: the new fg SGR was
present and the old one entirely absent in an 8617-byte capture. This is the
fact that makes the state-dir architecture below viable.

**Multi-line is load-bearing (measured THIS session, new).** The collapsed
single-line themes form is a KDL PARSE ERROR: zellij emitted its parse-error
help ("Missing `;` after a node name...") and rendered no session. The
multi-line form — one colour per line — passes `zellij setup --check` with
exit 0 and renders. A 1116-byte capture is what a parse failure looks like; a
working session captured 25680 bytes.

**Powerline is free (measured THIS session, new).** In the DEFAULT layout,
zellij's own status bar emitted all four powerline separator codepoints
(U+E0B0, U+E0B1, U+E0B2, U+E0B3) natively, coloured from the theme block, with
zero separator configuration. `zellij setup --check` independently reports
`[ARROW SEPARATOR]: ` (U+E0B0) — the same codepoint tmux-colors.conf uses, and
kitty's FiraCode Nerd Font already covers it. The `orange` slot is live
(rendered as truecolor SGR), not a dead key.

**Theme block shape.** `themes { <name> { fg bg black red green yellow blue
magenta cyan white orange } }` — 11 slots, hex string values accepted.

**Pipeline mechanics (measured in code this session).** commit.sh promotes ONLY
`$tmp$STATE_DIR/` via rsync. theme-doctor checks `[[ -f "$STATE_DIR/$f" ]]`.
theme-parity reads `$tmp$STATE_DIR/$fname`. theme-doctor contains NO
format-specific logic (zero contract_format / contract_extract references), so
a contract.json entry alone gives it full coverage with no code change.

**Native session serialization.** zellij ships `session_serialization`,
`serialize_pane_viewport` and `scrollback_lines_to_serialize` as built-in
options — the native equivalent of the tmux-resurrect + tmux-continuum plugin
pair, with no plugin manager, no AUR package and no headless fetch step.
</measured_facts>

<correction_to_brief>
**One item in the task brief is wrong, and this plan deviates from it
deliberately. Flagging rather than silently complying.**

The brief states: "`output_path` is `~/.config/zellij/config.kdl` — NOT
`~/.local/state/theme/`, which breaks this repo's usual convention. Say so in
the template header."

That shape cannot work. Measured in code, three independent reasons:

1. `commit.sh` promotes exactly one directory: `rsync -a --delete
   "$rendered_dir"/ "$STATE_DIR"/` where `rendered_dir="$tmp$STATE_DIR"`.
   matugen's `-p` prefixes the tmp dir onto the resolved absolute output_path,
   so a template targeting `~/.config/zellij/config.kdl` renders to
   `$tmp$HOME/.config/zellij/config.kdl` and is deleted with the tmp dir. It
   would never reach the desktop, and the failure is silent.
2. `theme-doctor` resolves every contract file as `[[ -f "$STATE_DIR/$f" ]]`.
3. `theme-parity` resolves every contract file as
   `"${RENDERED_DIRS[$target]}/$fname"`, i.e. `$tmp$STATE_DIR/$fname`.

So a contract entry — which the brief explicitly requires (20 -> 21) — is
structurally impossible for a file outside the state dir.

**The requirement the brief was protecting is fully preserved.** matugen still
renders the WHOLE config.kdl; only its location changes, plus one symlink. The
symlink path is measured to live-reload under rsync replacement (see
`<measured_facts>`), and `ln -sf` from the state dir into an app's config path
is not a convention break at all — it is the established idiom commit.sh
already uses five times, for walker, yazi, satty, gtk-3.0 and gtk-4.0.

D-02 below is the corrected decision. The template header must document THIS
reasoning, so a later reader does not "fix" it back toward the brief's shape.
</correction_to_brief>

**(b) lib/contract.sh** — add the `kdl` format.

Deviation from the tmux-set/fish-set idiom, and it is a deliberate improvement,
not drift: those formats keep two hand-mirrored regexes in lockstep, and the
file's own comments warn twice that a name matched in one half but not the other
is a silent false-pass generator. Rather than adding a third pair of mirrored
regexes to be kept aligned by discipline, define ONE shared emitter and have
both branches call it. Drift becomes structurally impossible instead of merely
warned about.

Add a helper function near the other module-level helpers that takes a path and
emits name-TAB-value for every colour slot in the themes block. Implement it in
python3 — the same language and heredoc shape the existing toml and json
branches already use, and the reason install.sh needs no new dependency. It must:
  - strip lines whose first non-whitespace characters are the KDL line-comment
    marker, so the template's header can never contribute a key;
  - track brace depth and note when the themes node opens, so only nodes nested
    inside it are considered;
  - match a bare identifier followed by a double-quoted value, emitting the
    identifier and the value with its quotes removed;
  - exit non-zero when it produced no pairs at all, matching the lua-table
    branch's stated discipline that a failed extraction must be loud, never a
    silent empty pass that vacuously matches every other empty extraction.

In `contract_extract_names`, the kdl branch calls that helper and reduces it to
the first tab-separated field, sorted and unique — the same sorted-unique shape
every other name branch produces.

In `contract_extract_values`, the kdl branch calls the SAME helper and emits its
output unchanged.

Both branches carry a comment stating that they share one emitter, and why that
is stronger than the mirrored-regex idiom used by tmux-set and fish-set directly
above. Also update the format list in `contract_format`'s own doc comment to
include the new tag.

**(c) theme-parity** — add kdl to the `enforce_emptiness` case list in Layer 3,

comment: the kdl extractor is scoped to the themes block, so every key it
declares is definitionally a colour, exactly the property that puts the other
formats in that list. This makes an empty colour value, and a zero-pair
extraction, a hard failure rather than a vacuous pass.
