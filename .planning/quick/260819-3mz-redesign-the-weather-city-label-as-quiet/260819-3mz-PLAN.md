# Quick Task 260819-3mz — Quiet the city label; seed Alexandria

Two operator reports against `260818-v3m`:
1. "I don't like it, redesign it."
2. "My current location is Alexandria not Cairo."

## Report 2 is the bigger one

`weather.json` held `30.04, 31.24` — Cairo. The label was correctly reporting
what it was told; **the forecast itself was the wrong city's**, ~180 km off.
Measured at the time: Alexandria 25.6 °C against the 28.5 °C on screen.

It also retroactively justifies the geocode decision. Alexandria's timezone is
**also `Africa/Cairo`**, so the timezone fallback would have said "Cairo" while
the operator sat in Alexandria. The hypothetical raised during design — "someone
in Giza also gets Cairo" — was the operator's literal situation.

## Report 1, diagnosed against the type scale

Operator selected: *wrong place or size entirely* + *it floats / feels detached*,
and chose the quiet-typographic direction.

Measured scale: **display 32 / heading 20 / body 16 / label 12**. The label
shipped at `fontLabel` — the smallest step in the whole scale — directly beneath
a 32 px number. That is the size half.

Structurally it was its own `Row` with `anchors.horizontalCenter`, centred across
the entire hero including the condition glyph, aligned to nothing beneath it.
That is the floating half.

## Changes

**WeatherTab.qml**
- City moves from a centre-anchored sibling `Row` into the temperature/condition
  `Column`, as its first child — sharing that column's left edge with `25°` and
  `Mainly clear`. Shared edge is what kills the detachment.
- `location_city` glyph removed; `Font.AllUppercase` removed. The repo has zero
  precedent for either (no `toUpperCase` / `letterSpacing` / `font.capitalization`
  in any other `.qml`), and the primary-glyph/muted-text split read as two
  unrelated elements.
- `fontLabel` -> `fontBody`; single `Colours.onSurfaceVariant` role.
- Preserved: hidden when empty (never a dash), and therefore zero height — a QML
  `Column` skips non-visible children, so the advisory size formula is untouched.

**stow.sh**
- Seed Cairo -> Alexandria, so a fresh install reproduces the operator's real
  setup instead of silently serving another city's forecast.
- **Two decimal places, city centroid** — the seed's own comment (D-30) states
  the repo is public and precise coordinates committed to git are self-doxxing.
  The live `~/.local/state/theme/` copy carries full precision; this one must not.
  Verified the coarse value still reverse-geocodes to "Alexandria", not a suburb.

**Host state (not the repo)**
- `~/.local/state/theme/weather.json` lat/lon updated to full precision
  Alexandria, written atomically. The watched `FileView` invalidates the Cairo
  cache on the coordinate mismatch, refetches, and re-geocodes.

## Verify
qmllint, `bash -n stow.sh`, colour-lint, motion-lint, quickshell-doctor,
theme-doctor. Then operator confirms the label reads "Alexandria" and sits
aligned with the temperature.
