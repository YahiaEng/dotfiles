# Quick Task 260728-48c — Generalize the module guard

## Why

`dkms-verify` (260728-3na) closes the failure that caused the 2026-07-28 black
screen, but it only knows about DKMS. Demonstrated blind spot:

```
$ SRC_DIR=<empty> dkms-verify
dkms-verify: no DKMS modules registered — nothing to check.
exit=0
```

Green light while checking nothing. Arch has dropped the proprietary kernel-module
packages entirely (`nvidia`, `nvidia-dkms`, `nvidia-lts` are gone at driver 610); the
survivors are `nvidia-open-dkms` (DKMS) and `nvidia-open` / `nvidia-open-lts`
(prebuilt, shipping `.ko` files into `usr/lib/modules/<exact-kver>/extramodules/`).
On a prebuilt setup there are no DKMS modules at all, so the current guard passes
vacuously on a system it is not protecting.

The failure mode does not disappear on prebuilt — it changes shape, from "DKMS did
not build" to "driver package not rebuilt in lockstep with the kernel". `nvidia-open`
depends on plain `linux` with **no version constraint**, so the pairing is maintained
by repo publishing discipline, not by pacman.

The guard should answer the question that actually matters — *can this kernel load its
NVIDIA driver?* — regardless of where the module came from.

## Goal

One check that covers DKMS and prebuilt module sources, so the strategy can change
without silently losing coverage.

## Tasks

### Task 1 — `system/usr/local/bin/kernel-module-verify`

**Files:**
- `system/usr/local/bin/kernel-module-verify` (new)
- `system/usr/local/bin/dkms-verify` (deleted — renamed, scope widened)

**Action:** Two independent passes over kernels enumerated by `pkgbase`.

- **Pass 1 — DKMS registration** (unchanged from 260728-3na): every registered
  `/usr/src/*/dkms.conf` module must report `installed` for every kernel, honouring
  `BUILD_EXCLUSIVE_KERNEL`. Still matches `dkms status` **output text**, never exit
  status — dkms 3.4.1 exits 0 and prints `<mod>: added` for a never-built kernel.
- **Pass 2 — driver presence, source-agnostic** (new): when NVIDIA userspace
  (`nvidia-utils`) is installed, every installed kernel must be able to resolve the
  `nvidia` module. Uses `modinfo -k <kver> -F filename nvidia`, verified to resolve
  `updates/dkms/` and `extramodules/` transparently and to exit 1 when absent.

  Two distinct failures, two distinct remedies:
  - `.ko` file absent entirely → module missing. Remedy depends on source: DKMS if a
    matching `dkms.conf` is registered, otherwise the prebuilt package suggested from
    the kernel's own `pkgbase` (`linux` → `nvidia-open`, `linux-lts` →
    `nvidia-open-lts`).
  - `.ko` present but `modinfo` cannot resolve it → index stale, remedy is
    `sudo depmod <kver>`. A module not in `modules.dep` is not loadable by udev, so
    this is a real failure, not cosmetic.

**Verify:** clean against real state; detects a missing kernel; ignores orphan trees;
**and no longer passes vacuously when DKMS is empty but a kernel lacks its driver.**

**Done:** all cases behave as specified, `shellcheck -S warning` clean.

### Task 2 — Rename the hook

**Files:**
- `system/etc/pacman.d/hooks/99-kernel-module-verify.hook` (new)
- `system/etc/pacman.d/hooks/99-dkms-verify.hook` (deleted)

**Action:** Same triggers and `99-` ordering. Drop `Depends = dkms` — the script must
now run on systems with no DKMS installed at all, which is exactly the configuration
Pass 2 exists to cover. Keeping that dependency would reintroduce the blind spot at
the hook level.

**Done:** hook fires independently of dkms being installed.

### Task 3 — Update `install.sh`

**Files:** `install.sh`

**Action:** Point both `install` lines at the new filenames; refresh the comment block.

**Verify:** `bash -n install.sh`; `shellcheck` clean.

## must_haves

**Truths:**
- Pass 2 catches a kernel with no NVIDIA module even when zero DKMS modules exist.
- Kernel enumeration still uses `pkgbase`, never a directory glob.
- DKMS detection still matches output text, never exit code.
- The hook no longer depends on `dkms`.

**Artifacts:**
- `system/usr/local/bin/kernel-module-verify`
- `system/etc/pacman.d/hooks/99-kernel-module-verify.hook`
- `install.sh` pointing at both
