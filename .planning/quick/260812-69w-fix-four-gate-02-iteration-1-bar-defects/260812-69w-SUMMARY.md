## Issues Encountered

- **Probe C's `grabToImage`/`Timer` initially never fired.** Root cause: the two off-screen comparison `Text` items, declared directly inside `IdleInhibitorCapsule.qml`'s body, were swept into `BarCapsule.qml`'s shared `contentGrid` positioner via the `default property alias content: contentGrid.data` mechanism — the same mechanism that legitimately routes every capsule's real content there. Wrapping the probe items in a zero-size isolating `Item` (so only that zero-size wrapper, not its grandchildren, is subject to the positioner) fixed it. This is now the documented pattern for any future probe that needs to add off-screen instrumentation to a `BarCapsule`-rooted file.
- **The `shell.qml` hot-reload file watcher stopped responding to `touch`/write on that one file specifically** after roughly 20 reload cycles in this session, while touching any *other* qml file (e.g. `LauncherCapsule.qml`) continued to trigger a full reload reliably and instantly. Every reload in this task was ultimately achieved this way. This cost real time chasing a false lead (suspected `margins.top` compositor behavior, suspected coordinate-frame bug) before the watcher-staleness explanation was confirmed by cross-checking against `journalctl` (which proved `quickshell.service` never actually restarted — `Active: since 02:40:26 EEST`, unbroken through the whole task) and by successfully triggering reloads via a different file. Worth flagging for future quick tasks in a long-running session: if `touch shell.qml` stops producing a `Reloading configuration...` line, touch a different already-imported qml file instead of assuming a restart or a deeper bug.
- **Two missing imports on the first pass of `BarTooltipHost.qml`** (`LazyLoader` needs `import Quickshell`; `Design.*` needs `import "../dashboard"`) — caught immediately via the live error log (`Type BarTooltipHost unavailable` / `ReferenceError: Design is not defined`) and fixed before Task 2's commit; no broken state was ever committed.
