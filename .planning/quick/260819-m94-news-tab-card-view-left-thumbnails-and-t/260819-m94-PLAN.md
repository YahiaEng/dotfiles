## Two design points this plan resolves, recorded rather than assumed

**1. Namespaced tag names are handled robustly instead of guessed.**
Whether Qt's `responseXML` reports `<media:thumbnail>` as the qualified name
`"media:thumbnail"` or the local name `"thumbnail"` was **not** measured, and
`_childrenNamed()` compares `nodeName` exactly. Rather than guess, Task 1 adds
`_childrenNamedNs(node, localName)`, which accepts a child whose `nodeName` is
either `localName` **or** ends with `":" + localName`. That is correct under
**both** behaviours, costs three lines, and removes the need for a `qml6` exit-code
probe cycle. The live gate in Task 1 (`image` values actually landing in
`news-cache.json`) then proves end-to-end which branch fired, mechanically.

**2. `view_mode` is persisted by a surgical read-modify-write, not `writeAdapter()`.**
`Colours.qml:33` records the standing rule that QML must never become a second
writer of `$STATE_DIR`; `news-sources.json` is exempt from that specific hazard
because it is in `contract.json`'s `engine_owned_files`, which
`lib/commit.sh:115` turns into an `rsync --delete` **exclude**. But
`writeAdapter()` would re-serialise the whole adapter — including
`newsState.sources`, which `NewsBackend.qml:342-353` records as **not a native
JS Array on this Qt build**. Round-tripping it through the adapter risks
clobbering the operator's source list. So: **no `onAdapterUpdated` hook**.
`setViewMode()` reads the raw text, `JSON.parse`s it, sets one key,
`JSON.stringify`s it, and `setText`s it — the same idiom `writeCache()`,
`WeatherBackend.writeCache()` and `NotifServer` already use — and **refuses to
write, with a log line, if the parsed object has no usable `sources` length**,
so a malformed file can never be replaced by a lossy rewrite.

Consequence, and it is the desirable one: `viewMode` is a **readonly computed
property derived from the file**, so the screen and the disk can never disagree.
A failed write means the toggle visibly does not flip — honest feedback rather
than a silent divergence. This mirrors, verbatim, the LIVE-MEASURED CORRECTION
`NewsBackend.qml:132-149` already applied to `sources` for the same reason.

## Task 1 — `NewsBackend.qml`: image extraction, the third fence, `view_mode`

### (a) The namespace-tolerant child lookup

Add **directly beneath `_childrenNamed()`** (declaration order in this file is
load-bearing — see its header; everything stays above the two `FileView` blocks):

`_childrenNamedNs(node, localName)` — walks `node.childNodes` and pushes any
child whose `nodeName` is exactly `localName`, or whose `nodeName` ends with
`":" + localName`. Comment it with the reason from "Two design points" above:
the qualified-vs-local behaviour of this build's `responseXML` is unmeasured, so
the lookup is written to be correct either way rather than to bet on one.

### (b) The image extractor

Add `_imageOf(itemNode)` — a **general** preference order, no feed-specific
branch anywhere:

1. `_childrenNamedNs(itemNode, "thumbnail")` → first node's `url` attribute via
   the existing `_attrOf()`.
2. else `_childrenNamedNs(itemNode, "content")` → first node's `url` attribute.
3. else `_childrenNamed(itemNode, "enclosure")` → the first whose `type`
   attribute starts with `"image/"`, take its `url` attribute.
4. else `""`.

`enclosure` is unnamespaced in RSS, so it uses the plain `_childrenNamed`.

### (c) The THIRD fence point

Return `""` from `_imageOf()` for any candidate URL that does not start with
`root.allowedScheme`. **The item is still accepted** — only its image is
dropped, and it renders the glyph fallback. Log the drop (guard-logging
discipline: no guard in this file returns silently).

Then update the header's fence section: it currently says the allowlist is
enforced at **TWO** separate points and names them. It must now say **THREE**
and name the third (image-URL acceptance in `_imageOf()`), with the same
one-sentence rationale the other two carry — an image URL is a **new remote-host
class**, and a hostile feed response can carry one just as easily as a hostile
link.

Also rewrite the header's two host-naming blocks (the fence paragraph ~line 30
and the "three default hosts, named" block ~line 107-111) to the **four** new
hosts: `feeds.bbci.co.uk/news/world/rss.xml`,
`feeds.arstechnica.com/arstechnica/index`, `lwn.net/headlines/newrss`,
`www.phoronix.com/rss.php`. Change "three default hosts" to "four". **The
dropped host string must not survive anywhere in this file — see discipline
note 1.**

### (d) Wire `image` through parse, accept, and cache

- RSS branch: `image: root._imageOf(it)` alongside title/link/dateStr.
- Atom branch: `image: root._imageOf(e)` — Atom feeds can carry the same
  `media:*` children, and the extractor is format-agnostic, so this costs nothing
  and is not a feed-specific branch.
- Acceptance filter: carry `image: raw.image` into the accepted object. **Do not
  reject an item for a missing or bad image** — the whole point of the fallback
  tier is that a text-only source is a first-class source.
- `loadCache()`: revalidate the same way the other fields are — 
  `image: typeof it.image === "string" && it.image.indexOf(root.allowedScheme) === 0 ? it.image : ""`.
  Comment that **absent-key and empty-string converge on the same render path**,
  which is exactly why the spec needs **no migration step and no cache
  invalidation** for items written before this change.
- `writeCache()` needs no change — it stringifies `root.items` wholesale.

### (e) `view_mode`

## Task 2 — `NewsPane.qml`: the view toggle and the card delegate

### (a) The toggle chip

The existing `selectorHost` `Column` holds `selectorChip` then `selectorOptions`.
Wrap the chip in a `Row` so the new toggle sits **beside** it, per the spec's
layout, and leave `selectorOptions` as the Column's second child so the inline
expand still drops under the filter chip:

```
Column (selectorHost)
 ├─ Row (chipRow, spacing: Design.spacingSm)
 │   ├─ selectorChip      ← unchanged
 │   └─ viewToggleChip    ← NEW
 └─ selectorOptions       ← unchanged
```

`viewToggleChip` **mirrors `selectorChip` exactly** — same `BarRoles.capsule`
fill, same `radius: height / 2`, same `implicitWidth: <row>.implicitWidth +
Design.spacingMd * 2`, same `Behavior on color` through `Motion.standardDuration`
and `Motion.standardEasing`. Contents: one glyph `Text` at
`Design.iconSizeMd` in `Design.symbolFontFamily`, plus one label `Text` at
`Design.fontBody`; both `BarRoles.capsuleFg`, both `Text.PlainText`.

- Glyph: `root._cardMode ? "view_agenda" : "view_list"`.
- Label: `root._cardMode ? "Cards" : "Compact"`.
- **It is a toggle, not a dropdown** — `onClicked` calls
  `root.newsBackend.setViewMode(root._cardMode ? "compact" : "cards")` directly.
  No expand step, no third chrome state. Guard the click with `root._hasBackend`
  exactly as `selectorMouseArea` already does.

Add `readonly property bool _cardMode: root._hasBackend && root.newsBackend.viewMode === "cards"`
next to the existing `_hasBackend`. **One place decides the mode**, the same
discipline `paneState` already carries in this file — the delegate, the chip
glyph and the chip label all read this one property and can never disagree.

### (b) The delegate — one delegate, two modes

Do **not** fork into two delegates. A second delegate is a second place for the
row rhythm to drift, and the spec's whole point is that geometry is identical
between an image row and a glyph row.

`readonly property int _thumbSize: 76` on `root` (module-local — see "Ground
truth", with the `ClockPopout`/`MediaPopout` precedent and the 4px-grid check).

**Height** — compact must stay byte-identical to today:

```qml
height: root._cardMode
    ? (Math.max(root._thumbSize, headlineContent.implicitHeight) + Design.spacingMd * 2)
    : (headlineContent.implicitHeight + Design.spacingSm * 2)
```

That is the spec's own arithmetic: `max(76, ≈70) + 32` = **108px** in cards,
and today's `implicitHeight + 16` untouched in compact.

**The thumbnail slot** — mirrors `NotifCard.qml`'s `iconSlot` (lines ~186-193)
and inherits its hard rule verbatim: *always reserved, never blank, the card
never changes width*.

```qml
Item {
    id: thumbSlot
    anchors.left: parent.left
    anchors.leftMargin: Design.spacingSm
    anchors.verticalCenter: parent.verticalCenter
    visible: root._cardMode
    width: root._cardMode ? root._thumbSize : 0
    height: root._cardMode ? root._thumbSize : 0
    // ... capsule-filled Rectangle + glyph Text + Image, see below
}
```

**Text column re-anchor** — and the trap it avoids:

```qml
anchors.left: thumbSlot.right
anchors.leftMargin: root._cardMode ? Design.spacingMd : 0
anchors.right: parent.right
anchors.rightMargin: Design.spacingSm
```

With `thumbSlot.width === 0` and `leftMargin === 0` in compact, the text column's
left inset stays exactly `Design.spacingSm` — today's value. **Without the
conditional `leftMargin` this silently shifts compact by 16px**, which is the
one thing the spec forbids. The spec's "306px" text column is illustrative of the
proportions; the real layout is anchor-derived so it cannot drift if the surface
width ever changes.

**The fallback tier — two tiers, one shorter than `NotifCard`'s four.** The slot
is a `Rectangle` filled `BarRoles.capsule` with `radius: Design.spacingSm`,
holding:

- a centred glyph `Text` — `"newspaper"`, `Design.symbolFontFamily`,
  `Design.iconSizeMd`, `BarRoles.capsuleFg` — visible when the image did not
  resolve. `newspaper` is deliberately the **same glyph tab 1 carries**, exactly
  as `NotifCard`'s final tier is the generic bell that ties to notifications.
  There is **no icon-theme tier** here, because a feed has no `app_icon`
  equivalent — record that, so a future reader does not "restore" a missing tier.
- the `Image`, `anchors.fill: parent`, `clip: true`,
  `fillMode: Image.PreserveAspectCrop`, `asynchronous: true`, and
  `sourceSize.width` / `sourceSize.height` **both pinned to `root._thumbSize`**
  so decode is bounded regardless of source dimensions (Ars ships 500×500, BBC
  240×135 — both downscales into 76). Visible only on `status === Image.Ready`,
  so a URL that 404s falls through to the glyph rather than leaving a hole.

**THE ZERO-REQUEST RULE, and the trap that breaks it:**

```qml
source: root._cardMode && headlineDelegate.modelData.image ? headlineDelegate.modelData.image : ""
```

Qt issues a network request iff `source` is non-empty. **`visible: false` does
NOT prevent an Image from loading** — gating on `visible` would silently violate
the spec's "compact issues zero image requests". The `source` binding is the
load-prevention mechanism; `visible` and `width` are layout only. Say so in a
comment at the binding, because this is exactly the kind of thing a later
"simplification" removes.

### (c) Card-mode meta line

  `dateMs === 0` branch.
- **cards** — a `Row`: a `BarRoles.capsule`-filled, `radius: height / 2`
  `Rectangle` wrapping the source name at `Design.fontLabel` in

  compact's own handling.

## Out of scope

Unchanged from 260819-6oy, plus the spec's two new exclusions:

- **No `og:image` scraping.** Measured at ~1.2 MB and ~13 s per refresh plus
  browser-UA spoofing. Phoronix is a text-only source by design.
- **No BBC CDN width rewriting.** The 240px original is already 3× oversampled
  for a 76px slot. The rewrite is recorded in the spec so the option is *known*,
  not so it is taken.
- **No thumbnail in compact mode.** The spec flagged this and it was approved as
  written: the toggle is image-on / image-off, not two sizes of image.
- **No feed-specific extraction code.** One general preference order or nothing.
- **No cache migration or invalidation.** Absent-key and empty-string converge on
  the same render path — that is why none is needed.
- **No new `Design.qml` token.** The 76px thumb is module-local.
- **No in-shell source editor**, no article bodies or reader view, no refresh
  timer beyond the manual button, no read/unread state, no JSON Feed support.
- **No gate-script edits.**
- Anything under `fastfetch/`, the weather panel, or the bar.
