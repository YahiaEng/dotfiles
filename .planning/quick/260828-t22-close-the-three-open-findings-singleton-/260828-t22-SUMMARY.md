# Close the three findings left open by 260828-so7

Two of the three are closed with code. The third is deliberately not taken, and
one of the "findings" turned out not to be a defect at all.

## Two measurements reordered the whole task

**1. `qml-import-check` does not validate singleton member names.** Positive
control: injected `BarRoles.thisRoleDoesNotExist` into a live file and the gate
still reported `0 unresolved references across 191 file(s)`. Its own header says
why — dotted forms are "enum/attached references" and are excluded structurally.

**2. Quickshell watches only files it has actually LOADED.** A comment touch on
the loaded `SystemCapsule.qml` produced a reload (`delta=5`, one
`Configuration Loaded`); the identical touch on the lazily-loaded
`UpdatesPopout.qml` produced **zero** log lines.

Together those mean a bad role name on a lazily-loaded surface is invisible to
`qmllint` (blind here), to `qml-import-check` (by design), and to the runtime log
(never loaded) — until a user opens that surface and sees a wrong colour. So the
75-reference migration had **no safety net at all**. Build the net first.

## A correction I owed, and made

260828-so7's commit and SUMMARY cited the hot reload as evidence its BarRoles
routing loaded cleanly. `UpdatesPopout.qml` has never been loaded, so the reload
never exercised it — the `Configuration Loaded` lines came from other activity.
The static gates were real and stand; that runtime claim did not. Withdrawn in
both the so7 SUMMARY and its STATE.md row rather than quietly dropped, and the
gap it exposed is now closed statically.

## Task 1 — `singleton-prop-check` (new gate)

Resolves every `<Singleton>.<member>` against the members that singleton
declares. Singletons discovered from `qmldir` manifests — **26 found**, never
hand-listed, so tomorrow's singleton is covered without editing the gate.

A new gate rather than an extension of `qml-import-check`, which resolves *types*
and would have to contradict its own documented model to do this.

**Deliberately over-approximates**: members are collected from anywhere in the
singleton's file, not just its root object. `Colours.qml` declares its palette
inside a nested `JsonAdapter` behind an alias layer, and a strict top-level parse
would false-fail every `Colours.*` consumer in the tree. It catches names that
exist **nowhere** — the typo/removed-role class — and does not police scope. A
fixture pins that nested shape so nobody "tightens" it later.

Self-test 4/4, including two fixtures that must **pass**: an enum lookalike
(`Roles.SomeEnum`, capital second segment) and a bogus member appearing only in a
comment and a string literal. Live: `singletons=26 scanned=191 violations=0`.
Poison-tested against a **real** site, not only fixtures.

## Task 2 — `TapHandler.PassiveOnly` does not exist

Measured against `/usr/lib/qt6/qml/QtQuick/plugins.qmltypes`: `GesturePolicy` has
exactly four values, and `PassiveOnly` appears **nowhere in Qt**. Every
assignment failed at runtime and the handler silently used its default.

A **population, not an instance** — all four `gesturePolicy` lines in the repo
were this same invalid value (`SliderRow`, `ToggleRow`, `SelectRow`,
`StepperRow`). Only `SelectRow` appeared in the log, because it was the one
instantiated; the other three were equally broken and equally silent.

**Removed, not replaced.** What shipped — and what the operator approved live in
round 5 — *is* the default. Substituting a real-but-different policy would change
approved behaviour on surfaces that cannot be exercised from an agent shell. The
comments, which described a handler that "never grabs the point", were corrected
to say what actually happens.

Not runtime-confirmed: these rows were not loaded, so no reload fired. Operator
confirms by opening Settings.

## Task 3 — nine popouts migrated, WINDOWS row 57 closed

All **75** `Colours.*` references across the nine SectionPopout-family files now
route through BarRoles. `QSD_BAR_COLOUR_ROLE_EXEMPT` shrinks from ten entries to
one. `bar-colour-role-routing` goes `scanned=18` → `scanned=27`, `offenders=none`
— nine files came out from behind the exemption.

Two exact-alias roles added (`popoutSurface`, `popoutSurfaceVariant`) rather than
reusing `capsule`/`barSurface`, which are the same palette tokens **carrying
alpha** (0.85/0.55). Substituting those would have changed how nine surfaces
render. Every mapping is value-identical, so no popout can look different by
construction — appearance changes belong to a separate decision made against a
render, not smuggled in under a refactor.

Replacement was single-pass with word-boundary matching (so `onSurface` cannot
corrupt `onSurfaceVariant`), code only, never comments. Per-file counts matched
the pre-measured baseline exactly, zero unmapped roles.

WINDOWS row 57 closed in both the table **and** its JSON twin, with the array
re-parsed to prove it still loads.
