# Quick Task 260828-u0r — Expand the emitted colour-role set

## Objective

The theme pipeline emits 19 colour roles to QML. matugen offers 50. Add the
Material 3 tonal-surface ladder and the other high-value missing roles, through
**one** pipeline so the static-preset and matugen-dynamic branches emit an
identical role set.

This unblocks two follow-on tasks: the settings NavRail cannot render
Caelestia's grouped filled pills without `surfaceContainerHigh`, and shell
components currently fake elevation with alpha tints over `surface`.

## Measurements that decided the design

All figures below were measured on this host, not assumed.

**1. The gap.** `matugen color hex … --json hex` exposes **50** roles under
`colors.*`. `matugen/.config/matugen/templates/qml-palette.json` emits **19**.
31 unemitted. `modules/Colours.qml` mirrors the same 19 exactly.

**2. The static branch already runs through matugen.** `lib/generate.sh:85`
renders static presets with `matugen json "$palette" -c "$MATUGEN_CFG"` — the
same config and the same templates as the dynamic branch. Parity is by
construction (D-03), so the template is the single place to add roles.

**3. But matugen does NOT synthesize missing roles from a partial palette.**
Probed role-by-role against `palettes/catppuccin.json` (24 keys), with
`surface` as a positive control:

| Probe | Result |
|---|---|
| `surface` (positive control) | OK — `#1e1e2e` |
| `tertiary_container`, `on_tertiary_container`, `error_container`, `on_error_container` | **OK** — already in every preset |
| `surface_container{,_low,_lowest,_high,_highest}`, `surface_dim`, `surface_bright`, `outline_variant`, `scrim`, `shadow`, `inverse_*` | **MISS** — "Value does not exist in the context" |

So the four `*_container` roles are free wins, and the rest must be supplied to
matugen for static presets.

*Instrument note:* the first run of this probe reported every role MISSING
including `surface`. That was the harness, not the data — the loop ran under
zsh, which does not word-split unquoted parameters, so `for r in $ROLES`
iterated once with the whole string as one role name. The positive control is
what caught it. Re-run under `bash`, the table above is the real result.

**4. The ladder is a linear blend of `surface` toward `on_surface`.** Solved
per channel across 3 unrelated source colours × 2 modes. Channel spread is
mostly <0.007, i.e. the relationship really is a single scalar per role:

| role | dark `t` | light `t` |
|---|---|---|
| `surface_container_lowest` | −0.0274 | −0.0271 |
| `surface_container_low` | +0.0392 | +0.0255 |
| `surface_container` | +0.0591 | +0.0521 |
| `surface_container_high` | +0.1084 | +0.0771 |
| `surface_container_highest` | +0.1605 | +0.1032 |
| `surface_dim` | 0.0000 | +0.1422 |
| `surface_bright` | +0.1819 | 0.0000 |

Reconstructing matugen's own output from these fractions: **worst per-channel
error 9/255**, typical <4/255. The residual is because matugen blends in HCT
(chroma-preserving) and this is an sRGB blend; the worst case is the warm
light palette. Acceptable — for static presets there is no matugen ground
truth to be wrong against, the presets are hand-authored.

**5. The other derivations.** Also measured across the same 6 palettes:
- `scrim` = `shadow` = `#000000` — constant in every mode, every palette.
- `outline_variant` = blend(`outline` → `surface`, t ≈ **0.60**) (measured
  range 0.590–0.613).

**6. Polarity detection is already owned.** `lib/mode.sh`'s
`theme_engine_detect_mode` is the THM-01 single source of truth and is already
in `generate.sh`'s scope. Independently confirmed that a luminance comparison
of `surface` vs `on_surface` classifies all 6 measured palettes correctly, but
the existing helper is used rather than re-deriving it.

## Scope

**Adding 14 roles** (19 → 33):

- ladder (5): `surfaceContainerLowest`, `surfaceContainerLow`,
  `surfaceContainer`, `surfaceContainerHigh`, `surfaceContainerHighest`
- (2): `surfaceDim`, `surfaceBright`
- (1): `outlineVariant`
- (2): `scrim`, `shadow`
- (4, free — already in every preset): `tertiaryContainer`,
  `onTertiaryContainer`, `errorContainer`, `onErrorContainer`

**Deliberately deferred, with reason** (reported, not silently dropped):

- `inverse_surface`, `inverse_on_surface`, `inverse_primary` (3) — niche
  (snackbar/tooltip inversion), and `inverse_primary` measured as *the
  opposite mode's* `primary`, which a single-mode static preset cannot supply.
  No clean derivation; no consumer today.
- the 12 `*_fixed*` roles — MD3's cross-mode-consistent accent set. No
  consumer in this shell and no static-preset source.
- `source_color` — generator metadata, not a paint role.

## Tasks

1. **`lib/generate.sh` — augment static presets before matugen sees them.**
   Add a derivation step that reads the preset, computes the 10 derived roles
   from `surface`/`on_surface`/`outline` using the fractions in §4/§5 and the
   mode from `theme_engine_detect_mode`, and writes an augmented palette to the
   temp render tree; point the static branch's `matugen json` at that instead
   of the preset. Presets stay hand-authored at 24 keys, and any future preset
   gets the new roles automatically.

2. **`templates/qml-palette.json`** — add the 14 roles.

3. **`modules/Colours.qml`** — add the 14 to the inner `base`/`onRoles`
   objects, the `readonly property alias` layer, and the `roles` array,
   honouring the file's documented X/onX split constraint.

4. **Gates:** `theme-doctor`, `theme-parity`, `colour-lint`,
   `singleton-prop-check`, `quickshell-doctor`.

## Verification

- Both branches emit an identical 33-key `palette.json` (compare a static
  preset render against a materialyou render, key sets only).
- No role resolves to the `#FF00FF` debug magenta default in `Colours.qml`.
- All gates green.
