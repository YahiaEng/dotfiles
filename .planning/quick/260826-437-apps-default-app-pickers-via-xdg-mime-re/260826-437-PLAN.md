## Decisions this plan makes, and why

**D-1 — `indexLabel`, defaulted to `label`, on all seven row primitives.** The search index needs a
stable key; the user needs a real title. Those are two different strings and have been conflated
since the index was built. `property string indexLabel: root.label` is a binding, so every one of
the ~176 existing rows keeps its exact current key with zero call-site edits and `RowIndex.qml`
stays byte-identical apart from the one entry Task 1 touches. All seven get it, not just `NavRow`,
so `Pages.qml` can read one property unconditionally and so the next repeater-backed row — whatever
type it is — is already unblocked.

**D-2 — Only `AllAppsPage` is converted; the other four repeater sites are reported, not changed.**
"Resolution & refresh rate" repeated per monitor and "Per-app volume" repeated per audio client are
the *same* setting name genuinely appearing N times, with the device/app name already in subtext.
"App" appearing 52 times is a different thing: the label carries no information at all. Converting
the other four is a cosmetic decision the operator has not asked for and would touch three more
pages. They are listed in the SUMMARY as now-unblocked, with the one-line shape.

**D-3 — CHECK B is taught `indexLabel` AND is made comment-stripping, in the same commit.** The
first half is mandatory: without it AllAppsPage's `{pageIdx: 11, subPageIdx: 1, … label: "App"}`
entry fails the gate the moment the row's `label:` goes dynamic. The second half is a two-line
hardening of the same block that makes the gate header's existing claim true and closes the
matches-its-own-comment class — the one this repo has already shipped twice. Implemented with a
**herestring, never a pipe**: `stripped=$(strip_comments "$f")` then `grep -qF … <<<"$stripped"`,
because `X | grep -q` under `pipefail` can exit 141 on a match and silently flip a verdict.

**D-4 — The two new Apps rows store a DESKTOP ENTRY ID; the two existing ones keep storing an
EXECUTABLE.** Opposite value types, deliberately, in the same section. `apps.terminal`/`apps.audio`
are exec'd directly by four consumers in argv arrays, so they must be bare executables (D-6 of the
prior task). `xdg-mime default` takes a desktop-entry *file name* and nothing else. `_exe()` must
never be applied to the new rows and `_filteredModel()` is left untouched — a second helper is
added rather than one helper made polymorphic.

**D-5 — The per-package command is `paru -S --needed <name>`, with NO `-y`, one command for both
sources.** Three separate judgements:
  - *No `-y`.* `pacman -Sy <pkg>` / `paru -Sy <pkg>` is the exact construct Arch's own wiki names as
    the partial-upgrade footgun: it refreshes the database and then installs one package against a
    system that has not been upgraded, dragging in newer dependencies. Omitting `-y` bounds the
    operation to the database already on disk. Combined with the measured fact that `checkupdates`
    syncs to a *temporary* db, the honest worst case becomes "paru reports nothing to do" — a no-op
    — rather than a broken system. That trade is stated in the UI, not hidden.
  - *`--needed`.* Turns the stale-database case into an explicit skip instead of a silent reinstall
    of the same version.
  - *One command, not a repo/AUR branch.* `paru` is a pacman wrapper: `paru -S <name>` resolves a
    repo package through pacman and an AUR package through a build. Both existing update paths in
    this tree already shell `paru` (`UpdatesPage.qml:208`, `SystemCapsule.qml:588`). A `sudo pacman
    -S` branch for repo packages would add a second code path, a second privilege-escalation shape,
    and no capability. The `source` field is still used — it draws the AUR tag, as it does today.

**D-6 — The risk is surfaced two ways: a two-step arm on the cell, and one searchable InfoRow.**
  - *Two-step arm.* First click arms the cell (error-coloured ring + an in-cell line naming the
    risk); second click launches; a 6 s Timer or arming any other cell disarms. This settings
    surface has no dialog primitive, and a 50-cell grid where one stray click starts a partial
    upgrade is not acceptable. The arm puts the warning at the point of action, where it is read.
  - *One `InfoRow "Single-package updates"`*, immediately above the grid — so the risk is
    discoverable by reading and by searching, not only by clicking. `pageIdx: 14` goes 3 → 4
    entries.
  - *No opt-in Prefs toggle.* The operator asked for this feature deliberately on their own
    machine; shipping it default-off would mean shipping its absence. The arm already makes
    accidental invocation impossible, which is the actual risk being managed.

**D-7 — Model = `gio`-registered ∩ category, current value = `xdg-mime query default`.** Two reads
per row, four short-lived bounded `Process` children on the Apps page, each justified:
  - The *model* must be "apps that declare they can open this type" — that is the thing being
    written. `DesktopEntry` cannot answer it (measured: no MIME field), `gio mime` can.
  - Intersecting with the operator's measured category predicate (`FileManager`, `Player`) drops
    `kitty-open.desktop` from the file-manager list — registered for `inode/directory`, but not a
    file manager.
  - The *current value* must come from `xdg-mime query default` because that is what `xdg-open`
    consults on this host (measured above), and it disagrees with `gio`'s answer today.
  - Four processes is not a cost worth optimising on a page whose sibling already spawns
    `checkupdates` (a full `pacman -Sy` into a temp db) and `paru -Qua` (network).

**D-8 — Writes go through `Quickshell.execDetached`, reads through a page-scoped `Process`.** The
repo's 260822-sht rule is about work that must outlive the surface: a `xdg-mime default` write
fired as the user navigates away must not be killed mid-write. The four reads are bounded and
naturally capped by the page's lifetime, exactly as `UpdatesPage`'s own two probes are, and its
header already records that reasoning.

**D-9 — No new Prefs keys anywhere in this plan.** `~/.config/mimeapps.list` is the store for both
new pickers and `xdg-mime` is its only writer. `Prefs.qml` is deliberately absent from
`files_modified`; if a task finds itself wanting a Prefs key, that is a signal the design drifted.

This is the vertical slice: one new property threaded through primitive → matcher → gate → first
consumer, proven end-to-end by a runnable gate. Ship it alone, as one atomic commit, before either
page task.

The bug being fixed is not "AllAppsPage has a bad label". It is that this module has ONE string
doing TWO jobs — the row's displayed title and the search index's lookup key — so any row whose
title must vary is forced to display a constant. That forcing is real and documented:
`Pages.qml:_recollectRows()` matches the jump target with an exact comparison against the row's
`label`, and `settings-index-check` CHECK B greps the page file for the RowIndex label verbatim.
Enumerating rows statically dodged it twice (AboutPage's nine system fields, UpdatesPage's package
grid). A Repeater over installed apps cannot dodge it. Separate the two jobs.

**Step 1 — the property, on all seven primitives.**

Add to each of `InfoRow.qml`, `NavRow.qml`, `SelectRow.qml`, `SliderRow.qml`, `StepperRow.qml`,
`TextRow.qml`, `ToggleRow.qml`, immediately beneath the existing `property string label`:

    property string indexLabel: root.label

A binding, not a copy — a row that never sets it tracks `label` forever, so all ~176 existing rows
keep their exact current jump key and no call site outside `AllAppsPage.qml` changes. Document it
in each file in one line, and in `common/`'s own convention terms: *the string RowIndex keys on and
`settings-index-check` greps for; override it only when the displayed `label` is dynamic.* Do NOT
add it to `PageBase`/`SettingsSection`/`StackPage` — they are not rows and declare no `focusable`.

**Step 2 — `Pages.qml` matches on the key, not the title.**

Add a small helper declared ABOVE `_recollectRows()` (this file's declare-before-construction-time-
use discipline, and `_recollectRows` is reached from `Component.onCompleted` via `_swapTo`):

    function _rowKey(row) — returns row.indexLabel when it is a non-empty string, else row.label.

Replace the exact comparison inside `_recollectRows()`'s jump block with a comparison against
`root._rowKey(root._focusableRows[j])`. The defensive fallback is there because `_collectFocusableRows`
pushes anything declaring `focusable === true`, which is a duck-type contract, not a base class —
a future row type that forgets `indexLabel` degrades to today's behaviour instead of matching
`undefined`. Nothing else in the jump block moves: `_applyRowFocusVisual()` stays immediate, the
scroll stays behind `Qt.callLater`, and the not-found `console.warn` keeps naming the label — a
guard that returns silently is what turned a real rejection into "the edit did nothing" in a prior
wave on this exact surface.

**Step 3 — `settings-index-check` CHECK B (D-3).**
