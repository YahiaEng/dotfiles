protocol since waybar was retired (Phase 18 Plan 20, RETIRE-02) and the tray capsule
was deleted under Phase 18.1 D-15, so apps that minimise to tray hide into a tray that

<measured_ground_truth>
Verified on this host during planning. Do not re-derive; do not "correct" any of it
from memory.

**`SystemTray.items` is an `UntypedObjectModel`** whose `values` property is a
`QObjectList` with a `valuesChanged` notify signal
(`/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes:1631-1643`). So
`SystemTray.items.values` is a plain JS array that re-evaluates on change and can be
`.slice()`d — this is what makes the D-1 inline/overflow split possible with no
manual index bookkeeping. Repo precedent for the identical idiom on a different
ObjectModel: `modules/launcher/Launcher.qml:193`
(`DesktopEntries.applications.values.filter(...)`).

**`display()` signature**
(`/usr/lib/qt6/qml/Quickshell/Services/SystemTray/quickshell-service-statusnotifier.qmltypes:203-209`):
`display(QObject* parentWindow, int relativeX, int relativeY)`. `QsWindow.window` is
the reachable parent-window handle inside a bar capsule — `IdleInhibitorCapsule.qml`
already uses it (`IdleInhibitor { window: QsWindow.window }`).

**Material Symbols ligatures**, checked against the installed
`MaterialSymbolsRounded[FILL,GRAD,opsz,wght].ttf` glyph order with `fontTools`, with a
deliberate absent control that correctly read ABSENT: `expand_more` PRESENT,
`apps` PRESENT. Both are safe to use; no further ligature check is needed for this plan.

**`Design.barGlyphSize` (16) is the bar's icon size, not `iconSizeMd` (24).**
`dashboard/Design.qml:160-175` records borrowing the dashboard's `iconSizeMd` for bar
glyphs as the measured root cause of GATE-02's "unmistakably larger" failure. The
deleted 18-10 tray used `iconSizeMd`; that is one of the things being corrected here.

**`~/.config/quickshell/modules` is a whole-directory stow symlink into this repo**, so
a new file under `quickshell/.config/quickshell/modules/bar/` is live at the linked
path immediately. No `stow` re-run is needed for the lints to see it.

**Gate invocations** (all take a directory root; a single file path makes them scan 0
surfaces and FAIL check C — do not pass one file):

  — CHECK A "all Colours.* references resolve", CHECK B "no hard-coded colour".
- `hypr/.config/hypr/scripts/motion-lint ~/.config/quickshell`
  — CHECK A "all Motion.* references resolve". **This is the token-resolution proof**
  the house rules require; a token that is merely read but undeclared fails CHECK A.

  (no `Colours.*` in a non-exempt `modules/bar` file) and
  `bar-colour-alpha-resolution`.

**`quickshell.log` start marker** is the line `quickshell-launch.sh: starting`
(`quickshell-doctor:2868`). The log contains null bytes — `grep` treats it as binary,
so **every grep of it needs `-a`**.

**Restarting the shell**: `systemctl --user restart quickshell.service`. The unit is
live (`is-active` = active) and systemd-owned, so this is detached and survives the
agent's shell — unlike a foreground relaunch, which silently kills the shell when the
agent's shell exits.

  byte-identical to an `Active` one.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tray app (any desktop app) → shell process | An arbitrary application publishes `icon`, `title`, `tooltipTitle`, `tooltipDescription` and a DBusMenu over the session bus, and the shell renders them in a permanently-mounted surface. |
| DBusMenu → compositor popup | The menu content and its actions are owned by the foreign app; Quickshell builds the popup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-65s-01 | Spoofing | `title` / tooltip strings rendered in `TrayCapsule.qml` and `TrayPopout.qml` | medium | mitigate | Every tray-supplied `Text` declares `textFormat: Text.PlainText` and elides — no rich-text or link parsing on an attacker-influenced string. No tray string is ever used to construct a command, path or dispatch string anywhere in either file. |
| T-65s-02 | Tampering | `SystemTrayItem.menu` (`DBusMenuHandle`) | low | accept | Per CONTEXT CORRECTION 2 the menu is opened via `item.display(...)` and rendered by Quickshell's own DBusMenu implementation — the shell hand-rolls no menu tree, so this plan adds no new parsing surface. Residual risk is Quickshell's, not this repo's. |
| T-65s-03 | Denial of Service | inline icon row width | low | mitigate | D-1's hard `inlineLimit: 3` bounds the bar's growth by construction — an app registering many tray items cannot push the clock or any other capsule off-screen. |
| T-65s-SC | Tampering | package installs | n/a | accept | This plan installs no packages. `Quickshell.Services.SystemTray` and `Quickshell.DBusMenu` ship inside the already-installed `quickshell` package (verified present at `/usr/lib/qt6/qml/Quickshell/`), so no package-legitimacy gate applies. |
