# Quick Task 260819-pi3 — In-shell news source editor

## Objective

Promote `.planning/seeds/news-source-editor-ui.md`: add, remove, enable/disable
and RENAME news feeds from inside the notification centre's News tab, with a
LIVE PROBE of the pasted URL before anything is written to
`~/.local/state/theme/news-sources.json`.

The seed estimates this as phase-sized. The operator was told that and chose
quick-task execution, then widened the scope again (probe + editable names) on
the same terms. It is planned here as **four** tasks, not the usual two or
three — see "Why four tasks" below.

## Scope

**IN:**

1. A gear chip beside the existing filter chip, opening a manage-sources
   overlay.
2. One row per source: enable/disable toggle, inline rename, delete.
3. Add: paste a URL → **live probe** → editable name prefilled from the feed's
   own title → commit.
4. Validation with specific inline reasons, reusing the existing rules
   (`allowedScheme`, `maxSources`, `_validSources()`'s non-empty-name rule).
5. Persistence through the read-modify-write idiom, with its refuse-on-malformed
   guard intact.
6. A backend accessor exposing ALL sources including disabled ones.
7. Filter/identity reconciliation on delete, disable and rename.

**CUT — state these plainly in the SUMMARY:**

- **Drag-to-reorder.** Headlines sort by date and selection is round-robin by
  source (`_finishRun()`), so list order affects nothing but tie-breaks. Most
  QML-expensive item, least load-bearing.
- **Per-source tunables** (`max_items_per_source` etc. stay hand-edited).
- **Any change to the four seeded defaults** in `stow.sh` — the seed block and
  the live host file are untouched by this task.

## Decisions taken while planning (with the measurement behind each)

### D-1 — Delete gets a row-scoped inline two-step confirm, not a modal

Deleting is data loss on a hand-curated list, so a bare one-tap delete is a
footgun. A modal is out of proportion **and has no precedent**: this repo's
established idiom for exactly this is inline and row-scoped —
`WifiPanel.qml:119` (`property var confirmForgetNetwork: null`), `:726`
(`readonly property bool isConfirmingForget: ...`) and `:1085-1118` (the
`Forget <name>?` / `Forget` / `Cancel` inline row), which its own comment says
mirrors `BluetoothPanel.qml`'s `forgetConfirmLabel` "character for character".
Copy that shape. **Disable gets no confirm — it is reversible.**

### D-2 — Confirm and edit state are keyed by URL, never by row index

A `splice()` shifts every index after it. An armed confirm holding index 2
would, after an unrelated delete, arm a different row. URLs are unique by this
task's own duplicate rule, so every mutator takes the source's `url` as its
identity handle and matches by exact string; a handle that no longer matches is
logged and no-ops. Mirrors `WifiPanel.qml`'s keying by the network OBJECT rather
than by position, for the identical reason.

### D-3 — `sourcesFile` does NOT gain `atomicWrites: true`

Anchor 7 asks for a decision. **No**, and the reason is not "it does not matter":

- `setViewMode()` already writes this exact file through `setText()` with
  `atomicWrites` unset, and that path is shipped and operator-approved (260819-m94).
  Enabling it now changes the write mechanism *underneath a proven-working path*
  to benefit a new one.
- Whether `watchChanges: true` still fires across whatever replace-on-write
  `atomicWrites` performs on this build is **not measured**, and this project's
  standing rule forbids betting on it. The whole editor depends on the watch
  firing — `allSources` re-derives from it.
- The exposure it would close is a crash between truncate and write of a <1 KB
  buffer. The blast radius is bounded by two existing facts: `_writeSources()`
  refuses to write over a file it cannot parse (so a torn file is never
  *compounded*), and `stow.sh:382` re-seeds the file when absent, so the recovery
  is `rm` + re-run `stow.sh`.

If a torn write is ever actually observed, the fix is to set `atomicWrites: true`
on `sourcesFile` **and re-verify that an external edit still hot-updates the
pane** — do not do the first without the second.

### D-4 — Name length is bounded at the input; layout is bounded in pixels

Operator-authored names render into four `Text` elements. Two are already safe
(the dropdown row and the compact meta line both `elide`), two are **not**: the
filter chip's label (`NewsPane.qml:176-182`) has no width and no elide and drives
`selectorChip.implicitWidth` directly, and the card meta capsule
(`sourceCapsuleText`, `:631-638`) has neither.

A character-count bound cannot guarantee layout here: `Design.qml:98-107`
deliberately pins **no** font family — the shell inherits the GTK font from
gsettings, by design, so pixel width per character is not knowable at plan time.
So the two guarantees are separate:

- **Data hygiene (input rule):** 1–32 characters after normalisation. Rejects
  empty/whitespace-only (which `_validSources()` would silently drop) and absurd
  paste-bombs.
- **Layout (pixel rule, font-independent):** cap those two unbounded `Text`
  elements with `width: Math.min(implicitWidth, <cap>)` plus
  `elide: Text.ElideRight`.

Markup is already inert: every `Text` in `NewsPane.qml` that renders a name sets
`textFormat: Text.PlainText` (`:179`, `:388`, `:612`, `:635`, `:720`). New rows
must do the same. Control characters are stripped by `_normaliseName()` — a
single-line field cannot type a newline but a paste can carry one.

### D-5 — The probe is a second CALLER of one transport, not a second fetcher

`_fetchSource()` today entangles transport with run bookkeeping. Extract
`_fetchXml(url, onDone)` — the XHR, the `allowedScheme` re-check, the
`maxResponseBytes` bound, the `_activeXhrs` registration — and make
`_fetchSource()` and `probeSource()` both call it. One implementation, one fence,
and `abort()` already kills the probe on centre close for free.

The probe **must not** touch `requestsInFlight`, `sourcesOk`, `sourcesFailed`,
`lastError` or `_runBuffer`: `_fetchSource()`'s callback fires `_finishRun()` on
`requestsInFlight === 0`, so a probe sharing that counter would publish a
half-built run. The probe carries its own `probeState` register instead.

### D-6 — After a source is added or enabled, refresh is deferred, never immediate

`refresh()` reads `root.sources`, which derives from the child `JsonAdapter`.
Calling it straight after `setText()` reads the pre-write value — the exact
"child's binding lags the parent's signal" class this file's own
`onCentreOpenChanged` comment documents (quick task 260819-426, one full debug
cycle). So: set a flag, and let `onSourcesChanged` — the change signal of the
readonly computed property, which the file already relies on re-deriving
correctly — consume the flag and `Qt.callLater()` the refresh.

Without this, adding a feed appears to do nothing for up to `ttl_minutes` (15).

## Why four tasks

Two backend seams (mutation+identity, transport+probe) and two UI surfaces
(the editor shell and rows, the two-stage add flow). Tasks 1+2 and 3+4 each
touch one file, sequentially. Folding 1+2 into one task would put ~250 lines of
new backend into a single edit of an 843-line file whose declaration order is
load-bearing; folding 3+4 would do the same to the pane. The task cap is a
context-quality heuristic, not a budget — four small commits beat two large ones
here.

## Standing discipline carried in from the predecessor

- **Every property and every function goes ABOVE the two `FileView` blocks.**
  `NewsBackend.qml:69-88` records why: a member declared below its own
  construction-time call site throws `TypeError: ... is not a function`, logged
  ONLY to `~/.cache/quickshell.log`, and presents as a silently empty News tab.
- **Never `Array.isArray` on anything reached through `newsState`** — anchor 5,
  measured live and recorded at `NewsBackend.qml:434-449`. Duck-type on
  `typeof x.length === "number"`. `loadCache()`'s existing use of that predicate
  against a real `JSON.parse` result is correct and must remain (the gate below
  asserts exactly one occurrence in the file, not zero).
- **`//` line comments only** in both QML files, so every comment-stripping gate
  keeps working.
- **`pipefail` + `grep -q` is banned in every gate.** Under `pipefail`,
  `X | grep -q` can exit 141 on a match, flipping a verdict as a function of file
  length. Every gate below uses `grep -c` with an explicit numeric comparison.
- **Do not name a gate's banned token in a code comment.** Every zero-count gate
  below strips `//` lines first (`grep -vE '^[[:space:]]*//' FILE | grep -c TOK`),
  because a gate that greps its own warning prose reports a false failure.
- **Screenshot before the SECOND code-reasoned layout fix.** During 260819-m94
  three successive layout fixes reasoned from source were all wrong and each
  widened the defect; one screenshot showed the truth in seconds.
  `grim -g "$(hyprctl -j layers | ...)"` on the single notif-centre layer surface
  is SAFE on this host — only fullscreen capture hits the known SIGSEGV.
- **Do not anchor a QQC2 `Control`'s `contentItem`** — it breaks the control's
  implicit sizing and shrinks its background below its content. Use the control's
  own padding, and set `width`/`height` explicitly the way `WifiPanel.qml:993-997`
  does.
