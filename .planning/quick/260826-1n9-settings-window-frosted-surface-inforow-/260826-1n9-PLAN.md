## Decisions this plan makes, and why

**D-1 — Frost is 0.78 on the interior Rectangle, and the window becomes transparent.** Operator-
locked opacity. Applied the way all five precedent surfaces apply it (`color: "transparent"` on the
window + `Qt.rgba(...)` on the interior fill), because that is the shape that is known to work on
this compositor and because the window's own `color:` is invisible under the full-bleed background
Rectangle anyway. The colour **role stays `Colours.surfaceVariant`** — the operator asked for
frost, not for a different colour.

**D-2 — `InfoRow` gains `property string icon: "info"`.** Defaulted, so all 40+ existing call
sites render byte-identically and no other page needs touching in the same commit. This is the
minimum change that fixes F2, and it fixes it once for About, Updates and every future page.

**D-3 — About enumerates nine named rows; the Repeater goes.** The static-label rule exists because
a Repeater's per-item label breaks `pendingRowLabel`'s exact-match jump key. Nine system fields are
a **fixed** set, so the Repeater was never buying anything — nine literal `InfoRow`s give nine real
titles, nine RowIndex entries, and nine independently searchable rows, with no primitive change and
no gate change. Absent fastfetch fields render with an honest "Not reported by fastfetch" subtext
rather than disappearing, because `_collectFocusableRows` does not filter on `visible` and a hidden
row would still occupy a keyboard-focus slot.

**D-4 — Updates' package list is a `component PackageCell`, not a row primitive.** Package count is
dynamic, so any row-primitive delegate re-creates exactly the repeated-static-label defect being
fixed. A local `component PackageCell: Rectangle` is invisible to `ROW_PRIMITIVE_RE` (measured
above), so the grid needs zero RowIndex entries and the page's three real rows stay exactly
indexable. **The grid does not scroll independently** — it flows inside `PageBase`'s existing
Flickable, which provides the scrolling. A nested scrollable inside a Flickable produces the
wheel/drag routing conflict this repo has already been bitten by; one scroller per surface.

**D-5 — "Update all" stays a `NavRow`.** The operator asked for it to be prominent. A bespoke
button would be invisible to `_collectFocusableRows` (unreachable by keyboard) and to
`ROW_PRIMITIVE_RE` (unindexed, unsearchable). Prominence is bought with the `download` glyph, its
own section, and first position — not by leaving the row system.

**D-6 — Apps pickers store an EXECUTABLE token, filtered by Category.** Operator-locked filters.
The stored value must be an executable because all four consumers exec it directly and two build
argv arrays; `Prefs`' own defaults are already executables. Both ambiguous `DesktopEntry` fields
are read through a normaliser that accepts either a list or a `;`-joined string, because
`quickshell-core.qmltypes` declares them `QString` while the docs say list — a measured ambiguity,
not a guess.

**D-7 — Kitty-only flags become conditional, not universal.** `SessionPage.qml:194` passes
`-o background_opacity=0.85 -o font_size=11`, which only kitty understands. Since the picker now
really can change the terminal, those two pairs are appended only when the configured terminal's
basename is `kitty`; otherwise the argv falls back to `<term> -e <editor> <file>`. `-e` is kept
unconditionally because it is the near-universal spelling and is what the other two call sites
already use. A per-terminal flag matrix is **not** built: this host has exactly one terminal family
installed (measured: two desktop entries, both kitty), so a matrix would be unverifiable code.

**D-8 — The weather city writes to `Prefs`, never to `weather.json`.** `weather.json` already has
one owner (`WeatherBackend`'s watched `FileView`) and one hand-editing contract. A settings-page
writer would be a second writer to a watched file. Instead `lat`/`lon` become computed properties
with a **Prefs-first-then-weather.json** chain — the identical shape, in the identical file, that
`unitsTemp`/`unitsWind`/`unitsPrecip` already use, added by the previous task for the identical
reason. Auto mode leaves a hand-edited `weather.json` fully authoritative.

**D-9 — Forward geocoding lives in `GeocodeBackend`, on the same fenced host.** Turning a typed
city into coordinates needs a name→coordinate lookup. Nominatim's `/search` path is the **same
host** `GeocodeBackend` already owns, so the one-host-per-fenced-file rule holds with no new host
and no new privacy surface — but the file's header must be updated to say it now carries both
directions, exactly as `WeatherBackend`'s header was corrected when the first geocode landed. The
lookup fires only on an explicit city commit; never on a timer, a refresh or a summon.

**D-10 — `TextRow` is a real row primitive, not an inline TextField.** An inline `TextField` (the
shape `NetworkPage.qml:423` uses for the Wi-Fi password) counts zero in `ROW_PRIMITIVE_RE`, which
means unindexed, unsearchable and unreachable by keyboard. The city field is a first-class setting,
so it gets a first-class row. It wraps QQC2 `TextField`, which is **measured safe here** — both
`NavRail.qml:48` (the settings search box) and `NetworkPage.qml:423` render correctly. `SliderRow`'s
header warns about QQC2 `Slider` specifically, and that warning does not transfer to a control this
tree already renders in two places.

**Resolution model — implement exactly this.**

For each `*.qml` under the target, build the set of type names it may legally reference:

1. **Its own directory.** If that directory contains a `qmldir`, the resolvable set is exactly the
   type names that `qmldir` declares (including `singleton` and `internal` entries) — an
   undeclared sibling `.qml` in a qmldir-bearing directory is NOT resolvable, which is the whole
   reason `common/qmldir` discipline exists. If there is no `qmldir`, every sibling `*.qml`
   basename resolves.
2. **Each `import "<relative path>"` directory**, by the same qmldir-or-basenames rule. Resolve the
   path relative to the file. A path that does not exist is itself a FAIL, named.
3. **Each `import <Dotted.Module>` (unquoted)** — map dots to directories under the QML root
   (`qmake6 -query QT_INSTALL_QML`, falling back to `/usr/lib/qt6/qml`), then union every type name
   found in `exports: ["<Module>/<Name> <version>"]` across that directory's `*.qmltypes` files.
   This is what keeps `Singleton`, `HyprlandFocusGrab`, `PanelWindow`, `Process`, `StdioCollector`,
   `FileView`, `JsonAdapter`, `Scope`, `StackView`, `TextField`, `Transition`, `Connections`,
   `Behavior` and every other module type from reading as a false positive — **derived from the
   installed modules, never a hand-written allowlist**. A module directory with no `.qmltypes` is
   reported as a NOTE and its imports are treated as unresolvable-but-not-failing, so a future Qt
   layout change degrades to noise rather than a wall of false failures.
4. **Inline components declared in the file itself**: `^\s*component\s+([A-Z][A-Za-z0-9_]*)\s*:`.
5. **The file's own root type id** and any `id:` values are not types and are never referenced as
   types — do not add them.

For each file, collect the identifiers it REFERENCES:

- object declarations: a line matching `^\s*([A-Z][A-Za-z0-9_]*)\s*\{`
- typed property declarations: `property\s+([A-Z][A-Za-z0-9_]*)\s`, including the
  `required property` and `readonly property` forms
- list-typed declarations: `list<([A-Z][A-Za-z0-9_]*)>`

Before matching, strip `//` line comments, `/* */` block comments and double-quoted string
literals — a gate that matches its own or its target's prose is a failure class this repo has
already shipped (`grep-gate-matches-own-comment`). Do NOT match dotted forms (`Text.WordWrap`,
`Easing.BezierSpline`, `StackView.Immediate`, `TextInput.Password`, `Component.onCompleted`): those
are enum/attached references, not instantiations, and the anchored patterns above already exclude
them — confirm that on the real tree rather than assuming it.

Report each unresolved identifier as `FAIL <file>:<line> — type "X" is not supplied by any import`,
and list the file's import scopes underneath so the fix is obvious.
