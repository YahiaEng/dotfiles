## Operator decisions (locked 2026-08-27)

| # | Question | Answer |
|---|---|---|
| 1 | Which plate | **All four**, behind pickers — the repo's own established pattern (screensaver's 4 styles, dashboard's `lanes`/`column`) |
| 2 | Which scanners | **Whichever is more secure — security is the priority.** Read as: install the full set (clamav, arch-audit, rkhunter, lynis), defaults on |

## Two findings that constrain decision 2 and 4

**A. The stock nftables ruleset would break Docker and both k3d clusters.**
`/etc/nftables.conf` ships `chain forward { policy drop }`. That chain and Docker's
own `ip filter FORWARD` register at the same hook and priority; a DROP from either
kills the packet. Docker is active with 4 networks (`bridge`, `host`, `k3d-app`,
`k3d-platform`). The stock file also carries `tcp dport ssh accept`, pre-opening a
port for a daemon that is not running.

→ The repo ships its OWN ruleset: `input policy drop` with loopback/established/
ICMP allowances, **no forward chain** (Docker governs forwarding), **no SSH allow**.
More secure than stock AND non-breaking. Stock is preserved as a backup on install.

**B. Real exposure today is zero, and the pane must say so.**
Every listener is on loopback: `:11434` Ollama, `:631` CUPS, `:53` local DNS,
`:37700` a bun dev server. "Unfirewalled" is true; "exposed" is not. Reporting
alarm where there is none trains the operator to ignore the pane.

## Privilege model

Device health needs NO runtime privilege (measured): the user is in `wheel` and can
read the system journal; `smartctl --json` is supported; `sensors -j` parses.
A root timer writes a JSON snapshot; the shell only ever reads files.

Privileged ACTIONS (decision 4) go through exactly one helper,
`security/bin/security-action`, invoked via `pkexec`. It takes a **fixed verb from a
hardcoded allowlist** and takes no free-form arguments from the shell — the allowlist
is the security boundary. A pane that can run arbitrary root commands is a worse
vulnerability than the ones it reports.
