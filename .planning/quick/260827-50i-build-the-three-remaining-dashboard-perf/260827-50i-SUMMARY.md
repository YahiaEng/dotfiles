## What was built

**Prerequisites (242544a9)** — landed separately so the layout commits are pure
layout.
- `Dial.qml`: opt-in `startAngle`/`sweepAngle`, defaulting to the exact values
  that were hardcoded, so every existing call site draws identical pixels. The
  track arc reads them too — at the default that is still a full circle, but a
  narrowed sweep needs both arcs sharing an origin.
- `Design.qml`: a shared rounding ladder (18/28/42/56 + a full-round sentinel).
  Existing per-surface radii untouched; nothing re-pointed at it.
- `SystemResources.qml`: `cpuName`, `distroName`, `uptimeSeconds`/`uptimeText`.
  Static facts one-shot and cached on first open (the hwmon/GPU probe doctrine);
  uptime rides the existing ~30s slow timer. All fail quiet — labels, not D-41
  readings, so none carries a state register.
- Later, for P1's network card: `netRxTotal`/`netTxTotal`, the raw
  /proc/net/dev counters, published rather than left in private `_netPrev`.

**P2 "arcs" (03eea9e8)** — CPU and GPU as 270° arcs at double weight; memory,
storage, network as flat tiles. The sweep's 90° gap is where each hero's caption
sits. Battery demoted to the network tile's foot, still governed by the
overturned D-41.

**D1 "bento" (67c407ff)** — the reference's grid. Six same-fill cells separated
only by radius, which is what the new ladder is for.

**P1 "cards" (8090ade5)** — hero CPU/GPU pair, utility row, battery tank. The
plate the D-41 overturn was taken for: the tank is absent, not empty, with no
battery, and its 104px returns to the utility cards.

**P4 "dials" (4b6ed15e)** — the five-dial row BECOMES plate P4. Battery dial
gone (not hidden) to a status line, dials 176 → 128 with the ring following
17 → 13, and the tab settles at 712 so the 280px width jump between Dashboard
and Performance disappears. The rate pair stops floating and gets the plate's
card. Two departures from the drawing, both because a later operator decision
outranks it: dial order stays GPU/CPU/Memory/Storage (set at 14-10 Task 4's
render gate; the plate's change list says nothing about order), and the battery
line hides when absent per the 2026-08-26 ruling rather than reading "No battery
on this host" for ever.

**D3 "column" (fa15968f)** — the 400px column BECOMES plate D3. `contentWidth`
400 → 712, which was the whole measured defect: a 400px column inside a 760px
frame left ~180px of dead margin on each side permanently. Media and resources
pair on one line. The hero row gains a weather readout opposite the clock, from
the same shared backend the Weather tab and DashLanes already read.

Both plates were implemented as transformations of the existing files rather
than as new siblings. Writing `DashWide.qml`/`PerfTight.qml` beside the
originals would have left the originals selectable, which is the opposite of
what was asked — and both plates are framed by the study as edits anyway
("one binding + re-proportioning", "a handful of constants").

## Decisions taken (not deferred)

**Two width families, because the study designs two.** D1's own spec note says
"these two tabs have to be chosen together". So `DashBento` and `PerfCards`
share 944 of content (drawer 1040); `DashLanes`, `PerfTelemetry` and `PerfArcs`
share 712 (drawer 808). Picking within a family does not animate the drawer's
width; picking across them does — a property of the plates, not a defect.
Compressing D1 to 712 was rejected on measurement: the media column alone is
236, leaving 460 for a row carrying a 250px weather cell plus a 92px avatar and
three lines of text. The settings subtext names the pairing.

This narrows, rather than contradicts, STATE.md's "declare the same 712 in any
new layout" note — that note was written while every live layout was narrow, and
it still binds the whole narrow family, P2 included.

**Toggles moved out of the media column in D1.** The plate folds them into the
media foot as three generic tiles. `QuickToggles` is a six-chip row dividing its
own width evenly; at 236px that is ~27px a chip. They run across the left
stack's foot at 692 instead — more room than "lanes" gives them (356). Media
spans three rows rather than two. Documented in the file header.

**The morphing usage badge is a Canvas polar blob.** Radius varies as
`1 + amp*cos(lobes*theta)`, amplitude and lobe count both rising with load,
animated so it morphs rather than snaps; at idle the amplitude is zero and it is
a circle. Their `MaterialShape` presets are a compiled C++ plugin, and a build
step in front of "reproduces from one script" costs more than the shape. The
header says it is an approximation rather than implying otherwise.

**D1 leans on radius and gap for separation.** `Colours.qml` publishes no
`surfaceContainer` role and the theme pipeline does not generate one — confirmed,
not assumed. That is the study's own stated fallback for this plate.

## Two defects the capture found in D3 that the code review did not

Both were caught by rendering the result, not by reading it:

1. **The resources strip was clipped.** Four dials carrying used-of-total detail
   lines never fit beside the media widget — measured on the capture,
   `5.5/31.3 GiB` ran straight through `10.3 GiB / 1.8 TiB`. This is exactly why
   the plate draws that cell as ring + short label only. The detail lines are
   gone, labels are CPU/RAM/Disk, the strip's width is DERIVED from the visible
   dial count and the caption pitch rather than hand-picked, and battery follows
   the D-41 overturn — four dials on a laptop, the plate's three here. The full
   figures stay one click away on the Performance tab the strip deep-links to.
2. **Every ring in that strip had an invisible track.** `Dial`'s default
   `trackColor` is `surfaceVariant` and the strip's card fill is also
   `surfaceVariant`, so the unfilled remainder drew as nothing — a bare arc with
   no ring behind it. Same mechanism as 14-10's invisible GPU ring; **fourth**
   occurrence of that class. Pre-existing, not introduced by this task, but
   visible in the capture and fixed here.

## NOT verified — handed to the operator

**No Performance layout has been rendered — now three of them, not two.**
`PerfArcs`, `PerfCards` and the transformed `PerformanceTab` (P4) are all
gate-proven and unseen. There is no `quickshell:performance` global (only `quickshell:dashboard` and
`quickshell:media` exist, `shell.qml:1829`/`:1896`), the Performance tab's Loader
is `active` only when it is the current tab, and no click-injection tool exists
on this host — `wtype` types into the focused window, and Hyprland has no click
dispatcher. So all three are **gate-proven and code-reviewed but not seen**.

What that leaves genuinely unproven, as opposed to merely unseen:
1. **The 270° arc.** `Dial`'s new `startAngle: 135` / `sweepAngle: 270` path has
   never been rendered — the bento rail exercises the DEFAULT angles only. If
   the arc opens at the wrong clock position, both Performance plates show it.
2. **The morphing usage badge.** The Canvas blob has never painted.
3. **Card heights in all three.** Every one is derived, but "derived" was true
   of the heights that still clipped a play button last round.
4. **P4's whole retune** — the 128px dials, the rate card, the battery status
   line, and whether 712 actually leaves the four dials looking right rather
   than lost in a frame that no longer shrinks to them. D3's equivalent
   re-proportioning is where BOTH defects above were hiding, so P4's is the
   single most likely place for another.
