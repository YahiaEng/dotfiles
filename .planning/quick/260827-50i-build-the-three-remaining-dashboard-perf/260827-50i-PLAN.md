## The width decision (the one genuine fork, taken not deferred)

The study designs **two width families** and says so itself: D1's spec note reads
*"It settles at 1040 — which fixes the frame jump only if Performance also lands at
1040 (P1 does; P2/P3/P4 don't). These two tabs have to be chosen together."*

So a single uniform width is not available without redrawing a plate. Compressing D1
to 712 was tested on paper and breaks its own composition — the media column alone is
236, leaving 460 for a row that has to carry a 250px weather cell plus an identity
cell with a 92px avatar and three lines of text.

**Taken:** build to the study's own two families.

- **narrow** — `contentWidth: 712` → drawer 808 — `DashLanes` (D2), `PerfTelemetry` (P3), **`PerfArcs` (P2)**
- **wide** — `contentWidth: 944` → drawer 1040 — **`DashBento` (D1)**, **`PerfCards` (P1)**

Picking within a family is jump-free. Picking across families reproduces the width
animation, which is the study's stated property of these plates, not a defect
introduced here. The settings subtext names the pairing so the choice is informed.

This narrows STATE.md's "declare the same 712 in any new layout" note rather than
contradicting it: that note was written while both live layouts were narrow, and it
still binds every narrow-family layout, P2 included.
