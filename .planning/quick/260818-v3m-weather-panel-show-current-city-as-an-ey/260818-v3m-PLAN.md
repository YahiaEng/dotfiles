# Quick Task 260818-v3m — Weather hero eyebrow: the current city, reverse-geocoded once per coordinate change

## Objective

The weather panel shows a temperature and a condition with no indication of
*where*. Put the city name above the temperature as an eyebrow, resolved from
the operator's `lat`/`lon` by a reverse geocode that runs **once per coordinate
change** — never on a refresh, never on a summon, never on a schedule.

Four things ship:

1. **A new fenced component** — `GeocodeBackend.qml`, the ONLY file under
   `quickshell/` that names the reverse-geocode host. `WeatherBackend.qml` keeps
   the forecast host. The one-file fence becomes **one host per fenced file**.
2. **A four-step resolution chain** in `WeatherBackend.qml`, published as
   `cityLabel` + `cityLabelSource`, cached alongside the forecast.
3. **The eyebrow** in `WeatherTab.qml`'s hero stack, above the temperature.
4. **An honest fence comment** — `WeatherBackend.qml`'s header currently asserts
   a rule the code will no longer follow. Correcting it is not optional cleanup;
   it is the load-bearing edit of this task after the feature itself.

## Measured ground truth — do NOT re-derive any of this

Every fact below was measured on this host during planning. Treat it as given.

**The fallback already exists, free.** `timezone=auto` is already in
`buildRequestUrl()` (`WeatherBackend.qml:274`), so every response carries
`payload.timezone` — currently `'Africa/Cairo'`, confirmed present in the live
`~/.local/state/theme/weather-cache.json`. Last `/` segment with `_`→space is a
usable name with zero network.

**Nominatim, verified live against the operator's real coordinates (30.04, 31.24):**

```
https://nominatim.openstreetmap.org/reverse?lat=<lat>&lon=<lon>&format=jsonv2&zoom=10&accept-language=en
```

returns `name: "Cairo"`, `address.city: "Cairo"`, `address.state: "Cairo"`,

## Architecture — the seam

```
weather.json  ──  city (optional manual override)  ─┐
                  lat/lon ──► coordsValid ──────────┤
                                                    ▼
WeatherBackend.qml            _revalidateAgainstSettings()   ← the ONE
  (host: api.open-meteo.com)      │ coords changed?           coordinate-change
                                  ├─ clears payload           detector
                                  ├─ clears _cachedCity
                                  └─ _resolveCityIfNeeded()
                                            │
                                            ▼
                          GeocodeBackend.qml   (host: nominatim.openstreetmap.org)
                                            │  resolved(city)
                                            ▼
                              _cachedCity  ──► writeCache()  ──► weather-cache.json
                                            │
                                            ▼
                      cityLabel / cityLabelSource  ──► WeatherTab.qml eyebrow
```

**Resolution order for `cityLabel`, first hit wins:**

| # | Source | `cityLabelSource` | Network |
|---|--------|-------------------|---------|
| 1 | `city` key in `weather.json` (optional manual override) | `"override"` | none — and **no geocode request is issued at all** |
| 2 | geocoded city, cached in `weather-cache.json` | `"geocoded"` | one request, once per coordinate change |
| 3 | `payload.timezone` last segment, `_`→space | `"timezone"` | none, works offline |
| 4 | nothing | `""` | eyebrow does not render — no placeholder dash |

**Why the city is NOT written back into `weather.json`:** that file is the
operator's hand-edited settings surface. Writing derived data there risks
clobbering their own edits. Operator-approved adjustment to the original
instruction.

**Why `GeocodeBackend` mounts as a child of `WeatherBackend`, not at shell root:**
`shell.qml` mounts backends at the root when *multiple surfaces* consume them
(the bar + the dashboard, per D-14). The geocoder has exactly one consumer, no
timer of its own, and needs `drawerOpen` + `coordsValid` handed straight down.
A root mount would add a `shell.qml` binding for zero benefit. **`shell.qml` is
deliberately not modified by this task.** The fence is about which FILE carries
a host string, not which object owns the instance.

## Task 1 — `GeocodeBackend.qml`: the second fenced host

**Files:**
- `quickshell/.config/quickshell/modules/dashboard/GeocodeBackend.qml` (new)
- `quickshell/.config/quickshell/modules/dashboard/qmldir`

**Action:**

Create `GeocodeBackend.qml`, root type `Scope` (`import QtQuick` +
`import Quickshell`; no `Quickshell.Io` — this file opens no file). Non-visual,
no timer, no `FileView`. Mirror `WeatherBackend.qml`'s structure and comment
discipline; this file is read as its sibling's twin.

Header comment must state, in its own words:
- This is the ONE place in the repository from which a reverse-geocode request
  may be issued — the one-host-per-fenced-file rule, the same discipline
  `WeatherBackend.qml` applies to the forecast host.
- **Privacy:** the operator's coordinates now reach a SECOND host. That is a
  real change from the previous single-host design and is stated plainly, not
  buried.
- **Rate policy:** the service's published policy requires a descriptive
  User-Agent and caps at roughly one request per second. A once-per-coordinate-
  change lookup sits trivially inside that. Say explicitly that this call must
  never be moved into the fetch loop or onto a timer — the comment exists so
  nobody later "optimises" it there.
- **`accept-language=en` is load-bearing**: measured, its absence returns the
  local-language name.
- `D-41` widget-state vocabulary is carried by every `modules/dashboard/` file,
  including non-visual backends — carry `property string widgetState` here too,
  values `"populated" | "pending" | "empty"`.

Properties:
- `property bool drawerOpen: false` — lifecycle gate (D-32), handed down by the
  parent. Starts nothing while false.
- `property var lat: null`, `property var lon: null` — raw JSON values handed
  down, same `var`-not-`real` discipline as the parent (a hand-edited string
  must stay detectably non-numeric).
- `property bool coordsValid: false` — **handed down from the parent, never
  recomputed here.** One validator in the tree, not two.
- `readonly property string reverseEndpoint: "https://nominatim.openstreetmap.org/reverse"`
- `readonly property string userAgent: "quickshell-dashboard-weather/1.0 (+https://github.com/YahiaEng/dotfiles)"`
  — descriptive, with contact, per the service's policy.
- `property bool requestInFlight: false`, `property var _currentXhr: null`
- `signal resolved(string city)`

`buildRequestUrl()` — build the five params off `reverseEndpoint`, every value
through `encodeURIComponent`: `lat`, `lon`, `format=jsonv2`, `zoom=10`,
`accept-language=en`. Same shape as the parent's `buildRequestUrl()`.

`resolve()` — the only entry point. Guards, in order: return if `!drawerOpen`;
return if `!coordsValid` (T-14-03's mitigation applies identically here — no
request on invalid coordinates, ever); return if `requestInFlight`. Then
`requestInFlight = true`, build the URL, `xhr.open("GET", url)`,
`xhr.setRequestHeader("User-Agent", root.userAgent)` (measured allowed by this
Qt build — see ground truth), `xhr.send()`.

In `onreadystatechange`, on `DONE`: clear `requestInFlight`/`_currentXhr`;
`status !== 200` → `console.log` and return, leaving the previous label
untouched. On 200, `JSON.parse` inside try/catch, pass through
`_cityFromResponse()`, and emit `resolved(city)` only if that returns a
non-empty string. A malformed response must leave the previous label untouched
and never half-render — the exact discipline `applyResponse()` already uses.

`_cityFromResponse(json)` — explicit shape check before any read: return `""`
unless `json` is a non-null object. Then, first non-empty string wins, in order:
`json.address && json.address.city`, `json.address.town`,
`json.address.village`, `json.name`. Trim the result. Anything else → `""`.

`onDrawerOpenChanged` — when it goes false, `abort()` any outstanding request
inside try/catch and clear `requestInFlight`, exactly as the parent does. Zero
idle footprint (D-32).

Register the type in `qmldir` **in the same commit that creates it**, per that
manifest's own standing rule, with a short comment block naming this quick task
and why the type exists (second fenced host, not a singleton, one ordinary
instance owned by `WeatherBackend`):

```
GeocodeBackend 1.0 GeocodeBackend.qml
```
