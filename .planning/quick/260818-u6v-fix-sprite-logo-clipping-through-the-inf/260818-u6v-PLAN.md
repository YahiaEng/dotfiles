# Quick Task 260818-u6v — Sprite logo clipping + drop satan_cross

Two operator-reported defects in `260818-srl`. Diagnosis was completed by
systematic debugging against live measurements captured from a **real kitty
window**; no re-derivation needed.

## Defect 1 — sprite GIFs draw through the info box

### Root cause (measured)

Nothing anywhere sets `logo.width`/`logo.height` — zero grep hits across
`config.fish`, the matugen template, the picker and `lib/fastfetch.sh`.

Raw fastfetch output captured from inside a real kitty window:

| logo path | indent mechanism | uniform? |
|---|---|---|
| ASCII (`file`) | **41 real spaces** = 37 art cols + 2 left + 2 right | yes |
| `none` | column 0 | yes |
| sprite (`kitty-icat`) | **`ESC[3C`** — cursor-forward 3, i.e. only `padding.left` | — |

The kitty graphics control string is `a=T,q=2,f=24,t=s,s=200,v=200,S=120000,I=<id>`
in **every** variant tested. `s=200,v=200` is the source pixel size and there are
**no `c=`/`r=` cell-scaling keys**. Therefore `--logo-width` does *not* scale the
image — it only reserves text columns and moves the placement cue. The image is
always drawn at its natural pixel size.

Kitty cell geometry, measured live: window 2440x640 px over 244x32 cells =
**10 x 20 px per cell**. Sprites are 200x200 px (`fastfetch-sprites.py` `S = 200`)
=> natural footprint **20 cols x 10 rows**.

fastfetch reserved 3 columns for something occupying 20. The box was drawn
straight through the sprite.

### Fix (verified)

Pass `--logo-width 20 --logo-height 10` on the **sprite branch only**. Proven:
cursor-forward moves 3 -> 23 and every line, top `┌` rule included, lands
uniformly at `ESC[23C`. (`--logo-width 24` -> 27, uniformly.)

Not applied to the `file` or `none` branches — fastfetch measures text art itself
and the flags are meaningless there.

`box-close.awk` is **not** implicated and must not be touched: it measures from
the first `│`, which stays correct on `ESC[3C`-prefixed lines, and the graphics
payload line carries no `│` so it passes through untouched.

### Documented coupling

The reservation is correct only while the sprite canvas is 200x200 **and** kitty's
cell is 10x20 px, which follows from `font_size 12.0` in `kitty.conf`. A materially
smaller font shrinks cells, raises the natural column count above 20, and the
clipping returns. Querying cell size at runtime would cost another ~14ms `kitten`
spawn per shell, so this is a *documented* coupling, not a silent assumption —
recorded both at the call site and beside `S` in the generator.

## Defect 2 — drop satan_cross from the picker

At 71 columns it pushes the box much further right than the others (arch 37,
cyberpunk_mask 44, illuminati 48, star 52). Operator asked to remove the **option**,
not the art: `art/satan_cross.txt` stays on disk and committed.

Removed from `config.fish:27` and the picker's two enumeration arrays
(`ASCII_NAMES`, `ASCII_NAMES_P`). Entry count 13 -> 12.

Migration: a state file still holding `satan_cross` must fall through the existing
validation chain to themed ASCII (arch), never to the stock builtin logo. Confirmed
by test.
