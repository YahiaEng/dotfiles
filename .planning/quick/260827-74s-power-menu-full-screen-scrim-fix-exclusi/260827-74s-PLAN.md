## Evidence gathered before planning

**(a) The scrim really is short, and by exactly the reserved zone.**

`hyprctl monitors -j` → `reserved = [left 0, top 6, right 50, bottom 6]`.
With the power menu open, `hyprctl layers -j`:

```
DP-1 lvl=3 ns=quickshell-session x=0 y=6 w=2510 h=1428
```

Not `0,0 2560x1440`. The deficit is 50px on the right and 6px top/bottom —
the reserved zone, exactly. `grim -g` captures of both edges confirm it
visually: the right-hand edge bar (workspaces 5/6) renders bright and
un-dimmed beside a blurred, scrimmed desktop, and a 6px bright strip sits
above the scrim at the top.

Cause: `PowerMenu.qml:188` sets `exclusiveZone: 0`. An explicit non-negative
`exclusiveZone` **overrides** `ExclusionMode.Ignore` and places the surface
inside every other surface's reservation. The file's own comment at :189-196
blames layer ORDER and claims `Ignore` solves the extent problem; the
measurement above shows it does not. Same wrong-cause note as `Bar.qml:613`.

Positive control that a full-span layer surface is achievable here:
`hyprshutdown`'s own overlay measured `0,0 2560x1440` in the same session.

**(b) Shutdown/Reboot wait forever, and it is hyprshutdown doing the waiting.**

`PowerActions.qml:46,50` run
`cliphist wipe; hyprshutdown --post-cmd 'systemctl reboot|poweroff'`.

`strings /usr/bin/hyprshutdown` (0.1.1-6) shows its registered options are
`dry-run`, `no-exit`, `top-label`, `post-cmd`, `verbose`, `no-fork`, `vt`,
`help` — **no timeout of any kind**. Its UI strings are `Shutting down...`,
`Waiting for your apps to exit.`, `Force quit`, and
`<i>You can force quit Hyprland, but that risks losing unsaved progress.</i>`.

Confirmed live under `--dry-run --no-exit --no-fork --verbose`: it loops
`Re-closing apps` / `Updated state: apps size 14` indefinitely. It only ever
stops when the last app exits or the operator clicks Force quit. That
indefinite loop is the reported hang.

Counter-evidence for the alternative (systemd timeouts): the journal holds two
clean power-key poweroffs which bypass hyprshutdown —

- Aug 22 05:19:55.548 power key → 05:19:57.043 `Reached target System Power Off` (1.5s)
- Aug 24 18:31:44.087 power key → 18:31:45.380 `Reached target System Power Off` (1.3s)

with `app-graphical.slice` removed 75ms into the Aug 24 teardown. So systemd's
90s `DefaultTimeoutStopSec` is not being reached; the polite per-app close is.

**The graceful path was never load-bearing.** `04-01-SUMMARY.md` Task 2 records
the FIX-01 hang as **never reproduced** — "No hang reproduced", "intermittent /
not currently reproducible on demand" — and the hyprshutdown wrap was applied on
a structural bare-`systemctl`-is-uwsm-incorrect argument, not on evidence.

## Operator decision (locked)

Presented with three bounded options (10s cap / drop entirely / 30s cap), the
operator chose **drop hyprshutdown entirely** from Shutdown and Reboot. The
trade-off was stated before the choice and accepted: apps are killed when the
compositor exits rather than asked to close, so unsaved work is likelier lost,
and this reverts the Phase 4 FIX-01 decision and retires requirement QPOWER-04's
mechanism.

### Task 1 — Power menu scrim spans the true screen

**Files:** `quickshell/.config/quickshell/modules/session/PowerMenu.qml`

**Action:** Change `exclusiveZone: 0` → `exclusiveZone: -1`. Rewrite the
adjacent comment so it records the measured cause (zone beats mode) instead of

### Task 2 — Shutdown and Reboot stop waiting on apps

**Files:** `quickshell/.config/quickshell/modules/session/PowerActions.qml`

**Action:** Replace the Reboot and Shut Down `command` strings with
`cliphist wipe; systemctl reboot` and `cliphist wipe; systemctl poweroff`.
Leave Lock, Log Out, Suspend and Hibernate untouched. Record the decision, the
trade-off and the QPOWER-04 impact in the file header.

**Scope note — Log Out is deliberately NOT changed.** It is the one remaining
`hyprshutdown` consumer and carries the same indefinite wait. The operator
asked about Shutdown and Reboot; widening to Logout is theirs to call, and it
is flagged in the SUMMARY rather than silently done.

**Verify:** `grep hyprshutdown PowerActions.qml` returns only the Log Out line.

**Done:** Both actions dispatch a bare `systemctl` verb after the cliphist wipe.
