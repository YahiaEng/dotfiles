<objective>
Build a Caelestia-style **edge bar**: two always-on strips flush to the top and
bottom screen edges that the dashboard and the launcher visually attach to and
animate out of, with a settings toggle (default ON), a static centre bulge,
palette-driven colour, and smooth concave attachment corners that apply in both
edge-bar mode and regular mode.

Purpose: give the shell a single always-present frame that makes its two
summonable surfaces read as parts of the desktop rather than as panels dropped
on top of it, and make the spawn location discoverable without a keybind.

Output: one new shared QML component (the concave corner), one new QML surface
(the strip, instantiated twice), one new Prefs key with its settings row, one
gate registry row, and the dashboard/launcher edits that attach them.
</objective>

**GT-1 — the gate registry is a hard, closed contract.**
`hypr/.config/hypr/scripts/quickshell-doctor` line 344 defines
`QSD_BAR_SURFACE_ROWS`. Its reverse-closure check
(`_qsd_assert_bar_surface_registry_reverse`, line 1903) walks every `.qml` under
the shell root, and any file that declares `WlrLayershell.namespace` and is
neither a registry row's file (matched by BASENAME) nor a member of
`QSD_KNOWN_NONBAR_FRAMES` (line 437) counts as `unregistered` and FAILS the
gate. A new layer surface cannot ship without a row.

**GT-2 — the obvious namespace name would break the gate.**
The row `bar/SectionPopout.qml|quickshell-bar-|pattern|3|noreserve|transient`
matches ANY namespace starting with `quickshell-bar-` plus at least one
character. The live half (`_qsd_assert_bar_surface_registry_live`, line 1961)
requires every bar-family-shaped namespace to match EXACTLY ONE row. So
`quickshell-bar-edge-top` would match two rows, count `unmatched`, and fail —
the identical trap the registry header documents at length for
`quickshell-bardrawer-` and `quickshell-bartip-`. The working prefix is
therefore `quickshell-baredge-` — no hyphen after `bar`. It still begins with
`quickshell-bar` (so the live half's broad candidate net still sees it and
asserts its level and PID) and with `quickshell-` (so the family-wide
blur/`ignore_alpha` layer rules still apply).

**GT-3 — a reserving surface is legal, and the forward check proves it.**
`_qsd_assert_bar_surface_registry_forward` (line 1842) applies its
`exclusiveZone: 0` assertion ONLY when a row's fifth column reads `noreserve`.
A row whose fifth column reads `reserve` is exempt, exactly as
`Bar.qml|quickshell-bar|exact|2|reserve|permanent` already is. The check
"no summoned surface adds a reservation" (line 2919) is a summon-and-diff over
the shortcuts manifest; a PERMANENT surface sits in both snapshots and cancels
out. `bar-reserved-zone-stability` (line 1562) measures a delta across a
bar-visibility toggle, which moves only the bar's own axis. Also note
`permanent_count` in the live half increments only on an EXACT match of
`quickshell-bar`, so two further permanent surfaces cannot break its
`permanent == 1` assertion.

**GT-4 — file placement decides which colour rule applies.**
`_qsd_check_bar_colour_role_routing` (line 2119) scans `<shell root>/bar` ONLY,
and forbids every non-exempt file there from reading `Colours.*` directly —
those files must go through `BarRoles`. Placing the strip at
`modules/EdgeBar.qml` (a sibling of `Bar.qml`, `Dashboard.qml`, `Overview.qml`)
puts it outside that scan and lets it read `Colours.*` directly, which is what
R9 and CONTEXT.md both ask for. Placing it under `modules/bar/` would silently
route it through `BarRoles` instead.

**GT-5 — `Colours.*` roles are STRING-typed, not colour-typed.**
`modules/Colours.qml` lines 100-139 declare every role as
`property string ...: "#FF00FF"`. Reading `.r`/`.g`/`.b` off one yields BLACK
silently. Both existing surfaces avoid this the same way — `Launcher.qml:117`
and `Dashboard.qml` each declare a local `readonly property color surfaceBase:
Colours.surface` and blend off THAT. quickshell-doctor's
`bar-colour-alpha-resolution` check enforces this under `modules/bar` only, so
under `modules/` it is on the author, not on a gate.

**GT-6 — `PanelWindow.mask` exists on this build.**
`/usr/lib/qt6/qml/Quickshell/_Window/quickshell-window.qmltypes:709-718`
declares `mask` on `WindowInterface`, type `PendingRegion` (exported as
`Quickshell/Region`), write `setMask`, notify `maskChanged`. No file in this
repo uses it yet — this plan introduces the first use, so treat it as
unproven-until-run rather than as established repo idiom.

**GT-7 — both host panels are centred, fixed-width, inside full-screen
surfaces, and neither clips.** `Launcher.qml:452-454` — `id: panel`,
`width: 640`, `anchors.horizontalCenter`. `Dashboard.qml:558-561` — `id: panel`,
`width: dashboardWindow.drawerWidth`, `anchors.horizontalCenter`. Both parent
windows anchor all four edges. A corner piece parented to `panel` therefore has
real room to paint OUTSIDE the panel's own bounds on both sides. This is what
makes Task 1's additive design possible.

**GT-8 — Motion tokens available.** `Motion.qml` exposes exactly
`standardDuration/Easing`, `emphasizedIn/Out`, `staggerOffset`, `spatialIn/Out`,
`spatialMove`, `ambient`, `borderRotateDuration`, plus `motionEnabled`. Nothing
else resolves. `motion-lint` proves a site reads a token, NOT that the token
exists — an undeclared name silently becomes `undefined` and Qt falls back to
250ms.

**GT-9 — the family layer rules already cover a new `quickshell-*` namespace.**
`hypr/.config/hypr/config/windowrules.lua:367` sets `blur = true` and `:401`
sets `ignore_alpha = 0.5` for `^quickshell-.*`. A new namespace inherits both
with no edit, PROVIDED its fill alpha stays above 0.5. No `windowrules.lua`
change is required by this plan; if one is ever wanted it must be declared
AFTER the family regex, and `hyprctl reload` silently DROPS layer-rule edits —
only `hyprctl eval` or a compositor restart applies them.

<design_decisions>
Three decisions the planner took that CONTEXT.md left open. Each is stated so a
reviewer can overturn it cheaply rather than discover it in the diff.

**P-1 — The concave flare is an ADDITIVE corner piece, not a rewrite of
`GradientBorder._roundedRect`.**
CONTEXT.md correctly warns that R7 needs new path geometry. It does — but that
geometry does not need to live inside the existing ring builder. Two measured
reasons: (a) the panel's fill is a `Rectangle` (`Launcher.qml:486-493`,
`Dashboard.qml:637-646`) and a `Rectangle` cannot render a concave corner at
all, so a radius-side change would leave the fill square while only the rim
flared; (b) the flare must paint OUTSIDE the panel's bounds, which a component
filling the panel cannot do. So a new `AttachedCorner.qml` sits beside the
panel, paints its own fill and its own rim segment, and leaves both existing
surfaces' proven `Rectangle` + `GradientBorder` pair untouched. Lower blast
radius, and the tracer proves it on one surface before the second adopts it.

**P-2 — In edge-bar mode both panels sit FLUSH against their strip (margin 0);
in regular mode the existing 10px margin is untouched.**
R7 says the corners are "where the surface meets the edge strip". A surface
10px away from the strip does not meet it, and a flare hanging in mid-air is
not the requested shape. So the MARGIN branches on the toggle — not the corner
shape. This honours D-5 exactly: D-5 branches DIRECTION and forbids branching
SHAPE, and says nothing about margin. The margin branch is what lets the
unbranched shape read correctly in both modes. In regular mode the flare is
decorative rather than attached, which is the literal consequence of the
operator's "applies in BOTH modes".

**P-3 — The bulge IS the hover target; there is no new invisible hot-zone
surface.**
CONTEXT.md offers `HotZone.qml` as the reveal precedent, and its shape is
reused — but not its extra surface. The strip is already always-mapped at the
exact place R5/R6 want hover, and D-3 made the bulge a permanent landmark
precisely so the operator can see where to hover. Putting the hover handler on
the bulge means zero new layer surfaces, zero extra registry rows, and exact
agreement between what the operator SEES and what actually triggers. The
click-inert posture `HotZone.qml`'s header documents for T-18-16-01 carries
over verbatim and is enforced by a gate in Task 5.
</design_decisions>

<execution_rules>
These apply to EVERY task below. They are carried in from prior tasks on this
host and each one has already cost a session.

1. **Never spawn a `qml6` probe script.** Each opens a real window and a loop of
   them takes the session down. Use static greps, the three gate scripts,
   `hyprctl -j`, Python, or `~/.cache/quickshell.log`.
2. **`grim -g` REGION capture only — never a full-screen `grim`.** A full-screen
   capture SIGSEGVs the compositor into safe mode on this NVIDIA host. Region
   capture of a layer surface is safe and is the intended visual instrument.
   Read captures NEAREST-upscaled and cropped.
3. **After ANY QML edit: restart the shell, then read `~/.cache/quickshell.log`
   BELOW the last start marker.** All three lint gates are structurally blind to
   a bad QML import — they will stay green while the shell fails to load.
4. **Restart AFTER the last edit of a task, not before.** Incubated pages
   otherwise keep serving stale QML.
5. **`Prefs` is `watchChanges: false`.** A live shell will not see a hand-edit to
   `prefs.json`. Round-trip through `setValue()` or restart.
6. **A green gate only proves what it can see.** `colour-lint` once read 202/0
   while 18 unthemed tooltips shipped. Where a gate is blind, say so in the
   SUMMARY rather than reporting the green number as proof.
7. **Declare QML members before any construction-time use.** An out-of-order
   member throws "is not a function" and a fallback chain then produces a
   plausible wrong answer.
8. **No input-injection tool exists on this host, and `wtype` types into the
   focused browser.** Every hover check goes to the operator.
9. **Push to origin at every task boundary.** GSD commits but never pushes.
