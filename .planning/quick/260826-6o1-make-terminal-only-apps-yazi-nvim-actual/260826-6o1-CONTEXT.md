# Context — terminal-only apps as xdg default handlers

## The defect (measured, not inferred)

`xdg-open`'s generic resolver takes the first word of a `.desktop` entry's `Exec=`
line and runs it directly, **ignoring `Terminal=true`**. Hyprland matches no
`detectDE` case in `/usr/bin/xdg-open`, so `DE=generic` routes to
`open_generic_xdg_mime` — this was settled by reading the script during quick task
260826-437, not by guessing between `gio` and `xdg-mime`.

Consequence: selecting a `Terminal=true` entry in Settings → Apps writes a default
that opens **no window**. `AppsPage.qml:352` already documents this in a comment;
`AppsPage.qml:403` only *labels* the entry `" (needs a terminal)"` rather than
making it work.

Affected entries on this host:

| Entry | `Exec` | `Terminal` | `MimeType` | `Categories` |
|---|---|---|---|---|
| `/usr/share/applications/yazi.desktop` | `yazi %f` | `true` | `inode/directory` | `System;FileManager;FileTools;ConsoleOnly` |
| `/usr/share/applications/nvim.desktop` | `nvim %F` | `true` | `text/plain` + 14 more text/* | `Utility;TextEditor;Development` |

`vim.desktop` is registered for the same text types and is in the same class.

## Decision — LOCKED by the operator

**Stowed wrapper `.desktop` entries + one repo script that reads `apps.terminal`
at launch time.** Rejected: shell-generated wrappers (creates host-side state that
goes stale the moment `apps.terminal` changes, and needs a regeneration hook), and
dropping `Terminal=true` entries from the pickers (reverses the nvim File-editor
option deliberately added in 260826-437 the same day).

Shape the operator approved:

```
hypr/.config/hypr/scripts/open-in-terminal
  term=$(jq -r '.apps.terminal // "kitty"' \
         ~/.local/state/quickshell/prefs.json 2>/dev/null)
  exec "${term:-kitty}" -e "$@"

yazi/.local/share/applications/yazi-terminal.desktop
  [Desktop Entry]
  Name=Yazi File Manager
  Terminal=false
  Exec=.../open-in-terminal yazi %f
  MimeType=inode/directory;
  Categories=System;FileManager;

Picker shows:  "Yazi File Manager"   <- works
  (raw yazi.desktop no longer offered)
```

## Why this shape (evidence)

- **Stowing `.desktop` files is an existing repo idiom, not new machinery.**
  `vscodium/.local/share/applications/` already ships three of them
  (`codium.desktop`, `claude-code-url-handler.desktop`, `Vampire Survivors.desktop`).
  So the wrapper is reproducible via `stow.sh` + `install.sh` with no host-only state,
  satisfying the CLAUDE.md reproducibility constraint by construction.
- **The wrapper never goes stale.** `apps.terminal` is a *bare executable name*
  (`Prefs.qml:285` default `"kitty"`), read live by the script on each launch. A
  generated `Exec=kitty -e yazi %f` would snapshot the terminal instead.
- **`-e` is this repo's established terminal-invocation convention** — already
  hardcoded at `SystemCapsule.qml:588` and `UpdatesPage.qml:167,302` as
  `[Prefs.getValue("apps.terminal"), "-e", …]`.
- **`DesktopEntry.runInTerminal` is a real property**, verified in
  `/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes:386` — the picker filter has
  a sound basis and will not silently no-op.

## Constraints carried into the plan

- Preserve each entry's own field code: yazi uses `%f` (single file), nvim uses `%F`
  (multiple). Do not normalise them to one.
- `~/.local/state/quickshell/prefs.json` currently has `apps: null` — the key is
  absent until the user first changes it. The script MUST fall back to `kitty`
  on a missing key, a missing file, and malformed JSON. `jq` 1.8.2 is installed
  (`/usr/bin/jq`).
- New stow-package paths must be reflected in `stow.sh` / `install.sh` if the
  package is new; `yazi` and `nvim` are already in `stow.sh`'s `PACKAGES` list.
- `stow-link-check` (`hypr/.config/hypr/scripts/stow-link-check:231`) carries an
  explicit package allowlist — check whether a new `.local/share/applications`
  path under `yazi`/`nvim` needs registering there.
- Gate baselines to hold (quote the scope with the number): `qml-import-check 0/135`,
  `settings-index-check 177/0`, `colour-lint 401/0`, `motion-lint 588/0` default
  scope / `406/0` quickshell-only scope.

## Agent safety — operator-only, do not run

`xdg-mime default …`, any quickshell restart, `quickshell-doctor`, and screenshots
are operator-only on this host. Verify the write path by inspection; leave live
confirmation to the operator checklist in the SUMMARY.
