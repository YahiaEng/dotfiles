# 260826-6o1 — terminal-only apps as working xdg default handlers

Closes the open item carried out of 260826-437: `yazi.desktop` was offered in the
File explorer picker with a `" (needs a terminal)"` suffix and **would not open a
window if selected**. The same applied to `nvim`/`vim` in the File editor row.

## Cause

`xdg-open`'s generic resolver never reads `Terminal=true`. Read from
`/usr/bin/xdg-open`: Hyprland matches no `detectDE` case, so `DE=generic` routes to
`open_generic_xdg_mime` → `search_desktop_file`, whose operative lines are

```sh
command="$(get_key "${file}" "Exec" | first_word)"
if command -v "$command" >/dev/null; then
    ...
    env "$command" "$@"
```

The first word of `Exec` is run directly, PATH-resolved. `Terminal` is never
consulted. So a console app set as a default handler produces no window.

## What shipped

**1. `system/usr/local/bin/open-in-terminal`** (`e0c2ff16`) — resolves the terminal
at launch from `~/.local/state/quickshell/prefs.json` (`.apps.terminal`), then
`exec "$term" -e "$@"`. Reading it live rather than baking one in means changing
Settings → Apps → Terminal takes effect with no regeneration step and nothing to go
stale. Installed via `install.sh`'s existing `sudo install -Dm755` pattern, mirroring
`kernel-module-verify`.

It goes to `/usr/local/bin` rather than a `$HOME` path because **a `.desktop` `Exec=`
line cannot contain `~` or `$HOME`**, and hardcoding `/home/aorus` — the precedent set
by `claude-code-url-handler.desktop` — would break the entries for any other username.
An absolute system path is username-independent and always on PATH.

**2. Two `Terminal=false` wrapper entries** (`390cee3a`) —
`yazi-terminal.desktop` (`inode/directory`, `%f`) and `nvim-terminal.desktop`
(nvim's MimeType list verbatim, `%F`). Field codes kept per-entry, not normalised.
Both `desktop-file-validate` clean.

**3. `AppsPage.qml` drops `Terminal=true` entries** (`cbed007b`) instead of labelling
them. `DesktopEntry.runInTerminal` verified real at
`/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes:386` before being relied on.

## Two findings that changed the shape mid-task

- **`~/.local/share/applications` is a whole-directory stow fold** into
  `vscodium/.local/share/applications`. The wrappers went into that existing package;
  a second package targeting the same path would have forced stow to unfold it. That
  directory also has a deliberate deny-all + explicit-opt-in ignore rule, so both
  wrappers needed `!` lines alongside `codium.desktop`.
- **There was no `mimeinfo.cache`**, and this was load-bearing. Without it `gio mime`
  reports only system entries — measured here, it listed `yazi.desktop` but *not* the
  stowed `codium.desktop` despite codium declaring `inode/directory`. The pickers build
  their candidate lists from exactly that output, so the wrappers would have been
  invisible. `stow.sh` now runs `update-desktop-database`; the generated cache is
  covered by the directory's existing deny-all.
  A second gate on visibility: `TryExec` hides the wrappers until the launcher is
  installed, which is why the `install.sh` step is required, not optional.

## Known limitation

`vim.desktop` is now dropped with no replacement — wrappers exist only for yazi and
nvim, and vim is not a stow package here. Add a third wrapper if vim is wanted back.

## Operator checklist — not run by this agent

`xdg-mime default`, quickshell restarts, `quickshell-doctor` and screenshots are
operator-only on this host.

1. Restart quickshell through the unit, then open Settings → Apps.
2. **File explorer** should list *Yazi File Manager* and *Thunar File Manager*, with
   no "(needs a terminal)" suffix anywhere on the page.
3. **File editor** should list *VSCodium* and *Neovim*.
4. Select *Yazi File Manager*, then confirm the write path and that it opens a real
   window:
   ```
   xdg-mime query default inode/directory     # -> yazi-terminal.desktop
   xdg-open ~/Downloads                       # -> yazi inside your terminal
   ```
5. Change Settings → Apps → Terminal to something else and re-run `xdg-open ~/Downloads`
   — it should open in the *new* terminal with no other action. This is the property
   the generated-wrapper approach would not have had.
