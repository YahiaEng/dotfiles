# Quick Task 260820-4b2 — Flip the tmux retirement registry entry to `retired`

## Objective

Arm the blocking retirement-check tier for the `tmux` surface by flipping its
registry status from `pending` to `retired`, now that the host package is gone.

## Why now — measured ground truth (2026-08-20)

The entry shipped `pending` in 260820-2yz for exactly one reason, recorded in the
script's own header: the `host-package` class is BLOCKING and runs `pacman -Q tmux`
against the live host, where the package was deliberately still installed
(D-04/D-07 — repo retirement is not host uninstall).

That condition no longer holds. Measured on this host before planning:

| Probe | Result |
|---|---|
| `pacman -Q tmux` | `error: package 'tmux' was not found` |
| `pacman -Q tmux-plugin-manager` | `error: package 'tmux-plugin-manager' was not found` |
| `command -v tmux` | not on PATH |
| `pgrep -a tmux` | no process |
| `~/.config/tmux` | absent (never a dangling symlink — STATE.md's note was stale) |
| `~/.local/share/tmux` | removed (was tmux-resurrect state) |
| `retirement-check tmux` (pending) | all 16 classes clear; `host-package: 0 reference(s)` |

Two corrections to the notes carried in STATE.md, both measured rather than assumed:
`~/.config/tmux` did not exist at all, so there was no dangling symlink to remove;
and tpm was not "4 orphaned clones" but the pacman package `tmux-plugin-manager`
3.1.0-1, which **depends on `tmux>=1.9`** and therefore had to be removed in the
same transaction.
