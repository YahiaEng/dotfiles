# Quick Task 260819-6oy — News tab in the notification centre, with a source dropdown

## Objective

The notification centre shows one thing: notifications. Give it a second pane —
headlines pulled from a hand-editable list of RSS/Atom feeds — reachable from a
tab bar that lives inside the header band the centre **already has**, so not one
pixel of surface geometry moves.

Four things ship, in this order:

1. **The contract registration and the seed** — both new state files declared in
   `contract.json`'s `engine_owned_files` **before** anything can create them,
   and `news-sources.json` seeded by `stow.sh` with the three default feeds.
2. **`NewsBackend.qml`** — the fenced feed fetcher: XHR + `responseXML` + a
   manual `childNodes` walk covering RSS and Atom, merged, sorted, capped,
   cached, open-gated on `NotifServer.centreOpen`.
3. **`NewsPane.qml`** — the source dropdown, the headline list, and six
   distinct render states.
4. **`NotifCentre.qml`** — the header band becomes a two-tab bar, the history
   region becomes page 0 of a pager, the News pane becomes page 1.

The ordering is not cosmetic. **Tasks 2 and 3 land and are verified before Task
4 touches NotifCentre's structure**, so a tab restructure is never being
debugged at the same time as a feed parser.

## Locked design — from `.planning/notes/news-tab-feed-parsing.md`

That note is the design contract. Every decision in it was measured on this
host during a `/gsd-explore` session and is **NOT open for re-derivation**:

- **`XmlListModel` is ruled out.** Qt6 removed its `xml` string property and it
  has **no `get()`** — only `reload()` and `errorString()`. It can drive a view
  delegate and nothing else, so filtering/merging/caching from JS is impossible.
- **`getElementsByTagName` is ABSENT** from Qt's QML DOM. Walk `childNodes`.
- **CDATA** is handled by concatenating child `nodeValue`s (measured: BBC wraps
  every `<title>` in CDATA and it extracted correctly).
- **Atom `href`** reads via `node.attributes[i].nodeValue`.
- One ~20-line walker covers both formats. Proven: RSS 30/30 items with
  title+link+pubDate; Atom 4/4 entries.
- **Tab layout:** `TabBar` + `SwipeView` synced one-way *from* the pager, in the
  **existing** header band. No vertical space added. The count folds into the
  tab label.
- **Source list:** seeded, hand-editable `news-sources.json`, watched
  `FileView` + `JsonAdapter`. Defaults BBC World / NPR / LWN. **No in-shell
  editor UI** (deferred).
- **Refresh:** open-gated on `NotifServer.centreOpen`. Paint cache first, refetch
  only past a ~15-min TTL. Manual ⟳ button. Zero timers, zero network while
  closed.

## The fence — a deliberate, recorded widening of the one-host rule

`WeatherBackend`/`GeocodeBackend` fence a host by holding its literal in a
`readonly property string` and grepping that exactly one `.qml` file names it.
**That shape does not fit here**, because the feed hosts live in an
operator-editable JSON file by design (locked decision 2), not in the QML.

The rule is therefore widened, explicitly, and the widening is recorded in
`NewsBackend.qml`'s own header exactly as quick task 260818-v3m recorded its
own correction rather than leaving a false claim standing:

- **`NewsBackend.qml` is the ONE `.qml` file from which a feed request may be
  issued.** Verified by grep: exactly three `.qml` files in the tree construct
  an `XMLHttpRequest`, and this is the third.
- Because the host list is operator-editable, the literal-host fence is
  replaced by a **scheme allowlist**: `https://` only, enforced in **two**
  places — at source validation (a non-https source is never fetched) and again
  at item acceptance (a non-https `link` never enters the model). Two
  enforcement points, because they guard two different attack surfaces: a
  mistyped/hostile *source* and a hostile *feed response*.
- The three default host strings appear in exactly two places: `stow.sh`'s seed
  block and `NewsBackend.qml`'s header comment documenting the defaults. No
  other `.qml` file names any feed host.

### The DOM helpers — three small functions, no library

- `_childrenNamed(node, name)` → array. Loop `node.childNodes`, compare
  `nodeName`. **This is the replacement for the absent `getElementsByTagName`.**
  Return `[]` (never null) on a null node.
- `_textOf(node)` → string. Loop `node.childNodes`, concatenate every
  `nodeValue` that is a string, trim. This is what makes CDATA transparent.
  Return `""` on a null node.
- `_attrOf(node, name)` → string. Loop `node.attributes` by index, compare
  `nodeName`, return `nodeValue`. Guard a null/absent `attributes` collection.
  This is the Atom `<link href>` reader.

### `_parseFeed(doc, sourceName)` → array of items

Explicit shape check first, and **log every rejection** — a guard that returns
silently makes total failure look like a plausible wrong answer:

- `doc` null, or `doc.documentElement` null → log with the source name, return `[]`.
- Read `doc.documentElement.nodeName`:
  - `"rss"` → items are `documentElement > channel > item`. Per item:
    `title` = `_textOf` of the first `title` child; `link` = `_textOf` of the
    first `link` child; `date` = `_textOf` of the first `pubDate` child.
  - `"feed"` → entries are `documentElement > entry`. Per entry:
    `title` = `_textOf` of the first `title` child; `link` = `_attrOf(linkNode,
    "href")` preferring a `link` whose `rel` is absent or `"alternate"`;
    `date` = `_textOf` of `updated`, falling back to `published`.
  - anything else → log the unrecognised root name and return `[]`.
- Date: `Date.parse(str)`; `NaN` → `0`. **Never drop an item for an unparseable
  date** — a dateless item sorts last and still shows.
- **Acceptance filter (the second https enforcement point):** accept an item
  ONLY when `title` is a non-empty string AND `link` is a string starting with
  `root.allowedScheme`. Everything else is rejected, counted, and the per-feed
  reject tally is logged with the source name. This is what makes the pane's
  click handler safe without a confirm dialog — a `javascript:`, `file:` or
  plain-`http` link from a hostile or compromised feed never enters the model.
- Emit each accepted item as
  `{ title, link, dateMs, source: sourceName }`.
- Cap the returned array at `maxItemsPerSource`.

### `_validSources()` → array

From `newsState.sources`: keep entries that are non-null objects with a
non-empty string `name`, a string `url` starting with `allowedScheme`, and
`enabled !== false`. Cap at `maxSources`. **Log each rejection with its array
index and the specific reason** (not an object, missing name, non-https url,
over the cap). Publish the result as `sources`. This is the first https
enforcement point, and the list the dropdown reads.

### `_fetchSource(src)`

Guards, in order, each logged if it fires: `!centreOpen` → return;
`src.url` does not start with `allowedScheme` → return (defence in depth — this
should already be unreachable through `_validSources()`, and if it ever fires
the log says the validator has a hole).

Then `requestsInFlight++`, XHR GET, `setRequestHeader("User-Agent",
root.userAgent)` (measured allowed by this Qt build — `user-agent` is not in
the QML-XHR forbidden-header table, per 260818-v3m's binary inspection), push
the xhr onto `_activeXhrs`, `send()`.

In `onreadystatechange`, on `DONE` — decrement `requestsInFlight` FIRST, remove
from `_activeXhrs`, then classify:

| Condition | Action |
|---|---|
| `status === 0` | `sourcesFailed++`, `lastError = "network"`, log the source name |
| `status !== 200` | `sourcesFailed++`, `lastError = "http " + status`, log source + status |
| `responseText.length > maxResponseBytes` | `sourcesFailed++`, `lastError = "oversize"`, log source + byte count |
| otherwise | `try { push _parseFeed(xhr.responseXML, src.name) into _runBuffer; sourcesOk++ } catch (e) { sourcesFailed++; lastError = "parse"; log source + e }` |

A source that parses cleanly but yields **zero** items still counts as
`sourcesOk` — success-with-nothing is a different state from failure, and the
pane renders them differently.

Finally: `if (root.requestsInFlight === 0) root._finishRun();`

### `_finishRun()`

Merge `_runBuffer`, sort by `dateMs` descending, cap at `maxItemsTotal`, assign
to `items` **in one assignment** (never incrementally — a half-rendered list is
the failure mode the whole shape-check discipline exists to prevent), set
`fetchedAtMs = Date.now()`, clear `_runBuffer`, update `widgetState`.

**Write the cache ONLY if `sourcesOk > 0`.** If every source failed, leave both
`items` and the cache exactly as they were — that is what makes "no network,
open the centre, still see yesterday's headlines" work rather than blanking the
pane. Log the skip.

### `refresh(force)` — the only entry point

Guards, each logged: `!centreOpen` → return; `requestsInFlight > 0` → return;
`!force && !isStale` → return ("cache fresh, N minutes old, skipping"). Then
reset `sourcesOk`/`sourcesFailed`/`lastError`/`_runBuffer` and call
`_fetchSource` for each entry in `sources`.

### `abort()`

Loop `_activeXhrs`, `abort()` each inside try/catch, clear the array, zero
`requestsInFlight`, clear `_runBuffer`. Zero idle footprint (D-32).

### (c) The six render states

One `readonly property string paneState` — exactly one place the decision
lives, so the overlays can never disagree with each other:

```
readonly property string paneState: {
    if (!root._hasBackend)                                   return "error";
    var b = root.newsBackend;
    if (b.visibleItems.length > 0)                           return "populated";
    if (b.items.length > 0)                                  return "filtered-empty";
    if (b.requestsInFlight > 0)                              return "pending";
    if (b.sources.length === 0)                              return "unconfigured";
    if (b.sourcesFailed > 0 && b.sourcesOk === 0)            return "error";
    return "empty";
}
```

| `paneState` | Trigger | Glyph | Headline | Sub-line |
|---|---|---|---|---|
| `populated` | ≥1 item after filtering | — | the list | quiet footer line, see below |
| `filtered-empty` | items exist but the chosen source has none | `filter_list` | "No headlines from {source}" | tappable "Show all sources" → clears `selectedSource` |
| `pending` | 0 items, ≥1 request in flight | `autorenew`, rotating | "Fetching headlines…" | — |
| `error` | 0 items, every source failed (or no backend) | `cloud_off` | "Couldn't reach the feeds" | `lastError` + "Tap ⟳ to retry" |
| `unconfigured` | 0 valid sources in the file | `newspaper` | "No news sources configured" | "Edit ~/.local/state/theme/news-sources.json" |
| `empty` | 0 items, ≥1 source succeeded | `newspaper` | "No headlines right now" | "{N} sources checked" |

**This is the answer to every error case the task asks about:**

- **No network** — every XHR returns `status 0`. If the cache had items,
  `_finishRun()` never overwrote them, so `visibleItems` is non-empty and the
  pane stays `populated`, with the footer line naming the failure. If there was
  no cache, `error`.
- **Feed 404** — that one source fails, the others still merge, so the pane is
  `populated` and the footer says "1 of 3 sources unreachable". Only if *all*
  sources 404 does it become `error`.
- **Malformed XML** — `responseXML` is null, or the walk throws; the catch
  block counts it exactly as a 404 and logs `parse`. Identical rendering.
  It can never half-render: `_finishRun()` assigns `items` in one statement
  from a fully-built buffer.
- **Zero items** — sources succeed but yield nothing. `empty`, visually
  distinct from `error`, because success-with-nothing is not a failure.
- **Zero sources** — `unconfigured`, and it names the file to edit, since
  there is no in-shell editor by design.

The `populated` footer line — one `Text` at `Design.fontLabel` /
`BarRoles.capsuleFg`, visible only when it has something to say:

- `sourcesFailed > 0` → "{failed} of {failed+ok} sources unreachable"
- else `isStale` → "Updated {relative age} ago"
- else hidden entirely (a `Column` skips non-visible children, so it costs zero

`onClicked: newsBackend.refresh(true)`. While `requestsInFlight > 0`, rotate it
with a looping `RotationAnimation` at `Motion.ambientDuration` /
`Motion.ambientEasing` — a loop period, which is what that token is for.

**The cross-fade between the two buttons must go through `Qt.callLater`.** This
is the same bug class the existing `on_HasHistoryChanged` handler already works
around in this very file: an animation's `to` expression, read at the instant
the change-notify signal is delivered, races ahead of the dependent property's
own binding re-evaluation and restarts toward the value it is already sitting
at. Keying an opacity animation on `pager.currentIndex` hits it identically.
Defer the restart by one event-loop tick, exactly as the existing handler does.

### (f) The pager

Insert a `SwipeView` where `historyRegion` currently anchors, and move
`historyRegion` inside it as page 0:

```
Connections {

}

    id: pager
    anchors.top: header.bottom
    anchors.left: parent.left
    anchors.right: parent.right

    anchors.rightMargin: Design.spacingMd     // moved up from historyRegion
    anchors.bottom: footerHost.top
    anchors.bottomMargin: Design.spacingLg    // moved up from historyRegion
    clip: true
    spacing: 0

        currentIndex: pager.currentIndex

        spacing: pager.spacing
        orientation: pager.orientation
        snapMode: ListView.SnapOneItem
        boundsBehavior: Flickable.StopAtBounds
        highlightRangeMode: ListView.StrictlyEnforceRange
        preferredHighlightBegin: 0
        preferredHighlightEnd: 0
        highlightMoveDuration: Motion.standardDuration
        maximumFlickVelocity: 4 * (pager.orientation === Qt.Horizontal ? width : height)
        keyNavigationEnabled: false           // ← Escape handler survives
    }

    Item { id: historyRegion /* anchors REMOVED — SwipeView sizes its pages */ clip: true ... }

    NewsPane { newsBackend: centreWindow.newsBackend }
}
```

Four things about that block are not optional:

1. **The `Connections` block, not a plain binding.** `TabBar` writes its own
   `currentIndex` imperatively when a button is clicked (Container's internal
   click handling), which breaks a plain binding after the first tap. This is
   what makes the one-way flow — pager holds selection, header reports it —
   hold for the surface's whole lifetime. `Dashboard.qml:936-942` verbatim.
2. **`focus: false` + `keyNavigationEnabled: false`.** These are why
   `content`'s `Keys.onEscapePressed` (line 265) keeps working.
   `Dashboard.qml:1060-1064` records exactly that reason. Escape-to-close is a
   named verification step below, not an assumption.
3. **`highlightMoveDuration: Motion.standardDuration` is a source assertion.**
   motion-lint's QML raw-value check anchors on a lowercase `duration:` and
   never matches the camel-cased property name, so a literal here would pass
   every gate in this repo silently. Carry `Dashboard.qml:1064-1069`'s comment
   forward so the next reader knows the gate does not cover this line.
4. **`historyRegion` drops ALL its anchors.** SwipeView sizes its own pages;
   leaving anchors on a page fights that sizing. The `leftMargin`/`rightMargin`
   /`bottomMargin`/`clip` move **up** to the pager, so the rendered box is
   identical to today's. `historyRegion`'s children keep their own
   `anchors.centerIn: parent` / `anchors.fill: parent` and are unaffected.

**Neither page goes behind a `Loader`**, unlike Dashboard's four tabs. Each
page's real cost is already gated at its own data source — the history
`ListView`'s model is gated on `centreWindow.visible`, and `NewsBackend` is
gated on `centreOpen`. A `Loader` would add a destroy/recreate cycle on every
tab switch that the list's scroll position would pay for, and buy nothing.

**A horizontal pager is safe over the history page** because the centre's
history rows carry no horizontal drag gesture — `NotifGroup.qml:705-711`
records the deliberate choice of an explicit close glyph over swipe-to-dismiss.
Note that in a comment; it is the fact that makes this whole layout viable, and
a future reader adding swipe-to-dismiss to the centre needs to find it.

## Out of scope

- **An in-shell source editor.** Adding, removing or reordering feeds is done
  by editing `~/.local/state/theme/news-sources.json`. Locked decision 2
  defers the editor to a seed; the dropdown built here is a *filter*, not an
  editor.
- **Article bodies, images, or a reader view.** Headlines and links only.
- **Any refresh timer.** The gate is `NotifServer.centreOpen` plus the manual
  ⟳ button. Zero timers by design (D-32) — do not add a "background refresh".
- **Read/unread state per headline.** No persistence beyond the cache.
- **Hiding the count at zero.** A behaviour change, not this task's; see (d).
- **JSON Feed support.** Trivial via `JSON.parse` per the note, but no default
  source needs it — add it when one does.
- **Editing any gate script.**
- Anything under `fastfetch/`, the weather panel, or the bar.
