# Quick Task 260819-426 — Summary

## What was wrong

Not the lookup. `_revalidateAgainstSettings()` runs during construction (the state
`FileView` load calls `loadCache()` → `_revalidateAgainstSettings()`), and it called
`_resolveCityIfNeeded()` — which, along with the `GeocodeBackend` child, was declared
about 200 lines further down the file and did not yet exist on the object.

```
WeatherBackend.qml[313]: TypeError: Property '_resolveCityIfNeeded'
of object WeatherBackend_QMLTYPE_21 is not a function        (x18)
```

Every invocation threw. `city` stayed empty. The resolution chain fell through to
step 3, the timezone fallback — and `Africa/Cairo` prints "Cairo" whether the
coordinates are Cairo's or Alexandria's.

**That is what made it dangerous.** The bug produced a plausible wrong answer, not a
visible failure. It was equally invisible in Cairo, where the wrong path happened to
agree with reality.

## What was NOT wrong (each eliminated by measurement, not reasoning)

- **Nominatim** returns HTTP 200 and `Alexandria` for the component's exact URL and
  exact User-Agent. With no User-Agent it returns 403 — so the header matters, and it
  is sent.
- **Qt's User-Agent handling.** A local HTTP listener received the component's UA
  string verbatim from a QML XHR. The earlier plan-time check only proved `user-agent`
  is absent from Qt's forbidden-header table — necessary, not sufficient. This closes
  that gap end-to-end.
- **Qt → Nominatim over TLS.** A `qml6` harness got HTTP 200 and the Alexandria
  payload.
- **The wiring.** Both call sites present; brace-depth analysis confirmed the resolver
  is a root-level member, not accidentally nested.

## Fix

`GeocodeBackend` child and `_resolveCityIfNeeded()` moved above
`_revalidateAgainstSettings()`, with a comment stating that the order is load-bearing
and must not be undone.

**Verified: 18 TypeErrors before the reload, 0 after.**

`cityLabelSource` still reports `timezone` at rest, correctly — `resolve()` returns
early while the drawer is closed. It fires on the next drawer open.

## Two things that made this hard to see

1. **The systemd unit journals nothing.** `journalctl --user -u quickshell` is empty;
   every QML warning and `console.log` goes to `~/.cache/quickshell.log`, the
   launcher's own sink. Looking in the journal first cost real time.
2. **`console.log` is invisible under `qml6`** in this environment, so the throwaway
   harness had to report its result over a local HTTP socket instead of printing it.
