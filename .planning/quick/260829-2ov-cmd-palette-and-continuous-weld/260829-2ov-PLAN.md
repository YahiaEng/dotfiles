## Task 1 — `cmd` word route: a flat command palette over MenuTree

**Files:** `quickshell/.config/quickshell/modules/launcher/LauncherState.qml`,
`.../CommandMode.qml` (new), `.../qmldir`, `.../Launcher.qml`

**Action:**
- `LauncherState.qml`: append `modeCommands: "commands"` (APPEND, never insert —
  this file's own standing rule) and add `"cmd": root.modeCommands` to
  `_wordRoutes`, beside `pkg`/`icon`/`font`. No other change: `routePrefix`,
  `routePartial`, `queryArg` and `_routeQuery` all iterate `_wordRoutes`
  generically, so the accent painting, the partial-match feedback and the
  prefix-stripping all come free.
- New `CommandMode.qml`, modelled directly on `MenuMode.qml`: walks
  `MenuTree.roots` **recursively** into a flat leaf list carrying a `_trail`
  breadcrumb, fuzzy-scores `trail + " " + text` with the shared `fuzzy.js`, and
  activates a row through the **same four branches** `MenuMode.activate()` uses,
  in the same order: `workbench` → `PackagesBackend.openWorkbench`, `appearance`
  → `AppearanceBackend.openAtelier`, `mode` → set `LauncherState.mode` (no
  dismiss), `command` → `Quickshell.execDetached(["sh","-c", …])` + dismiss.
- `qmldir`: `CommandMode 1.0 CommandMode.qml`, declared in the same commit that
  creates the file (this manifest's own rule).
- `Launcher.qml`: `case LauncherState.modeCommands: return commandComponent;`
  plus the `Component { id: commandComponent; CommandMode { dismissCallback:
  launcherWindow._beginDismiss } }` pair, and a `{ prefix: "cmd ", label:
  "Commands" }` row in the `;` providerlist's `_entries`.

**Verify:** `grep` the four touched files for the new identifiers; `colour-lint`
and `motion-lint` clean; `singleton-prop-check` resolves `MenuTree.roots`,
`PackagesBackend.openWorkbench`, `AppearanceBackend.openAtelier`; the hot-reload
line in `~/.cache/quickshell.log` shows no QML load error (the ONLY instrument
that sees one — qmllint/qmlformat fail silently here).

**Done:** typing `cmd` in the launcher lists every MenuTree leaf; `cmd theme`
narrows to Style ▸ Theme and Enter opens the theme picker.

## Task 2 — the weld's end capsules clear the core's cap

**Files:** `quickshell/.config/quickshell/modules/Bar.qml`

**Measured, not assumed** (grim + raw per-pixel dump at x2500–2560, the repo's
standing rule): the weld slab spans x2502–2554, the `Colours.surface` core spans
x2506–2550 (44 = `barColumnWidth`), and its pill cap is centred at **y=32 with
radius 22**, core top at **y=10** (`_weldCapDepth` = `edgeBarThickness` 6 +
`edgeBarWeldRim` 4). `barContent` takes `topMargin/bottomMargin = _weldCapDepth`
and `startZone.y = 0`, so the app-drawer capsule's box starts at **y=10, the
cap's apex, where the pill has zero width** — and the box is itself 44 wide, the
core's full width. Its corners are outside the shape. Same at the bottom for the
power glyph.

**Action:** the run-axis content inset becomes the **cap tangent line** —
`_weldCapDepth + coreDepth / 2` = 10 + 22 = **32**, the first y at which a
44-wide box fits inside a 44-wide pill. Introduced as a named
`_weldContentRunInset` so Task 3 can reuse it on the other axis.

**Verify:** re-measure the same column with grim after the reload; the first
capsule's top edge must land at the cap's tangent, not its apex.

**Done:** app-drawer and power glyphs no longer crowd the screen edge.

## Task 3 — horizontal Continuous: the rail wraps the bar

**Files:** `quickshell/.config/quickshell/modules/Bar.qml`

`_continuousWeld` is hard-gated `&& vertical`, so a horizontal bar gets no weld at
all today — it floats plainly under the top rail.

**Action, keeping the blast radius at zero for the vertical path:**
- Split the predicate rather than widening it. `_continuousWeld` keeps its exact
  present meaning (continuous **and vertical**) so every consumer that must stay
  vertical-only is untouched by construction: `margins.top/bottom → 0`, the
  `implicitWidth` growth, both weld stubs, the vertical slab, `popoutBulgeDepth`,
  and the two `PopoutController` Bindings (`rootAttached`/`rootInset` — a
  horizontal bar has no bulge shelf to publish). Add `_continuousWeldH`
  (continuous and NOT vertical) and `_welded` (either) for the pieces that are
  genuinely shared.
- Horizontal weld geometry, transposed from the vertical one:
  - `margins.left/right → 0` so the slab spans the full screen width, exactly as
    the vertical weld's `margins.top/bottom → 0` spans the full height. Neither is
    the anchored (reserving) edge, so `reserved` stays `[0, 48, 0, 0]`.
  - `implicitHeight → Design.barHeight + 2 * edgeBarWeldRim` (50). The extra 8
    overhangs into the client area and reserves nothing — the same non-reserving
    overhang idiom the vertical weld's leftward widening already uses.
  - One horizontal slab `Shape`, `EdgeBarPath.buildOutline` with
    `axis: "horizontal"`, `bulge: false` (an explicit branch — `b = 0`
    self-intersects, per that file's own note) and `re = depth / 2` (true pill
    caps, the builder's stated precondition).
  - The gradient is the **strip's**, not a second one: same `_stripGradX1` /
    `_stripPeriod` mapping the weld stubs already use, generalised so a
    horizontal bar's surface origin and the top strip's period resolve for its
    own orientation. That is what makes the rim colour-continuous with the rail
    directly above it at every x.
  - The core `Rectangle` becomes orientation-aware rather than duplicated.
    Horizontal takes a **uniform `edgeBarWeldRim` inset on both axes** — the
    vertical core's asymmetric 10px end inset exists only to swallow the
    perpendicular rail runs, and a horizontal bar has none, so a symmetric rim is
    both correct and literally "wrapped".
- `barContent` becomes orientation-aware on the same two quantities: the run axis
  takes `_weldContentRunInset` (Task 2) and the depth axis takes the rim. Its
  `width` stays a real number in every branch — **never `: undefined`**, the trap
  this file's own header records.

**Verify:** flip to horizontal from Settings, `hyprctl monitors -j` still reads
`reserved [0, 48, 0, 0]`, grim the top band and confirm rail → rim → core → rim
with no seam; flip back to vertical and re-confirm Task 2's measurement is
unchanged.

**Done:** the horizontal Continuous bar reads as wrapped by the rail, matching the
vertical identity.
