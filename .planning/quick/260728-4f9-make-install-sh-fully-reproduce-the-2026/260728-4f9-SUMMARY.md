## Decisions worth recording

**The LTS kernel goes in `section_hardware()`, not `PACMAN_PKGS`.** `--core-only` drives
the container/VM verification gate, where installing a second kernel is meaningless and
slow. It sits *outside* the `lspci | grep -qi nvidia` guard, because a fallback kernel is
worth having whatever the GPU vendor.

**Its position within the section is load-bearing.** After the NVIDIA block so the DKMS
module is registered when the LTS kernel lands and the alpm hook builds for it in the
same chain; before the limine block so the regenerated `limine.conf` picks up the entry.
Confirmed on the reference host: installing `linux-lts` produced both the nvidia build for
`6.18.40-2-lts` and its limine entry unattended.

**The verification gate is non-fatal by construction.** `install.sh` runs under
`set -euo pipefail`; an unguarded non-zero exit would abort *after* everything was
installed, converting a useful warning into a confusing failure. Tested explicitly — a
simulated failure prints the warning and the script reaches the end with exit 0.

**`nvidia-dkms` → `nvidia-open-dkms` was cosmetic, not a bug.** Verified
`nvidia-open-dkms` declares `Provides: nvidia-dkms` and `Replaces: nvidia-dkms`, so the
old name resolved to the right package. Corrected because it no longer said what it meant.

## Known consideration

The pacman hook is installed *after* all package transactions in a fresh run, so it never
fires during `install.sh` itself — the explicit end-of-run gate is the reporting path.
On a **re-run** against an already-provisioned host the hook does exist, and a genuine
failure would surface mid-run. `alpm-hooks(5)` confirms `AbortOnFail` is **PreTransaction
only**, so a PostTransaction hook can never abort a transaction or leave packages
half-installed; the worst case is `install.sh` stopping early on a real problem that
warranted attention anyway.
