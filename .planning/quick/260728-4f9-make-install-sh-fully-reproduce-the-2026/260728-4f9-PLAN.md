# Quick Task 260728-4f9 — Close the reproducibility gap

## Why

Tasks 260728-3na and 260728-48c fixed the live machine and put the guard in the repo,
but an audit of `install.sh` against what was actually changed on this host shows a
fresh install would still come out **materially different**. Three gaps.

## Audit: live machine vs. what install.sh reproduces

| Change made on this host | Reproduced by install.sh? |
|---|---|
| Orphaned kernel trees removed (13, 6.8 GB) | n/a — a fresh machine has none |
| `linux-modules-cleanup.service` enabled | ✅ yes (260728-3na) |
| `kernel-module-verify` + hook installed | ✅ yes (260728-48c) |
| **`linux-lts` fallback kernel installed** | ❌ **no — entirely absent** |

| **Post-install soundness check** | ❌ **no — nothing verifies the result** |

## Tasks

### Task 1 — Correct the NVIDIA package name

**Files:** `install.sh` (`NVIDIA_PKGS`, ~line 217)

**Action:** `nvidia-dkms` → `nvidia-open-dkms`.

Arch dropped the proprietary kernel modules at driver 610 — `nvidia`, `nvidia-dkms` and
`nvidia-lts` are gone from the repos. `nvidia-open-dkms` declares
`Provides: nvidia-dkms` and `Replaces: nvidia-dkms`, so the current entry still resolves
and installs the right thing. This is therefore **not** a correctness bug — it is a
name that no longer says what it means, and it would confuse the next person reading it.

**Verify:** `pacman -Si nvidia-open-dkms` resolves; name matches what is installed here.

**Done:** array names the package that actually gets installed.

### Task 2 — Install the LTS fallback kernel

**Files:** `install.sh` (new `FALLBACK_KERNEL_PKGS` array + `section_hardware()`)

**Action:** Add `linux-lts` and `linux-lts-headers`, installed in `section_hardware()`.

Placement rationale:

- **In `section_hardware()`, not `PACMAN_PKGS`** — `--core-only` drives the container/VM
  verification gate, where installing a second kernel is meaningless and slow. This is
  boot-resilience, which is exactly what that section is for.
- **Outside the `lspci | grep -qi nvidia` guard** — a fallback kernel is worth having
  regardless of GPU vendor.
- **After the NVIDIA block, before the limine block.** After NVIDIA so the DKMS module is
  already registered when the LTS kernel lands and the alpm hook builds for it in the
  same transaction chain; before limine so the regenerated `limine.conf` picks up the new
  entry. Verified on this host: installing `linux-lts` produced both the nvidia build for
  `6.18.40-2-lts` and its own limine entry, unattended.
- `linux-lts-headers` is required because the driver is DKMS — it must compile against
  the LTS kernel. (It would be unnecessary under a prebuilt `nvidia-open-lts` strategy,
  which is deliberately not what this repo uses.)

**Verify:** array present, installed in the right order, added to `VERIFY_PKGS` when not
`--core-only`.

**Done:** a fresh non-`--core-only` install ends with two bootable kernels.

### Task 3 — Post-install verification gate

**Files:** `install.sh` (after the section calls, before "Next steps")

**Action:** Run `kernel-module-verify` at the end of a full install and surface the
result before the user reboots into a freshly built system.

- Skipped under `--core-only` (no hardware section ran, so no kernel/driver work to check).
- Guarded on the binary existing.
- **Non-fatal.** `install.sh` runs under `set -euo pipefail`, so an unguarded non-zero
  exit would abort the script *after* everything is already installed — turning a
  useful warning into a confusing failure. The script's own precedent for this is the
  `|| echo "  ⚠ ..." >&2` pattern at the swayosd/ollama enables.
- Its output is the last thing before "Next steps", where it will actually be read.

**Verify:** `bash -n`, `shellcheck`; gate runs and reports on this host; a simulated
failure does not abort the script.

**Done:** a fresh install tells the operator whether its kernels are sound.

## must_haves

**Truths:**
- A fresh full install produces two bootable kernels, both with NVIDIA modules.
- The verification gate cannot abort install.sh.
- `--core-only` behaviour is unchanged (container gate must stay green).
- `NVIDIA_PKGS` names the package actually installed.

**Artifacts:**
- `install.sh` — `NVIDIA_PKGS` corrected, `FALLBACK_KERNEL_PKGS` added,
  `section_hardware()` extended, verification gate added.

## Out of scope

- Removing orphaned module trees from install.sh — destructive, and a fresh machine has
  none. The reaper service handles accumulation going forward.
- Switching to the prebuilt `nvidia-open` / `nvidia-open-lts` strategy — evaluated in
  conversation, decision was to stay on DKMS.
