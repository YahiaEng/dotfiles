# Fix the three quickshell-doctor failures

## Objective

`quickshell-doctor` was run live for the first time on 2026-08-28 (it had been
mis-classified as operator-only; the restart it was feared for is behind the
opt-in `--with-compositor-reload`, and the agent shell's cgroup is disjoint from
`quickshell.service`). It reported **25 passed, 3 failed**. All three failures
were independently confirmed by direct file reads, not taken from the gate's
labels. This task fixes all three.

## Why this matters

Two of the three are real defects that shipped precisely *because* the gate was
never run — the third is a bug in the gate itself that made it report a false
failure while silently skipping a real assertion. This is the
"a gate you refuse to run reports nothing" class.

## Tasks

### Task 1 — launcher-log check: `grep` without `-a` on a NUL-containing log

**File:** `hypr/.config/hypr/scripts/quickshell-doctor:145,3005`

`~/.cache/quickshell.log` contains NUL bytes (`file` reports `data`), so GNU
grep short-circuits to "binary file matches" and returns no lines. Consequences,
in order of severity:

1. `LAST_START_LINE_NO` is empty → check 3 reports FAIL although 3 healthy
   startup lines exist (latest `2026-08-28T18:27:37`).
2. **The `else` branch is never entered, so the crash/abort-marker assertion —
   the check that actually matters — never runs at all.** A real crash marker
   would have been invisible. Verified manually: 0 crash markers since the last
   startup.

**Action:**
- Add `-a` to the `grep -n` at line 3005.
- Add a `QSD_FIXTURE_LAUNCHER_LOG` seam at line 145, matching the 15 existing
  `QSD_FIXTURE_*` seams, so the check becomes poison-testable at all. Inert when
  unset (reads the live log), exactly like every sibling seam.
- Add two fixtures + self-test assertions:
  - `compliant-nul-bytes-launcher.log` — contains NUL bytes *and* a startup line
    followed by clean output → must PASS (this is the regression fixture; it
    fails without `-a`).
  - `poisoned-crash-after-start-launcher.log` — NUL bytes, a startup line, and a
    `Segmentation fault` after it → must FAIL. This is the assertion that was
    being skipped; the poison proves it now actually runs.

**Done when:** both new fixtures assert their recorded verdicts under
`--self-test`, and the live check passes.

### Task 2 — `bar-surface-registry`: unregistered layer-shell frame

**File:** `hypr/.config/hypr/scripts/quickshell-doctor` (`QSD_BAR_SURFACE_ROWS`)

`modules/screensaver/ScreensaverSurface.qml` declares
`WlrLayershell.namespace: "quickshell-screensaver"`, `WlrLayershell.layer:
WlrLayer.Overlay` (level 3) and `exclusiveZone: -1`, and appears in neither
`QSD_BAR_SURFACE_ROWS` nor `QSD_KNOWN_NONBAR_FRAMES`. Added by `1d6fa3b2` (the
idle saver). Enumerated all 17 declaring files under the scan root against the
11 rows + 6 known frames — it is the only one unaccounted for.

**Action:** add the registry row, mirroring how the Phase 19 notification family
rows were added (registered, not waved through `QSD_KNOWN_NONBAR_FRAMES` — that
set is for frames that PREDATE the registry, which this does not):

```
"screensaver/ScreensaverSurface.qml|quickshell-screensaver|exact|3|noreserve|transient"
```

Every field verified against the file, not assumed: `exact` because the
namespace is a bare string with no suffix; `3` = Overlay; `noreserve` because
`exclusiveZone: -1` reserves nothing.

**Done when:** `bar-surface-registry` reports `unregistered=0`.

### Task 3 — `bar-colour-role-routing`: route `UpdatesPopout.qml` through BarRoles

**Files:** `quickshell/.config/quickshell/modules/bar/UpdatesPopout.qml`,
`quickshell/.config/quickshell/modules/bar/BarRoles.qml`

7 direct `Colours.*` references. The nine sibling popouts are exempt under
phase 18.1's *scope fence* — but `UpdatesPopout.qml` was written after that
fence, in `45401821` (quick task 260828-75k), so the rationale does not extend
to it. `WINDOWS.md` row 57 is still `open` and says a future phase "should
remove this exemption and shrink `QSD_BAR_COLOUR_ROLE_EXEMPT`". Adding a tenth
entry would widen a blind spot the ledger says to narrow.

**Mapping — every one resolves to a byte-identical colour, so this is pure
indirection with zero visual change:**

| line | was | becomes | both resolve to |

| 86  | `Colours.onSurface`        | `BarRoles.popoutFg`    | `Colours.onSurface` |
| 96  | `Colours.tertiary`         | `BarRoles.warn`        | `Colours.tertiary` |
| 109 | `Colours.outline`          | `BarRoles.outlineColour` | `Colours.outline` |
| 121 | `Colours.outline`          | `BarRoles.outlineColour` | `Colours.outline` |
| 137 | `Colours.primary`          | `BarRoles.accent`      | `Colours.primary` |

Six of the seven map to roles that already exist. Only `Colours.onSurface` has

**Alpha calls stay `Qt.alpha(...)`, never `Qt.rgba(role.r, ...)`** — the
`bar-colour-alpha-resolution` check passes today and must keep passing.

**Done when:** `bar-colour-role-routing` reports `offenders=none` with
