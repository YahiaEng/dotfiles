## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed Caelestia's `signal unlock` to `signal
unlockRequested`**
- **Found during:** Task 1
- **Issue:** The plan's Task 1 action text instructs copying
  `caelestia-lock/Lock.qml`'s `WlSessionLock { signal unlock; ... }` shape
  verbatim. Measured directly against
  `/usr/lib/qt6/qml/Quickshell/Wayland/quickshell-wayland.qmltypes`: the
  installed `WlSessionLock` type already exposes a native `Method { name:
  "unlock" }`. QML does not allow a component instance to redeclare a
  member name inherited from its C++ base type — a custom `signal unlock`
  on the same `WlSessionLock` instance would collide with that inherited
  method and fail to compile.
- **Fix:** Renamed the custom trigger signal to `unlockRequested`
  everywhere in the module tree (`Lock.qml`, `LockPam.qml`,
  `LockSurface.qml`). The deferred-unlock architecture is otherwise
  unchanged: PAM success fires `unlockRequested`, `LockSurface`'s exit
  animation runs, and the animation's own last step is the `PropertyAction`
  that actually sets `lock.locked = false`.
- **Files modified:** `modules/lock/Lock.qml`, `modules/lock/LockPam.qml`,
  `modules/lock/LockSurface.qml`
- **Commit:** `a1416f3a`

## The shell would not start, behind three green gates

The executor reported success with `qml-import-check`, `colour-lint` and
`motion-lint` all passing. `~/.cache/quickshell.log` said otherwise:
quickshell had refused the **entire configuration** with a five-level cascade
ending `LockField.qml[81]: ScriptModel is not a type` — a missing
`import Quickshell`. Nothing looked wrong on screen only because the live shell
keeps its last-good config when a reload fails.

Root cause of the ESCAPE, which mattered more than the bug: `qml-import-check`
collected type references from line-anchored shapes only, so `model: ScriptModel {`
— a type used as a **property value** — was structurally invisible to it. That
is the second escape of the exact class the gate exists to close (the first,
`common/StackPage.qml` in quick-260825-wj2, is named in the gate's own header).
Fixed in `dc5c8d53`, proven with a two-file fixture differing ONLY in whether
the type starts its line: 1 FAIL / 1 silent pass before, 2 FAIL after, and 0
unresolved across 160 files on the real tree.

**The reusable instrument:** the hot-reload verdict in `~/.cache/quickshell.log`
(`Configuration Loaded` vs `Failed to load configuration`) answers "did this QML
actually load" with **no restart**, which matters because restarting the shell
from an agent shell is forbidden here. Every fix below was verified that way.

## The lesson that generated three of the five rounds

Every recurring "still too small / still wrong" traced to a **hardcoded constant
tuned by eye** — `heightMult 0.86`, then font sizes, then `cqw*15`. The class
only closed when the size was *derived from its container* instead of picked.
Same shape as the duration bug: reading a fallback constant instead of the live
value. Prefer a derivation over a number wherever the number can drift.
