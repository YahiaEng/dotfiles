Studies

Seven directions for the two weakest panes of the Super+D drawer — Dashboard and Performance — drawn to scale in your live Dracula palette, each carrying what it would actually cost in QML.

What's actually wrong

Four measurements, taken off the source rather than off a screenshot. They're why these two tabs are the ones worth redrawing, and they constrain every direction below.

400in a 760 frame

The Dashboard tab's content column is contentWidth: 400 (DashboardTab.qml:288) but the drawer floor is dashboardMinWidth: 760 (Design.qml:820). 180px of dead margin sits on each side, every time you open it. Plate D-0 draws the gap.

1040vs 760

Performance renders at 1040 wide; Dashboard at 760. drawerWidth is bound to whichever tab is active (Dashboard.qml:443), so the whole window animates 280px wider and back every time you cross between the two tabs.

1container tint

Colours.qml exposes 19 roles, no helper functions, and no surfaceContainer. On dracula, surfaceVariant, primaryContainer and secondaryContainer are all byte-identical #44475a — one tint above surface, not a ramp.

This is the same trap 14-10 already hit, when a GPU ring drawn in primaryContainer turned out to be invisible against its own track. Any direction built from stacked cards has to solve it.

0rounding scale

Design.qml has per-surface radii scattered through it — popoutCornerRadius: 20, attachedCornerRadius: 24, the drawer's own 28 — but no shared rounding scale. Caelestia's bento leans on exactly that (four different radii across six cells), so a bento direction means adding one.

Performance

Worth knowing before you read these: the reference moved. Our tab was built against a Caelestia that showed a compact gauge cluster — PerformanceTab.qml cites it by name in its own round-2 comment. At the pinned SHA that composition no longer exists upstream. Their Performance tab is cards now, with no dial row anywhere in it.

Structure
Their exact grid: weather and identity across the top, stacked clock / calendar / resource rail beneath, media spanning both rows down the right. Toggles fold into the media column's foot.
The trick
Every cell is the same fill and differs only by corner radius — 18 for the narrow rails, 28 for calendar and identity, 42 for weather, 56 for media. That's what stops six identical rectangles reading as a spreadsheet.
Cost
add a rounding scale to Design.qml needs a container tint new: uptime, distro, avatar stacked 19/•••/41 clock
Also
It settles at 1040 — which fixes the frame jump only if Performance also lands at 1040 (P1 does; P2/P3/P4 don't). These two tabs have to be chosen together.
The tint problem bites hardest here Six cells all painted #44475a on a #282a36 ground is one flat slab of colour broken only by 16px gaps. Caelestia gets separation from m3surfaceContainer sitting between surface and surfaceVariant — a role we don't generate. Either the theme pipeline learns to emit one, or this direction leans entirely on radius and gap to do work that colour normally does.

Picking

Pick one from each set — and pick them together, because the pairing is what decides whether the drawer keeps resizing when you cross tabs.

  1. If you want the reference: P1 + D1. Both land at 1040, the drawer stops jumping, and the shell looks like Caelestia's. It's also the most work, and it needs the container-tint question answered first.
  2. If you want the biggest gain per unit of work: P2 + D2. Everything at 760, no new backend, no new palette role, and both tabs get a real hierarchy.
  3. If what you actually want is to know what your machine is doing: P3 + D2. The telemetry strip is the only direction here that answers a question the current tab can't.
  4. If you just want the defects gone: P4 + D3. Cheapest possible pass — dead margin gone, frame jump gone, dead battery dial gone, nothing redesigned.

Mixing across widths is allowed — it just means keeping the resize animation, which is a legitimate choice if you like it.
