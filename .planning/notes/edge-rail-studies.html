The thesis

A rail is an attachment root, not a border

In most rices a screen frame is decoration. In yours it is structural: each strip is the thing a panel grows out of, with the bulge sized to exactly the panel that spawns from it and an AttachedCorner flare welding the two into one silhouette. That is why the bulge is 760 wide on top and 640 on the bottom — those are the dashboard and launcher widths, read from shared tokens.

So before choosing a shape, it is worth knowing what each edge actually holds. This map is measured, not assumed — the notification centre's slide direction came from reading which margin it animates.

Recommended · Continuous

Three rails plus the bar, welded into one silhouette

It is the only direction where every edge is doing a job. Top and bottom keep their panels. The right edge stops being a gap in the frame and becomes the bar itself — which is already a floating 44px slab inset 10px, so the rail can run straight into it with the same corner language AttachedCorner already speaks. The left stays open, deliberately: an unclosed frame that admits its own asymmetry looks intentional, whereas a closed one with a dead edge looks like the dead edge was missed.

It also costs the least new screen of any multi-edge option — the right side is already reserved for the bar, so you are paying for geometry you have already bought.

  1. Continuous is the one I would build. Most integrated, no dead edge, cheapest reservation of the multi-edge set.
  2. Bracket is the interesting outsider — it is the only direction that can reserve nothing at all and still read as a frame, because corners are where windows are already rounded away.
  3. Halo if you want the frame quieter rather than different; it is the current design at 2px with the gradient doing all the work.
  4. Closed only if you will move something to the left edge. A media flyout or the notification centre would both fit there and would make the fourth rail honest.
  5. Segmented is the one that adds information rather than shape — worth a spike on its own terms, not as a frame decision.

Every number on this page was measured on the live session, not estimated: geometry from hyprctl -j monitors and hyprctl -j layers, palette from ~/.local/state/theme/palette.json, widths from the shared Design tokens, and the notification centre's edge from which margin it animates.

Mockups render the desktop dark in both page themes, because the desktop is dark in both. Strip thickness is true to scale — if 6px looks slight here, that is what 6px looks like.
