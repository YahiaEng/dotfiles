Undoing this choice is cheap — it is a stylesheet plus a layout-field change, no migration and no published contract — so it is rated reversible. It reaches you as a checkpoint not because the door is one-way but because option B trades away a locked decision (D-09's glyph-as-text) to satisfy another locked decision (D-08's name reveal), and that trade is the user's to make, not the planner's or the executor's.

Extend the stylesheet with the six-hue identity. Zero literal colour values beyond the scrim alpha 09-02 already documented.

First define the two derived hues near the top of the sheet, after the import, using the `@define-color NAME mix(@a, @b, ratio);` idiom the waybar sheet you read established (that idiom is a durable 08-14 finding: mix() works inside @define-color and survives theme-doctor's non-empty-provider check). Six names are needed because the derived capsules need a mixed container fill, a mixed on-container glyph colour, AND a mixed base hue for their border: `vhue-teal-container` as a 0.5 mix of `@secondary_container` and `@tertiary_container`; `on-vhue-teal` as a 0.5 mix of `@on_secondary_container` and `@on_tertiary_container`; `vhue-teal` as a 0.5 mix of `@secondary` and `@tertiary`; `vhue-purple-container` as a 0.4 mix of `@primary_container` and `@error_container`; `on-vhue-purple` as a 0.4 mix of `@on_primary_container` and `@on_error_container`; `vhue-purple` as a 0.4 mix of `@primary` and `@error`. The 0.5 and 0.4 ratios and the two names are carried unchanged from the Phase 8-14 precedent. Applying mix() at the CONTAINER level is new in this repo (Phase 8 mixed base hues for opaque fills) — write a comment saying so and flagging it for confirmation at the 09-04 render gate.

Then write six id-selector rule groups. The id matches each button's `label` field, which wleave sets as the GTK widget name. Per capsule, in the D-05 left-to-right order, set `background-color` to the container role at 0.35 alpha via `alpha(...)`, `color` to the matching on-container role, and `border-color` to the base hue at 0.5 alpha:

lock uses `@primary_container` / `@on_primary_container` / `@primary`. logout uses `@secondary_container` / `@on_secondary_container` / `@secondary`. suspend uses `@tertiary_container` / `@on_tertiary_container` / `@tertiary`. hibernate uses `@vhue-teal-container` / `@on-vhue-teal` / `@vhue-teal`. reboot uses `@vhue-purple-container` / `@on-vhue-purple` / `@vhue-purple`. shutdown uses `@error_container` / `@on_error_container` / `@error`.

Note the reservation rule: only shutdown may reference the error role family directly. reboot's derived hue deliberately approaches error without equalling it, which is what preserves the severity gradient — do not "simplify" reboot to plain `@error` at a lower alpha.

Do NOT reproduce the retired sheet's hover pattern of inverting to an opaque fill with an `on_*` glyph. Wrapping a named colour in `rgba()` is not valid GTK CSS for named colours; use `alpha()` on the named colour, or an `@define-color` intermediate, as above.

Then the hover and focus feedback. Because D-08 requires keyboard focus to render IDENTICALLY to hover, write every interaction rule as a paired selector list covering both `:hover` and `:focus` on the same declaration block — never a hover rule with no focus twin. Per capsule the interaction state raises the fill to about 0.55 alpha of the same container role, sets `border-color` to the full-opacity base hue, and adds a soft `box-shadow` glow in that same hue at low spread. Add a shared `button` rule providing the scale: `transform: scale(1.06)` on the paired hover/focus selector, with `transform-origin: center`, and a `transition` on `background-color`, `border-color`, `box-shadow` and `transform` using the overshoot easing the retired sheet used (`cubic-bezier(0.55, 0, 0.28, 1.68)`). GTK4 CSS does support `transform` and `transform-origin`, unlike GTK3 — but that is a documentation claim, not something rendered yet, so if the 09-04 gate shows no scaling, fall back to animating `min-width`/`min-height`/`margin` in step (keeping the derived content-box arithmetic consistent) and record the deviation.
