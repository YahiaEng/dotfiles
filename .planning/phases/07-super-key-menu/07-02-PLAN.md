<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `keybinds.conf` (config file) → `keybind-doctor` (parser) | A parser reads a config file's content. If it executed rather than displayed that content, a crafted config line would achieve arbitrary code execution as the user. |
| physical keyboard → compositor | A rebind mistake here is a self-inflicted denial of service against the user's own input device. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04 | Elevation of Privilege | `keybind-doctor` parsing `keybinds.conf` | high | mitigate | Parser is display-only: `printf '%s'` on every parsed field, never `eval`, never `source`, never command-substitution on parsed content. Asserted by an explicit `grep` acceptance criterion. This is the V5 control RESEARCH.md's Security Domain names. |
| T-07-05 | Denial of Service | Super+Escape kill-bind (`pkill walker`) | low | accept | Requires physical keyboard access, which already implies full session control on a single-user personal desktop. Consistent with the project's existing threat model — no remote-access surface exists. The bind's benefit (lockout escape hatch) is the entire point of D-03. |
| T-07-06 | Denial of Service | keyboard lockout from a bad rebind | high | mitigate | Three layers: (a) an authenticated second TTY confirmed before any edit, gated by a blocking human checkpoint; (b) the kill-bind proven in isolation FIRST; (c) a one-command revert (`git checkout -- keybinds.conf && hyprctl reload`) documented in the checkpoint. Additive-only edits in this plan mean no existing bind can break. |
| T-07-07 | Tampering | `keybind-doctor` mutating compositor state | medium | mitigate | Report-only discipline copied verbatim from `theme-doctor`. Acceptance criterion asserts `hyprctl binds -j` is byte-identical before and after a run. |
</threat_model>
