## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo menu TOML → elephant `sh -c` execution | Action strings are executed by the elephant daemon. They are static, repo-authored, version-controlled content — no runtime user input reaches them. |
| menu → existing Phase 5/6 scripts | The menu is a new *caller* of scripts that already have their own audited threat model (Phase 6 closed 53/53 threats). It adds an invocation path, not new logic. |
| Power entry → `wlogout.sh` → system power actions | The only destructive path reachable from the menu. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-14 | Elevation of Privilege | menu action strings executed via elephant's `sh -c` | medium | mitigate | Every action string is a fixed literal authored in-repo and version-controlled. No action interpolates runtime input, reads from a variable, or contains `sudo`. elephant runs unprivileged under `uwsm app --`. Asserted by acceptance criteria that pin each action's exact target. |
| T-07-15 | Tampering | duplicated power-action logic drifting from the audited path | medium | mitigate | D-19: the Power entry delegates to the single existing `wlogout.sh`. Acceptance criteria explicitly assert the action contains NO inline `systemctl`/`hyprshutdown` call — a second copy of the power logic is exactly the drift that made `powermenu.sh` dangerous (it had lost hibernate and carried its own stale hyprshutdown calls). D-20 deletes that second copy. |

The one deliberate forward reference (`cheat-sheet.sh`, landed by 07-08) is flagged in a TOML comment so it does not read as a bug. |
