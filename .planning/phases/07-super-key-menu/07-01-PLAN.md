<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo TOML → elephant `sh -c` | Menu action strings authored in-repo are executed by the elephant daemon via `sh -c`. The strings are static repo content under version control, not runtime user input. |
| elephant daemon ↔ walker frontend | A private Unix-socket protocol between two independently-versioned packages. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | elephant menu action `sh -c` execution | medium | mitigate | Every action string is static, repo-authored, version-controlled content. No action interpolates runtime input. No action contains `sudo`. elephant itself runs unprivileged under `uwsm app --` (confirmed via `autostart.conf`). |
| T-07-02 | Tampering | `~/.config/elephant/menus/` | low | mitigate | The directory is a stow symlink tree into the git-tracked repo — a host-side modification is visible as a broken/replaced symlink, and `git status` in the repo is the audit trail. No host-only menu state (D-34). |
| T-07-03 | Denial of Service | `elephant-restart.sh` killing the daemon pair | low | accept | Requires local shell access, which already implies full session control on a single-user desktop. The script's bounded readiness wait plus nonzero-exit-on-failure means a failed restart is loud, not silent. |
</threat_model>
