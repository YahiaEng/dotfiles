# Phase 19 — UI Design Contract

> Visual and interaction contract for the notification popup stack, the slide-out
> centre, and the shared quick-toggle grid (QNOTIF-01..11). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. This is a Quickshell/QML shell,
> not a web/shadcn stack — the shadcn gate does not apply (see Design System
> below). Every token named here already exists in `modules/dashboard/Design.qml`
> / `modules/Colours.qml` / `modules/Motion.qml` / `modules/bar/BarRoles.qml`
> unless marked **NEW** — new tokens are named in the identical convention
> (camelCase `readonly property`, a provenance comment citing this file) so
> GATE-04's hex-literal lint has a token to point authors at instead of a raw
> value. Per D-19-00, every design decision below defaults to Caelestia's real
> shipped behaviour (verified against its checked-out source this milestone,
> `.planning/research/FEATURES.md` § NOTIF/OSD as the durable fallback); every
> divergence is named explicitly, never silent.

**Color** (`Colours.qml`, routed exclusively through `BarRoles.qml` per D-19-43 — never a direct `Colours.*` reference from a notification-family file): `Colours.primary`/`onPrimary` (via `BarRoles.accent`/`onAccent`), `Colours.error`/`onError` (via `BarRoles.danger`/`onDanger`), `Colours.surface`/`onSurface`, `Colours.surfaceVariant`/`onSurfaceVariant` (via `BarRoles.capsule`/`capsuleFg`/`capsuleHover`/`capsuleTrack`), `Colours.secondary`/`onSecondary` (via `BarRoles.fillClock`, cited only for contrast — not used by this surface), `Colours.primary`/`onPrimary` again for the badge (via `BarRoles.fillNotification`/`fillNotificationFg`, already load-bearing for the bell).

**Motion** (`Motion.qml`): `standardDuration 200`/`standardEasing` (routine, frequent transitions — popup enter/reflow, toggle hover), `emphasizedInDuration 300`/`emphasizedInEasing` (centre slide-in, popup card expand), `emphasizedOutDuration 150`/`emphasizedOutEasing` (centre slide-out, popup dismiss, toast exit — the established "quick to leave" asymmetry). **Frame components reused verbatim**: `GradientBorder.qml` (rim, every new frame below), the `HyprlandFocusGrab` + `dismissRequested()` pattern (popup pin-free/click-outside dismissal parity — **not** used for the centre itself per D-19-18's no-exclusive-focus rule, see below), `Component.onCompleted` cascade-arming idiom, the custom `Slider` `background`/`handle` geometry already established in `AudioPanel.qml`/`AudioPopout.qml` (track height 8 / radius 4, handle 20×20 — reused shape, **recoloured** through `BarRoles` per the note in "Sliders" below, a deliberate divergence from `AudioPopout.qml`'s own direct `Colours.*` reads, which predate D-19-43's routing rule and are not a pattern to copy forward).

## Popup Card & Stack (QNOTIF-02/03/04/05, D-19-01..13)

### Placement and stack behaviour
- **Anchor**: always top-right (D-19-01), both bar orientations — only the top margin shifts to clear whichever edge the bar currently reserves (`Bar.qml`'s own live `exclusiveZone`, read at runtime, never a hardcoded offset).
- **Card width**: `notifSurfaceWidth` (430px) fixed. Height content-driven (compact vs. expanded, see below).
- **Stack**: a `ListView` with `move`/`displaced` transitions (Caelestia's own mechanism, `.planning/research/FEATURES.md` § NOTIF) — cards enter at the top, reflow downward as siblings above dismiss. Depth governed by a height clamp against the screen (Caelestia) plus a `+N more` summary card (this project's addition, D-19-03) when the clamp truncates. The `+N more` card shares `notifSurface` chrome, centred text, click opens the centre.
- **Motion**: slide + fade from the top-right edge, `Motion.standardDuration`/`standardEasing` for entrance and reflow (routine, frequent — several a day); `Motion.emphasizedOutDuration`/`emphasizedOutEasing` for dismissal (the established fast-out register).

### Card anatomy (compact state, default)
- Row: `notifImageSize` (42px) icon/image slot → `Design.spacingMd` (16px) gap → column of summary (`Heading`, 1 line, `Text.ElideRight`) + one body line (`Body`, `Text.ElideRight`).
- Padding: `Design.spacingMd` (16px) on all sides, matching the popout-body padding convention Phase 18 already established.
- Corner radius: `Design.popoutCornerRadius` (20px), uniform on all four corners — the card floats fully clear of every screen edge, the same reasoning 18-UI-SPEC.md gave for the section popout's own uniform rounding.
- Rim: `GradientBorder`, `Design.borderWidth` (3px) — reused component, zero new code, consistent with every other panel-family surface.

### Expanded state (D-19-05)
- Triggered by a vertical drag past `notifExpandThresholdPx` (32px) in either direction — `expanded = diffY > 0`, Caelestia's own binary (drag down expands, drag up collapses), sharing the same `MouseArea` as the horizontal dismiss gesture (disambiguated by which threshold fires first, never two separate hit-areas).
- Reveals: full (non-elided) body text, the image/icon at full `notifImageSize` if larger content exists, and the notification's own action buttons (D-19-04) plus the always-present "copy body" action.
- Hover (separately) pauses the dismiss timer and resumes on leave (D-19-06) — not a reset, not sticky. Hover does NOT expand the card; expand is drag-only.

### Gestures (D-19-07/10, verbatim mechanism cited in RESEARCH.md Pattern 3)
- Horizontal drag past `notifDismissThresholdFraction` (30% of card width) in **either** direction dismisses (`popup = false`) — never destroys the underlying data; it stays in history. Card snaps back to `x: 0` if released short of the threshold.
- Middle-click closes immediately, same non-destructive semantics.
- Left-click on the card body: invokes the notification's `default` action if it has exactly one action (Caelestia's `actionOnClick` convention, D-19-10), otherwise dismisses.
- **No gesture is destructive** — this is the one rule every other rule in this section answers to.

### `replaces_id` in-place update (D-19-08, QNOTIF-05)
- A re-send with a matching `replaces_id` updates the SAME card in place: summary/body/hints/actions rebind live via property-changed signals (RESEARCH.md Pattern 2), the dismiss timer restarts at the new `expireTimeout`, and the card's position in the stack and its `ListView` index are **unchanged** — no re-entrance animation, no reflow of siblings. Visually this must look like nothing moved except the text/ring.
- **Verification note for the planner (not this document's job to build, but load-bearing for the render gate)**: the fault-injection fixture in RESEARCH.md Pattern 2 (two `Notify` calls with the same `replaces_id`, asserting unchanged stack position + full timer reset) must pass before GATE-02, since QNOTIF-05 carries extra verification weight under the no-soak retirement (D-19-42).

### Ring progress (D-19-09)
- A `hints.value` notification (0-100, clamped per RESEARCH.md's Security Domain guard against an out-of-range sender value) draws a `PathAngleArc` ring over the icon slot: track `BarRoles.capsuleTrack`, fill `BarRoles.accent`, stroke `notifRingStrokeWidth` (3px). `sweepAngle: (clampedValue / 100) * 360`.
- This is the update's visible readout — a download/volume-style progress notification reads as "the same card, ring advancing," not as new cards stacking (ties directly to the `replaces_id` no-reflow rule above).

### Critical urgency (D-19-11)
- The **whole card** swaps `notifSurface`/`notifSurfaceFg` for `BarRoles.danger`/`onDanger` — background, text, icon tint, all of it, not just an accent stripe.
- Never auto-dismisses (no dismiss timer starts).
- Still subject to the same height clamp as any other card — no cap exemption, so an app marking everything critical cannot wall off the screen (CONTEXT's own explicit anti-abuse rule).

### Icon fallback chain (D-19-12)
- image hint → named `app_icon` via icon theme → desktop-entry icon → generic Material Symbols bell glyph (`"notifications"`). All four tiers render inside the identical `notifImageSize` (42px) slot — never a blank slot, never a card that is a different width depending on which tier resolved.

### Markdown and link confirmation (D-19-40)
- Body text renders through an allowlist filter (bold/italic/link only, everything else escaped) before `Text.MarkdownText` — this document's contract is the VISUAL result: rendered bold/italic inline, a link rendered as underlined `BarRoles.accent`-tinted text, nothing else ever gets rich formatting.
- Hovering a link shows the raw URL first, reusing `BarTooltip.qml`'s exact existing tooltip chrome (`BarRoles.capsule` pill, `BarRoles.capsuleFg` text, `Design.tooltipDelayMs` 400ms delay) — no new tooltip component.
- Clicking a link does not open it immediately: it reveals a small inline confirm affordance (same `BarRoles.capsule` pill language, "Open link?" + a confirm/cancel pair) anchored at the link's position; confirming calls `Qt.openUrlExternally`. This is a deliberate extra step beyond Caelestia's own unconfirmed-click behaviour (named divergence, D-19-40), justified because any session process can send a notification.

## The Centre — Frame, Summon, Content Order (QNOTIF-06, D-19-14..18/23)

### Frame
- Own top-level `PanelWindow`, right-edge slide-out (D-19-14), sibling of the bar and the popup stack — not a dashboard tab, not built on `PanelDialog`.
- `notifSurfaceWidth` (430px) wide, full screen height (`anchors.top` + `anchors.bottom`, D-19-15) — matching Caelestia's verified `sizes.sidebar.width: 430`.
- Background: `BarRoles.notifSurface` (the same `0.78`-alpha `Colours.surface` base the popup card uses — one visual family across both surfaces, per D-19-02's own "a card looks identical floating or in history" intent extended to the frame itself).
- Rim: `GradientBorder`, `Design.borderWidth` (3px) — same as every other panel-family surface.
- Corner radius: uniform `Design.popoutCornerRadius` (20px) on the frame's inner (screen-facing) corners only — the frame is full-height and edge-flush on three sides (top, bottom, right), so only the left edge (facing into the desktop) has a visible corner to round; treat this the same way `PanelDialog`'s bottom-only rounding answers to ITS own edge-flush geometry — a reasoned difference, not an oversight.
- Namespace: `"quickshell-notif-centre"` — inside the `^quickshell-.*` family regex, so blur/`ignore_alpha` apply with zero new Hyprland config (see Design System above); an exact-match `animation = "slide"` row is still needed, matching `quickshell-dashboard`'s own precedent.
- `exclusiveZone: 0` — a slide-out overlay, reserves nothing (matches `PanelDialog`, the section popouts, and the dashboard drawer).
- **No exclusive keyboard focus** (D-19-18): `WlrLayershell.keyboardFocus: WlrKeyboardFocus.None`. Escape closes it; typing continues to reach whatever application is actually focused. This is a deliberate divergence from the popup card's own `HyprlandFocusGrab`-based click-outside dismissal — the centre dismisses only via its own explicit toggle (bell/`Super+N`) or Escape, never a stray click into the desktop behind it, since it carries no focus grab to detect one.

### Motion (D-19-23, verbatim shape cited in RESEARCH.md Pattern 4)
- One property, `offsetScale` (0 = fully open, 1 = fully closed), drives both position and opacity in lockstep: `anchors.rightMargin: (-implicitWidth - 5) * offsetScale`, `opacity: 1 - offsetScale`, `visible: offsetScale < 1`. A single `Behavior on offsetScale` reading `Motion.emphasizedInDuration`/`emphasizedInEasing` for open and `Motion.emphasizedOutDuration`/`emphasizedOutEasing` for close (matching every other dismissible-surface's in/out asymmetry).
- `visible: offsetScale < 1` stops the surface rendering once fully closed — the zero-idle-when-closed discipline this shell already holds every other dismissible surface to.

### Summon (D-19-16)
- Bar bell click and `Super+N` both toggle it — the bell's existing five-name contract (`openCentre()`) is repointed internally onto this frame's own `IpcHandler`/`GlobalShortcut` target; the bell's own rendering (glyph/fill/badge) is unchanged by this phase, see Design System above.
- `Super+N` moves from an `exec_cmd` shelling to `swaync-client` onto this repo's own `hl.dsp.global("quickshell:notif-centre")` + `GlobalShortcut` pattern (RESEARCH.md's cited established idiom, matching `Super+D`/`Super+A`/`Super+O`).
- Opening the centre clears the in-flight popup stack immediately (D-19-37) and marks the unread badge count back to zero (the bell's existing `unreadCount > 0` badge-visibility binding does this for free once the backend's own count resets on open).

### Content order (D-19-17 — deliberately inverts swaync's order)
Top to bottom, no scrolling of the footer:
1. **Header** — live unread/total count (`Label`, left) + clear-all icon button (right, D-19-28), `Design.popoutHeaderHeight` (48px) band, `Design.spacingMd` (16px) horizontal inset.
2. **Grouped history** — scrollable, fills remaining vertical space (see next section).
3. **Pinned footer** — toggle grid + volume/mic/brightness sliders, fixed height, never scrolls, `Design.spacingLg` (24px) top padding separating it from the history list, `Design.spacingMd` (16px) internal padding.

## Shared Quick-Toggle Grid (QNOTIF-07, D-19-19) — the checkable no-drift contract

**What "no drift" means, made checkable rather than a vibe check**: the drawer's grid and the centre's grid are the SAME `QuickToggles.qml` component, promoted to a `pragma Singleton`-backed shared type (the identical `Colours.qml`/`Motion.qml`/`Design.qml` conversion precedent, RESEARCH.md Pattern 5), instantiated twice. Any visual difference between the two renderings is by construction a bug in a shared component, not two independently-maintained copies that could disagree — there is no second implementation to compare against, so "checkable" here means: **if the two instantiations ever render differently, that is impossible unless the singleton itself is broken**, which is a stronger guarantee than a render-gate comparison could give.

- Existing chip geometry, unchanged: 6 tiles (`gaming`, `dnd`, `dark`, `volume`, `wifi`, `bluetooth`), each `(containerWidth - spacingSm × 5) / 6` wide — already width-responsive, so hosting it inside the centre's 430px footer requires no new layout math, only confirming it fits without truncation at that width (part of UI Considerations below).
- **The "Do Not Disturb" label constraint carries forward unchanged**: `QuickToggles.qml`'s own header comment records that Phase 14's render gate explicitly rejected shortening it to the acronym "DND" — this phase's DND tile keeps the full two-line "Do Not Disturb" label. Do not re-abbreviate it when repointing the tile's backend.
- DND's truth source moves from a `swaync-client -dn/-df` read to the D-19-19 singleton's own persisted property (file-backed per D-19-36, NOT `PersistentProperties` — see RESEARCH.md Pitfall 2). The tile's visual states (lit/unlit, pending-ripple-then-truth-driven) are unchanged — only where the truth comes from changes.
- Gaming mode and DND remain visually and behaviourally independent (D-19-35) — the gaming tile never drives the DND tile's lit state, and vice versa.

## History, Grouping & Clearing (QNOTIF-06, D-19-24..32)

- **Persistence**: `~/.local/state/quickshell/notifications.json`, `FileView`-loaded at startup — this is a visual-contract note only insofar as it means the history list is NEVER empty-by-construction on a fresh shell start if prior notifications exist; the empty state above is a genuine zero-history state, not a "hasn't loaded yet" state (no loading skeleton for history — see UI Considerations).
- **Grouping**: per app, collapsed by default. Each `NotifGroup` header row: app icon (`notifImageSize`-scaled down to `iconSizeMd`, 24px, inside the list context — the 42px size is reserved for the popup card's own primary icon slot, not repeated at full size in every collapsed group row), app name (`Heading`, `BarRoles.capsuleFg`), count badge (`notifBadgeSize`, 20px, `BarRoles.fillNotification`/`fillNotificationFg`), `expand_more` chevron rotating 180° on expand (`Motion.standardDuration`).
- **Order**: groups sorted by most-recent activity, newest at top (D-19-27) — never alphabetical.
- **Per-notification row (inside an expanded group)**: `notifImageSize` (42px) icon slot, summary (`Body`), relative timestamp (`Label`, right-aligned, one shared ticker per D-19-32 — never a per-row `Timer`), action buttons if the sender's session is still live (D-19-31 — hidden entirely, not disabled/greyed, on any notification reloaded from disk, since D-19-31's own rule treats every disk-loaded notification as sender-gone).
- **Clear-all** (D-19-28): icon button (`clear_all` glyph) in the header, scale+fade appears only when count > 0 (`Motion.standardDuration`), `BarRoles.capsuleFg` at rest, `BarRoles.accent` on hover — moved into the header specifically because D-19-17's pinned footer already occupies the floating-bottom-right position Caelestia itself uses (named, layout-forced divergence).
- **Three clear levels** (D-19-29): per notification (swipe or an explicit per-row dismiss control), per app group (a small `close` glyph on the group header), clear-all — all three batch through `notifHistoryBatchSize` (30 items per timer tick) for clear-all/per-group, so a large history never visibly stalls the centre.
- **Cap**: `notifHistoryCap` (100), oldest dropped silently on overflow — no user-visible "history full" message; this is bookkeeping, not a state the design needs to surface.

## Suppression, DND & the Toast Frame (QNOTIF-09/10, D-19-33..37)

- **Suppression is visual-only**: a suppressed notification never becomes a popup card, but always appears in history exactly as if it had (D-19-33) — no distinct "suppressed" visual treatment exists anywhere; the record and a delivered notification are visually identical once in the centre.
- **Fullscreen suppression** (D-19-34, QNOTIF-10): full suppression, not a shortened timeout — reuses this repo's own already-shipped `shell.qml:448-462` fullscreen guard (RESEARCH.md Pattern 6), no new visual state.
- **DND tile** (shared grid, see above) is the only user-visible suppression control; gaming mode suppresses independently and never touches the DND tile's own lit state (D-19-35).

### Toast frame (D-19-36) — NEW top-level frame type, reused by Phase 20's OSD

Per ROADMAP.md's Phase 20 note ("the OSD reuses the transient-toast frame type built [in Phase 19]"), this phase must build a generic small-transient-notice frame, not a one-off DND-only widget. Specified generally enough for that reuse:

- **Placement**: top-center, anchored clear of both the top-right popup stack (D-19-01) and the right-edge centre — the three transient/persistent surfaces never overlap.
- **Frame**: `BarRoles.notifSurface`/`notifSurfaceFg`, `Design.popoutCornerRadius` (20px, uniform — floats clear of every edge), `GradientBorder` rim (`Design.borderWidth`, 3px) — same visual family as the popup card and centre, so all three read as one system.
- **Sizing**: content-hugging, capped at `notifToastMaxWidth` (320px). A single icon + one line of text for the DND case; Phase 20's OSD reuse is expected to swap the content region for a value readout, not the frame chrome.
- **Motion**: slides down + fades in from the top edge, `Motion.standardDuration`/`standardEasing` (routine — this fires on every DND toggle, an everyday action); exits the same way after `notifToastDurationMs` (2000ms) with no user interaction required or possible — a toast is never dismissible by click, only by its own timer, since it is feedback, not content.
- **Namespace**: `"quickshell-notif-toast"` — inside the `^quickshell-.*` family regex, blur/`ignore_alpha` apply automatically; needs its own exact-match `animation = "slide"` row.
- **Content for this phase**: icon (`do_not_disturb_on`/`do_not_disturb_off`, `iconSizeMd`) + text (see Copywriting Contract), `Design.spacingMd` (16px) padding, `Design.spacingSm` (8px) icon-to-text gap.

## GATE-02 Render-Gate Criteria (checkable, per D-19-42's "no deletion before the gate")

GATE-02 requires the replacement be judged "at least as good as swaync" — this section makes that decidable. Run per this milestone's established discipline: checkpoints during the phase (at minimum once per surface — popup, centre, toggle grid, sliders, toast) **plus one blocking final pass** before RETIRE-03's deletion commit. A criterion only passes when confirmed live (a real notification sent, a real drag performed, a real theme switch), never "looks right in the source."

### A. Aesthetic judgment — against swaync's own `config.json`/`style.scss`

1. Popup cards are 430px (up from swaync's 380px) and read as visually part of the same family as the bar's capsules and popouts — rounded corners, `GradientBorder` rim, theme-reactive fill — never swaync's flat unthemed card.
2. The centre is 430px, full-height, right-edge slide-out — visually distinct from swaync's 420px control-center panel only in the numbers, not the character (translucent surface, rim, theme-reactive).
3. Switching the live theme re-colors every notification-family element (card fill, ring progress, badge, toggle tiles, sliders) within one crossfade, with zero literal-hex flash — extending GATE-02's own bar precedent to this surface.
4. Critical-urgency cards are unmistakably distinct from normal cards (whole-card colour swap, D-19-11) — never merely an accent stripe.
5. The empty state reads as a deliberate design moment (illustration + headline), never a blank list or "0 notifications" text.

### B. Capability audit — against swaync's `config.json` behaviour

1. Popups stack, reflow smoothly, and respect swaync's exact timeout numbers (5s / 3s low / never-critical, D-19-04) — nothing about the daily rhythm changes.
2. Swipe-to-dismiss works in both directions; middle-click closes immediately; no gesture destroys a notification (verify by checking it appears in history after every dismiss gesture).
3. A `replaces_id` re-send (real fault-injection fixture, RESEARCH.md Pattern 2) updates the same card with zero re-animation/reorder — the one requirement carrying extra verification weight under D-19-42.
4. Action buttons work end-to-end against a real sending application (blueman's bluetooth pairing prompt is the concrete required proof, D-19-39 — no GTK fallback dialog, working Accept/Reject, `body`+`actions` present in `GetCapabilities`).
5. The shared toggle grid renders identically in the dashboard drawer and the centre, and toggling DND in either location instantly reflects in the other (the "no drift" contract above, confirmed live not just by code inspection).
6. Volume/mic/brightness sliders in the centre move the same live values the bar's own audio popout and scroll-to-adjust already drive — no separate, disagreeing volume state.
7. DND survives a deliberate bar-process kill+respawn (QBAR-10's restart wrapper) — the one capability swaync never had to prove, since it was never restarted by this shell's own machinery.

**Pass bar**: all of A and all of B confirmed live. Any single failure blocks RETIRE-03's deletion commit until fixed and re-checked, per this milestone's own precedent (Phase 18's GATE-02 needed three iterations before passing).
