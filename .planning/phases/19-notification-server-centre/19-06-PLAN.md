## Explicit planner assumption (19-UI-SPEC.md's one unresolved consideration, N6 empty)

19-UI-SPEC.md leaves exactly one state-coverage row unresolved: whether a slider row should HIDE
entirely when its backend is *entirely absent* (no audio device at all), as distinct from
*present but inert* (this host's brightness, which has no backlight device). No locked decision
and no research finding resolves it — D-19-20 and D-19-21 both assume all three backends are
reachable in some form.

**Assumed default: render the row disabled, never hide it.** Reasons: (1) the copywriting
contract already specifies a fourth-state string for a backend-unavailable control, which only
has somewhere to render if the row exists; (2) the footer is a fixed-height pinned band, and a
disappearing row would change the surface's shape between hosts, which the empty-state section
explicitly avoids elsewhere; (3) a hidden control is indistinguishable from a control the shell
forgot to build, whereas a disabled one with an explanatory tooltip tells the user why.

This is an assumption, not a decision. Surface it to the developer at the render gate in plan
19-08 — if a machine with genuinely no audio device is ever in scope, the hide-versus-disable
call should be made deliberately rather than inherited from this default.

closing note says 4, while the table itself marks exactly 3 (N2 error, N4 error, N7 error) plus 1
unresolved. The table is ground truth; all three backstops are carried in this phase's plans
(N2 in 19-04, N7 in 19-05, N4 here).
