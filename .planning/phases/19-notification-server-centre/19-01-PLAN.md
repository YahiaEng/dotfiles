<objective>
TRACER. Wire one real notification from a real application, across the D-Bus session bus,
through a Quickshell-owned `org.freedesktop.Notifications` server, into a real on-screen popup
card — end to end, production quality, committed.

This is the thinnest path that touches every layer Phase 19 will modify: bus ownership →
server singleton → per-notification wrapper → popup surface → card chrome → token/colour
layer → compositor layer rules. Every expansion plan in waves 2-4 builds out from this proven
slice; none of them re-proves the architecture.

Purpose: catch an architectural dead-end after one commit instead of after ten. The phase has
no soak window and no rollback (D-19-42), so the path must be proven before any breadth is
added to it.

Output: a working notification server plus a single compact popup card, the complete
`Design.qml` / `BarRoles.qml` token surface every later plan consumes, and the compositor
layer rules for all three new namespaces.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session D-Bus → shell process | Any process running as this user may call `Notify` with arbitrary `summary`, `body`, `app_name`, `app_icon`, `image` and `hints` values. This is the phase's primary new inbound surface and it did not exist before this plan. |
| shell process → compositor | The shell declares layer-shell namespaces; the compositor applies blur/alpha rules by namespace match. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Tampering | `NotifCard.qml` summary/body `Text` | high | mitigate | Explicit `textFormat` plain-text pin on both sender-controlled text elements in Task 3, so Qt never auto-detects and renders rich text from sender data. Same control class as `15-SECURITY.md`'s T-15-08b. |
| T-19-02 | Spoofing | `org.freedesktop.Notifications` name ownership | high | mitigate | The server is instantiated at `shell.qml` root scope with no lazy guard, so the name is held for the whole process lifetime; the owner-count assertion in Task 2's acceptance criteria fails on any second owner. | T-19-04 | Information Disclosure | sender-supplied `image`/`app_icon` path | medium | mitigate | Icon resolution goes through the toolkit's own icon-theme resolver in plan 19-04; this plan adds no code path that opens a sender-supplied local filesystem path directly. |
| T-19-SC | Tampering | package installs | low | accept | This phase installs no new package — RESEARCH.md § Package Legitimacy Audit records the gate as not applicable. `swaync` is removed, not replaced. |
