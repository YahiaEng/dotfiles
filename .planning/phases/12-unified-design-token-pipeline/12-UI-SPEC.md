# Phase 12 — UI Design Contract

> Visual and interaction contract for Phase 12. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Domain note (read before applying the template literally):** this is not a web/React
> project. There is no shadcn, no Tailwind, no browser DOM. The "UI surfaces" this phase
> touches are: (1) the Quickshell token inspector (`modules/Probe.qml`, summon-only,
> QtQuick/QML), (2) one retrofitted GTK4 stylesheet (`wleave/style.css`), and (3) Hyprland
& compositor-level bezier curves (no visual chrome of their own — proven only via
> `hyprctl animations -j` readback and the inspector's replay row). The five other GTK
> surfaces (waybar, swaync, walker, SwayOSD, AGS) and the 14 Hyprland `animation =`
> assignment lines are explicitly **out of scope** — Phase 13 retrofits them. Every
> template section below is reinterpreted for this stack rather than skipped; sections
> that do not apply (shadcn preset, icon library, registry) are marked not applicable
> rather than deleted, so the checker's 6-dimension pass still has something to check
> against.

## Spacing Scale

Declared values (must be multiples of 4) — governs the one new visual layout this phase
touches, the token inspector (`Probe.qml` → token-inspector rewrite). wleave's existing
pixel measurements are retrofit-only for motion custom properties and are **not**
re-audited for spacing this phase.

| Token | Value | Usage in the token inspector |
|-------|-------|-------------------------------|
| xs | 4px | Gap between a swatch's colour chip and its token-name label |
| sm | 8px | Gap between adjacent swatches inside a role group (Row spacing) |
| md | 16px | Gap between role groups (colour roles / motion semantic pairs / replay row) — replaces the existing ad hoc `spacing: 12` in `Probe.qml`'s `Column`/`Row` |
| lg | 24px | Panel outer padding (all four edges) |
| xl | 32px | Gap between the header band (screen + theme label) and the swatch grid below it |
| 2xl | 48px | not used this phase (no page-level chrome in a diagnostic panel) |
| 3xl | 64px | not used this phase |

Exceptions: the existing `Probe.qml` `spacing: 12` (Column) and `spacing: 8` (Row) are
superseded by `md`/`sm` above during the inspector rewrite — not a new exception, a
correction to land on the scale. No other exceptions.

QtQuick Controls does not resolve `px` the way CSS does; declare explicit
`font.pixelSize` bindings so the inspector renders identically regardless of platform
font-metric defaults (Qt's own recommendation for cross-platform QML — verify this
resolves as expected on the installed Qt6 build before relying on it, per standing
constraint 2).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 400 | 1.3 | Token-name caption under each swatch (e.g. `primary`, `surfaceVariant`, `emphasized-in`) |
| Body | 14px | 400 | 1.4 | Replay-row button text, TextField/placeholder text (existing probe controls) |
| Heading | 18px | 600 | 1.2 | Section titles: "Colour Roles", "Motion — Semantic Pairs", "Replay" |
| Display | 22px | 600 | 1.2 | The header banner: `Screen: {name} · Theme: {current-theme} ({mode})` |

Exactly 2 weights declared: 400 (regular, all body/label text) and 600 (semibold,
headings and the header banner only — never used for swatch fills or body copy).

## Color

The 17 Material You roles below are **pre-existing and locked** — this phase does not
choose new hex values, it declares which of the existing roles the token inspector must
surface and how the 60/30/10 usage split maps onto roles already in production
(`hyprland-colors.conf`, all 17 `contract.json`-listed colour files). Source: codebase
(`matugen/.config/matugen/config.toml`, `hyprland-colors.conf` template).

| Role | Existing matugen key | Usage |
|------|----------------------|-------|
| Dominant (60%) | `surface` / `background` + their `on_*` pair | Inspector panel background, wleave window background (unchanged) |
| Secondary (30%) | `surface_variant` / `secondary_container` + `on_*` pairs | Swatch card fills, role-group panel backgrounds inside the inspector |
| Accent (10%) | `primary` / `tertiary` | Reserved for: the crossfade-demo target rectangle, the replay-row's currently-animating element, and the Display-role header banner text. Never used for ordinary swatch fills or body text. |
| Destructive | `error` / `on_error` | Reserved for: the single "unmapped token" debug swatch (see UI Considerations → empty/loading below) and terminal-red FAIL lines in `theme-doctor`/motion-lint output. Not used decoratively anywhere in the inspector. |

### QML palette contract (D-11)

`Colours.qml` (Quickshell `Singleton`, `quickshell/.config/quickshell/modules/`) exposes
one camelCase property per matugen key, 1:1, no renaming beyond the snake_case→camelCase
convention QML requires: `primary`, `onPrimary`, `primaryContainer`, `onPrimaryContainer`,
`secondary`, `onSecondary`, `secondaryContainer`, `onSecondaryContainer`, `tertiary`,
`onTertiary`, `surface`, `onSurface`, `surfaceVariant`, `onSurfaceVariant`, `background`,
`onBackground`, `outline`, `error`, `onError`.

**Missing/malformed key fallback:** render `#FF00FF` (debug magenta), never a silent
black/white default. A broken token mapping must be visually loud, not visually plausible
— same lesson D-24 applied to motion-reference resolution, applied here to colour.

## Motion Token Contract

The actual deliverable of this phase. Two-layer schema per D-05 — `durations` (ms) +
`easings` (cubic-bezier control points) — plus a **trimmed semantic layer** (D-25) pairing
them into the names real surfaces consume. `motion.json` carries the **full** scales below
as raw data; only the semantic pairs listed further down are wired to a real surface this
phase.

### Duration scale (full — MD3 Expressive, carried in full per D-25)

| Token | ms |
|-------|-----|
| short1 | 50 |
| short2 | 100 |
| short3 | 150 |
| short4 | 200 |
| medium1 | 250 |
| medium2 | 300 |
| medium3 | 350 |
| medium4 | 400 |
| long1 | 450 |
| long2 | 500 |
| long3 | 550 |
| long4 | 600 |
| extra-long1 | 700 |
| extra-long2 | 800 |
| extra-long3 | 900 |
| extra-long4 | 1000 |

### Easing scale (full — cubic-bezier control points)

**Finding worth stating plainly: the repo's three existing hand-authored Hyprland
curves already ARE MD3 curves** — this pipeline formalises names already in production
use, it does not invent new curve shapes for the core three:

| Token | Control points | Existing repo curve it formalises |
|-------|----------------|-----------------------------------|
| `standard` | 0.2, 0, 0, 1 | `md3_standard` (identical) |
| `emphasized-decelerate` | 0.05, 0.7, 0.1, 1 | `md3_decel` (identical) |
| `emphasized-accelerate` | 0.3, 0, 0.8, 0.15 | `md3_accel` (identical) |
| `linear` | 1, 1, 1, 1 | `liner` (identical) |

**Naming collision guard:** because Phase 12 emits curves *additively* alongside the 12
hand-authored Hyprland beziers (D-04 — no `animation =` line is rewired this phase), every
emitted bezier name gets a `motion-` prefix to guarantee zero collision with the existing
set (`wind`, `winIn`, `winOut`, `liner`, `md3_standard`, `md3_decel`, `md3_accel`,
`overshot`, `crazyshot`, `smoothOut`, `smoothIn`, `bounce`): emit as `motion-standard`,
`motion-emphasized-decelerate`, `motion-emphasized-accelerate`, `motion-linear`.

### Semantic pairs wired to a real surface this phase (trimmed per D-25)

Only these three are consumed by anything real this phase — the inspector's swatches and
wleave's retrofit. Additional semantic pairs are Phase 13's job as it retrofits the
remaining five surfaces and the 14 Hyprland assignment lines.

| Semantic name | Duration | Easing | Reserved for |
|---------------|----------|--------|--------------|
| `standard` | short4 (200ms) | `standard` | General-purpose fades/transforms — wleave's existing 200ms `transform` transition (`style.css:230`), the inspector's non-entrance state changes |
| `emphasized-in` | medium2 (300ms) | `emphasized-decelerate` | Entrance/reveal motion — wleave's `capsule-entrance` keyframe (`style.css:559-560`, already hand-copies these exact 4 numbers "with a comment saying so" per D-19 — this is the drift this pipeline eliminates), inspector swatch entrance if styled |
| `emphasized-out` | short3 (150ms) | `emphasized-accelerate` | Exit/dismiss fades — wleave's existing 150ms `opacity`/`transform` transition (`style.css:455`) |

wleave's hover overshoot curve (`cubic-bezier(0.55, 0, 0.28, 1.68)` at `style.css:230`,
distinct from the entrance curve, explicitly liked by the human at gate per the existing
comment block) is **out of scope** this phase — only the entrance keyframe is retrofitted,
per D-19's exact framing.

### Reduced-motion / motion-scale axis (D-06, D-08, D-21)

Named presets, never a bare float (state-axis naming convention above). Multiplier table
lives in `motion.json`, not in `motion.sh` (D-21):

| Preset | Multiplier | Mechanism |
|--------|-----------|-----------|
| `off` | not a multiplier — toolkit-disabled | Hyprland `animations { enabled = false }`; QML `Animation.enabled = false`; GTK `enable-animations` GSettings key set `false` (D-20) |
| `reduced` | 0.5× | Every emitted duration halved, then clamped |
| `normal` | 1.0× | Baseline — matches today's hand-authored values unchanged |
| `lively` | 1.25× | Slightly slower/more expressive than baseline; optional, not required by TOKEN-05, offered because the axis already exists (D-06) |

**Collapse guard (D-09):** every emitted duration is clamped to a floor of **40ms** —
chosen because it sits just under the smallest legitimate scale token (`short1` = 50ms),
so `reduced`'s 0.5× never needs the floor for anything above `short1` but guarantees no
token can ever collapse to an ambiguous near-zero value. Collapse at the floor **warns**,
never fails (D-09) — a low-scale value that reads as instant is not a defect.

### GTK4 CSS custom-property contract (wleave retrofit target, D-19)

wleave is GTK4, which has real CSS custom properties (verified this phase — see
`code_context` in `12-CONTEXT.md`). The lint's compliant-surface definition for GTK4 is
crisp: **no raw duration/timing-function literal — every value must come through
`var(--motion-*)`.**

```css
:root {
  --motion-duration-standard: 200ms;
  --motion-duration-emphasized-in: 300ms;
  --motion-duration-emphasized-out: 150ms;
  --motion-easing-standard: cubic-bezier(0.2, 0, 0, 1);
  --motion-easing-emphasized-decelerate: cubic-bezier(0.05, 0.7, 0.1, 1);
  --motion-easing-emphasized-accelerate: cubic-bezier(0.3, 0, 0.8, 0.15);
}
```

Proposed retrofit mapping (line numbers per the current file — confirm at implementation,
the file may have shifted): `style.css:230` transform transition → `var(--motion-duration-standard)` /
`var(--motion-easing-standard)`; `style.css:455` opacity/transform transition →
`var(--motion-duration-emphasized-out)` / `var(--motion-easing-emphasized-accelerate)`;
`style.css:559-560` `capsule-entrance` `animation-duration`/`animation-timing-function` →
`var(--motion-duration-emphasized-in)` / `var(--motion-easing-emphasized-decelerate)`. The
hover curve at `style.css:230`'s sibling rule stays a hand-authored literal — out of scope
per D-19.

### QML consumption mechanism (proposed — verify against the installed Qt6 build)

QML's `Easing.BezierSpline` accepts arbitrary cubic-bezier control points on any
`Behavior`/`PropertyAnimation`: `easing.type: Easing.BezierSpline`, `easing.bezierCurve:
[x1, y1, x2, y2, 1, 1]`. This UI-SPEC proposes `Motion.qml` (a second Quickshell
`Singleton`, sibling to `Colours.qml`, same `FileView`/`JsonAdapter` pattern per D-11)
exposing `Motion.standardDuration`/`Motion.standardBezier` etc. **Not yet verified against
this project's installed quickshell/Qt6 build** — standing constraint 2 applies; RESEARCH/
PLAN must confirm `Easing.BezierSpline` behaves as documented before the executor relies on
it, exactly the same discipline already applied to the Hyprland `bezier =` and GTK4
`cubic-bezier` findings this phase.

## Token Inspector — Surface Contract

The one styled visible surface this phase ships (D-10, D-15). Summon-only via
`Super+Shift+G`, root stays headless (Phase 11 D-02 unchanged). Its content is
diagnostic by design (D-15) — the "never pretty" intent survives through *what it shows*,
not through refusing colour.

**Required content, top to bottom:**

1. **Header banner** (Display role, 22px/600): `Screen: {screen.name} · Theme:
   {current-theme} ({mode})` — reads directly from the existing `current-theme`/`mode`
   state files plus the existing `screenLabel` logic already in `Probe.qml`.
2. **Colour Roles** section (Heading, 18px/600): one swatch per matugen role — a coloured
   chip plus its `Label`-role token-name caption underneath (e.g. `primary`,
   `surfaceVariant`). Swatches read live from `Colours.qml`.
3. **Motion — Semantic Pairs** section: one row per semantic token (`standard`,
   `emphasized-in`, `emphasized-out`) showing the token name, its resolved duration, and
   its resolved easing name.
4. **Replay** section: a button labelled **"Replay motion"** that re-triggers each
   semantic pair's animation on demand (D-16) — makes the human render-gate repeatable in
   seconds rather than costing a full theme switch.
5. **Theme-switch crossfade**: the swatch fills themselves use `Behavior on color {
   ColorAnimation { duration: Motion.standardDuration } }` so switching theme while the
   inspector is open visibly crossfades rather than hard-cutting (D-11's whole reason for
   choosing JSON + Singleton over a generated document).
6. **TOKEN-06 side-by-side** (stretch, D-26): if attempted, a toggle/button labelled
   **"Spring / MD3"** switches the replay row between a `SpringAnimation` variant and the
   bezier variant, with a label under the replay row stating which is currently playing.
   Explicitly optional — its absence changes nothing else in this contract.

The existing counter-button, text field and hand-edited JSON label from Phase 11's
`Probe.qml` (QS-02 proof instruments) are retained unchanged underneath the above, per
Phase 11's viability-gate ownership — this phase does not remove working instrumentation.
