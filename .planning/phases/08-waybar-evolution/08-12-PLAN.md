<design_system>
This is the binding design contract for all four layouts. Plans 13 and 14 inherit it verbatim.
It supersedes 08-UI-SPEC.md's "no redesign — this is a styling trim" clause, which the user's
explicit redesign directive has overridden.

**Rule 1 — the window is always transparent.** `window#waybar { background: transparent; }`
in every layout, with no exception. The visible surface lives one level in, on
`window#waybar > box`. This one rule is what fixes the reported dark slab. 08-03 painted
`alpha(@background, 0.90)` directly onto the window in all four sheets; that is the bug.

**Rule 2 — one surface, one neutral.** The island is `@bar-surface` (theme.css:
`alpha(@surface, 0.55)`). Modules get NO background fill by default. They are bare glyphs and
text sitting on the shared island. The previous design gave every module its own accent-hued
pill — five competing hues (@tertiary cpu/pulseaudio, @secondary memory/network, @primary
temperature, @error power, @outline gaming) — which is the "eyesore" and the "terrible colour
scheme". Delete it. Do not replace it with a different set of per-module hues.

**Rule 3 — chroma encodes state, nothing else.** `@accent` appears on exactly one resting
element: the active workspace. Everything else in a resting bar is `@fg` or `@fg-dim`. Chroma
is otherwise permitted ONLY on: `#temperature.critical` and `#battery.critical` (`@danger`),
`#battery.warning` (`@warn`), `#custom-gaming-mode.on` (`@accent`), `#mpris` while actually
playing (`@accent`), and `#custom-power:hover` (`@danger` — a hover, not a resting state; the
power button must NOT be a permanently-lit red pill).

**Rule 4 — one radius scale.** 14px bar island, 10px segment, 6px workspace button. Nothing
else. (The current tree has an ad-hoc mix plus one invalid `border-radius: 10` with no unit.)

**Rule 5 — `min-height: 0` on the `*` reset.** Its absence inflates every module. Note
style-floating.css currently sets `min-height: 10px`, which is the inflation, not a fix.

**Rule 6 — a `min-width` floor on `#workspaces button`.** 14px. GTK collapses a button below
its natural size once you reset its padding to zero; every well-rated config re-floors it. Its
absence is the reported "compressed" workspaces.

**Rule 7 — glyph-only modules get their own font-size.** One global size cannot serve both
13px text and a 16px icon. Body text is 13px; glyph-only modules are 16px.

**Rule 8 — role names only.** Layout sheets reference `@bar-surface`, `@fg`, `@accent` etc.
Raw palette token names appear ONLY in theme.css. `waybar-design-lint` CHECK B enforces this.
</design_system>

<task type="auto">
  <name>Task 1: Rewrite waybar-modules.css as the shared neutral design system</name>
  <files>waybar/.config/waybar/waybar-modules.css</files>
  <action>
Rewrite this file wholesale against the design_system contract above. It is the highest-leverage
file in the phase — it is imported by all four layouts, so getting it right is most of the
redesign.

Delete the entire per-module accent-hue block. Today `#cpu`, `#memory`, `#temperature`,
`#pulseaudio` and `#network` share a grouped rule that gives them a `@surface_variant` fill plus
a per-module coloured bottom-border, and `#custom-theme`/`#custom-waybar-layout` carry a filled
`@primary` background while `#custom-power` carries a filled `@error` background. All of that
goes. Replace with: the system modules group gets padding and a transition and NO background and
NO border; their colour is `@fg`. The two custom buttons get `@fg` and no fill. `#custom-power`
gets `@fg` at rest and swaps to `@danger` only on hover.

Restore the active workspace as a genuine focal point. 08-03 drained it to a transparent 2px
underline, which is why full and minimal read as flat and characterless. Bring back a filled
pill: `#workspaces button.active` gets `background: @accent; color: @on-accent;` with the 6px
radius. This is the ONE accent-filled element in a resting bar and it is what gives the bar a
focal point. Inactive buttons are `@fg-dim` on transparent; hover is `@fg` on
`@bar-surface-hover`.

On `#workspaces button`, set `min-width: 14px` (Rule 6) alongside the padding, and give it the
6px radius. Do NOT set `padding: 0; margin: 0` — that is the collapse that produced the reported
compression in floating.

Add a `#workspaces button.urgent` state using `@danger`, and `#workspaces button.occupied` using
`@fg` (occupied is a real, meaningful distinction from empty, and the current tree renders it in
a colour identical to the bar background, making it invisible).

Set glyph-only module font-size to 16px on the modules that carry only an icon
(`#custom-theme`, `#custom-waybar-layout`, `#custom-power`, `#custom-notification`,
`#custom-gaming-mode`). Leave text-bearing modules at the inherited 13px.

State rules: `#temperature.critical` → `@danger`. `#battery.warning` → `@warn`;
`#battery.critical:not(.charging)` → `@danger`. Keep the existing critical-battery blink
keyframes if you keep an animation, but retarget its colours to role names. `#mpris` → `@fg` at
rest; add a playing state in `@accent`; `#mpris.paused` → `@fg-dim`; keep `#mpris.stopped`
fully collapsed (transparent, zero padding/margin) so it does not leave a hole in the bar.
`#custom-gaming-mode.on` → `@accent`, off → `@fg-dim`.

Style the tooltip to match the island: `@bar-surface` background at the 10px segment radius,
`1px solid @fg-dim` border (the current `2px solid @primary` is chroma on a non-state element —
it violates Rule 3), and `tooltip label { color: @fg; }`.

Every colour reference in this file must be a theme.css role name. Zero raw palette tokens.
  </action>

radius at all; give it enough margin (6px) to read as an island.

radius, not through a stroke.
