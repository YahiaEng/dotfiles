The design system is defined in 08-12-PLAN.md's `<design_system>` block and was approved by the
user at plan 12's checkpoint. Read it there and follow it. It is not restated here — one source
of truth.

Floating's ONE structural divergence from full/minimal: the surface does not go on a single
`window#waybar > box`. Floating is three separate capsules, so the surface goes on
`.modules-left`, `.modules-center` and `.modules-right` individually. Everything else — the
transparent window, the single neutral surface colour, chroma-for-state-only, the 14/10/6 radius
scale, `min-height: 0`, the 14px workspace min-width floor, role-names-only — is identical.
</inherited_design>

<task type="auto">
  <name>Task 1: Rewrite style-floating.css as three capsules on an invisible bar</name>
  <files>waybar/.config/waybar/style-floating.css</files>
  <action>
Rewrite this sheet wholesale. It currently carries ~340 lines of per-module accent-hued pills
(`#cpu` filled `@primary`, `#memory` filled `@tertiary`, `#pulseaudio` filled `@tertiary`,
`#network` filled `@secondary_container`, `#custom-media` filled `@secondary`, `#tray` filled
`@secondary_container`, `#custom-power` filled `@error`, `#custom-updates` filled `@primary`,
`#custom-wallpaper` filled `@secondary`, `#backlight`/`#battery` filled `@secondary`,
`#custom-launcher` filled `@primary_container`) — that is the rainbow, and it all goes. Nearly
every rule in the file is deleted rather than edited.

Import chain, same as full/minimal: `theme.css`, then `waybar-font.css`, then
`waybar-modules.css`, then LAST `../../.local/state/theme/waybar-visibility.css`.

The `*` reset: `font-size: 13px; min-height: 0; border: none; border-radius: 0;`. Note the
current file has `min-height: 10px` (the module-inflation bug) and `border-radius: 10` with NO
UNIT (an invalid declaration GTK silently drops) — both are fixed by writing the reset correctly.

`window#waybar` gets `background: transparent;` and `color: @fg;` and nothing that paints. This
is the fix for the reported dark bar. Keep `transition: opacity 0.3s ease;` for the idle-dim
path. Delete the `window#waybar.hidden { opacity: 0.2; }` rule ONLY if you confirm nothing sets
that class — `waybar-visibility.sh` uses the file-presence-is-state mechanism (per the Phase 08
decision that no class is ever added to waybar's own window), so this rule is almost certainly
dead. Grep before deleting; if something does set it, leave it.

The capsules: `.modules-left`, `.modules-center`, `.modules-right` each get
`background: @bar-surface;` at the 14px bar radius, with padding (4px vertical, 8px horizontal)
and a margin (6px) so the three capsules read as distinctly separate floating objects with visible
gaps between them and clear space to the screen edge. This separation IS the floating layout's
identity — if the three capsules touch or run to the edge, it stops reading as floating.

Modules inside the capsules get NO background fill of their own. They inherit the shared neutral
system from waybar-modules.css. A module fill inside a capsule surface produces the "pill inside
a pill" double-stacking that made the old design look heavy.

Workspaces: the shared sheet already supplies the 14px min-width floor, 6px radius, `@fg-dim`
inactive, and the `@accent`-filled active pill. DO NOT override `padding` or `margin` to zero
here — that override is the exact cause of the reported compression. If floating needs tighter
spacing than the shared default, adjust the shared value or use a small non-zero value; never
zero. Delete the current `#workspaces { font-size: 4px; }` and
`#workspaces button.occupied { font-size: 4px; color: @surface; }` rules outright — a 4px font
renders workspace glyphs as unreadable specks, and `@surface` is now the same colour family as
the capsule, which is why occupied workspaces were invisible.

Delete the `#window { color: transparent; }` rule if the window title is meant to be visible;
if floating deliberately hides the title, keep it hidden but do it by not listing the module in
config-floating.jsonc rather than by painting it transparent. Check the config before deciding.

Keep the battery blink keyframes but retarget to `@danger`/`@on-danger` role names.

Every colour reference must be a theme.css role name. Zero raw palette tokens (CHECK B).

Then LOOK at it: `echo floating > ~/.cache/current-waybar-layout && ~/.config/hypr/scripts/waybar-launch.sh`,
`theme-apply tokyonight`, `grim /tmp/bar-floating-tokyonight.png`; then `theme-apply catppuccin-latte`,
`grim /tmp/bar-floating-catppuccin-latte.png`. Inspect both yourself before handing to the human:
are there three visually separate capsules with wallpaper showing between them? Are the workspace
buttons legible rather than specks? Is there exactly one accent element at rest?
