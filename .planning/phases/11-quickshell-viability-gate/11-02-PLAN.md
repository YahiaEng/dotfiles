<objective>
Repair `keybind-doctor` so it is a working instrument again, and extend it to cross-check the second, newly-introduced keybind registration mechanism.

Purpose: MAINT-01 is not filler in this phase. QS-05 requires proving there is no duplicated global keybind across **two independent registration mechanisms** — Hyprland `bind =` lines and Quickshell `GlobalShortcut` — and `keybind-doctor` is the instrument for that proof. It is currently worse than useless: it dies on a `jq` parse error and then false-negatives all 78 binds as "not registered", reporting failures that are not real. Plan 03's `quickshell-doctor` calls it as one of its checks, so it must be green before that gate is built. Phases 14 and 16 each add a Quickshell-owned chord, so the detector must work *before* then, not after.

Output: a repaired, extended `keybind-doctor`; a proven-to-fail collision check; amended ROADMAP and REQUIREMENTS wording; and a written record of why structured parsing was abandoned.
</objective>

Replace the cross-check block (currently lines 137-194) with a plain-text block parser. Drop the structured/JSON mode of the compositor bind query and its `jq` filters entirely from the executable path — every one of them. D-14's root cause is that Hyprland 0.56.0's serializer is *field-misaligned*, not merely malformed: it emits `false` where the modmask integer belongs, puts modmask's value into the submap string, and emits an unquoted keycode. A syntax-only repair would produce semantically **wrong** data while appearing to work, which is strictly worse than the current loud failure.

Parse blank-line-delimited blocks (`awk 'BEGIN{RS=""}'` or a bash equivalent). The **first line of each block is a variable block-type token whose letters encode the bind's flags** — do not strip a fixed `bind` prefix and do not assume the token is constant. Verified directly on this build: a `bindel =` declaration in `keybinds.conf` surfaces with the token `bindle` (letters reordered relative to the config flag string), and a `bindl =` declaration surfaces as `bindl`. Derive the release flag from whether the token's letter set contains `r`, mirroring the declared side's existing `*r*` test at line 106 so both sides of the comparison are built the same way. A parser that reports zero XF86-key or mouse-scroll binds registered is the warning sign that this was gotten wrong.

The remaining eight lines per block carry stable, correct, correctly-ordered field labels on this build: `modmask:`, `submap:`, `key:`, `keycode:`, `catchall:`, `description:`, `dispatcher:`, `arg:`. Extract `modmask`, `key`, `keycode`, `dispatcher` and `arg`, and build the same `modmask|key|keycode|release` tuple the declared side already builds at line 117 so the existing comparison logic is fed unchanged data.

Add a **shape guard** as its own named `check` (D-14 explicitly requires failing loudly if the text format ever changes shape). It must assert that at least one block was parsed, and that every parsed block carries the expected eight field labels in the expected order. If Hyprland changes the plain-text layout in a future release, this check fires by name instead of the parser silently returning garbage.

Preserve all four existing checks with equivalent semantics, each still a separate `check` call so a failure names itself:

1. **Manifest schema** — the file parses as JSON, is an array, and every entry carries non-empty `appid`, `name`, `chord.mods` and `chord.key`.
