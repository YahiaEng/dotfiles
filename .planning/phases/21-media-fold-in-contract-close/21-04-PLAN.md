<objective>
Repair the standing MPRIS-reader check so it asserts the invariant this phase actually
delivers, and prove it fails on both sides of the boundary rather than merely passing
once.

This is the phase's most consequential correction. The gate already contains a check for
MPRIS surface usage across the QML tree, written in Phase 11 before this repo had any
media widget, asserting the count is **zero**. Phase 18's D-18-05 legitimately repointed
the media backend onto the native MPRIS singleton — a correct, intended change — and
that check has been silently FAILING ever since. Verified live this session: the count is
1 and the check asserts 0, so it reports FAIL on an entirely healthy tree.

Purpose: turn a two-phase-old latent gate failure into QMEDIA-03's own durable guarantee.
Output: a repaired, correctly-named check with three-count self-test coverage.
</objective>

<assumption_delta_decision>
**Signal.** The deterministic detector fired on a `pluralization` signal (the term
"second", from the roadmap note that this phase removes the *second of three* readers).
That literal hit is about a **removal**, not a newly-introduced second case, and is not
the real delta.

**The real delta.** QMEDIA-03 changes the identity of the thing being counted. The
primary noun was *"an MPRIS **writer**, of which Quickshell must contain zero"* — a
Phase-11-era invariant. The primary noun is now *"an MPRIS **reader**, of which the
desktop must contain exactly one."* Two things moved at once: the noun (writer → reader)
and the cardinality (zero → exactly one). The existing check's own name was never
accurate even in Phase 11 — the file it now matches is a reader, and the check's comment
already conflates the two.

**Decision: `promote`.** Repair the existing check in place, promoting it to the new
primary noun and cardinality. Do not add a parallel counter in `retirement-check`.

**Rationale.** The obsolete assertion and a hypothetical new one would be two checks
making contradictory claims about the same match set — which is precisely the failure
mode that let this gate sit red for two phases without anyone noticing. Promoting in
place also closes the red gate as a side effect of delivering QMEDIA-03, rather than
leaving a known-failing check behind a passing new one.

**Confirmed against the live check before committing to it** (this session, not inferred):
the check body at `quickshell-doctor` lines 2867-2883 asserts `MPRIS_HITS -eq 0`; an
independent replay of its own find/grep loop over the live config directory returns
exactly 1 hit, in `MediaBackend.qml`. The check is therefore currently red, and `promote`
is the correct disposition.

**This also resolves D-21-16's "Claude's Discretion" question** — the choice between
`quickshell-doctor` and `retirement-check` is not actually open; the check already has a
home and that home is broken.

**Accepted debt: none.** `promote` creates no parallel structure and leaves nothing behind.
</assumption_delta_decision>
