**Correction the plan carries, and the executor must honour over the UI-SPEC's prose.**
The UI-SPEC describes this as adding "one additional branch" to the shared capsule
component's colour expression. That description elides a fact this task depends on: this
capsule never sets the shared component's `surfaced` property, so it takes the default,
and its baseline fill is therefore unconditionally transparent — bare glyphs on the
wallpaper, not the surfaced capsule fill. Confirmed this session: the only two occurrences
of the word in this file are prose comments, one of which states outright that the capsule
is unsurfaced and that its inner pill is consequently the visible element. The tint must
therefore fire regardless of the surfaced state, not as a variant inside the surfaced
branch.

Add a blended token pair to the bar's token file, following the file's existing blend
idiom exactly — build them from a colour-typed indirection property, never from a palette
value directly:
- a surface token: the bar's accent role blended at a low alpha. Start at `0.28`. This is
  a recommended starting point, not a locked value; it is render-gate adjustable roughly
  between `0.20` and `0.35` without touching the mechanism.
- a foreground token: kept on the ordinary on-surface role, deliberately NOT the on-accent
  role. A low-alpha accent wash over the capsule does not reach the on-accent contrast
  target, so switching the foreground would reduce legibility rather than improve it.

Override `color:` at the **instance level**, on this capsule file's own root capsule
object — not inside the shared component. Editing the shared expression would spread the
tint to every other capsule in the bar. The instance override rebinds the colour of the
one background rectangle the component already declares, which does not violate the rule
that no capsule component may declare its own background rectangle: that rule forbids a
SECOND rectangle, and this adds none.

The override's expression: when the live do-not-disturb flag is true use the new surface
token; otherwise fall through to exactly the shared component's existing expression,
reproduced unchanged, so nothing about the untinted appearance shifts.

Leave the inner clock pill's own fill alone. Tinting two nested layers simultaneously puts
two tints in conflict; do-not-disturb tints the outer capsule surface only.

Keep the notification server's own property as the single source of truth — the capsule
already reads it, so route that existing boolean rather than introducing a second holder.

Do not add a colour transition: the shared component already declares one on this same
property, and a base-type behaviour continues to apply to value changes driven by an
instance-level override. If live testing shows the change snapping rather than animating,
add an explicit local transition on the instance override using the standard duration and
easing tokens — never a raw number.

Verify the result holds in the vertical bar layout, where capsules render glyph-only.
