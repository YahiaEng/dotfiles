<objective>
Enumerate the retiring media card's real behaviour off the LIVE surface, while it
still exists, and turn that enumeration into the parity checklist the combined
deletion gate consumes.

This is a hard ordering constraint, not a nicety. D-21-08 and D-21-11 together say:
enumerate off the running card, build any genuine gap the enumeration finds, and only
then delete. Nothing in this phase that destroys the retiring tree may run before this
plan completes. D-21-08 also records the useful prior: the Media tab already carries
transport, seek, cover art, a volume band and the player-switcher pill, so the
enumeration is expected to CONFIRM parity rather than discover a backlog — but it is
still run, because the deletion is one-way.

Purpose: make the deletion decision evidence-based rather than assumed, and produce the
checklist half of D-21-20's one combined gate.
Output: `21-BEHAVIOUR-BASELINE.md`, committed before any destructive work.
