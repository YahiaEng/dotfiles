<objective>
Land QBAR-02's architecture: **one** entry list in which orientation is a property, not a
fork — plus the shared capsule chrome and the six pre-declared slots that let wave 3 run
genuinely in parallel.

Purpose: QBAR-02's requirement text is explicit that "orientation is a property of a
config-driven entry list, not a forked second layout." A plan that produces two arrangements
has failed the requirement even if both render perfectly, so the structure has to be right
before any capsule content exists. Three things land together for that reason:

1. **`BarEntryModel.qml` — the single entry list.** One ordered `capsules` array; every
   capsule carries a `zone` for BOTH orientations (D-18-13). One vocabulary of three zone
   names shared by both orientations, so `Bar.qml` renders three zone positioners regardless
   of orientation and a second arrangement is structurally unrepresentable. This singleton
   also owns the orientation value itself — which is what makes "orientation is a property of
   the entry list" literally true in code rather than a claim in a comment.
2. **`BarCapsule.qml` — the shared chrome.** `radius` at half the cross-axis extent (the full
   pill idiom `QuickToggles.qml` and `Overview.qml`'s mode indicator already use),
   `Colours.surfaceVariant` at rest, `Colours.surface` on hover through the repo's
   `Behavior on color` block. Every capsule is built from it, so the six can never drift.
3. **All six slots plus all the root wiring, up front.** This is the load-bearing structural
   decision of the phase. Wave 3 runs 18-08, 18-09, 18-10 and 18-11 in parallel, and that is
   only safe if each owns exactly one component file and none has to touch `Bar.qml`,
   `BarEntryModel.qml` or `shell.qml`. If a slot or a wiring line is missing here, wave 3
   serialises on a merge conflict.

Output: `modules/bar/` with its own `qmldir` and eight new types, one appended `Design.qml`
token (`barColumnWidth`), an orientation-driven `Bar.qml` root, and `shell.qml`'s complete
bar wiring.

**Explicitly NOT in this plan** (each owned by a named later plan, listed so the executor
does not helpfully build ahead): every capsule's actual content — `[system]` and
`[media + connectivity]` readouts are 18-08's, `[workspaces]` live icons are 18-09's,
`[tray]` is 18-10's, and the two athena drawers plus the four permanent extras in
`[clock + actions]` are 18-11's; the popout frame and hover mechanics (18-13/18-14); the hot
zone (18-16); the visibility owner and the `bar` IPC handler (18-15); the orientation
**toggle UI** that writes the config value (18-11, D-18-30 — this plan defines and reads the
contract only); the doctor checks (18-17).

Also not this plan's: replacing `~/.cache/current-waybar-layout`. That file is the retired
bar's own four-layout selector and dies with it at 18-20; the orientation value lives at a
new path under quickshell's own state directory, deliberately carrying no retired-surface
name so `retirement-check` (18-06) finds nothing to flag in its blocking tier.
</objective>
