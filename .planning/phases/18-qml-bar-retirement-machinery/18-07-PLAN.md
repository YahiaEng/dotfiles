<objective>
Give the bar a supervisor: a new systemd `--user` unit, `quickshell.service`, with an
explicit `Restart=on-failure`, `RestartSec=`, `StartLimitIntervalSec=` and
`StartLimitBurst=` (D-18-40), replacing the transient uwsm scope as quickshell's — and only
quickshell's — launch path.

Purpose: QBAR-10 asks for one observable thing, "the bar returns automatically if its
process dies — no manual restart", and today nothing provides it. `quickshell-launch.sh`
guards, logs and execs; it does not supervise. The bar shipped in 18-01 is the first surface
in this repo that is permanently mounted, so its process death is now a visible desktop
outage rather than the invisible loss of a headless probe root it was through v3.0 — and
from Phase 19 the same process also carries the notification server.

**Name the deviation, because it is the point of D-18-40.** Every autostart entry in this
repo — the wallpaper daemon, waybar, its fullscreen watcher, quickshell today, swaync, the
AGS media applet, elephant, walker, hypridle, swayosd, the polkit agent and both clipboard
watchers — launches through a transient uwsm scope in `app-graphical.slice` with no
`Restart=` directive anywhere. There is zero precedent in this repo for a custom systemd
`--user` unit; the only stowed systemd artifact that exists is a drop-in overriding
swaync's packaged unit. This plan makes quickshell the first exception, deliberately, and
records that in the shipped source so it never reads as an accident. The shape to copy is
the packaged-but-unused `waybar.service` (`Restart=on-failure`, sitting `disabled` while the
bar has actually been running from a uwsm scope this whole time) — copied selectively, with
each divergence justified below rather than inherited.

**The backoff numbers are chosen here, not inherited.** RESEARCH.md's Assumption A3 records
that no artifact locks them; its suggestions are engineering judgement. This plan picks
`RestartSec=2`, `StartLimitIntervalSec=60` and `StartLimitBurst=5`, and Task 1 states the
reasoning in the unit itself. Systemd's own defaults were measured on this host
(`RestartSec` 100ms; `DefaultStartLimitIntervalUSec=10s`, `DefaultStartLimitBurst=5`) and
both are actively wrong for this workload — see the rate-limit truth in `must_haves`.

**Environment parity is the real risk, and it is measured, not assumed.** A uwsm scope is
forked by the caller and inherits Hyprland's environment; a native unit is forked by the
systemd user manager and inherits the manager's. Those are different blocks. Verified on
this host this session: the manager's block already carries `WAYLAND_DISPLAY`,
`XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`, every XDG base dir, the `QT_*` set and —
critically — `HYPRLAND_INSTANCE_SIGNATURE`, which uwsm exports through
`UWSM_FINALIZE_VARNAMES`. So parity is achievable. But that one variable arrives
asynchronously from uwsm's finalize, and `Quickshell.Hyprland` is dead without it, so this
plan does not leave it to a race: Task 2 adds it to the import-environment line that already
runs first in the autostart handler, and Task 3 proves the resulting environment by diffing
two real `/proc/<pid>/environ` captures.

Output: the unit, its stow reproducibility guarantee, the one-line mechanism swap in
`autostart.lua`, a header correction in `quickshell-launch.sh`, and `18-RESTART-PARITY.md`.

Explicitly NOT in this plan (each owned by a named later plan, listed so the executor does
not helpfully build ahead): any `quickshell-doctor` check — GATE-03's structural checks are
18-17's, and the existing launcher-log and pgrep assertions keep passing unchanged here; the
multi-hour soak that consumes this plan's zero-added-process fact (18-18); any bar capsule,
popout, auto-hide or IPC work; and any change to how the other twelve autostart entries
launch — they stay on uwsm scopes, and widening this deviation beyond quickshell is out of
scope.
</objective>

<interface_context>
Verified directly on this host this session — do not re-derive, and do not substitute a
remembered systemd behaviour for one of these.

**`Restart=on-failure` semantics** (`/usr/share/man/man5/systemd.service.5.gz`, read
directly; `man` itself is not installed on this host, so read the gzipped page with `zcat`
if it needs re-checking): the service restarts when the process "exits with a non-zero exit
code, is terminated by a signal (including on core dump, but excluding the aforementioned
four signals)". Those four, defined in the same page's clean-exit list, are **SIGHUP,
SIGINT, SIGTERM and SIGPIPE**. Consequence for this plan: a plain `pkill` (SIGTERM) does NOT
trigger a restart. Only SIGKILL, another non-exempt signal, or a non-zero exit does.

**Defaults being overridden** — `RestartSec=` "Defaults to 100ms" (same man page);
`systemctl --user show -p DefaultStartLimitIntervalUSec -p DefaultStartLimitBurst` reports
`10s` and `5` on this host.

**Directive sections** — `StartLimitIntervalSec=` and `StartLimitBurst=` are documented in
`systemd.unit(5)` and belong in the `[Unit]` section; `systemd.service(5)` only
cross-references them. Putting them under `[Service]` is a deprecated compatibility path.
`Restart=`, `RestartSec=`, `Type=`, `Slice=` and `ExecStart=` belong in `[Service]`.

**The shape being copied** — `systemctl --user cat waybar.service` on this host:
`[Unit]` carries `PartOf=graphical-session.target`, `After=graphical-session.target`,
`Requisite=graphical-session.target`; `[Service]` carries `ExecStart=/usr/bin/waybar`,
`ExecReload=kill -SIGUSR2 $MAINPID`, `Restart=on-failure`; `[Install]` carries
`WantedBy=graphical-session.target`. It is packaged, `disabled`, and vanishes with the
`waybar` package at 18-20 — read it live before then if it needs re-checking.

**Current launch shape** — `uwsm app` defaults to `-t scope` in `app-graphical.slice`
(`uwsm app --help`, uwsm 0.26.6-1), confirmed by the live cgroup of the running process:
`…/user@1000.service/app.slice/app-graphical.slice/app-Hyprland-quickshell\x2dlaunch.sh-<hash>.scope`.

**Systemd specifiers** — `%h` expands to the user's home directory. This repo already uses
it in `swaync/.config/systemd/user/swaync.service.d/override.conf`, for exactly the reason
it is used here: no hardcoded username, so the unit is host-independent. Systemd does not
run `ExecStart=` through a shell, so `~` would NOT expand and no shell metacharacter has any
meaning in that line.

**The manager environment a unit inherits** — `systemctl --user show-environment` on this
host already contains, verbatim: `HYPRLAND_INSTANCE_SIGNATURE`, `WAYLAND_DISPLAY`,
`XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`,
`XDG_CACHE_HOME`, `XDG_DATA_HOME`, `XDG_CURRENT_DESKTOP`, `XDG_SESSION_TYPE`,
`QT_QPA_PLATFORM`, `QT_AUTO_SCREEN_SCALE_FACTOR`, `QT_WAYLAND_DISABLE_WINDOWDECORATION`,
`PATH`, `HOME`, and `UWSM_FINALIZE_VARNAMES` (whose value names
`HYPRLAND_INSTANCE_SIGNATURE` as one of the variables uwsm exports here). It does NOT
contain `QSG_RENDER_LOOP` — that one is exported by `quickshell-launch.sh` itself, which is
precisely why the script stays the unit's exec target rather than being bypassed.

Three divergences from `waybar.service` — record each one in the header with its reason,
because each is a considered omission rather than an oversight:

1. **No install stanza, and therefore no enable step.** Enabling would write a wants-symlink
   into the user's own systemd tree that never lands in the repo, and this project's stated
   core value is that the whole setup reproduces from a clone plus one script. Omitting the
   stanza makes that failure mode structurally impossible rather than merely discouraged —
   the unit cannot be enabled even by accident, and `systemctl --user is-enabled` reports it
   static. The autostart handler starts it explicitly instead, which also keeps that file as
   the single readable inventory of what this session launches.
2. **No hard requirement on the graphical session.** `waybar.service` carries one. Measured
   on this host: the graphical session target and the compositor's own autostart handler
   both timestamp inside the same one-second tick, so a hard requirement is a coin-flip
   between a running bar and a start refused for a session that is a fraction of a second
   from ready. The ordering directive is kept, which costs nothing and cannot fail;
   `PartOf=` is what actually matters here and it is kept — it is what stops the unit at
   session end, which is in turn what stops the restart policy from retrying forever against
   a compositor that no longer exists.
3. **No reload directive.** `waybar.service` maps reload onto a signal because that is
   waybar's whole style-reload mechanism. Quickshell hot-reloads its QML on file change
   natively, and the visibility actuation seam is an IPC call arriving in 18-15. Inventing a
   reload verb here would create a second, untested control path for something no caller
   asks for.

The `Slice=` value is not decoration: it puts the supervised process in the same cgroup
parent the uwsm scope uses today, so nothing that targets that slice — resource control,
session teardown — changes behaviour across the cutover.
