<objective>
Close the phase's two measurement requirements on the surface that finally makes both of them
answerable: measure OVER-04's frame-rate term that has stood UNMEASURED since Phase 16
(LEDGER-03), and prove the always-on bar's resting cost does not drift across a multi-hour
session (QBAR-11).

Purpose: this phase built the first Quickshell surface in this repo with **no dismissed state**.
Every prior surface — `Dashboard`, the three panels, `Overview` — is LazyLoader-summoned and
destroyed on dismiss, so each one inherits the zero-idle doctrine for free: whatever it schedules
stops when the user closes it. The bar inherits none of that. Anything it schedules runs for the
whole session, and the three backend gates 18-05 widened are the first gates in this repo's
history that never go false. That is the phase's named hazard, and this plan is where it stops
being a warning and becomes a number.

Four things make this plan the right place for LEDGER-03 as well, rather than a separate errand:

1. **The instrument is the same class of question.** OVER-04's frame-rate rows were left
   UNMEASURED because the only instrument on hand froze the machine. The safe alternative —
   Qt's own render-timing instrumentation under `QSG_RENDER_LOOP=threaded` — is already cited in
   `quickshell-launch.sh`'s own header as the basis for the threaded-loop decision on this host.
2. **The bar-idle control is a QBAR-11 measurement wearing a LEDGER-03 hat.** An always-on
   surface that renders frames while nothing changes burns GPU for the entire session. That
   number belongs to both requirements, and taking it once serves both.
3. **The frame-rate run needs a process restart; the soak needs an uninterrupted one.** Ordering
   the frame-rate campaign first means the clean restart that ends it becomes the soak's t=0, so
   the whole plan contains exactly one restart instead of two.
4. **Both requirements fail the same way — by producing a comforting number nobody can attribute.**
   A soak with no start reading, and an fps figure with no stated conditions, are the same defect.

Output: two measurement artifacts, four corrected ledger locations, and one blocking decision put
to the developer with a measured cost attached.

**Explicitly NOT in this plan** (named so the executor does not helpfully build ahead): any QML
edit whatsoever — no capsule, no backend, no gate expression, no `shell.qml` change, including the
GPU-sampler re-narrowing this plan measures and deliberately does not perform; GATE-03's

**`/proc` fields this plan reads, with their exact units:**
- `ps -o rss= -p <pid>` — resident set size in KiB, integer, whole pages.

- `/proc/<pid>/stat` — fields 14 and 15 are `utime` and `stime` in clock ticks. `getconf CLK_TCK`
  reports 100 on this host, so one tick is 10ms.
- `/proc/<pid>/cgroup` — the supervised process's path ends in `/quickshell.service` (18-07).
