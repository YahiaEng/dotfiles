# Phase 18 — UI Design Contract

> Visual and interaction contract for the QML bar (QBAR-01..12) and its section
> popouts (QBAR-09). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This is a Quickshell/QML shell, not a web/shadcn stack — the shadcn gate does
> not apply (see Design System below). Every token named here already exists in
> `modules/dashboard/Design.qml` / `Colours.qml` / `Motion.qml` unless marked
> **NEW** — new tokens are named in the identical convention (camelCase
> `readonly property`, a provenance comment citing this file) so GATE-04's
> hex-literal lint has a token to point authors at instead of a raw value.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Quickshell/QML shell, not a React/Next.js/Vite stack. shadcn gate not applicable. |
| Component library | This repo's own token + frame system: `modules/dashboard/Design.qml` (spacing/type/icon tokens), `modules/Colours.qml` (Material You palette singleton), `modules/Motion.qml` (duration/easing singleton), `modules/dashboard/PanelDialog.qml` (shared detail-panel frame — read for contrast, not reused directly, see "New popout frame" below), `modules/dashboard/GradientBorder.qml` (animated rim component, reused as-is) |

| Font | Body/UI text: `Qt.application.font` (system default — no family override exists anywhere in this shell; confirmed by grep, the only `font.family` uses in the whole `modules/` tree are the icon font and one capability probe). Icons: Material Symbols Rounded via `Design.symbolFontFamily`. |

- `modules/Dashboard.qml` — `exclusiveZone: 0` / `ExclusionMode.Normal` precedent for surfaces that reserve nothing; the bar is the first surface with `exclusiveZone > 0` and must not copy this file's zero-reservation posture.
- `waybar/.config/waybar/config-athena.jsonc` — the shape this bar redesigns toward (floating capsule, `height: 40`, `margin-top: 6`, `margin-left/right: 10`, discrete drawer groups, live-window-icon workspaces, `window-rewrite` glyph map).

## Reused Tokens (do not redeclare)

**Spacing** (`Design.qml`): `spacingXs 4` · `spacingSm 8` · `spacingMd 16` · `spacingLg 24` · `spacingXl 32` · `panelPadding 24` · `tooltipDelayMs 400` · `borderWidth 3` (Hyprland `general:border_size` parity number) · `iconSizeMd 24`.

**Typography** (`Design.qml`): `fontDisplay 32` (`weightDisplay` = `Font.Medium`) · `fontHeading 20` (`weightEmphasis` = `Font.DemiBold`) · `fontBody 16` (`weightBody` = `Font.Normal`) · `fontLabel 12` (`weightBody`). Line-height: `lineHeightTight 1.2` for Display/Heading, `lineHeightNormal 1.5` for Body/Label — established by `PanelDialog.qml`'s own declared constants, reused here rather than restated as a third copy.

Note for the record: the generic UI-SPEC template asks for exactly 2 weights. This codebase already has 3 established weight tokens (`weightDisplay`/`weightEmphasis`/`weightBody`) in active use across every surface built since Phase 14. Reuse-by-name takes priority over the generic constraint — do not introduce a 4th.

**Color** (`Colours.qml`, 19-key Material You palette, live-reloaded from `~/.local/state/theme/palette.json`, never a literal hex in QML): `primary`/`onPrimary`, `primaryContainer`/`onPrimaryContainer`, `secondary`/`onSecondary`, `secondaryContainer`/`onSecondaryContainer`, `tertiary`/`onTertiary`, `surface`/`onSurface`, `surfaceVariant`/`onSurfaceVariant`, `background`/`onBackground`, `outline`, `error`/`onError`.

**Motion** (`Motion.qml`): `standardDuration 200` / `standardEasing`, `emphasizedInDuration 300` / `emphasizedInEasing`, `emphasizedOutDuration 150` / `emphasizedOutEasing`, `staggerOffsetDuration 50` / `staggerOffsetEasing`, `ambientDuration` (scale-floored loop period, base 1000) / `ambientEasing`, `borderRotateDuration` (Hyprland-synced rim period, base 10000). All gated on `motionEnabled`; every `Behavior`/`NumberAnimation`/`ColorAnimation` in this contract follows the repo-wide `enabled: Motion.motionEnabled` idiom.

**Frame components reused verbatim**: `GradientBorder.qml` (rim), `Cascade.qml` (entrance stagger), the `HyprlandFocusGrab` + `dismissRequested()` dismissal pattern, the `Component.onCompleted` cascade-arming idiom.

## Spacing Scale

Declared values (must be multiples of 4) — this project's established scale, reused verbatim:

| Token | Value | Usage on this surface |
|-------|-------|------------------------|
| xs | 4px | Icon-to-value gap within one capsule item; popout anchoring gap from bar edge |
| sm | 8px | Gap between discrete section capsules (D-18-09); horizontal capsule padding; gap between multiple items inside one grouped capsule |
| md | 16px | Popout internal padding (`popoutHeaderHeight`'s content inset, popout body padding) |
| lg | 24px | Not used on the bar itself; reserved for the dashboard drawer it still defers to (D-18-17) |
| xl | 32px | Not used on this surface |

Exceptions (all **NEW**, declared above): `barHeight 40`, `barEdgeMargin 6`, `barSideMargin 10`, `barColumnWidth 44`, `hotZoneDepth 4`. None of these are multiples of the 4/8/16/24/32 *scale progression*, but three of the five (`barHeight 40`, `barColumnWidth 44`, `hotZoneDepth 4`) ARE still multiples of the base 4px grid — consistent with `Design.qml`'s own `borderWidth: 3` precedent of a hand-carried parity/reference number living alongside the scale rather than forced into it.

**Grid exemption, explicit and limited to exactly two tokens**: `barEdgeMargin 6` and `barSideMargin 10` are NOT multiples of 4 (6 ÷ 4 = 1.5, 10 ÷ 4 = 2.5) and are declared here as the **only two** exemptions from the 4px grid in this entire document. They intentionally break the grid because they reproduce `config-athena.jsonc`'s exact outer margins (`"margin-top": 6`, `"margin-left"`/`"margin-right": 10`) byte-for-byte, so the replacement bar lands positionally identical to the waybar it retires — load-bearing for GATE-02's aesthetic/side-by-side parity judgment (see "Bar shape" and GATE-02 above). This exemption applies **only** to the bar's outer offset from the screen edge. Every internal spacing value on this surface — capsule padding, icon/text gaps, popout padding, and every other token in this document — stays strictly on the 4px grid; no future token may cite this exemption to justify a non-4px value elsewhere.

The generic template's `2xl (48px)` / `3xl (64px)` rows are **not part of this codebase's established scale** (`Design.qml` stops at `spacingXl`/`panelPadding`) — do not introduce them for this phase.

## Bar Shape & Capsule Grouping

- **Posture**: floating detached capsule row/column (D-18-08), never edge-flush. `barEdgeMargin` (6px) gap from the physical top edge (horizontal) or right edge (vertical); `barSideMargin` (10px) inset from the perpendicular edges.
- **Discrete capsules, not one continuous pill** (D-18-09): each capsule is `barHeight` tall (40px, full height of the bar), radius `barCapsuleRadius` (`height/2` = 20, a full pill — the same segmented-pill idiom `QuickToggles.qml` and `Overview.qml`'s mode indicator already use, not a new shape). Fill: `Colours.surfaceVariant` at rest.
- **Gap between capsules**: `spacingSm` (8px) — this supersedes athena's own `"spacing": 0` (continuous-drawer) convention; D-18-09 is explicit that grouping boundary must equal interaction-target boundary.
- **Capsule count**: 5–6, grouped by concern (D-18-10). Canonical group order (this is the ONE entry-list order both orientations read from, per D-18-13):

  `[launcher drawer] → [system: cpu/ram/disk/updates] → [workspaces] → [media] → [connectivity: audio/network/bluetooth/battery] → [clock] → [actions: gaming/bell/settings/power] → [tray]`

  Exact capsule *boundaries* within this order are Claude's Discretion per CONTEXT — the concrete split locked here: **6 capsules** — `[launcher]` `[system]` `[workspaces]` `[media + connectivity]` `[clock + actions]` `[tray]`. Media and connectivity share a capsule because both are "glanceable status, click for detail" the same way; clock and actions share one because both are low-frequency-interaction singletons that would otherwise be four separate 1-item capsules, working against the "discrete capsule = interaction boundary" rule's own spirit (a capsule with 4 icons for 4 unrelated one-off actions is still one visual/interaction unit, matching `group/settings`'s existing multi-module-drawer precedent in `config-athena.jsonc`).

## Section Capsule Internals

Applies to every non-tray capsule (system, workspaces, media+connectivity, clock+actions):

- **Horizontal internal padding**: `spacingSm` (8px) each side, minimum. A capsule holding multiple items (e.g. system: cpu/ram/disk/updates) additionally inserts `spacingSm` (8px) between each item — reused, not a new gap token.
- **Icon/text pairing**: icon (`iconSizeMd`, 24px) then `spacingXs` (4px) gap then the short value text (`fontLabel`, 12px). This mirrors `PanelDialog.qml`'s header identity Row (`icon, spacingSm, title`) at a tighter gap appropriate to the bar's density — `spacingXs` not `spacingSm`, because the bar's own row already carries a coarser `spacingSm` between whole items.
- **Min-width**: none enforced by default — a capsule shrinks to fit its content. Two named exceptions:
  - Workspace capsule (vertical orientation): fixed-height slots per D-18-12, not shrink-to-fit.
  - Every text-bearing vertical-orientation entry: fixed `barColumnWidth` (44px), per D-18-14.
- **Truncation**: none, anywhere. No bar text element is ever hard-truncated with an ellipsis. This is by construction (D-18-07's rationale generalized): every value is short/bounded (a glyph, a 1–3 digit percentage, a stacked 5-character time). Where a value's width could visibly jitter (e.g. `"5%"` vs `"100%"`), reserve worst-case width with right-aligned fixed-width numeric formatting so the capsule never visibly resizes on a value change — this is this document's explicit resolution of the long-text/overflow consideration for numeric readouts (see UI Considerations below).

## Orientation Transform Rules (QBAR-02)

One entry list; each entry carries a `zone` per orientation (D-18-13) — never two arrangements.

- **Horizontal** (top strip): capsules in a `Row`, left→right in the canonical group order above, laid out in three zones mirroring athena's own `modules-left/center/right` precedent:
  - `left`: launcher, system
  - `center`: workspaces
  - `right`: media+connectivity, clock+actions, tray
- **Vertical** (right-edge column, D-02 "right" per Scoping Decisions): capsules in a `Column`, top→bottom, in the **same canonical order**, no center-banding (a column has no visual-balance reason to center one group the way workspaces are centered horizontally — that centering was specifically about a wide horizontal strip). Tray stays fixed at the bottom, mirroring its "end of the bar" position in the horizontal reading order.
- **What rotates**: nothing rotates geometrically. The bar's own root layout swaps `Row`→`Column` (and vice versa); every capsule's *internal* content stays laid out left-to-right (icon, then text) in both orientations — only the capsule-to-capsule axis changes.
- **What re-stacks**: text-bearing entries switch from a single inline `Row` (icon + value, horizontal) to a fixed `barColumnWidth` (44px) stacked form (D-18-14) — clock becomes two stacked `fontLabel` lines; other readouts become glyph above short value, or glyph beside an abbreviated value, whichever fits 44px without truncation (per-entry call, not a single rule — the acceptance bar is "no truncation," not "identical stacking shape everywhere").
- **What is dropped**: nothing. Every entry present in one orientation is present in the other (QBAR-02's own text: "carrying clock, battery, network, bluetooth, audio and CPU/RAM/disk... in both orientations"). Workspace live-window icons cap at the fixed-height slot's capacity and overflow to `+N` (D-18-12) in BOTH orientations, not only vertical — this keeps the two orientations' workspace behavior identical rather than inventing a horizontal-only unlimited-width mode that would then have to newly cap when rotated.

## Section Popout Frame (QBAR-09) — NEW type, deliberately distinct from `PanelDialog`

D-18-15 rejects reusing `PanelDialog` (a fixed 850×620, `anchors.top`-only, compositor-centred, `exclusiveZone: 0` dialog) because reusing it would just reopen the same surface `Super+A` already opens. The new type is a **glance surface**, not a second detail surface — same relationship `Overview.qml` (Super+O) already has to full window management (D-18-17). Concretely:

- **Content scope, locked here** (not fully resolved in CONTEXT — this is this document's resolution): each popout shows a **compact summary + primary quick actions only** — e.g. the audio popout shows the master volume slider and the 2–3 most relevant sinks/sources, not `AudioBackend`'s full unbounded stream list; the wifi/bluetooth popouts show current connection + a short list of nearby/paired entries, not the full scan result. Full, unbounded lists remain `PanelDialog`'s job. Every popout carries a **"Open in dashboard"** wayfinding link at its foot, visually identical to `PanelDialog`'s existing Advanced button (`Colours.surfaceVariant` pill, never accent-toned, D-15-06's own rule extended here) — clicking it opens the matching `PanelDialog` panel (audio/wifi/bluetooth) or the matching `Dashboard.qml` tab (clock→calendar tab if one exists, else the calendar view directly; resources→Performance tab; media→Media tab).
- **Frame chrome, matched to `PanelDialog` by construction where D-18-15 asks for review-based parity to actually be checkable**:
  - `cornerRadius`: `popoutCornerRadius` (20) — uniform on all four corners, **not** `PanelDialog`'s bottom-only rounding. This is a deliberate, reasoned difference, not an oversight: `PanelDialog` is bottom-only rounded because it sits flush against the true top edge (`anchors.top`, `margins.top: 10`); this popout floats fully clear of every edge (anchored off a floating bar capsule, `spacingXs` gap on all sides), so it has no edge to sit flush against and uniform rounding is the shape-correct choice, exactly as `Overview.qml`'s mode-indicator pill is fully rounded for the same reason.
  - Background: `Colours.surface` at `panelSurfaceOpacity` (0.78, reused by name from `PanelDialog.qml` — same translucency-over-blur treatment, same `Behavior on color` crossfade using `Motion.standardDuration`/`standardEasing`).
  - Rim: `GradientBorder`, `borderWidth: Design.borderWidth` (3), same stops/period as every other panel — reused component, zero new code.
  - Header: `popoutHeaderHeight` (48px, smaller than `PanelDialog`'s 72 — no Advanced button occupies this band, only the wayfinding link at the foot). Content: icon (`iconSizeMd`) + title (`fontHeading`/`weightEmphasis`/`Colours.onSurface`), left-aligned with `spacingMd` (16px) inset — same visual grammar as `PanelDialog`'s `headerIdentity` Row, tighter inset (`spacingMd` not `panelPadding`) matching the popout's smaller footprint.
  - Body: `popoutMinWidth`–`popoutMaxWidth` (300–360px), padded `spacingMd` (16px). Bounded content lays out directly; a section whose content is inherently unbounded even at glance scope (e.g. more nearby networks than fit) gets the identical `Flickable`/scroll-exempt treatment `PanelDialog.qml`'s D-15-07 already established, generalized to this frame.
  - Entrance/exit motion: entrance = `Motion.emphasizedInDuration`/`emphasizedInEasing` (matches every other panel-family surface's arrival grammar); dismiss = `Motion.emphasizedOutDuration`/`emphasizedOutEasing` (deliberately the faster of the pair — "quick to leave" is the established MD3 in/out asymmetry this codebase already encodes numerically, 300ms in vs 150ms out).
  - Namespace: `"quickshell-bar-<section>"` (e.g. `quickshell-bar-audio`), following the `WlrLayershell.namespace: "quickshell-" + suffix` convention (D-42/D-43) so the family-wide `^quickshell-.*` blur/`ignore_alpha` layer rules apply automatically with zero new Hyprland config — this is also the literal string GATE-03's structural checks and GATE-04's lint should look for when confirming this new frame is registered.
  - `exclusiveZone: 0` (a glance surface reserves nothing, matching `PanelDialog`'s own `exclusiveZone: 0`).
- **Anchoring per orientation** (the piece `PanelDialog`'s single fixed anchor never had to solve):
  - Horizontal bar: popout's top edge sits `spacingXs` (4px) below the bar's bottom edge, horizontally centred on the triggering capsule — clamped inward from the screen edge if the capsule sits near one (never let the popout run off-screen).
  - Vertical bar: popout expands **leftward** (D-18-11, matching the drawer-expansion direction already decided for this orientation) — its right edge sits `spacingXs` (4px) left of the bar's left edge, vertically centred on the triggering capsule, clamped the same way against the top/bottom screen edges.
- **Interaction**: hover-to-preview, click-to-pin (D-18-18), governed by the hover mechanics below.

## Popout Hover Mechanics (D-18-19..22)

| Rule | Contract |
|------|----------|
| Reveal/preview race | Hover-preview is suppressed until (a) the bar's reveal animation has fully settled AND (b) the pointer has moved at least once on the settled bar. Implemented as a boolean latch set on the reveal `Behavior`'s completion + the first `MouseArea.positionChanged` after it — not a timer guess. |
| Dwell before preview | `popoutDwellMs` (400ms, NEW token above) |
| Unpinned dismiss | Closes when the pointer has left BOTH the triggering capsule and the popout, held as one combined hover region, after `popoutDismissGraceMs` (200ms, NEW token) — long enough that a diagonal move from capsule into popout survives, short enough that leaving decisively closes promptly |
| Pinned behaviour | Ignores hover entirely once pinned (a click while previewing, or a click on an already-open preview, pins it); dismisses only on click-outside — identical mechanism to `PanelDialog`'s `HyprlandFocusGrab` + `dismissRequested()`, reused verbatim, plus the existing one-open-at-a-time invariant (opening/pinning a second popout dismisses the first through the same single guarded summon path `shell.qml`'s `openPanel()` already establishes for every other surface) |

## Auto-Hide & Reveal Motion Contract (QBAR-07/08)

- **State model** (D-18-23, replaces today's 3-state waybar model with a corrected 3-state model — the dim state is deleted, not merely renamed):
  - `visible` — bar rendered, `exclusiveZone` reserved (`barHeight + barEdgeMargin*2` = 52px horizontal, `barColumnWidth + barEdgeMargin*2` = 56px vertical — same edge-margin token doubled on both axes by construction, so the two orientations' reservation math stays symmetric).
  - `hidden-idle` — bar fully invisible (opacity 0 / off-canvas, never `IDLE_DIM_OPACITY`'s old 0.05 — that lit sliver is the exact thing QBAR-07 exists to kill), `exclusiveZone` **still reserved** (no window reflow while merely idle, preserving today's no-reflow-on-idle property per D-18-23).
  - `hidden-hard` — bar fully invisible, `exclusiveZone` **released** (windows reflow), driven by fullscreen, gaming mode, or the keybind.
- **Reveal**: an invisible input-only hot zone, `hotZoneDepth` (4px, NEW token), spanning the **full length of the physical screen edge** (full monitor width for horizontal/top, full monitor height for vertical/right) — not just the bar's own floating footprint — so the pointer can "slam to the edge without aiming" regardless of where along that edge it arrives (D-18-25's own stated goal, read literally). Present only while hidden (created/destroyed with the hidden state, never a polling timer — QBAR-11's zero-idle constraint).
- **Reveal motion**: bar slides in from off the hidden edge + fades, using `Motion.standardDuration`/`standardEasing` (this is a frequent, routine transition — MD3's "standard" pair, not "emphasized," is the correct register; "emphasized" is reserved for rarer, attention-getting moments like a popout's entrance).
- **Re-hide motion**: bar slides out + fades using `Motion.emphasizedOutDuration`/`emphasizedOutEasing` (the same fast-out grammar as popout dismissal — a consistent "quick to leave" feel across every dismissible surface in this shell).
- **Re-hide timing**: only after the reveal condition has ended (pointer left the hot zone AND bar / Super released) AND no popout is open AND `barReHideGraceMs` (600ms, NEW token) has elapsed with the condition still cleared — the bar must never vanish under the pointer mid-interaction (D-18-26).
- **Idle vs. fullscreen/gaming/keybind, visually**: identical to the user — both are a fully invisible bar. The only difference is `exclusiveZone`, which is not visible, it is felt only through whether other windows reflow. This document records that distinction exists so a future screenshot-based render-gate check does not mistake "no visible difference" for "the two states are the same."

## System Tray Rendering (QBAR-05)

- Always visible, no chevron, no threshold collapse (D-18-04) — the tray IS its own capsule, positioned last in the canonical group order.
- Capsule chrome: identical to every other capsule (`Colours.surfaceVariant` fill, `barCapsuleRadius` pill), holding a `Row`/`Column` (per orientation) of tray icon cells.
- Icon cell: `iconSizeMd` (24px) icon centred in a `spacingXs`-padded (4px each side, 32×32 total) hit target, `spacingXs` (4px) gap between cells — the same icon-cell geometry as every other section's icon, so the tray never reads as a visually distinct sub-widget.
- Empty tray (0 icons): the capsule collapses to zero width/height and disappears from the layout entirely — no "no tray icons" placeholder text on a glance surface this dense (this document's resolution of the empty-state consideration for the tray, see UI Considerations below).
- Menu (`Quickshell.DBusMenu`, QBAR-05): opens anchored using the identical per-orientation anchoring rule as a section popout (below the icon for horizontal, leftward for vertical), styled as a `Colours.surfaceVariant` rounded-rect (radius 12 — smaller than `popoutCornerRadius`, since this is a native menu list, not a custom popout, and should read as lighter chrome), rows in `fontBody`/`Colours.onSurfaceVariant`, hover row tinted `Colours.surface`.
- Broken/missing tray pixmap: render a Material Symbol `"apps"` placeholder glyph rather than a blank cell — never an empty hit target with no visual (this document's resolution of the tray's error-state consideration).

## Interaction States

Applies to every capsule and every popout-triggering element, unless a section overrides a specific cell above (tray, workspaces):

| State | Visual treatment |
|-------|-------------------|

## GATE-02 Render-Gate Criteria (checkable, per D-18-31/32)

GATE-02 requires the bar be judged "at least as good as the four layouts it replaced" — this section makes that decidable rather than a vibe check. Run per D-18-31: checkpoints during the phase (at minimum once per capsule group as it is built) **plus one blocking final pass** before `RETIRE-02`'s deletion commit. A criterion is only "passed" when confirmed live (clicked, scrolled, toggled, actually theme-switched) — "looks right in the source" never counts.

### A. Aesthetic judgment — against athena (D-18-32's first half)

1. Every capsule is a fully rounded, discrete pill with a visible gap to its neighbors — never one continuous bar (matches D-18-09, contradicts athena's own `"spacing": 0`, which this redesign deliberately supersedes).
2. The bar floats clear of the screen edge with a visible margin on every visible side — never edge-flush.
3. Workspace indicators show live per-app window icons in the `{icon} {windows}` shape — never dots, pills, or bare numbers.
4. Switching the live theme re-colors every bar element (capsule fills, active-state tints, the `GradientBorder` rim) within one crossfade, with zero literal-hex flash anywhere.
5. The bar reads as *denser* than end-4/Caelestia, not simplified toward them: both drawers (launcher + settings), the always-visible tray, and all four extras (power, gaming toggle, bell, updates+idle) are visibly present, not folded away or deferred — this is the explicit check against the standing instruction not to simplify toward the reference shells.

### B. Capability audit — against `config-full` / `config-floating` / `config-vertical` (D-18-32's second half)

1. Every readout the three retired layouts collectively exposed (clock, battery when present, network, bluetooth, audio, cpu/ram/disk) is present and live on the new bar.
2. Clicking a workspace switches to it (the capability dead under waybar 0.15.0's compiled-in dispatch — QBAR-03's whole reason for existing).
3. Scrolling on the audio section adjusts volume; scrolling on the brightness-bearing section adjusts brightness (parity with `config-floating`'s scroll bindings).
4. The horizontal↔vertical toggle (settings drawer + Super-menu, D-18-30) reaches the vertical orientation and every readout present in horizontal is still present, in the 44px stacked-text form, with no truncation.
5. Tray icons render and their menus open on click, in both orientations.
6. Nothing deliberately cut during athena's own 08-16 evolution (e.g. the old tray-folded settings sub-menu) is expected back — only a genuine `full`/`floating`/`vertical`-exclusive capability counts as a regression if missing.

**Pass bar**: all of A and all of B confirmed live. Any single failure blocks the deletion commit (`RETIRE-02`) until fixed and re-checked — per D-18-31's own cited precedent (this repo has shipped visibly broken surfaces through fully green automated gates three times already: Phase 6, Phase 8's bar, Phase 16's two false passes).
