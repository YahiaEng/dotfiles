<objective>
Close the two remaining carried warnings from 06-REVIEW.md, both in the theme engine's lib/.

**WR-03** is a latent `set -e` abort: `grep -c` **always prints a count** ("0") even when it exits 1 on zero matches, so `$(grep -c '^\[' file || echo 0)` captures `0` from grep AND `0` from the fallback, yielding the two-line string `0\n0`. The subsequent `[[ "$install_sections" -eq 1 ]]` then becomes an arithmetic syntax error (exit 2), and under theme-apply's `set -e` that aborts the reload fan-out mid-run — every step from Zen onward is skipped. The trigger is narrow (an installs.ini that exists but has no section headers), but the `|| echo 0` false-safety idiom is worth removing on sight.

**WR-06** is the same bug class this repo has now shipped and fixed **five separate times** (logs/, last-wallpaper/, current-theme, .last-render-error.log, icon-theme, font-choice — each documented at length in commit.sh's own comment block): `reload.sh` writes `$STATE_DIR/walker-relaunch.log`, a root-level engine-owned state file that is never part of the rendered tree, and it is missing from the rsync `--delete` exclusion list. So every theme commit destroys it. The impact is bounded (the same theme-apply run usually recreates it seconds later), but the previous run's diagnostics are lost on every switch even when the new run never reaches the walker step — and the failure notification points the user at a log a later switch may have just wiped. The file's own stated invariant ("engine-owned root-level files must survive --delete") is violated.

Purpose: clear the last two warnings blocking a clean phase-6 close.
Output: two hardened theme-engine lib files, with the reload fan-out and commit atomicity intact.
</objective>

  <action>
At line 119, `install_sections=$(grep -c '^\[' "$zen_root/installs.ini" 2>/dev/null || echo 0)` is broken because `grep -c` prints its count to stdout **and then exits 1** when the count is zero. Command substitution captures both grep's `0` and the fallback's `0`, so `$install_sections` becomes the two-line string `0\n0` — and `[[ "$install_sections" -eq 1 ]]` on the next line is then an arithmetic syntax error (exit 2), aborting the whole reload fan-out under `set -e`.

Replace it with the two-step form: capture `grep -c '^\[' "$zen_root/installs.ini" 2>/dev/null` on its own, move the failure tolerance **outside** the command substitution as a trailing `|| true` on the assignment statement, then default an empty capture to `0` with a parameter expansion. That keeps grep's real count when there is one, and yields a clean single-line `0` when there is not — never the concatenation of both.

Change nothing else in `theme_engine_reload_zen`: the `~/.zen`-absent early return (D-26 lazy self-heal), the installs.ini-then-profiles.ini fallback ordering (Pitfall 5), the `realpath -m` resolution, and the awk profile extraction are all correct.

  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `rendered_dir` (matugen output) -> `rsync -a --delete` -> `$STATE_DIR` | A destructive one-way sync into the live state directory. Anything in `$STATE_DIR` that is not in the rendered tree and not excluded is **deleted**. This is the single most destructive operation in the theme engine. |
| `~/.zen/installs.ini` / `profiles.ini` -> profile path -> symlink target | Browser-written config parsed by the engine, and the parsed value becomes a filesystem path. Untrusted-shaped input crossing into a path operation. |
