<objective>
Close the two UAT major gaps blocking the Print-key screenshot suite (SHOT-01/02/03):

1. **Keybinds never fire (Gap 1).** The Print family is rebound by keycode (`code:107`)
   so bind matching bypasses keysym translation. This deterministically fixes
   `bind = ALT, Print` (which can never match on the us XKB keymap — `<PRSC>` is
   type `PC_ALT_LEVEL2`, so Alt delivers keysym `Sys_Req`, not `Print`) and is
   robust against keyboards whose physical PrtSc does not emit the `Print` keysym.

2. **Capture scripts pass a broken flag (Gap 2).** All three capture scripts pipe
   `hyprshot ... -r` into satty, but hyprshot 1.3.0's getopt optstring declares
   `r:` (argument-required) while `--raw` is boolean — util-linux getopt errors,
   drops `-r`, and hyprshot silently proceeds in NON-raw mode: it saves the PNG
   itself to `~` and writes nothing to stdout, so satty gets empty stdin and
   prints 'Error: Unrecognized image file format' twice. Replacing `-r` with the
   verified-clean long form `--raw` engages raw mode: hyprshot streams the image
   to stdout and returns before its own save path, so satty owns the save to
   `~/Pictures/Screenshots`.

Purpose: Restore the Omarchy-style freeze→annotate→save+copy screenshot flow that
Phase 06 shipped but that never worked end-to-end on real hardware.
Output: Rebound keybinds.conf + three corrected capture scripts.

Root-cause evidence: `.planning/debug/print-keybinds-not-firing.md` (keycode/keysym),
`.planning/debug/screenshot-script-errors.md` (hyprshot getopt bug). Both diagnosed,
fixes pre-verified, no fix applied yet.
</objective>
