# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Domain note:** Not a web/component-library UI. This phase spans **eight distinct visual surfaces**, all driven by the same bash/matugen pipeline established in Phases 1–5:

1. **wlogout** — GTK CSS button bar (redesign, WLOG-01)
2. **hyprlock** — Hyprland's own lock-screen DSL, not CSS (redesign, LOCK-01)
3. **SwayOSD** — GTK CSS pill overlay (new surface, OSD-01)
4. **Zen browser chrome** — Firefox `userChrome.css` (new surface, THM-05)
5. **satty** — TOML-configured screenshot annotator (new surface, SHOT-02)
6. **fzf-in-kitty pickers** — icon-theme + font-switcher, replicating Phase 5's wallpaper-picker pattern (UTIL-04/05)
7. **walker `--dmenu` pickers** — record-audio picker, reusing Phase 5's exit-130-cancel pattern (SHOT-03/D-06)
8. **walker native item grid** — emoji picker via elephant-symbols, already themed by the existing `walker-style.css` contract target (UTIL-01, zero new CSS work)

Every surface below reuses the **same 19-key palette schema** locked in `05-UI-SPEC.md` (`primary, on_primary, primary_container, on_primary_container, secondary, on_secondary, secondary_container, on_secondary_container, tertiary, on_tertiary, tertiary_container, surface, on_surface, surface_variant, on_surface_variant, background, on_background, outline, error, on_error`) — **no new palette keys are introduced this phase.** Sections below are adapted per surface; where a template section doesn't apply (e.g. px typography for a DSL-based surface), it says so and gives the real equivalent.

## Spacing Scale

Real box-model CSS is involved this phase (unlike Phase 5's terminal-only picker), so a real px scale applies. The codebase's existing templates (`wlogout.css`, `swaync-colors.css`, `walker-style.css`) already establish a working-but-not-strictly-8pt scale — this phase's new surfaces reuse it verbatim rather than introducing a second convention.

**Base scale (use these for all new/changed elements this phase):**

| Token | Value | Established usage (verified in repo) |
|-------|-------|----------------------------------------|
| xs | 4px | `walker-style.css` `.item-quick-activation` padding; SwayOSD default `segment` margin-left |
| sm | 8px | `swaync-colors.css` `.box` padding; `walker-style.css` `.search-container` margin-bottom |
| md | 12px | `walker-style.css` `.item-box` padding-h; SwayOSD default progress track `min-height: 6px` rounds to this family |
| lg | 16px | `swaync-colors.css` `.box-wrapper` radius unit; SwayOSD default `#container` margin (verified against upstream `style.scss`) |
| xl | 20px | `wlogout.css` button `border-radius` (existing, unchanged) |
| 2xl | 24px | new: satty toolbar container radius, Zen active-tab radius |
| 3xl | 48px | new: wlogout bar-to-edge safe margin if repositioned |
| 4xl | 64px | new: SwayOSD anchor margin from screen edge (bottom-center, D-24) |

**Exception (pre-existing, do not touch):** `10px` appears in `wlogout.css` (button margin/padding) and predates this phase's scale cleanup. It is out of scope to normalize — new elements added *within* the existing wlogout button rule may keep `10px` for consistency with the rule they extend; genuinely new standalone elements (new labels, new SwayOSD/Zen/satty rules) use the base scale above.

## Color

### 1. Palette schema — unchanged

Reuses the exact 19-key schema from `05-UI-SPEC.md` verbatim across every surface in this phase. No new keys. Verified against the live `theme-engine/.config/theme-engine/palettes/*.json` files (e.g. `rosepine.json`, `matte-black.json`, `catppuccin.json`) — all 19 keys present, no drift.

### 2. Per-surface 60/30/10 mapping

Each surface below is its own local dominant/secondary/accent instance of the shared palette — this is the same pattern Phase 5 used for the fzf picker (`05-UI-SPEC.md` §3), extended to five more surfaces.

**wlogout bar:**
| Role | Palette key | Usage |
|---|---|---|
| Dominant (60%) | `background` (scrim `rgba(0,0,0,0.6)`, unchanged literal) + `on_surface` | Full-screen dim overlay, unselected button text |
| Secondary (30%) | `surface` / `outline` | Button fill, button border |
| Accent (10%) | `primary` | **Reserved for:** hovered/focused button background + label reveal only. Per-action border-hue accents (`secondary` for logout, `tertiary` for suspend/reboot, `error` for shutdown) are preserved unchanged from the existing `style.css` — this is the one surface where multiple accent hues are intentional (each action has always had a distinct accent border; D-10 does not change this, only swaps icon rendering) |

**hyprlock:**
| Role | Palette key | Usage |
|---|---|---|
| Dominant (60%) | blurred wallpaper (`$image`, unchanged D-13) + `on_surface` | Background, date/battery/now-playing text |
| Secondary (30%) | `surface` / `secondary` | Input-field inner fill, greeting text |
| Accent (10%) | `primary` | **Reserved for:** time label, input outline, avatar border/fill. `tertiary` stays reserved for `check_color` (existing), `error` stays reserved for `fail_color`/failed-attempts counter (existing + new counter) — do not repurpose either for the new avatar/battery/now-playing elements |

**SwayOSD:**
| Role | Palette key | Usage |
|---|---|---|
| Dominant (60%) | `background` (`alpha(background, 0.85)`) | Pill fill |
| Secondary (30%) | `surface_variant` (`alpha(surface_variant, 0.6)`) | Progress track (`trough`/`segment`) |
| Accent (10%) | `primary` | **Reserved for:** progress fill (`progress`/`segment.active`) only. Icon + label text use `on_background`, not an accent color |

**Zen chrome (D-27):**
| Role | Palette key | Usage |
|---|---|---|
| Dominant (60%) | `surface` | Toolbar (`#nav-bar`, `#TabsToolbar`) and sidebar (`#sidebar-box`) background |
| Secondary (30%) | `surface_variant` / `on_surface_variant` | URL bar background, inactive-tab text |
| Accent (10%) | `primary` | **Reserved for:** active-tab background (`primary_container`/`on_primary_container` pair) and URL-bar focus border only. Never applied to bookmark bar icons or menu chrome (out of D-27's scope) |

**satty:**
| Role | Palette key | Usage |
|---|---|---|
| Dominant (60%) | `surface` | Toolbar background |
| Secondary (30%) | `on_surface` | Toolbar icon color |
| Accent (10%) | `primary` | **Reserved for:** selected-tool highlight only |

**Annotation color palette (D-31 — second documented literal-hex exemption, after Phase 5's fzf `bg:-1`):** `satty`'s `[color-palette].palette` array (format `RRGGBBAA`) is a curated 7-swatch row, default selection = `primary`:

```toml
[color-palette]
palette = [
  "{{primary}}ff",     # default selection
  "{{secondary}}ff",
  "{{tertiary}}ff",
  "{{on_surface}}ff",  # light mark (readable on dark screenshots)
  "{{background}}ff",  # dark mark (readable on light screenshots)
  "E53935ff",          # literal true red — exempted per D-31 ("standard palette row incl. a true red"); themes like hackerman/vantablack have no red hue in `error` (Phase 5 D-precedent), so a real red must exist as a fixed literal here
  "{{outline}}ff",
]
```

The `E53935ff` literal is the **only** hex allowed to bypass the zero-literal-hex rule in this file — every other slot is a rendered palette key, matching the project's established exemption discipline (fzf's `bg:-1`, this file's true-red).

## Copywriting Contract

Notification convention (established, reused verbatim): `notify-send -a "<App Label>" "<Title>" "<Body>" -i <freedesktop-icon-name> -t <ms>`. Verified existing icon names: `camera-photo`, `dialog-error`, `preferences-desktop-wallpaper`, `preferences-desktop-display`. Standard timeout: 2000–3000ms; error timeout: 6000ms (matches `reload.sh`'s existing walker-relaunch-failure notification).

| Element | Copy |
|---------|------|
| Screenshot captured (satty owns save+copy+notify, D-02) | `notify-send -a "Screenshot" "Screenshot Captured" "Saved to {path}\nCopied to clipboard" -i camera-photo -t 3000` — **identical wording/icon/timeout to the pre-existing `screenshot.sh` notification** so the surface swap (bare script → hyprshot→satty) is invisible to the user experience |
| Recording started (D-07) | `notify-send -a "Screen Recorder" "Recording Started" "Press Alt+Print to stop" -i media-record -t 2500` |
| Recording saved (D-04, with actions) | `notify-send -a "Screen Recorder" "Recording Saved" "Saved to {path}" -i media-record -t 3000` + notification actions `Open` / `Export GIF` |
| GIF exported (D-04) | `notify-send -a "Screen Recorder" "GIF Exported" "Saved to {path}" -i image-gif -t 3000` |
| Record-audio picker header (D-06, walker `--dmenu`) | `Select Recording Audio` |
| Record-audio picker options (D-06, exact order) | `🔇 Silent (no audio)` / `🔊 Desktop Audio` / `🎙️ Desktop + Mic` |
| Record-audio picker cancel (Esc, exit 130) | Silent abort, no notification — reuses Phase 5's exit-130-cancel pattern (`theme-switch.sh`) verbatim |
| Record-audio picker hard failure (nonzero, not 130) | `notify-send -a "Screen Recorder" "Error" "walker dmenu failed" -i dialog-error` — **reuses the exact existing string** already shipped twice (`theme-switch.sh`, `waybar-switch.sh`) for consistency |
| Color picked (D-22) | `notify-send -a "Color Picker" "Color Copied" "{HEX} copied to clipboard" -i color-picker -t 2500` — include a swatch image hint if the notification daemon (swaync) supports it; degrade gracefully to text-only hex if not (no hard dependency on image-hint support) |
| Emoji copied/typed (D-21) | `notify-send -a "Emoji Picker" "Emoji Inserted" "{emoji} typed and copied to clipboard" -i face-smile -t 2000` — fires only as a backup confirmation since typing is the primary feedback channel |
| Clipboard manual wipe entry (D-15, picker row) | `🗑  Wipe Clipboard History` |
| Clipboard manual wipe confirmation (destructive, D-15) | Prompt copy: `"This clears all {N} saved clipboard entries. This cannot be undone."` — Yes/No via walker `--dmenu`, **default focus = No** (destructive-safe default, never pre-select the destructive option) |
| Clipboard wipe completed | `notify-send -a "Clipboard" "History Wiped" "All entries cleared" -i edit-clear -t 2000` |
| Clipboard session-end wipe (D-15, automatic) | Silent — no notification (session is ending, nothing to show the user) |
| Icon theme applied (UTIL-04) | `notify-send -a "Icon Theme" "Icon Theme Changed" "Applied {ThemeName}" -i preferences-desktop-icons -t 2000` |
| Icon-theme picker empty state (no extra themes beyond Adwaita) | Heading: `No extra icon themes installed` / Body: `Run install.sh to add Papirus, Tela, or Colloid.` |
| Font switched (UTIL-05) | `notify-send -a "Font Switcher" "Font Changed" "Applied {FontName} — restart apps to see the full effect" -i preferences-desktop-font -t 2500` — worded generically since some surfaces (kitty) live-reload and others (vscodium) require a restart; never overpromise instant effect everywhere |
| Font picker empty/defensive state | `No nerd fonts detected — reinstall via install.sh` (should not occur given D-18's bundled 7-font floor; defensive copy only) |
| Zen theme rendered, browser running (D-28, notify-only) | `notify-send -a "Zen Browser" "Theme Updated" "Restart Zen to apply the new theme" -i web-browser -t 3000` — **never kill the browser process**, matches the accepted GTK3 stale-until-closed posture |
| Zen profile not yet resolvable (D-26, lazy self-heal skip) | **Silent** — logged non-fatally, no user-facing notification (avoids a false-alarm toast on every `theme-apply` before Zen has ever been launched) |
| SwayOSD feedback | n/a — the OSD pill itself *is* the feedback; no separate `notify-send` call |
| wlogout action execution | Unchanged — actions fire immediately on click/keybind (no new confirmation dialogs added; six actions already Phase-4-audited against uwsm) |
| Error state (general) | Reuse the existing sanitized-truncation pattern (`head -c 200 \| tr -d ...` before `notify-send`) already proven in `theme-apply` — no new unsanitized error surface introduced by any Phase 6 script |
