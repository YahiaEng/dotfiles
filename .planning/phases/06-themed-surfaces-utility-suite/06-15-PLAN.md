<objective>
Close the UAT minor gap where recorded videos are undecodable on a fresh install
(SHOT-03). Arch's vlc 3.0.23_2 packaging split codec plugins out of the base `vlc`
package into `vlc-plugins-*` packages, so a fresh machine has no player able to
decode gpu-screen-recorder output — the user had to install `vlc-plugins-all`
manually. install.sh currently has no vlc entry at all.

This plan adds the missing packages to `install.sh`'s `PACMAN_PKGS` array
(reproducibility constraint — everything must install from a fresh Arch system via
install.sh + stow, no manual host-only state):

1. **vlc + vlc-plugins-all** (official `extra` repo) — playback + all decode codecs
   for gpu-screen-recorder recordings.
2. **xdg-user-dirs** (official `core` repo) — optional hardening: guarantees
   `~/Pictures` exists and `xdg-user-dir PICTURES` / `XDG_PICTURES_DIR` resolve on a
   fresh system. (Not strictly required for the capture save path once 06-14's
   `--raw` fix lands — satty then saves via an explicit `--output-filename` — but
   it removes the fragile `${XDG_PICTURES_DIR:=~}` fallback that misdirected saves
   to `~` during the original UAT.)

Purpose: Fresh-install reproducibility for the recording half of the screenshot suite.
Output: Updated install.sh package list.
</objective>
