### Two findings from the planning read that RESEARCH.md does not contain

Both were read directly out of the installed type files this session. They sharpen tasks 1 and are the reason A3 and A6 are separate questions:

- **`UntypedObjectModel` (`/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes`, component at line 1602) exposes a readonly `values` property of type `QObjectList` with a `valuesChanged` notify signal, four insert/remove signals, an `indexOf(object)` method, and a `QAbstractListModel` prototype.** It has no `count` property and no `get(index)` method. 15-RESEARCH.md Pattern 2's example code and 15-PATTERNS.md's backend snippet both reach for `.count` / `.get(i)` — the type file says that shape does not exist. The probe must confirm the real one live and the artifact must correct both documents.
- **`PwObjectTracker` exists** (`Quickshell.Services.Pipewire/PwObjectTracker`, component at line 622 of `quickshell-service-pipewire.qmltypes`) with a read/write `objects` property of type `QObjectList`. RESEARCH.md never mentions it. If node data only binds while a node is tracked, then every mixer row, every device picker and the master volume slider read empty without one — a silent, total failure of the audio panel. This is question **A6** and it gates A1 being answerable at all.
