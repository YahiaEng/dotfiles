<objective>
Point the bar at the panels. Three manager clicks that today launch a GTK app —
one of them into a tray that the primary layout deliberately deleted — become
calls into the shell root's IPC handler, and `install.sh` finally declares the
package the wifi panel's Advanced button depends on.

This is small in diff and load-bearing in effect. It is the plan that makes the
phase's panels reachable the way a person actually reaches them: not by learning
a new chord, but by clicking the same network, bluetooth and volume pills they
already click. `Super+A` reaches audio only (D-15-04); every other entry point in
this phase arrives through the seam 15-03 built, and this plan is the first
consumer of it.

Two things here are corrections, not features. Athena's `network` left-click has
been dead since the layout's own comment at lines 34-38 removed `tray` from
`modules-right` — the applet it launches has nowhere to draw. And it is dead
twice over on a fresh machine, because the package that provides that applet was
never in `install.sh`; every one of the three GUI managers this phase hands off
to is supposed to be declared, two are, and the third has been host-only state —
the same failure class this project's own CLAUDE.md documents for the missing GTK
theme package (D-15-23).

Nothing is retired. The three managers move exactly one level deeper, behind each
panel's Advanced button, which is where PANEL-05 puts them anyway. The accepted
cost is that bar clicks now depend on the Quickshell process being alive — bounded,
because it autostarts and `quickshell-doctor`'s second check asserts it.

Purpose: PANEL-03 and PANEL-04 become reachable from the bar on every layout;
PANEL-05's wifi third stops being conditional on host state.
Output: ten rewired click keys across four waybar config files, one new
`PACMAN_PKGS` entry, a bounded before/after delta proof, and a human check across
the layouts whose click behaviour cannot be proven from source.
</objective>

## Deviations from the outline — surfaced, not silent

The outline's per-plan note for 15-08 names three rewirings and one package. Two
things below go beyond its literal text. Both are recorded here so a reader
comparing this plan against the outline sees a decision, not drift, and both are
put in front of the operator at Task 3 so either can be reversed in one line.

1. **Athena's `network` right-click is removed, not left in place.** The outline
   names which clicks to rewire and which two verbs to preserve; it is silent on
   this one. It is the other half of the exact mechanism being replaced: today's
   pair is "launch the applet" on the left and "kill the applet" on the right.
   Once the left click no longer launches it, the right click kills a process
   nothing in this repo starts. Leaving it would mean this plan *creates* a fresh
   dead click on the primary layout in the same edit that removes an old one,
   which inverts its own purpose. It is removed rather than repurposed —
   inventing a new binding is not D-15-05's scope.

2. **`config-full.jsonc` is reached, though the outline names four files.** The
   outline's four files are exactly right and this is not a fifth edit: `full` is
   a real, switchable layout (`waybar-switch.sh` discovers layouts by globbing
   `config-*.jsonc`, and `full` has its own compiled stylesheet), and it
   redefines neither the network nor the audio module. The `modules.jsonc` edit
   *is* how it gets rewired. Stated because the resolved-delta proof asserts a
   change in four resolved configs, not three, and that must not read as an
   unplanned file.
