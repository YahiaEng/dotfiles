<objective>
Close gap **G-15-2**: clicking Enable on the bluetooth panel does nothing.

AND-gate, both conditions required and both proven live:

1. **Environment.** The host's adapter (`hci0`, `60:E9:AA:20:44:B0`) is rfkill
   **soft-blocked**, so Quickshell's `BluetoothAdapter` binding refuses the `enabled = true`
   write outright and never reaches D-Bus. The running shell's own log carries six
   consecutive `Cannot enable adapter because it is blocked by rfkill.` lines
   (`~/.cache/quickshell.log:1650-1656`) matching the user's repeated clicks — visible only
   on stderr.
2. **Code.** `BluetoothBackend.qml` exposes only `adapterPresent`/`adapterEnabled` and never
   reads `adapter.state`, so `BluetoothAdapterState.Blocked` is not representable in QML at
   all (`grep` for it across `quickshell/` returns zero hits). `BluetoothPanel.qml` therefore
   has two branches where `WifiPanel.qml` has three, falls through to the *fixable*
   `adapterOffBranch`, and renders an Enable button that provably cannot work — violating
   the principle quoted in its own source at :273-275, *"never offer a control that cannot
   work."*

The user's stated guess — missing packages — is **disproven**, and that changes the copy.
`bluez 5.87-2`, `bluez-utils 5.87-2` and `blueman 2.4.6-2` are all installed, `bluetoothd`
has been up over a day, and a real controller is enumerated. The missing prerequisite is an
**unblocked radio**. The block is soft (user-recoverable), not a hardware killswitch, and it
is **persistent** — `systemd-rfkill` has saved value 1 for this device, so it survives
reboots and the panel will show an inert Enable on every boot until either the block is
cleared or the panel learns about it.

The panel cannot clear it itself: Prohibition P1 forbids shelling out, and the binding
refuses the write. **Disabled-with-reason is the only correct affordance — which is exactly
what the user asked for.**

Purpose: stop offering a control that cannot work, and say why in a way the user can act on.

Output: a third branch in the bluetooth panel, the blocked-state copy as locked contract, a
corrected verification record, and an honest open item for the half of UAT test 2 that this
fix unblocks but does not itself verify.
</objective>
