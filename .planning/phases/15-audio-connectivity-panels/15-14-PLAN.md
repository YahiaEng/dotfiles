<objective>
Close gap **G-15-4b**: there is no way to join a hidden network (one whose SSID broadcast is
turned off) from the wifi panel. Additive scope — not a regression against anything phase 15
promised, and the user confirmed during UAT that it should ship in this round.

**The non-obvious cost driver, measured not assumed:** this is NOT a UI-only addition.
`Quickshell.Networking` structurally cannot express a hidden network. Every connect verb is
an instance method on a `Network` object, and Quickshell filters blank-SSID access points out
of `wifiDevice.networks` entirely — so a hidden access point yields no receiver object to
call anything on. Measured at the same moment on this host: `nmcli` sees **5 hidden access
points, the strongest on the band**, while a quickshell probe reports total networks = 8 with
a blank-SSID count of **0**. `grep -i hidden` over the installed networking qmltypes returns
zero hits. `NMSettings` is not a registered QML type and cannot be constructed, and
`connectWithSettings` is still an instance method needing a receiver that does not exist.

A subprocess is therefore unavoidable — a first for this surface's networking path.

Purpose: reach the networks this host literally cannot see, without giving up the panel's
native connect path or its passphrase discipline.

Output: a hidden-network entry point that resolves a typed SSID into a real network object
and then gets out of the way.
</objective>

<user_decision_binding>
**D-15-4b-ROUTE-B (user-chosen, 2026-08-02, recorded in `15-UAT.md` as `user_decision` on
gap G-15-4b).** Route B is primary; Route A is a specified, documented fallback.

**Route B:** a directed rescan for one SSID is a probe that carries **no secret**. If the
access point answers, it materialises as a real `Network` object and the ENTIRE existing flow
works unchanged — expanded row, password row, `startConnect`, pending pulse, Cancel,
`connectFailed` row-scoped copy, Forget. Route B keeps the native passphrase call as the
single connect call site, keeps Prohibition P3 fully intact (the passphrase never leaves the
QML process), and reuses the existing failure-reason mapping.

**Route B also requires the profile follow-up.** A profile created from a revealed access
point defaults to hidden:no — verified live on this host's own saved profile — and would fail
autoconnect on a later boot because a passive scan will not find the network. The follow-up
is secret-free and REQUIRED, not optional.

**Route B cannot be proven up front** because no hidden SSID on this host is known — that is
the nature of hidden. Some access points are configured not to answer directed probes. The
plan therefore carries an explicit verification step against a real hidden access point, and
specifies Route A as the fallback if the probe goes unanswered.

**Route A (documented, NOT implemented unless Route B fails verification):** the single
combined connect verb with a hidden flag. It duplicates the connect verb, needs a new error
mapping because the CLI returns exit codes and stderr rather than the enum the panel maps,
and — the reason it is second choice — it puts the passphrase on argv, world-readable via
`/proc/<pid>/cmdline`, violating P3. Mitigable only by routing the secret through the
process's stdin with the CLI's interactive-ask flag so it never reaches argv at all. If Route
A is ever taken, that mitigation is mandatory, not optional.
</user_decision_binding>

<sequencing_and_risk>
This plan runs AFTER 15-13 and depends on it, because the hidden flow terminates in a
NetworkManager activation on both routes and therefore inherits the identical
wrong-password behaviour. The risk here is structurally **higher** than the ordinary case:
the user types SSID *and* passphrase from memory, and a wrong SSID on a hidden network is
indistinguishable from an out-of-range access point. Route A does not dodge this either.

Concretely, that means the not-found copy must be honest about the ambiguity rather than
asserting a cause it cannot know.
</sequencing_and_risk>

<prohibition_p1_exception>
Prohibition P1 states: *no panel may reach a CLI wrapper for any read or write that a native
`Quickshell.Networking` / `Quickshell.Bluetooth` / `Quickshell.Services.Pipewire` member
**already exposes***.

A directed probe for a non-broadcast SSID is not such a read. It was measured, not assumed:
the module exposes no hidden concept at all, filters blank-SSID access points out of the
model entirely, and offers no constructible settings type. There is nothing native to reach
for. **This is P1's documented exception, not a P1 violation** — and the executor must record
it as such in the file header, citing the measurement, or the next reader (or gate) reads it
as a breach.

Two fences keep the exception narrow and both are asserted mechanically:
- **Housing.** The subprocess lives in `WifiPanel.qml`, never in `WifiBackend.qml`. That file
  is deliberately subprocess-free — its own header says so, and a prior task gate asserts it
  contains zero `Process`. `WifiPanel.qml` already houses one subprocess for a documented
  reason (a generic host-binary probe, explicitly reasoned as "not a networking read"), so
  this is the second, and it must carry an equally explicit reason.
- **Surface.** The exception covers exactly two invocations: the directed probe and the
  profile follow-up. Neither carries a secret. Every other verb in the flow stays native.
</prohibition_p1_exception>

<state_constraint>
**Do NOT reuse `expandedNetwork` or any of the object-keyed properties for the hidden entry.**
Every pending, expanded, failed and confirm-forget property on this panel is keyed by the
network OBJECT, deliberately, per the file's own note at :95-99 (T-15-08) — two rows can
legitimately share an SSID and neither may act on the other. `handleRowPress`, `isExpanded`,
`collapseExpandedRow` and the no-secrets recovery all compare object identity. A hidden entry
has no object until the probe answers, so it cannot slot into any of them.

The hidden state is therefore PARALLEL and separately keyed. The typed SSID string is used
**exactly once** — to locate a real object by name the moment one appears — and from that
instant every subsequent piece of state is the object, so T-15-08 holds unbroken.
</state_constraint>

field does not hold focus — exactly the split the password row already documents.

**Cancel.** While a probe is in flight the search verb is replaced by a Cancel, reusing the
existing Cancel's shape. Pressing it clears the hidden pending state and stops the probe
watchdog. It does not need to kill the subprocess — a directed rescan is a fire-and-forget
probe with no side effect worth aborting — but say so explicitly in a comment rather than
leaving the omission to be read as a bug.

**Form close discipline.** Closing the form clears the SSID, the pending flag and the failure
copy together, so reopening never shows the previous attempt's residue. Opening the form
clears any expanded row, mirroring how pressing Forget already clears the expanded row: two
expansions of the same list must not be open at once.

**Panel dismiss.** All hidden state clears when the panel closes, so a dismissed panel leaves
nothing stranded for the next open — the same discipline 15-11's rescan edge follows.
