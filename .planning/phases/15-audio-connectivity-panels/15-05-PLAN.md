<objective>
Fill the empty body slot 15-03 left in the wifi panel with the whole of PANEL-03:
a scan with a visible in-progress state, a grouped and stable list of visible
networks, connection to an open network, and an inline password prompt that
accepts a passphrase on a secured one.

Four things make this more than list-rendering.

**The passphrase never touches a command line.** `connectWithPsk` is the only
accepted call path (D-15-14). Neither file this plan writes declares a subprocess
of any kind, so there is no command array anywhere in this plan that could carry a
secret — and Prohibition P3 closes the other half, keeping the PSK out of any
property that survives the row, out of the failure text, and out of the log. This
is the phase's gating threat (`T-15-01`, information disclosure, high) at the
configured blocking threshold, and it is mitigated structurally rather than by
discipline.

**Ordering is stable by construction, not by tuning.** Grouping is current →
saved → rest (D-15-16) and signal strength renders per row but never sorts. The
failure this prevents is concrete: a rescan lands, two rows swap, and the wrong
network is connected. Achieving it needs a first-seen ordering registry, because
the underlying model's own order is NetworkManager's to change.

**In-flight gets a real Cancel, not a spinner alone.** UI-SPEC E4's `loading` row
is new locked contract: the acted-on row shows the repo's existing pending
treatment *plus* a working abort, matching bluetooth's pairing grammar (D-15-19)
so both connectivity panels read identically. The UI-SPEC's own planner note is
carried forward honestly — this needs a NetworkManager deactivate path the panel
would not otherwise touch, and that path is inferred from the type information
rather than documented, so this plan measures it before it ships a button.

**Forget ships even though criterion 2 does not list it** (D-15-17). NetworkManager
persists a profile even after a wrong-passphrase attempt and later connects
silently reuse the bad PSK, so without `forget` one typo routes the user straight
back to nm-connection-editor — the app this phase exists to displace — triggered by
the most common possible error. It gets destructive treatment: separated placement,
`Colours.error` tone, and an inline confirm that names the network (P4).

Purpose: close PANEL-03 and ROADMAP criterion 2 in full.
Output: a `WifiBackend.qml` that owns the scan lifecycle, the grouped collections
and the four verbs, and a `WifiPanel.qml` whose body is the real network list with
its password, in-flight, failure and forget flows.
</objective>

## Binding correction — `15-PATTERNS.md` Pattern 4's snippet must NOT be copied literally

`15-PATTERNS.md` (Pattern 4, around line 318) shows the failure handler as:

> `row.failureText = ConnectionFailReason.toString(reason);  // built-in enum->string method, verified present`

The method is genuinely present — the qmltypes exports `ConnectionFailReason` as a
singleton with a `toString(reason)` method — but using it as the on-screen failure
text is **wrong for this phase** and must not be followed. It would render the raw
enum identifier to the user, which is exactly the jargon the Copywriting Contract
was written to prevent, and it would silently override five locked strings.

**Resolution, binding on this plan:** the row's failure text comes from one
five-branch mapping function in `WifiBackend.qml` that returns the UI-SPEC's locked
copy verbatim. The enum's own stringifier may be used for a diagnostic record in the
SUMMARY, never for a rendered string, and the acceptance criteria negative-grep the
mapping region for it.

| Boundary | Description |
|----------|-------------|
| Human keyboard → the panel's masked field | A wifi passphrase — the only secret this phase handles — crosses into the shell process and becomes a live value in a QML control |
