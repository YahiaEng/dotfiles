<binding_corrections>
## The DASH-08 guard is not bypassed by the tile path (outline Flagged Assumption 2)

`15-PATTERNS.md` (its `shell.qml` section, around line 199) says the panels' summon copies
`dashboardShortcut` "minus the fullscreen-refusal guard, which does not apply to panels".
**That is wrong and must not be followed.** REQUIREMENTS DASH-08 reads "Dashboard **and
panels** refuse to open over a fullscreen client", and ROADMAP Phase 14 criterion 5 reads
"neither the dashboard nor any panel opens over a fullscreen client."

**Binding on this plan:** the guard lives inside the single shell-root summon function
15-02 wrote, and this plan's chevron path is one more caller of it — not a second summon
site. Concretely: `QuickToggles.qml` emits, `DashboardTab.qml` relays, `Dashboard.qml`
relays, and `shell.qml`'s handler calls that one function. **No file in the relay chain may
read the fullscreen guard property, resolve a loader, or assign a loader's `active`
property.** If the relay were to do any of those it would become a second summon path and
the guard would exist twice, which is precisely the failure the resolution exists to
prevent.

14-01's live finding applies unchanged: the guard blocks both maximize and true fullscreen,
because Hyprland 0.56.1 exposes no IPC signal anywhere that distinguishes the two states
(proven three independent ways in 14-01; see `shell.qml`'s own header comment, which this
plan leaves byte-unchanged).

## The tile vocabulary and the panel vocabulary are different, and must be mapped

D-26's naming convention names a tile for **the state that lights it**, so the audio tile is
`volume` (lit when unmuted). The panel it opens is `audio` — that is the name 15-02's
dispatch resolves, the name 15-03's `IpcHandler` verbs take, and the string inside the
`quickshell-audio-panel` namespace. Passing `"volume"` to the shell-root summon would hit
the unknown-name branch, which 15-02 and 15-03 both specify as a **silent no-op** — so the
chevron would do nothing at all with no error anywhere. Carry the panel name as its own
model field; do not derive it from the tile name.

## Same-name property shadowing is a live-reproduced bug in this repo, not a style note

`Dashboard.qml` lines 400-412 record it in full: `DashboardTab` and `PerformanceTab` each
declare their own `property var systemResources`, and a binding written
`systemResources: systemResources` resolves its right-hand side to **that tab's own
not-yet-assigned property** under QML's innermost-scope-wins lookup, producing a silent
self-referencing no-op. It was live-reproduced once already — `PerformanceTab`'s `hasReader`
read `false` forever until fixed. This plan threads three more same-named properties down
the same chain, so **every** right-hand side must be fully qualified: `dashboardWindow.` in
`Dashboard.qml` and `root.` in `DashboardTab.qml`, never a bare name.
</binding_corrections>
