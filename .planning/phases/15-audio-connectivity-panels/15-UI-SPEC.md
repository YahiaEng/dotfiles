# Phase 15 — UI Design Contract

> Visual and interaction contract for the shared `PanelDialog` component and its three
> instances (Audio, Wifi, Bluetooth). Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Every token below is pulled from this repo's own live QML singletons
> (`Design.qml`, `Colours.qml`, `Motion.qml`) rather than invented — this phase's job is to
> **reuse** Phase 14's contract, not create a second one. Deviations from strict reuse are
> called out explicitly with their reason.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is a Quickshell/QML desktop shell, not a web/npm stack. The shadcn initialization gate is not applicable; there is no `components.json`/React/Next/Vite target in this repo. |
| Preset | not applicable |
| Component library | none — `QtQuick.Controls` (Basic style) is imported for structural primitives (`TabBar`/`SwipeView` precedent in `Dashboard.qml`) but every visual property is overridden from the `Colours`/`Motion`/`Design` singletons; `QtQuick.Controls.Material` is deliberately never imported (Dashboard.qml's own header comment: "this drawer's whole premise is that `Colours.qml` is the only colour source"). `QtQuick.Controls.Popup` is explicitly banned for this phase (D-15-12, D-15-19 — unverified inside a Wayland layer-shell surface on this Qt/quickshell build; use the inline expanding-row idiom instead). |
| Icon library | Material Symbols Rounded — variable font, FILL axis confirmed live-renderable on this build (Phase 14 D-28/A3, `qml6 grabToImage` verified). Reference: `quickshell/.config/quickshell/modules/dashboard/Design.qml:87` `symbolFontFamily`. |
| Font | No custom body/label font family is set anywhere in the repo-authored QML — every text element (outside the Material Symbols icon font) falls through to `Qt.application.font.family`, the platform Qt default (confirmed convention: `Dial.qml:55`'s `_defaultFontFamily: Qt.application.font.family` capability read, and no `font.family:` override exists in any dashboard/*.qml sibling file). Panels inherit this — do not introduce a font-family literal. |

**Source of truth for every token below:**
- `quickshell/.config/quickshell/modules/dashboard/Design.qml` — spacing, icon size, typography, tooltip delay
- `quickshell/.config/quickshell/modules/Colours.qml` — the 19-key Material You palette (all roles below are live aliases, never hex literals)
- `quickshell/.config/quickshell/modules/Motion.qml` — duration/easing pairs (`standard`, `emphasized-in`, `emphasized-out`, `stagger-offset`, `border-rotate`)
- `quickshell/.config/quickshell/modules/Dashboard.qml:224` — `cornerRadius: 28`, bottom corners only
- `quickshell/.config/quickshell/modules/Dashboard.qml:101` — `drawerMinWidth: 760`

**INVARIANT (repo-wide, `motion-lint`-enforced):** zero hex literals and zero raw duration/easing literals in any repo-authored QML. Every colour is `Colours.<role>`; every duration/easing is `Motion.<pairName>Duration`/`Motion.<pairName>Easing`. This applies to all new panel QML without exception.

## Spacing Scale

Declared values (multiples of 4, reused verbatim from `Design.qml` — do not declare a second spacing scale):

| Token | Value | Usage |
|-------|-------|-------|
| `Design.spacingXs` | 4px | Icon-to-label gaps inside a row (mute icon ↔ app name), split-affordance chevron inset |
| `Design.spacingSm` | 8px | Compact element spacing — between stacked rows in a list, between a tile's icon and its label |
| `Design.spacingMd` | 16px | Default element spacing — between the header band and the pinned control block, between sibling controls in the pinned block |
| `Design.spacingLg` | 24px | Section padding — used to derive `drawerWidth` margins in Dashboard.qml; reuse for the panel's outer content-column padding if D-15-03's centered-column discretion is exercised |
| `Design.spacingXl` | 32px | Layout gaps — reserve for major panel-internal separations only (e.g. between the pinned audio block and the scrolling app list, if a visual break is wanted beyond a plain divider) |
| `Design.panelPadding` | 24px | The header band's own internal padding (icon+title left, Advanced button right) — same constant Dashboard.qml's header uses, so the panel's header reads as the same object as the drawer's, just shorter-lived |

**Panel-specific token (new, this phase):**

| Token | Value | Usage |
|-------|-------|-------|
| `chipHeight` (reused from `QuickToggles.qml:94`) | 72px | The six-across quick-toggle tile row height (D-15-21) — "Do Not Disturb" wraps to two lines inside this height without regressing to "DND" (hard constraint, verify at render gate against the installed font) |

Exceptions: none. If the render gate finds the pinned audio block (D-15-10) too dense at these values, the pre-agreed fallback (D-15-11) is to drop the input-level slider — not to introduce a new spacing value.

## Typography

Reused verbatim from `Design.qml` — no new sizes or weights for this phase. Line-height ratios are new (Design.qml declares no line-height tokens; QML `Text` defaults to a 1.0 line-height multiplier) — the values below follow this template's standard recommendation and should be applied as explicit `lineHeight`/`lineHeightMode: Text.ProportionalHeight` on any multi-line text this phase introduces (network SSID + reason line, empty/off-state body copy).

| Role | Size | Weight | Line Height | Where used this phase |
|------|------|--------|-------------|------------------------|
| Heading | `Design.fontHeading` = 20px | `Design.weightEmphasis` (DemiBold) | 1.2 | Panel header title ("Audio" / "Wi-Fi" / "Bluetooth") |
| Body | `Design.fontBody` = 16px | `Design.weightBody` (Normal) | 1.5 | Per-app row app name, network SSID, device name, empty/off-state body line, "Advanced" button label |
| Label | `Design.fontLabel` = 12px | `Design.weightBody` (Normal) | 1.4 | Row-scoped failure reason text (D-15-09), battery/address detail line in an expanded bluetooth row, tooltip copy |
| Display | `Design.fontDisplay` = 32px | `Design.weightDisplay` (Medium) | 1.2 | Not expected in this phase's panels (reserved for drawer-level use, e.g. the clock) — declared here only for completeness; do not introduce a display-sized element in a panel without a documented reason |

Icon font: Material Symbols Rounded at `Design.iconSizeMd` = 24px for every glyph this phase adds (tile icons, mute/unmute icon, chevrons, header panel icon, Enable-button icon if any) — the unanimous sibling-agreement convention from six Phase 14 files.

## Color

All values are live `Colours.<role>` aliases (Material You roles, matugen-driven, re-colour on theme switch without restart per TOKEN-02) — **never** a hex literal. Roles listed below by name; do not resolve them to a hex value in any spec, plan, or implementation file.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Colours.surface` (panel body fill) / `Colours.onSurface` (body text) | Panel body background, scrolling list background, header band's own background if it reads as one surface with the body (render-gate discretion) |
| Secondary (30%) | `Colours.surfaceVariant` (fills) / `Colours.onSurfaceVariant` (text on those fills) | Pinned control block background (audio panel's master/device row), list-row hover/pressed background, expanded device-picker row background (D-15-12), expanded bluetooth device detail region (D-15-19) |
| Accent (10%) | `Colours.primary` (fill) / `Colours.onPrimary` (text/icon on that fill) | **Reserved for exactly:** (1) the lit state of a quick-toggle split tile when its verb is "on" — Wi-Fi radio on, Bluetooth adapter on, Volume unmuted (D-15-01/D-26 naming convention: all three sitting lit most of the time is intended, not a flaw); (2) the active fill/thumb of every slider this phase adds — master volume, per-app volume, input level (D-15-11); (3) the primary in-row action per state — Wifi "Connect", Bluetooth "Pair"/"Connect" (D-15-19's contextual verb); (4) the wifi scan progress line and the bluetooth pairing spinner (D-15-15, D-15-19). Accent is never used for body text, list-row default background, or the Advanced button (D-15-06 keeps Advanced a plain labeled button, not a primary-styled CTA — it is a wayfinding link out of the panel, not the panel's main action). |
| Destructive | `Colours.error` (fill/text) / `Colours.onError` (text on error fill) | **Reserved for exactly:** the Forget action (wifi network, bluetooth device — D-15-17/D-15-19's destructive-action separation) and the row-scoped failed-state text/icon (D-15-09's fourth widget state — "wrong password", "couldn't pair", etc.). Never used for the Disconnect verb, which is an ordinary reversible action, not destructive. |

**Fourth widget-state note (D-15-09, extends Phase 14's D-41 three-state vocabulary to four):** `populated` uses the roles above normally; `pending` uses `Colours.primary` at reduced opacity or the existing watchdog-timer chip treatment (reuse QuickToggles.qml's pattern, do not invent a new one); `empty` uses `Colours.onSurfaceVariant` at the quiet Material-Symbol-plus-one-line treatment (D-41/D-15-26 verbatim); `failed` uses `Colours.error` scoped to the affected row only, never panel-wide.

## Copywriting Contract

Every panel-level and row-level string this phase is known to need, resolved from CONTEXT.md's locked decisions. Exact icon-name/tooltip micro-copy not listed here is Claude's discretion at implementation time (per 15-CONTEXT.md's Discretion section) but must follow the voice established below (plain, no acronyms, names the fix or the cause — D-15-06's Phase 14 lesson: *"A fresh user will not know what their function is"*).

| Element | Copy |
|---------|------|
| Panel header titles | "Audio" / "Wi-Fi" / "Bluetooth" |
| Advanced button (all three panels) | "Advanced" — labeled text, never a bare glyph (D-15-06, locked) |
| Advanced button, target app absent | Button stays visible and enabled-looking but is disabled; tooltip/adjacent text: "{App name} is not installed" (D-15-22 — reason shown up front, never a silently hidden button) |
| Wifi primary CTA (secured network, password row) | Button: "Connect" |
| Wifi destructive action | Button: "Forget" — visually separated from Connect/Disconnect (own row region or trailing position with a gap, not adjacent), `Colours.error`-toned |
| Wifi destructive confirmation | Pressing "Forget" reveals an inline confirm, reusing the same press-to-reveal idiom as the row itself: *"Forget {network name}?"* with a confirming "Forget" and a "Cancel" — never a silent one-press forget (this is the destructive-confirmation instance the template asks for; no `QtQuick.Popup` dialog per D-15-12's platform constraint) |
| Wifi soft-off empty state | Heading/line: "Wi-Fi is off" — body: "Turn on Wi-Fi to see nearby networks" + an "Enable" button (D-15-26 case 1 — fixable, button present) |
| Wifi hardware-blocked empty state | Heading/line: "Wi-Fi is off" — body: "Turned off by a hardware switch" — **no button** (D-15-26 case 2 — unfixable in-panel, names the physical cause rather than implying a software toggle would help) |
| Wifi scan in-progress | Indeterminate progress line pinned under the header, no text needed beyond the line itself (D-15-15); an explicit refresh control stays available with its own tooltip, e.g. "Rescan" |
| Wifi network list, zero results after a completed scan | "No networks found" — refresh control remains visible (backstop copy — not explicitly locked in CONTEXT.md; verify at render gate) |
| Wifi row failure (D-15-09, per `ConnectionFailReason`) | `NoSecrets` → "Password required"; `WifiAuthTimeout` → "Wrong password"; `WifiClientDisconnected` / `WifiClientFailed` → "Couldn't connect"; `WifiNetworkLost` → "Network out of range"; `Unknown` → "Couldn't connect" — rendered inline on the affected row, password field (if open) stays open for retry |
| Bluetooth primary CTA (device row, contextual) | Row press label by state: "Pair" (unpaired) / "Connect" (paired, disconnected) / "Disconnect" (connected) — D-15-19, the row's press IS the CTA, no separate button |
| Bluetooth destructive action | Chevron-expanded "Forget" — visually separated from the row's press action, `Colours.error`-toned, same confirm-before-commit treatment as wifi's Forget |
| Bluetooth pairing in progress | Spinner + a real "Cancel" button wired to `cancelPair()` (D-15-19 — not a silent watchdog; the one operation where user-visible waiting is long enough to need a live escape hatch) |
| Bluetooth row failure (inferred, no native signal — Pitfall 2) | Pairing that ends without `bonded` becoming true, not user-cancelled: "Couldn't pair" — connect that reverts `Connecting→Disconnected`: "Couldn't connect" |
| Bluetooth adapter-off empty state | Heading/line: "Bluetooth is off" — body: "Turn on Bluetooth to see nearby devices" + an "Enable" button (D-15-26 case 3 — fixable) |
| Bluetooth no-adapter empty state | Heading/line: "No Bluetooth adapter" — body: "This device has no Bluetooth hardware" — **no button** (D-15-26 case 3's unfixable branch — states the absence plainly rather than implying a switch) |
| Bluetooth discovery opt-in control | Button: "Add device" (D-15-18 — discovery is opt-in, never automatic, to protect an active A2DP stream's radio) |
| Bluetooth device list, zero paired + discovery not started | Body: "No paired devices" + the "Add device" control remains the only path forward (backstop copy — not explicitly locked; verify at render gate) |
| Audio: nothing playing | The pinned master volume, device pickers and mic controls stay fully live and interactive; only the app-list region shows a quiet in-place placeholder, e.g. "Nothing is playing" — **not** a degraded/disabled panel (D-15-26 case 4, the one case explicitly NOT treated as an off/error state) |
| Audio per-app row, muted | No text change — muted state is carried visually twice (icon dims + slash overlay, slider track shifts to a muted tone) plus a hover tooltip naming the state, e.g. "Muted" (D-15-13) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state*
> coverage for this phase's list-collection, form and interactive-control elements. Empty-state
> and error-state COPY is defined above in `## Copywriting Contract` — rows below reference
> those entries rather than restating the copy.

**Elements classified:**
- Audio per-app volume list — `list-collection`
- Audio pinned control block (master volume, output/input device pickers, mic mute) — `form` + `interactive-control`
- Wifi network list — `list-collection`
- Wifi password entry row — `form`
- Bluetooth device list — `list-collection`
- Quick-toggle six-tile row — `interactive-control`
- Advanced button (×3) — `interactive-control`
- Panel header band — `static-content`

Applicable state considerations resolved: 15 covered, 4 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Audio per-app list | ✅ covered | Nothing-playing case renders the documented in-place placeholder while master/device/mic controls stay fully live — see Copywriting Contract "Audio: nothing playing" (D-15-26 case 4) |

| zero-one-many | Wifi network list | ✅ covered | Grouping and row shape are count-invariant — no singular/plural copy branch needed since rows are named entities, not a count summary; zero handled by the empty-state backstop above |
| zero-one-many | Bluetooth device list | ✅ covered | Same count-invariant grouping logic as wifi (D-15-18); zero handled by the empty-state backstop above |
| long-text | App name / network SSID / device name | 🧪 backstop | No locked decision on truncation treatment for unusually long names; recommend single-line elide-right (`Text.ElideRight`) with the full name available via hover tooltip, reusing Phase 14's established tooltip mechanism (`Design.tooltipDelayMs`) — this is a spec gap, not a contradiction, and should be confirmed live at the render gate against a real long app/device name |
