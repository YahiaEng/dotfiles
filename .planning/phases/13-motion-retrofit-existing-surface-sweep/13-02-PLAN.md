- `$motion-duration-<token>: <ms>ms;` — one per `.semantic` entry, from the `$resolved` TSV

- `$motion-easing-<name>: cubic-bezier(<a>, <b>, <c>, <d>);` — one per `.easings` entry,

  multiplier and floor applied as the semantic pairs so `reduced` and `off` reach them too

The filename must be `_motion.scss` (the leading underscore is what makes it a sass partial)

**B. `lib/motion.sh` — `theme_engine_compile_gtk3_stylesheets <tmp_dir>`.** Add the compile
function plus a module-level `GTK3_SCSS_TARGETS` array of `"<abs-source-path>:<output-name>"`
pairs, seeded with exactly one row this plan:

`"$HOME/.config/swaync/style.scss:swaync-style.css"`

(An array rather than inline invocations so plan 13-05 appends six waybar rows without
restructuring the function.) For each row, invoke:

`sass --no-charset --no-source-map --load-path="$tmp$STATE_DIR" <src> "$tmp$STATE_DIR/<out>"`

Three details are non-negotiable and each was verified directly on this machine:
- `--no-charset` is **mandatory**. A bare invocation emits a charset at-rule as line 1, and
  GTK3's `CssProvider` responds by discarding the ENTIRE stylesheet, not just that line — the
  same whole-stylesheet-discard failure class this repo already named WLOG-01. This fails
  silently: no error reaches swaync's stderr, the surface just looks unstyled.
- `--no-source-map` suppresses a `sourceMappingURL` comment and a stray `.map` file that
  would otherwise land in the state dir on every compile and break the contract manifest.
- `--load-path` must point at `$tmp$STATE_DIR`, the tmp tree — not the live state dir — so
  the partial the compile consumes is the one this same run just rendered.

Return non-zero on the first failing compile. Capture sass's stderr into `GENERATE_LOG`
using the same discipline `generate.sh` already applies to matugen — raw compiler stderr must
never reach a notification unsanitised.

**C. `lib/generate.sh` — wire the fourth sibling writer.** In `theme_engine_generate`,
immediately after the existing `theme_engine_render_motion_files "$tmp" || return 1` line,
add `theme_engine_compile_gtk3_stylesheets "$tmp" || return 1`. Propagated, never swallowed —
matching the house style of every other writer in that function. This placement is what makes
a failed compile commit nothing: everything renders into the tmp tree and `commit.sh` only
runs after `theme_engine_generate` returns 0, so the atomic render-then-commit invariant holds
unchanged. Do NOT add a post-commit compile — that would open a window where colour is applied
but stylesheets are not yet recompiled.

**D. Convert `swaync/.config/swaync/style.css` → `swaync/.config/swaync/style.scss`.** Use
`git mv` so history follows the file, then rewrite its content. Three mechanical changes:

1. **Interpolation-escape every GTK-CSS `@name` value reference.** In sass grammar, `@`
   beginning a token in expression position is always parsed as an at-rule keyword, so
   `color: @on_secondary;` aborts the whole compile with `Error: Expected expression.`
   Wrap the ENTIRE value string in `#{"..."}` interpolation — the escaped form produces
   output byte-identical to the original:
   - a bare reference becomes `color: #{"@on_secondary"};`
   - an `alpha()` call becomes `background: #{"alpha(@background, 0.72)"};` — the whole call,
     not just the inner name
   There are at least 19 such references (a direct scan of the current file finds ~40 `@`
   tokens once at-rule keywords are excluded); rewrite every one, and do not leave any
   dynamic or templated content inside an interpolation block.

2. **Rewrite the colour import for the OUTPUT location.** sass treats `@import url(...)` as
   an opaque string and never rewrites relative paths — verified by compiling into a
   different directory and diffing, all path segments came through byte-identical. Since the
   compiled sheet will live in the state dir as a sibling of the matugen colour render,
   line 1's `../../.local/state/theme/`-relative path becomes the bare filename
   `@import url("swaync.css");`. Colour stays a live import (D-03): a theme switch must keep
   re-colouring swaync through the existing matugen render and `swaync-client -rs` fan-out
   with no recompile, which is also what keeps the compiled sheet theme-independent for
   D-35's byte-identity assertion.

3. **Tokenize the six motion declarations.** Add `@use "motion" as m;` as the first line
   (before the colour import — sass requires `@use` at the top of the file). Every one of the
   six identical `transition: all <duration> <easing>;` rules at lines 31, 94, 104, 144, 180
   and 208 becomes:
   `transition: all #{m.$motion-duration-standard} #{m.$motion-easing-standard};`
   `motion.json`'s existing `standard` pair is `short4` (200 ms) + MD3 `standard`, an exact
   duration match — the only perceptual change is the easing keyword becoming the MD3 curve.
   Consume the partial with `@use`, never the legacy bare `@import` form, which emits a Sass
   3.0 deprecation warning to stderr on every single `theme-apply` run.
