  <name>Task 1: One-way door — untracking the wallpaper pointer (D-23)</name>
  <reversibility rating="one-way">Re-tracking a file that has been gitignored and locally rewritten means choosing a canonical target again from whatever the machine happens to be pointing at, not restoring a known state.</reversibility>
  <decision>Confirm untracking the wallpaper pointer before it leaves the index</decision>
  <context>
    The structural fact: `~/Pictures/Wallpapers` resolves into this repo's working tree (the
    stow link sits at a parent level), so `current.jpg` is a **tracked file inside the repo
    that five code paths rewrite at runtime** — the wallpaper library, the wallpaper picker
    and a file-manager action all write it, and the Material You generator and the lock screen
    both read it. Every switch to a static theme whose wallpaper differs from the committed
    target dirties a tracked file. That is why the committed stress test can never reach 10/10
    while its sequence contains such a theme — structural, not environmental (ledger entry 9,
    reproduced end-to-end at the Phase 12 close).

    D-23 chose to fix the tree, not the gate. Exempting the path from the clean-tree check was
    the rejected alternative: the tree genuinely *is* dirty after every static theme switch, so
    the gate would report clean while the stated invariant is false — the green-gate-over-
    broken-reality pattern behind the Phase 6 and Phase 8 failures — and it would leave the
    trap armed for anyone running plain `git status`. Untracking makes the invariant actually
    true, and applies the project's most-enforced rule directly: generated output lives in the
    state directory, never in git.

    Undo cost, and why this is one-way rather than costly: once the file is gitignored and the
    local copy has been repointed by normal desktop use, re-tracking does not restore a known
    state — it means picking a canonical target again from whatever the machine happens to be
    pointing at that day, and re-arming the trap. There is no revert commit that puts things
    back the way they were.

    The mitigation is the seed: the install path will point the untracked file at today's
    committed target so a fresh machine behaves byte-identically to now. Without that seed a
    fresh install would have no wallpaper pointer at all, because nothing currently seeds it —
    a fresh machine depends on the tracked symlink existing.
  </context>
  <options>
    <option id="untrack-and-seed">
      <name>Untrack, gitignore, and seed at install (D-23's choice)</name>
      <pros>The clean-tree invariant becomes true rather than unchecked; the stress test becomes able to reach 10/10; plain `git status` stops lying; consolidates with the existing install-time seed rather than adding a new failure class</pros>
      <cons>One-way — re-tracking later means choosing a canonical target again; the seed becomes load-bearing for fresh installs</cons>
