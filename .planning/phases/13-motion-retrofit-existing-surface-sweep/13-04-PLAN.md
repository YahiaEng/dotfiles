<assumption_delta_decision>
**Signal:** the deterministic assumption-delta detector fired once (`chosen`-family), on
criterion 5's phrasing — *"themes that are not yet installed, installs the **chosen** one from
the repos or AUR, and applies it live"*. Advisory, non-blocking.

**The noun that is now primary:** unchanged — the **icon-theme directory name** (a directory
under `/usr/share/icons` or `~/.local/share/icons` carrying an `index.theme` with a non-empty
`Directories=` key). That is what `~/.local/state/theme/icon-theme` stores, what the existing
apply function consumes, and what GSettings ultimately holds.

**What actually changes:** the browse path introduces a genuinely different noun — the
**package name** (`papirus-icon-theme`, `tela-icon-theme-git`). These are not
interchangeable, and the mapping is one-to-many: one package routinely ships several theme
directories (a light variant, a dark variant, colour variants). So the picker cannot assume
the chosen catalogue entry is the name it should write to the state file.

**Decision: `add-alongside`.** The package name is introduced as a second, clearly-separated
identity that exists only inside the browse and install path; it is never written to
`icon-theme` and never reaches the apply function. After an install, the picker re-runs its
existing directory-scan enumeration and resolves the package name to the theme directory names
that actually appeared — presenting them for choice when more than one did. Rationale: the
apply pipeline's identity model is correct and shipped; the alternative (promoting the package
name to primary) would require the state file, the apply function and GSettings all to learn a
name they cannot use.

**What would later force a promote:** a requirement to *uninstall*, *update*, or *report the
provenance of* an applied icon theme. Any of those needs "which package provided this
directory" persisted, at which point the package name becomes a first-class stored identity
alongside the directory name rather than a transient value inside one script run.
</assumption_delta_decision>

the line's source field:

- **Already installed** → fall through to the existing installed-theme preview path unchanged.
- **`repo`, not installed** → fetch and extract, do not install:
  1. Print `  ⟳ fetching <pkgname> …` and flush immediately, before the network call. fzf
     streams preview stdout as it arrives, so this is what the user sees during the download;
     icon-theme packages are tens of megabytes and a silent pane reads as a hang.
  2. Resolve the package URL with `pacman -Sp <pkgname>` — this needs no root (verified) and

  3. Download with `curl -fsSL` plus a wall-clock timeout and a maximum file size ceiling, into

     hangs the picker.
  4. Extract with `bsdtar` into `$CACHE_DIR/pkg/<pkgname>/`, restricted to the archive's
     `usr/share/icons` paths, with same-owner and same-permission restoration disabled and
     absolute-path extraction never enabled. Extraction only — never `pacman -U`, never the
     helper, so the package's own install hooks never run for a preview the user has not
     agreed to install.
  5. Render through the existing montage + `kitten icat` pipeline with the same cache key
     shape the installed path uses, so a second visit to the same entry is instant.
- **`aur`, not installed** → no prebuilt package exists to fetch. Fall back to the helper's
  package-metadata query and render it as text (description, version, upstream URL), with an
  explicit line stating that AUR entries are built from source and have no fetchable preview.

**D. Pitfall 6 — search BOTH icon directory conventions.** The current preview hardcodes a
`SIZExSIZE/category/` path filter, which is one of two conventions the freedesktop spec
permits. Verified this session against two real packages: one installed theme uses
`SIZExSIZE/category/`, and another fetched-not-installed theme uses the inverted
`category/SIZE/`. A single-pattern glob silently produces an empty montage for every theme
using the other convention. Replace the single filter with an ordered attempt: the
`SIZExSIZE` form first, then the inverted `category/SIZE` form, then the existing unfiltered
first-hit fallback. Apply this to BOTH the curated-name loop and the bulk fallback glob, and
to both the installed and the fetched preview roots.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mirror HTTPS → `curl` → `bsdtar` → cache dir | An untrusted `.pkg.tar.zst` archive fetched and extracted for preview, before the user has agreed to install anything |

| package name → theme directory name → state file → GSettings | A resolved identity written to state the engine consumes |
