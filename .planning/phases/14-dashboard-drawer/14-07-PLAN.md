current conditions and a real forecast — and, more importantly for DASH-06, stays
readable when the service is unreachable.

exactly like fresh plus one quiet badge, and that path is proven able to fail by
backdating the cache before it is trusted to pass.

conditions and forecast, readable rather than blank or broken when the weather
service is unreachable.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Open-Meteo HTTP response → the QML engine | Third-party network data is parsed and rendered inside a process that holds a compositor-exclusive focus grab; a parse that throws inside the drawer is not a broken widget, it is a broken surface holding the desktop's input |
| Hand-editable `~/.local/state/theme/weather.json` → the request URL | A user-owned dotfile supplies the coordinates and the three unit strings that become part of an outbound request; 14-02 wrote the file's shape, this plan is the consumer that must not trust it |
| `~/.local/state/theme/weather-cache.json` on disk → the render path | A file this process writes and re-reads across restarts, editable by anything running as the user, parsed on every shell start before any network call happens |
| The drawer's outbound request → a third-party host | Every fetch discloses a coordinate pair and a timing pattern to an external service that this project does not control and does not authenticate to |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-02 | Denial of Service | Malformed third-party JSON from the Open-Meteo response, or a corrupted `weather-cache.json`, reaching the QML engine | medium | mitigate | Every `JSON.parse` in this plan — the network response in Task 1's response handler and the cache file in `loadCache` — sits inside try/catch with a default-safe fallback, matching the discipline `Colours.qml` and `Motion.qml` already apply to `palette.json` and `motion.json`. Beyond parsing, a parsed object must pass an explicit shape check (a current block with a numeric temperature and an integer code; hourly `time` and `temperature_2m` arrays of equal length; a non-empty daily `time`) before it is allowed to become the payload, and a failed check leaves the last-good payload untouched rather than half-rendering the tab. Proven rather than asserted: Task 1 truncates the cache file mid-object and confirms the surface survives with one log line, and serves deliberately malformed response shapes through the endpoint seam. | T-14-03 | Tampering | `~/.local/state/theme/weather.json` coordinates — validation side (the seeding side was 14-02's) | low | mitigate | The two coordinates are received as raw `var` properties rather than as numbers, deliberately, so a hand-edited string stays a string instead of being silently coerced to zero and quietly relocating the drawer to the origin point. `coordsValid` then requires number type, finiteness and real latitude and longitude ranges, and nothing downstream may build a URL, start a request or write a cache while it is false — the tab renders the never-configured placeholder instead. | T-14-23 | Information Disclosure | The outbound forecast request to a third-party host | low | accept | Every fetch tells an external service roughly where this machine is and when its owner opened the drawer.
