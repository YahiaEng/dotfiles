<objective>
Compose the Dashboard tab. 14-04 mounted the quick-toggle block as its footer and
left everything above it empty; this plan fills that space with D-38's identity-first
single column and closes DASH-03.

Top to bottom: a clock and date hero, a display-only calendar month grid with today
highlighted and chevron-plus-wheel month navigation (D-34, and D-18's recorded
consequence that bare arrow keys stay reserved for tab cycling), a compact media
widget carrying art, a title/artist stack and play/pause only, and a CPU/Memory/Battery
resources strip built from 14-06's dial at a smaller diameter (D-39). Both the media
widget and the strip are tap targets that jump to their own full tab — the
compact-widget to its-full-tab deep-link convention D-39 and D-40 establish and Phase
15 inherits (D-40).

Neither widget owns any data. The compact widget reads the same `MediaBackend`
instance the Media tab reads; the mini-dials read the same `SystemResources` instance
the Performance tab reads. That is the whole point: this tab is a second view over
state the drawer already holds, never a second reader of it.

Purpose: DASH-03 and roadmap success criterion 3's Dashboard clause — a calendar,
date/time, a compact media widget and system resources at a glance.
Output: one filled `DashboardTab.qml`. No new file, no manifest edit, nothing else.
