## Supersession bookkeeping

`.planning/phases/14-dashboard-drawer/deferred-items.md` carries a
`## 14-09 Task 4` section with Items A and B. **This plan supersedes both.**

Split deliberately, because half of it is knowable before the gate and half is
not: **Task 3 marks both items PROMOTED**, naming this plan, in the same shape
the 14-06 entry already uses for its own RESOLVED annotation — that fact is
true the moment this plan exists and does not wait on anything. **The OUTCOME
line for each item lands with this plan's closing documentation commit**, after
the gate has answered, because Item A's outcome is precisely what the gate
decides (layered kept, tuned, or reverted to the single designed glyph) and
writing an outcome before the gate would be recording a result that has not
happened. Neither item may be left reading as open work at plan close.

The technical findings recorded there — the font's
absent colour tables, the query binary's presence and output shape, and the
sizing arithmetic — are INPUTS to this plan and are not to be re-derived by
any task here. That is a hard instruction, not a preference: re-deriving them
spends a render-gate session's context on questions that already have answers
in writing.

## Ownership fence — what this plan may not touch

This plan is the tenth and last in the phase and no sibling is executing in
parallel, so the wave-3 ownership fences are lifted. That is a licence to make
the changes named below, not a licence to improve anything else on the way
past. Specifically out of bounds:

- `Dial.qml`. The fifth dial needs no change to the dial component. Its
  `diameter` and `ringThickness` are already per-instance properties and the
  Performance tab already sets both; the tab changes its own two constants and

  to surface at the gate, not a quiet improvement** — the Dashboard tab's
  resources-strip height is hand-derived from that file's implicit-size
  formula, so a change to its typography or spacing constants silently
  mis-sizes a tab this plan is not otherwise touching.
- `DashboardTab.qml`. No GPU mini-dial. D-39 names the glance-timescale
  metrics and the human's request was specifically about the Performance tab.
  Adding a fifth mini-dial to a 44px strip that already had a caption-overflow
  fix is exactly the kind of unrequested addition the fence exists for.
- `WeatherPalette.qml` — **one comment-only exception.** Every colour the layered
  glyph needs already exists on it, so no value, no resolver entry and no scope
  sentence changes; editing any of those would re-open 14-09 Task 4's
  basename-narrowed hex invariant for no gain. The single permitted change is the

## The "D-11" mislabel — read this before looking anything up

`WeatherPalette.qml`'s header, `14-09-SUMMARY.md` and consequently this plan all
describe the palette exemption as an exemption to **"D-11's palette contract"**.
**That decision number is wrong.** In `14-CONTEXT.md`, D-11 is the DASH-08
fullscreen-refusal decision ("refusal is a silent no-op on TRUE fullscreen only;
maximized windows do not block") — nothing to do with colour. The actual contract
text is the repo-wide invariant line in the same file: *"Zero hex/duration literals
in repo-authored UI — everything through"* the token singletons.

The mislabel originates in 14-09, is baked into `WeatherPalette.qml`'s own source
header at its first two lines, and is therefore consistent with as-built — which is
why this plan keeps the citations rather than silently renumbering history. But an
executor sent to read "14-CONTEXT.md's D-11 for the palette contract" will find the
fullscreen decision and waste a lookup, on a plan that spends real effort forbidding
re-derivation. So: **the contract is the zero-literal invariant line, and
`WeatherPalette.qml`'s own header is the authoritative statement of the exemption
and its scope.** Read those two, not D-11.

Task 1 corrects the header comment in `WeatherPalette.qml` as a one-line
documentation fix. Recorded as a **documentation defect inherited from 14-09 and
corrected here**, not as something 14-09 got right — and corrected in the file
rather than only in this plan, so the next reader of the source is not misdirected
the same way.
