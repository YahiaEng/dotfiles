  <action>
    Fill `MediaBackend.qml` so the drawer becomes a third *reader* of the one media
    backend this repo already owns. Keep the stub's root type, its `drawerOpen` property,
    its `widgetState` register and its header fences; everything below is added beneath
    them.

    **Two paths, resolved once.** Declare two `readonly` string properties holding the
    home-prefixed paths to `media-status.sh` and `media-players.sh` under
    `.config/hypr/scripts/`, built from the home-directory environment read. Every command
    array in this file references one of these two and nothing else. There is no third
    script and no direct invocation of the underlying MPRIS command-line tool anywhere in
    the drawer — that tool is invoked in exactly one place in this repo, inside
    `media-players.sh`, behind `_valid_id`, and this file's whole job on the mutating side
    is to keep it that way.

    **The default-safe payload shape.** Declare one `readonly` object literal holding every
    field of the payload contract at its neutral value — the seven string fields empty, the
    two integer fields zero, the volume sentinel at the script's own no-volume value, and
    the seekable flag false. Initialise the live payload property from it, and fall back to
    it whenever a read produces nothing usable. Because every field always exists, no
    consumer ever reads an undefined member, and the empty state is a real value rather
    than a null check scattered through the tab.

    **The one streaming reader.** One `Process` running the status script's watch
    subcommand as a two-element argv array, with `running` bound to `drawerOpen` and its
    standard output attached to a line splitter. That binding is the whole lifecycle: the
    drawer opens and the child starts, the drawer is destroyed and the child dies. Nothing
    else in the drawer may read that stream — the Dashboard tab's compact widget reads this
    same instance's properties in 14-08, which is exactly why this component is mounted once
    at the shell root rather than instantiated per tab.

    Each line handler does four things in order: reject a line that is empty or whitespace;
    parse it inside a try/catch; reject a parse result that is not a plain non-null object;
    and only then assign it to the live payload property. A rejected line must leave the
    previous payload standing and must not touch the register or clear the screen — a
    truncated write or a garbled line is a transient, and blanking the tab for it would be
    a worse failure than showing one-second-old data. Do not log-spam on rejection; a
    single guarded warning at most, matching the token singletons' existing discipline.

    Note in the file why the reserved third subcommand is unused: a second child against the
    same script is the second backend D-35 forbids, and the watch stream already re-emits
    the whole payload whenever the elapsed seconds change, so the seek slider advances at
    the script's own one-second cadence for free.

    **Derived display fields — the surface both media views read.** Beside the raw payload,
    declare `readonly` derived properties so neither view re-derives presentation logic and
    14-08's compact widget inherits the same fallbacks for free:

    - a player-presence predicate, true when the payload's player field is non-empty;
    - a playing predicate, true when the status field equals the playing value the script
      passes through from the player, compared case-insensitively after trimming;
    - a display title: the title when non-empty, otherwise the player's own label, otherwise
      nothing — never a raw empty string reaching a text element;
    - a display artist and a display album: the trimmed field or nothing, with the tab
      deciding visibility rather than substituting placeholder words;
    - an art path, elapsed seconds, total seconds, a volume level, a has-volume predicate
      derived from the script's no-volume sentinel rather than from a zero test, and a
      seekable predicate that requires both the payload's own flag and a positive length.

    Drive `widgetState` from these: the empty state name while no player is present, the
    populated state name once one is, and the pending state name in the window between the
    drawer opening and the first line landing. All three names stay literal in the file —
    that register is the vocabulary Phase 15 inherits.

    **The player list.** The switcher chips need the id/label/active array only
    `media-players.sh list` can produce. Run it as a one-shot child inside this same file,
    collecting its whole standard output and parsing it in a try/catch that falls back to an
    empty array; a failed or malformed read leaves the chip row empty rather than throwing.
    This is not a second backend: it is the same sanctioned reader family, one file, one
    owner, a discrete query rather than a second stream — say so in the header so the next
    reader does not mistake it for a fence breach.

    Refresh it on three triggers and no others: when `drawerOpen` becomes true, when the
    payload's player field changes, and on a low-frequency timer whose `running` is bound to
    `drawerOpen`. The timer exists because a newly-launched second player changes nothing in
    the payload while the active selection stays put, so without it the chip row would go
    stale in exactly the situation the chips exist for. Its cadence is a named constant
    written as a timer interval and commented as a data-refresh cadence that is deliberately
    not a motion token — a poll cadence riding the motion-scale axis would reach zero at the
    off preset, which is the same reasoning 14-04 records for its watchdogs.

    **The mutator dispatch — the security-relevant part, and T-14-01's mitigation.** Declare
    one function per verb: play/pause, next, previous, seek, volume, and player selection.
    Each builds a fixed argv array whose only non-literal elements are the resolved script
    path and, where the verb needs them, the current player id and one numeric argument.
    Then, without exception:

    - the array is executed directly as argv. It is never joined into a string, never handed
      to a shell interpreter for re-splitting, and never assembled by concatenation.
    - the player id element comes only from the payload's own player field or from an entry
      of the parsed list — both of which `media-players.sh` already filtered through
      `_valid_id` before ever emitting them — and it is passed as its own array element so
      that even a hostile id is one argument rather than several. `media-players.sh`
      re-validates it and returns without invoking anything on failure, so the injection
      surface is closed twice over rather than filtered once.
    - the numeric argument is produced by converting a QML number to a plain non-negative
      decimal string, clamped into the valid range before conversion — seconds clamped to
