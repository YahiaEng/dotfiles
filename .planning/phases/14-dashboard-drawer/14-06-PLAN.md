  <action>
    Fill 14-03's `SystemResources` stub into the drawer's one resource reader. Keep
    the `Scope` root, the existing `drawerOpen` property and the D-41 register comment
    exactly where 14-03 left them; everything below is added inside.

    **Imports.** `QtQuick` for `Timer`, `Quickshell` for the environment helper,
    `Quickshell.Io` for the file readers and the storage subprocess, and
    `Quickshell.Services.UPower` for the battery. Nothing else — this file reads
    kernel counters and one typed service and has no other business.

    **Cadence constants (D-36).** Declare `readonly property int fastPollInterval:
    2000` for CPU, memory and network, and `readonly property int slowPollInterval:
    30000` for storage, plus `readonly property int cpuSampleWindow: 3` for the
    smoothing depth. Name them rather than writing bare numbers on the timers — and
    be aware that no gate in this repo will enforce that for you: the motion linter's
    raw-value check is anchored on a lowercase `duration` key followed by digits, and
    a timer's numeric period is structurally invisible to it. The acceptance criteria
    make this a source assertion for exactly that reason.

    D-36 asks for a ~30s battery cadence alongside storage. Battery gets no timer at
    all here, and that is an improvement rather than a deviation: the typed UPower
    wrapper is push-based, its device properties carry change notifications, so a
    binding updates the moment the device does and a poll would only add latency and
    work. Record that in the file header and in the SUMMARY so it reads as a decision
    rather than an omission.

    **Published metric properties.** Every consumer — this phase's Performance tab and
    the next plan-wave's mini-dial strip — reads these and nothing else, so the read
    path stays swappable:
    - `cpuFraction` (real, 0 to 1, the smoothed value)
    - `memoryFraction` (real, 0 to 1), `memoryUsedBytes`, `memoryTotalBytes`
    - `storageFraction` (real, 0 to 1), `storageUsedBytes`, `storageTotalBytes`
    - `netRxRate`, `netTxRate` (real, bytes per second — a rate, never normalised
      into a fraction of anything; D-36 is explicit that a rate is not a percentage)
    - `batteryPresent` (bool), `batteryFraction` (real, 0 to 1), `batteryStateText`
      (string)

    Alongside each metric, a D-41 state register: `cpuState`, `memoryState`,
    `storageState`, `networkState`, `batteryState`, each a string holding one of the
    three vocabulary values the stub already names. The stub's own `widgetState`
    property stays and reports the reader as a whole: empty until the first successful
    fast sample, pending while baselines are being established, populated once real
    values are flowing.

    **The three kernel readers.** One `FileView` each for `/proc/stat`,
    `/proc/meminfo` and `/proc/net/dev`. These are procfs, which has no change
    notification, so do not set `watchChanges` on them — they are pulled on the timer,
    not pushed. Set `blockLoading` true and `preload` false so that the reload-then-read
    the fast sampler performs returns the freshly read text rather than a cached
    previous one; confirm against the wrapper file you read which combination of
    `reload()`, `waitForJob()` and `text()` actually gives a synchronous fresh read on
    this build, and record the combination that worked in the SUMMARY rather than
    leaving the next reader of this file to re-derive it. A procfs read is
    microseconds, so blocking is the right trade here.

    **The fast sampler.** One `Timer`, its period bound to `fastPollInterval`,
    `repeat` true, and its `running` bound to `drawerOpen` and to nothing else. On
    each tick, in one function, read all three files and publish:

    *CPU.* Take the first line of the stat file — the aggregate `cpu` line — split it
    on whitespace, drop the leading label token and require at least eight numeric
    fields. The values in order are user, nice, system, idle, iowait, irq, softirq,
    steal, guest, guest_nice. Total is the sum of the **first eight only**: guest and
    guest_nice are already counted inside user and nice, and summing all ten
    double-counts virtualised time. Idle time is idle plus iowait. Against the
    previous tick's stored totals, compute busy delta over total delta; if the total
    delta is not positive, publish nothing this tick and keep the previous value.
    Push the instantaneous fraction into a rolling array capped at `cpuSampleWindow`
    entries and publish its mean as `cpuFraction` — that is D-36's light smoothing,
    and its depth is the constant so the render gate can retune it in one place.

    *Memory.* Scan the meminfo file for the total and available lines. Both are
    reported in kibibytes; multiply by 1024 to publish bytes. Used is total minus
    available — the available figure, not the free figure, because free excludes
    reclaimable cache and would report this machine as far more loaded than it is.
    Fraction is used over total, guarded on total being positive.

    *Network.* Skip the file's two header lines. Each remaining line is an interface
    name, a colon, then the counters. Split on the colon **first**: when a counter
    grows past the column width the kernel glues the first number directly onto the
    colon with no space, and a naive whitespace split silently mis-indexes every field
    on that line — this machine's wired interface is already in that state today. After
    the colon, the whitespace-separated values are receive bytes at index 0 and
    transmit bytes at index 8. Skip the loopback interface by name; sum the rest.
    Divide the delta against the previous tick by the real elapsed wall time between
    ticks rather than the nominal period, so timer drift does not inflate the rate. If
    either summed counter has gone **down** since the last tick — an interface
    disappeared, or a counter wrapped — publish zero for that tick and re-baseline
    rather than emitting a negative or absurd rate.

    Every one of those three parses goes inside its own try/catch with an explicit
    finite-number check before any value reaches a published property. A field that is
    missing, non-numeric or `NaN` must leave the previous good value untouched and put
    that metric's state register into the empty value; it must never reach the screen
    as a number. This is Security V5's defensive-parse rule applied to kernel text, and
    it is what stops one malformed line taking a whole tab down.

    **The storage reader.** There is no kernel pseudo-file that reports filesystem
    usage, so this one metric needs a subprocess. Declare a `Process` whose `command`
    is a fixed argv array — the `df` binary, a one-byte block-size flag, an output
    selector restricting the columns to size and used, and the root mount path — with
    no shell, no string interpolation and no user-supplied component anywhere in it.
    Collect its standard output with a `StdioCollector` and parse on the
    stream-finished signal: take the last non-empty line, split it on whitespace,
    require two finite numbers, publish total and used bytes and their fraction.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kernel pseudo-files (`/proc/stat`, `/proc/meminfo`, `/proc/net/dev`) → the drawer's QML engine | Untrusted-in-format (not untrusted-in-origin) text crosses into code that parses it by field index inside a surface holding a compositor-exclusive focus grab |
| The `df` subprocess's standard output → the drawer's QML engine | A child process's text output crosses into the same parser tier, with the added surface of process lifetime |
| The system UPower service (D-Bus) → the drawer's battery bindings | A separate system daemon's typed properties cross into bound values rendered on screen |
| The `batterySource` injection seam → the battery bindings | A deliberately substitutable input to the rendered battery figures |

Scope note: this plan reads local kernel counters, one local subprocess and one local
system service. It installs no package, fetches nothing over a network, constructs no
shell string and writes no file. The register below is scoped to that honestly rather
than padded — the phase's load-bearing threats (`T-14-01` media command injection,
`T-14-02` and `T-14-03` weather parsing, `T-14-SC` the flagged AUR font package)
belong to 14-05, 14-07 and 14-02; the surface, focus and exclusion-zone threats were
closed by the tracer in 14-01; the pager's binding-loop and gesture-routing threats
belong to 14-03.
