<objective>
Make the failure this phase *owns* impossible to miss.

Hyprland does not error when a client may not capture — it hands back nothing, and
a thumbnail silently renders blank. Phase 11's probe was allowed to leave blank
tiles blank; this surface is not, because "a window is simply absent from a
surface claiming completeness" is the worst way for criterion 1 to be false.

Three causes deserve three different answers. A first frame that has not landed
yet is momentary and self-resolving, so it gets a pending state. A genuinely blank
window and a denied capture are indistinguishable from the capture view alone —
the boolean is the only signal there is — so the failed state says what it knows
(the window's real title, which Hyprland IPC always has) and refuses to claim a
diagnosis it cannot make. And when *nothing anywhere* produces content, that is a
permission problem rather than fifteen simultaneously-slow windows, so it is said
once at the surface level instead of fifteen times on fifteen tiles.

This plan also closes OVER-02's other half: clicking a window thumbnail focuses
that window and its workspace, matching what pressing Enter on a selected window
will do in plan 16-07, so nothing has to be learned or tested twice.

And it proves all three states by fault injection. A state that has never been
rendered is a state that has never been tested — this repo has shipped visibly
broken surfaces through fully green mechanical gates twice.

Purpose: OVER-01's live thumbnails become honest about their own failures, and
OVER-02 gains window-level parity with the keyboard model.
Output: three capture states, one whole-grid catch, per-window click parity, and
captured evidence that each degraded state actually renders.
</objective>

<assumption_delta_decision>
**Signal:** `pluralization` on *another* ("Dragging a window thumbnail onto
**another** workspace tile moves that window there") and on *fallback*
("…either stays inside it or ships the documented **fallback** instead").

**The noun that is now primary.** The primary key for every operation in this
phase is **(window identity, workspace-target token)** — `HyprlandToplevel.address`
paired with a workspace token that is either an integer `1..10` or the literal
`special:magic`. "The focused window on the current workspace" is demoted to one
*instance* of that pair.

**Decision: `promote`.** This plan's contribution: click parity makes the *window*
an independently addressable target for the first time in this shell. Before this
task, clicking anywhere in a tile meant "go to this workspace"; after it, a
thumbnail is a thing you can point at and land on by identity. That is the
promoted noun becoming reachable through the pointer, and it is deliberately built
to match what plan 16-07's Enter key will do — one meaning, two input paths, so
nothing is learned or tested twice.

**Second signal — render mode.** Decision: `promote`, and this plan hardens it.
The three capture states live inside `WindowThumbnail` — the one general
representation — rather than being layered on by the tile or the surface. A tile
never has a state of its own; it aggregates. That is what makes UI-SPEC's E2
`partial` row resolvable structurally ("each window carries its own state, so no
fourth tile-is-partial treatment is needed") instead of demanding a fourth
composite state nobody wants to design. When D-16-07's ladder later switches the
capture mode, the state machine rides along unchanged because it sits on the
general representation, not on a live-specific one.
