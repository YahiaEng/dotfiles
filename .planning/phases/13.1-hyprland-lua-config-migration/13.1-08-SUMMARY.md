## Decisions Made

- **Fix both sides of the curve-ordering question (operator decision).** Sort the Lua-side registration for deterministic behaviour across fresh processes, AND make the gate's curve-array comparison order-insensitive. Sorted registration alone does not make the gate pass — proven live, since `hyprctl -j animations`'s own reported curve order (governed by Hyprland's own internal storage, not directly by Lua registration order) is stable within one compositor process but does not equal the committed baseline's order, which predates this migration and came from the old theme-engine-emitted hyprlang fragment.
- **Defer the hyprlock lock/unlock cycle rather than claim it passed.** A non-interactive automated session cannot safely enter a password into a PAM-backed secure prompt, and this bind carries documented prior incident history (`04-REVIEW.md` FIX-02). The mechanical half of criterion 4 is verified; the physical half is an honest, recorded gap for the operator.
- **Do not re-run quickshell-doctor.** Its headless-output probe SEGV-crashed the compositor in a prior session of this same plan (unrelated to the Lua migration — the crash is in Hyprland's own C++ screenshare/toplevel-export code, correlated with a DP-1 hotplug). It passed 13/13 earlier this plan; its true post-cutover result is left deliberately unverified rather than re-risking the same crash class during a live cutover.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Curve-registration order nondeterminism across fresh compositor processes**
- **Found during:** Task 3 (a prior executor session's diagnostic work, continued and resolved in this session per explicit operator decision)
- **Issue:** `config/animations.lua`'s `pairs()` loop over `tokens.motion.curves` (a Lua hash table) is exposed to Lua 5.5's per-process string-hash-seed randomization. A prior diagnostic session incorrectly concluded this was "deterministic, not flapping" from a same-process repeated-reload test, which structurally cannot observe per-process randomization.
- **Fix:** sorted-key iteration in `config/animations.lua` (proven stable across 5 separate fresh `lua` processes), plus an order-insensitive set comparison for the curve array in `hypr-equivalence-check`'s `animations.json` check (proven necessary — sorted registration alone does not make the gate match the baseline's own, unrelated, pre-existing curve order).
- **Files modified:** `hypr/.config/hypr/config/animations.lua`, `hypr/.config/hypr/scripts/hypr-equivalence-check`
- **Verification:** 8 deliberate fault injections (reorder=PASS; changed control point/missing curve/extra curve/leaf value change/leaf order swap/absent baseline=FAIL, both via the standalone comparison function and the real CLI entry point against a tampered baseline copy). D-10 semantics re-verified unchanged.
- **Committed in:** `d6b956e`
