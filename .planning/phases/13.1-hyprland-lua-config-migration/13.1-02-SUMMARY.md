# Phase 13.1 Plan 02: Tracer Slice — Lua Token Pipeline + Degradation Proofs Summary

**Proved the entire Lua-migration mechanism end to end on one real path — matugen-generated colour data merged with motion data into a single `~/.local/state/theme/hyprland-tokens.lua`, reached from inside the Hyprland config root only through a relative out-of-tree symlink, consumed by a real nested Hyprland instance via a defensive `require()` accessor — and then proved all three graceful-degradation branches (missing file, missing key, empty table) plus a verified two-command rollback, closing out both of the phase's genuinely novel architectural spines before any of the remaining seven config modules are ported.**

## Accomplishments

- `require()`'s config root follows `XDG_CONFIG_HOME` (not a hardcoded `~/.config/hypr`), and resolves through a relative out-of-tree symlink to a file structurally outside the config root — proven live, not assumed (this was RESEARCH.md's Assumption A1)
- A nested Hyprland instance boots successfully as a Wayland client inside the live session, fully addressable via `hyprctl -i <signature>`, and is cleanly torn down — the primary verification route is viable on this machine, the bounded single-run fallback was never needed
- Format selection is deterministic: with both `hyprland.conf` and `hyprland.lua` present, Hyprland always loads Lua, verified across two independent starts
- Full end-to-end pipeline proof against the live theme-engine and the live `dracula` theme: every one of the seven ported `general:` values is byte-identical to the committed pre-migration baseline
- All three D-13 degradation cases proven with real fault injection against the live pipeline: missing token file (falls through to literal defaults, compositor still starts), missing key inside a present table (that one value falls back, siblings unaffected), and empty `colors` table from the seed-only render (the real fresh-install case — every colour falls back, motion tables still populate)
