# Phase 13.1 Plan 06: Animation Surface Port + motion-lint Lua Path Summary

**Ported all 15 `animations.conf` leaves onto `hyprland-tokens.lua`'s generated motion tokens (closing the hyprlang load-order hazard entirely — the Lua module fetches its own tokens rather than depending on source order), and extended `motion-lint` with a Lua-aware reference-resolution/raw-value gate proven able to fail via three new committed fixtures.**

## Accomplishments

- `config/animations.lua` registers curves and all 15 animation leaves (`windowsIn`/`windowsOut`/`windowsMove`/`fadeIn`/`fadeOut`/`fadeSwitch`/`fadeShadow`/`fadeDim`/`border`/`borderangle`/`workspaces`/`specialWorkspace`/`layers`/`layersIn`/`layersOut`) from `tokens.motion.speed.*`/`tokens.motion.curves.*`, verified byte-identical to `.hypr-baseline/animations.json` on name/bezier/speed/enabled/style via a live `hypr-lua-harness` session.
- The `enabled` flag is derived by an explicit `== nil` test, never a boolean-or — verified live at the `off` motion-scale preset, where the Lua session reports `{"bool": false}` and the still-hyprlang live session reports `{"int": 0}` for the same disabled state.
- A missing `motion.speed` token (or an unregistered curve) skips that leaf's `hl.animation()` call entirely rather than substituting a hardcoded number — verified live by emptying the deployed token file's `speed` table and observing a clean `configerrors` with Hyprland's own built-in defaults (`overridden: false`) applied.
- `motion-lint` gained a full Lua-aware CHECK A/B path: `.lua` files under the hypr config tree are now scanned deny-by-default, `hyprland-tokens.lua` is loaded as a definition source through the real `lua` interpreter (reusing `lib/contract.sh`'s established `lua-table` pattern), and the legacy `hyprland-motion.conf` source became optional (its absence now prints a `NOTE` and is skipped rather than failing the run).
- Three new fixtures (`compliant-hypr.lua`, `poisoned-raw-hypr.lua`, `poisoned-dangling-hypr.lua`) are registered in `--self-test`, each independently proven to fail for the right reason when run in isolation; the eleven existing fixtures and the hyprlang path are byte-unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Generated token file scanned as a false-positive raw-value surface**
- **Found during:** Task 2, first default `motion-lint` run over the real deployed tree
- **Issue:** `~/.config/hypr/state/tokens.lua` (stow.sh's symlink into the generated `~/.local/state/theme/hyprland-tokens.lua`) lives physically inside the hypr config tree root, so the new `.lua` glob (with `followlinks=True`, required for stow-deployed symlinked directories) picked up the GENERATED token table itself as if it were a repo-authored surface — its own literal `points = { {0.2, 0}, {0, 1} }` curve definitions then failed CHECK B ten times, a false positive: this file is a definition SOURCE, not a scannable surface, exactly like `gtk-4.0-motion.css`/`motion.json`/`hyprland-motion.conf` which are excluded simply by living outside all scanned roots — this one needed an explicit realpath exclusion because it's reached through a followed symlink INSIDE a scanned root.
- **Fix:** Added `is_lua_tokens_file()`, comparing each candidate `.lua` file's realpath against `state_dir/hyprland-tokens.lua`'s realpath, and skip it during surface collection — mirroring the pre-existing fixtures-directory exclusion pattern.
- **Files modified:** hypr/.config/hypr/scripts/motion-lint
- **Verification:** Default run went from 10 spurious CHECK B failures to 0; `hyprland-tokens.lua` no longer appears in the surface list at all (by design — it is loaded separately as a definition source, not scanned as a surface); `motion-lint --self-test` and `--no-pending` both unaffected (14/14, 0 fail).
- **Committed in:** `de4977b` (Task 2 commit)
