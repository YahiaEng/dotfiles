<objective>
Retarget every tool that reads a file this phase is about to delete — before deleting it.

Purpose: this repository has a recorded decision named "consumer-check before retiring a toolkit",
written after a retirement left half-done consumers behind. Four live tools read hyprlang files
that plan `13.1-10` removes: `keybind-doctor` and `cheat-sheet-parser.sh` parse
`config/keybinds.conf`; `gaming-mode-toggle.sh` reads the generated
`~/.local/state/theme/hyprland.conf`; and `theme-stress-test` names that same generated file as a
required representative file. Deleting first and discovering that afterwards is how a one-way door
becomes an outage.

`keybind-doctor` matters more than the others: it is MAINT-01's instrument, it is the proof
mechanism for QS-05's no-duplicate-global-keybind requirement, and Phases 14 and 16 each add a
global keybind that it must be able to check.

Output: four retargeted tools, each proven to produce the same result on the Lua source as it did
on the hyprlang source. This plan runs during the soak window opened by `13.1-08` and changes
nothing about the running config.
</objective>

Point both parsers at `config/keybinds.lua` and prove the retarget produced identical results.

**`cheat-sheet-parser.sh`.** Change `CHEAT_SHEET_DEFAULT_CONF` to
`$HOME/.config/hypr/config/keybinds.lua` and rewrite its three extraction rules for Lua syntax:
a bind line is an `hl.bind(` call rather than a `bind… =` assignment; a description is the trailing
comment on that line, now introduced by the Lua comment marker rather than the hyprlang one; and a
section banner is a full-line Lua comment carrying the same box-drawing banner shape the hyprlang
file used. Keep the parser's stated invariant intact: it reads the file as text, extracts, and
never evaluates it. Preserve the existing display-only banner cleanup and the verbatim-description
rule — `cheat-sheet.sh` depends on both.

**`keybind-doctor`.** Change the `KEYBINDS_CONF` default to the Lua module, keep the optional
path-argument mechanism exactly as it is (it is what makes the poisoned-fixture proofs possible),
and rewrite the parsing layer only:
  - main-modifier resolution now reads the Lua local rather than a hyprlang `$variable`
    assignment, and the check text should name what it actually read;
  - declared-bind extraction now matches `hl.bind(` calls, and the reported source location
    should name the Lua file and line so the `file:line` diagnostics stay actionable;
  - the flag-letter normalisation logic that maps a hyprlang declaration keyword onto the
    compositor's reported form now maps the Lua options table instead — the `release`, `locked`,
    `repeating` and `mouse` fields;
  - the missing-description check applies to the Lua trailing comment;
  - the launcher-flag static grep keeps checking for the same known-broken invocation, against the
    Lua file.
  Everything downstream of parsing — the cross-check against the compositor's actual bind dump, the
  duplicate detection, the Quickshell global-shortcut manifest cross-check, the shape guard — stays
  unchanged. This is a parser swap, not a rewrite of what the tool checks.

**Prove equivalence, do not assume it.** While `keybinds.conf` still exists, run each tool against
both sources and compare:
  - `cheat_sheet_parse_binds` over the hyprlang file and over the Lua file must produce the same
    parsed set — same number of entries, same key descriptions, same section grouping. Diff the two
    outputs.
  - `keybind-doctor <path-to-keybinds.conf>` and `keybind-doctor <path-to-keybinds.lua>` must
    report the same pass and fail counts and the same exit code.

**Prove it can still fail.** The Phase 11 repair established that `keybind-doctor` carries
proven-to-fail behaviour, and that property must survive the parser swap. Create a throwaway
poisoned copy of `keybinds.lua` — one bind with its description comment removed, and one bind
duplicated — and confirm `keybind-doctor <poisoned-path>` exits non-zero and names both problems.
Do not commit the poisoned copy unless the tool's existing fixture convention calls for it.

Do not leave a fallback that reads `keybinds.conf` when the Lua file is missing. A silent fallback
would mean the retirement in `13.1-10` could break these tools without anyone noticing until the
next time someone opened the cheat sheet.
