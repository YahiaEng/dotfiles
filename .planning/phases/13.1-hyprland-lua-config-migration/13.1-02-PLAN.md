<objective>
Prove the entire migration mechanism end-to-end on one thin, production-quality path: a real
compositor booting a real Lua config that consumes a real generated token table produced by the
real theme-engine renderer — then prove rollback.

Purpose: this phase has two genuinely novel architectural spines, and both are cheap to prove now
and ruinous to discover late. Spine one is that a Lua config boots at all and is measurable
against the committed baseline. Spine two is that `require()` — which silently prefixes every
module path with the Hyprland config root — can reach a token file that lives in
`~/.local/state/theme/`. If either fails, everything downstream changes shape. Ten ported files
later is the wrong time to find out.

Output: the merged `lua-table` token pipeline, a bootable (but deliberately inert)
`hyprland.lua.disabled`, one ported config module, the `stow.sh` guarantees that make the token
file always exist, and recorded evidence of format selection, rollback and graceful degradation.

**What is deliberately NOT in this slice:** the other seven config modules. Those are functionality
gaps that later plans fill without changing any of the architecture proven here. Nothing in this
slice is a throwaway — every file written here is part of the final system.
</objective>

**Layer 1 — colour emission.** Create `matugen/.config/matugen/templates/hyprland-colors.lua` as a
*new, additive* template (leave `hyprland-colors.conf` in place — the hyprlang output is still the
D-12 rollback target's input and must keep being produced). It returns a flat Lua table: one
`<name> = "<value>",` entry for every `$<name> = <value>` assignment in
`hyprland-colors.conf`, same names, same `{{colors.X.default.hex_stripped}}` placeholders, same
`rgba(…ff)` wrapping, the same literal `rgba(00000055)` for `shadow`, and the same deliberately
blank value for `image`. Register it in `matugen/.config/matugen/config.toml` as a new
`[templates.hyprland_lua]` block with `input_path = "~/.config/matugen/templates/hyprland-colors.lua"`
and `output_path = "~/.local/state/theme/hyprland-colors.lua"`. Add no `post_hook` —
`lib/reload.sh` is the sole reload-fan-out owner (D-04).

**Layer 2 — the assembler.** In `theme-engine/.config/theme-engine/lib/motion.sh` add
`theme_engine_render_hypr_tokens <tmp_dir>`, called from `theme_engine_render_motion_files` after
its existing validation gate and after the current `hyprland-motion.conf` emission (which stays).
It writes ONE file, `$tmp_dir$STATE_DIR/hyprland-tokens.lua`, whose entire content is a header
comment plus a single `return { colors = { … }, motion = { … } }` table:
  - `colors` — read from `$tmp_dir$STATE_DIR/hyprland-colors.lua` (the fragment matugen just
    rendered into the same tmp tree). If that fragment is absent — which is exactly the fresh
    install/seed case where matugen has not run — emit `colors = {}` and continue; do not fail.
    After consuming it, remove the fragment from the tmp tree so it never reaches
    `~/.local/state/theme/` and never needs a `contract.json` entry.
  - `motion.enabled` — the same boolean `$motion_enabled` currently emitted.
  - `motion.speed.<token>` — one numeric entry per current `$motion_speed_<sem_token>` and
    `$motion_speed_indicator_<ind_name>` variable, key name = the variable name with the
    `motion_speed_` prefix stripped (so `$motion_speed_standard` becomes `speed.standard` and
    `$motion_speed_indicator_border_rotate` becomes `speed.indicator_border_rotate`). Reuse the
    existing `awk` `%.2f` conversion and `MOTION_HYPR_SPEED_DIVISOR_DS` divisor unchanged — the
    numbers must be byte-identical to what `hyprland-motion.conf` emits today.
  - `motion.curves.<key>` — one entry per `.easings` key in `$MOTION_JSON`, shaped
    `{ type = "bezier", points = { {x0, y0}, {x1, y1} } }` from the same four floats the current
    `bezier = motion-<key>, x0, y0, x1, y1` line emits. Note this is a structural change, not a
    textual one: four flat floats become a nested points array.
Values reach the file only through a quoting table-literal writer — every string value is written
with explicit surrounding quotes and any embedded quote or backslash escaped, and numeric values
are written unquoted. Never `printf` a raw value into Lua source without that treatment: unlike
hyprlang's `$var = value`, a `.lua` file is executed. Do not add a new Lua-specific validator;
extend the scope of the existing pre-write JSON validation instead.

**Layer 3 — the contract.** Add exactly one entry to
`theme-engine/.config/theme-engine/contract.json`: `{ "name": "hyprland-tokens.lua", "format":

**Layer 4 — reaching the file from inside the Hyprland config root.** `require()` is not stock Lua

cannot be required by its real path. In `stow.sh`, next to the existing motion-file seed block:

**Layer 5 — the Lua config.** Create `hypr/.config/hypr/lib/tokens.lua`, a small module exporting a
single `get()` function that returns the normalised token table: it calls `require` on
`"state.tokens"` through `pcall`, substitutes an empty table when the call fails or returns a
non-table, then guarantees `colors` and `motion` (and `motion.speed`, `motion.curves`) are tables
before returning. Every consumer obtains tokens by calling this function — never by reading a value
a previously-loaded module happened to set. That is what makes the D-13 "no module depends on
another being loaded first" property structurally true rather than a convention.

Create `hypr/.config/hypr/config/env.lua` containing the two `hl.env(<name>, <value>)` calls
translating `env.conf`'s two `env = ` declarations, positional two-string form as demonstrated by
the shipped example.

Create `hypr/.config/hypr/hyprland.lua.disabled` (the `.disabled` suffix is load-bearing: Hyprland

ported entry point named `hyprland.lua` would silently take over the next real login. The file is
renamed to `hyprland.lua` only at cutover). It must:
  - obtain the token table by calling `require("lib.tokens").get()` — the defensive read above is
    where D-13's guarantee actually lives; the `stow.sh` seed is the belt, this is the braces;

  - call `hl.config({ general = { … } })` reproducing `hyprland.conf` lines 27-35 exactly:

    `{ colors = { <primary>, <secondary>, <tertiary> }, angle = 45 }` and
    `col.inactive_border` as `<outline>` — where each of those four values is
    `tokens.colors.<name>` with an `or "<the literal value the hyprlang emitter produces today>"`
    fallback. Read the current values out of `~/.local/state/theme/hyprland.conf` to source those
    literals; do not invent them.

**Layer 6 — the verification harness.** The executor is running inside the compositor it is
migrating, so it cannot restart the live session to test a Lua config. Build
`hypr/.config/hypr/scripts/hypr-lua-harness` (executable, `#!/usr/bin/env bash`, `set -uo pipefail`)
once here — plans `13.1-03` through `13.1-08` all use it, so it is a real committed tool, not
throwaway scaffolding. Subcommands:
  - `start [--with-autostart]` — refuse (exit non-zero) if `~/.config/hypr/hyprland.lua` exists,
    because that would mean the live session is already on Lua and a nested run is not what the
    caller thinks it is. Otherwise `mktemp -d` a throwaway root, create `<root>/hypr/`, symlink
    every entry of `~/.config/hypr/` into it *except* `hyprland.conf`, and write
    `<root>/hypr/hyprland.lua` as a copy of `~/.config/hypr/hyprland.lua.disabled` with the
    `require("config.autostart")` line filtered out unless `--with-autostart` was passed —
    asserting that exactly one line was removed, so the harness entry point can never drift from
    the real one. Autostart is excluded by default because a nested instance running this repo's
    17 `exec-once` lines would spawn a second waybar, swaync, walker, quickshell and wallpaper
    daemon and fight the live session over layer namespaces and the
    `org.freedesktop.Notifications` bus name. Launch `Hyprland` nested with
    `XDG_CONFIG_HOME=<root>`, wait for the new entry to appear in `hyprctl instances -j`, and
    print its instance signature.
  - `hyprctl <args…>` — forward to `hyprctl -i <signature> <args…>` against the running nested
    instance.
  - `status` — print the signature, or exit non-zero when nothing is running.
  - `stop` — terminate the nested instance and remove the throwaway root.
The harness never writes to `~/.config/hypr/` and never writes into the repository working tree.

**Prove it end to end.** Start the harness, verify against the committed baseline (see acceptance
