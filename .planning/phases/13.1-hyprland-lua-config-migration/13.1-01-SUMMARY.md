# Phase 13.1 Plan 01: Baseline & Equivalence Gate Summary

**Built the read-only `hyprctl`-backed equivalence gate (modelled on `waybar-equivalence-check`) and used it to capture the committed pre-migration baseline — 80 binds, 46 option records, 4 documented-uncovered permission grants — from the still-hyprlang 0.56.1 compositor before any config file was touched.**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-07-28T02:25:13Z
- **Tasks:** 2
- **Files modified:** 7 (1 script + 6 new committed artifacts)

## Accomplishments

- `hypr-equivalence-check` — a new, executable, read-only tool with `--snapshot <outdir>`, `--uncovered`, `--baseline <dir>`, and a default check mode that diffs live `hyprctl -j binds`/`-j animations`/per-key `-j getoption` output against a committed baseline, exiting 0 only on exact match
- Option-key extraction parses the 8 hyprlang config files at run time (brace-nested block tracking, colon-joined key addressing matching `hyprctl getoption`'s own scheme) — never a hardcoded key list, verified live against the installed 0.56.1 binary for both flat (`decoration:rounding`) and deeply nested (`decoration:blur:enabled`, `decoration:shadow:offset`) keys
- D-10 gate semantics proven live in both directions: an altered baseline (`decoration:rounding` changed 12→99) FAILs with a unified diff naming the key; an absent/empty baseline FAILs with `FAIL` in the output and exit 1 — never a SKIP, never exit 0
- Committed `.hypr-baseline/` captured from the live, still-hyprlang compositor: `binds.json` (80 binds, matching the 63+4+6+4+2+1 = 80 declared across `keybinds.conf`), `animations.json`, `options.jsonl` (46 records, all valid JSON), `uncovered.txt` (4 permission-grant entries), `MANIFEST.md` (auto-generated `## Documented coverage limits (D-16)` section with reason + named compensating check per entry)
- Self-consistency proof: default-mode run against the freshly committed baseline on the still-live session passes 3/3 (PASS: 3 FAIL: 0), confirming the diff path itself works before any migration edit lands
- `COVERAGE.md` written with the reasoned `No external API integration: ...` declaration, satisfying the deterministic api-coverage detector that fires on the ROADMAP's "Lua API" wording

## Decisions Made

- Permission grants have no `hyprctl getoption` representation at all (not a lookup failure — there is structurally no per-grant key), so the snapshot script emits explicit synthetic `uncovered.txt` entries for the 4 grants rather than relying on a getoption failure to surface them; the compensating-check reference (13.1-06's side-by-side textual review) is baked directly into each entry's reason text so `MANIFEST.md`'s D-16 section is fully auto-generated and satisfies the acceptance criteria with no manual post-edit step.
- `ecosystem:enforce_permissions` (the toggle controlling whether grants are enforced) IS getoption-visible and resolves normally into `options.jsonl` — only the per-grant paths/types/modes beneath it lack introspection. This is a narrower and more accurate framing than treating the whole `ecosystem { }` block as uncovered.
