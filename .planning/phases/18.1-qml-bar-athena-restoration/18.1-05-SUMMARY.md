# Phase 18.1 Plan 05: Bar Drawers — Hover-Reveal Integrated With BarReveal Summary

**Both bar drawers (apps, settings) converted from click-toggle to hover-reveal with a dwell-open/grace-close contract, reading the bar's own reveal-machine settledness through an already-proven QsWindow.window handle rather than a second, competing hover system**

## Performance

- **Duration:** ~30 min, single session
- **Started:** 2026-08-11T14:53Z (approx)
- **Completed:** 2026-08-11T15:02Z (UTC)
- **Tasks:** 3/3

## Accomplishments

- Added a local hover-reveal mechanism to `LauncherCapsule.qml`'s apps drawer: `drawerHoverActive` fed by both the trigger cell's and the drawer strip's `HoverHandler`s through one `reportDrawerHover(source, entered)` entry point, so the pointer crossing the trigger-to-drawer gap never reads as a clean exit. `drawerDwellTimer` (`Design.popoutDwellMs`) opens the drawer only if still hovered AND `drawerSettled` at fire time; `drawerGraceTimer` (`Design.popoutDismissGraceMs`) closes it only if still unhovered at fire time — both re-evaluated inside the timer's own `onTriggered` body, not merely checked when armed.
- Mirrored the identical mechanism onto `ClockActionsCapsule.qml`'s settings drawer — same property names, same timer ids, same token references, verified structurally diffable to zero after normalizing the capsule id. `SettingsAxisCell`'s own click-launch-then-collapse behaviour and the settings trigger's plain `filled: settingsExpanded` binding (no new `fillActive` background) are both byte-unchanged.
- `drawerSettled` reads `Bar.qml`'s live `barRendered`/`barTransitionRunning` through the `QsWindow.window` handle — the same reachable path `ClockActionsCapsule.qml`'s pre-existing `barIdleInhibitor` binding (`window: QsWindow.window`) already proves live, confirmed as Task 1's precondition before writing the gate. Neither file references `PopoutController`, its dead `barSettled` latch, or `BarReveal` itself at all (0 matches in both files) — the drawer expands inside the bar's own window, which `Bar.qml`'s existing whole-content `barHoverHandler` already reports as hovered, so the bar's re-hide grace covers an open drawer with zero new wiring.
- An expanded drawer collapses immediately, with no grace, the instant the bar stops being settled — `onDrawerSettledChanged` stops both timers and calls `requestCollapse()` unconditionally, closing QBAR-07's boundary case (a drawer surviving into a hidden bar and reappearing expanded on the next reveal).
- Task 3 produced a written four-leg integration proof (grace ordering 200<600, dwell fire-time re-gate, bar-hide immediate collapse, zero `BarReveal` writes), all established by source assertion — this host has no synthetic pointer-input tool, a standing project finding, not new to this plan. Filed three honest `WINDOWS.md` `unrun-verify` rows (54-56) naming exactly which legs were not live-observed, deferred to plan 18.1-07's GATE-02 walkthrough.
- Restarted `quickshell.service` after Tasks 1 and 2 and confirmed a clean `Configuration Loaded` with zero new QML `WARN`/`ERROR` lines each time.
