## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed illegal Positioner-anchors layout bug before it shipped**
- **Found during:** Task 3 (updates fill pill)
- **Issue:** The plan's literal text describes `updatesFillPill` as a Rectangle placed "behind the updates Readout" with its own `visible: pendingUpdatesCount > 0` condition — implemented as a sibling item using `anchors.fill: updatesReadout`, this became a third child of `BarCapsule`'s `contentGrid` (a Grid Positioner via the `default property alias content: contentGrid.data` mechanism), and Qt Quick forbids anchors on a Positioner's direct children. Confirmed live: `quickshell.log` logged `QML Grid at @modules/bar/BarCapsule.qml[74:5]: Cannot specify anchors for items inside Grid. Grid will not function.` after this first attempt, and the bar's hot-reload subsequently stopped picking up further file edits.
- **Fix:** Moved the Rectangle inside the `Readout` component definition itself, gated by a new `property bool filled: false` (set `true` only on the updates instance), with its geometry bound to `readoutItem.width`/`readoutItem.height` instead of `anchors.fill`. It still renders behind the entry's glyph/value content by declaration order (declared before `entryGrid`), and inherits the instance's own `visible: pendingUpdatesCount > 0` gate for free — no separate condition to keep in sync.
- **Files modified:** `quickshell/.config/quickshell/modules/bar/SystemCapsule.qml`
- **Verification:** Restarted `quickshell.service` (`systemctl --user restart`) for a clean reload; `quickshell.log` carries zero warnings/errors from that restart through both live click tests. Screenshot confirms the green filled pill renders correctly behind only the updates glyph.
- **Committed in:** `6fdcf4c` (Task 3 commit)
