# Phase 18.1: QML Bar Athena Restoration - Context

**Gathered:** 2026-08-11
**Status:** Ready for planning
**Source:** ADR Ingest Express Path (docs/superpowers/specs/2026-08-11-qml-bar-athena-restoration-design.md)

<domain>
## Phase Boundary

Restore the Athena waybar's visual language to the Phase 18 Quickshell QML bar, which the operator judged worse than the bar it replaces. This is GATE-02's verdict, arriving before 18-20 deleted the waybar package rather than after. Root cause is one architectural decision, not four bugs: Athena applies colour as background fills across primary/secondary/tertiary, while the QML bar applies it as foreground tint only (`Colours.secondary` is never referenced once under `modules/bar/`). This is a styling and interaction job on an existing, near 1:1-complete module set — not a re-architecture. Phase 18's "redesign toward end-4/Caelestia rather than straight-port" premise is reversed for this surface.

</domain>

<decisions>
## Implementation Decisions

### Design target
- **D-01:** Bring Athena's look back — Phase 18's end-4/Caelestia redesign premise is reversed for the bar surface; Athena's `theme.scss` and waybar config are the reference, not a modern reinterpretation.
- **D-02:** Restore all four items in the restore set, not a subset: filled colour pills, hover-reveal drawers, Athena glyph set plus pacman state glyphs, and icon-only resource pills at rest.

### Colour architecture
- **D-03:** Introduce a new bar-scoped colour role layer at `modules/bar/BarRoles.qml`, registered as a singleton in the bar `qmldir`, mirroring Athena's `theme.scss` role names — not per-capsule colour edits.
- **D-04:** Every `BarRoles` row maps to a named Athena `theme.scss` source and a Material You `Colours.*` source, so the table diffs line-by-line against `theme.scss`: barSurface=alpha(surface,0.55), barSurfaceHover=alpha(surface,0.78), capsule=alpha(surfaceVariant,0.85), capsuleFg=onSurfaceVariant, capsuleHover=alpha(surfaceVariant,0.95), capsuleTrack=alpha(outline,0.5), accent/onAccent=primary/onPrimary, warn=tertiary, danger/onDanger=error/onError, fillClock/fillClockFg=secondary/onSecondary, fillUpdates/fillUpdatesFg=tertiary/onTertiary, fillNotification/fillNotificationFg=primary/onPrimary.
- **D-05:** The `alpha()` values are load-bearing and must be preserved exactly — Athena's capsules are translucent (`surfaceVariant` at 0.85 over a bar surface at 0.55, on blur); opaque capsules read as a solid grey slab and directly cause the "clunky" complaint.
- **D-06:** Consumption rule — after this change no file under `modules/bar/` references `Colours.*` directly; everything routes through `BarRoles`. This is the executable form of the promise `WorkspaceCapsule.qml:90` made in a comment while the code broke it.

### Component changes
- **D-07:** `WorkspaceCapsule.qml` focused slot changes from foreground tint to a filled pill — `background: BarRoles.accent`, `color: BarRoles.onAccent` — replacing the `color: slotFocused ? Colours.primary : contentColour` tint at line 349.
- **D-08:** Workspace slot identity becomes Athena's state glyph set with no numeral: active `󰮯`, default `󰊠`, urgent `󰧵`. Accepted cost, decided deliberately: loses the numeral's visual mapping to Super+N.
- **D-09:** Workspace glyph cells switch from `"Material Symbols Rounded"` (`Design.qml:103`) to FiraCode Nerd Font, which is already installed and carries both codepoint ranges — no new package needed.
- **D-10:** Restore Athena's full window-rewrite map on the workspace capsule: kitty, firefox, zen, codium, VSCodium, discord, spotify, obsidian, lutris, steam, thunar, yazi, with `󰊠` as the default glyph.
- **D-11:** Diagnose the suspected appId/class mismatch before fixing it — zen is mapped (`{ appId: "zen", glyph: "" }`) yet renders blank, which may be the font alone rather than a mismatch; fixing the wrong layer is the failure mode here.
- **D-12:** `SystemCapsule.qml` cpu/ram/disk entries become icon-only at rest with the value revealed on click, matching Athena's `format-alt`; the updates entry takes the `fillUpdates` background; thresholds use `warn` / `danger`.
- **D-13:** `ClockActionsCapsule.qml` clock takes the `fillClock` background, and the notification entry fills with `fillNotification` when the count is non-zero.
- **D-14:** `BarCapsule.qml` capsule background moves to `BarRoles.capsule` / `BarRoles.capsuleHover`, picking up Athena's translucency.
- **D-15:** `TrayCapsule.qml` is deleted along with its `BarEntryModel` entry and `qmldir` line, after an explicit consumer sweep — matching Athena, whose own config records dropping the tray because nm-applet/blueman icons duplicated the connections group.

### Interaction
- **D-16:** Both the apps drawer (`LauncherCapsule.qml:204`) and the settings drawer (`ClockActionsCapsule.qml:448`) change from click-toggle to hover-reveal; the drawers themselves are already complete and carry the named utilities (theme, wallpaper, font, icon theme) — only the trigger changes.
- **D-17:** Hover-reveal uses a close grace period so the drawer does not snap shut when the pointer crosses the gap between trigger and drawer, mirroring Athena's waybar `group` `transition-duration: 500`.
- **D-18:** Hover-reveal must be explicitly integrated with `BarReveal`'s existing hot-zone state machine and its 600ms grace timer plus create/destroy `HotZone` surface — explicit handling, not incidental coexistence, since two hover systems on one surface is the sharpest integration risk in this design.
- **D-19:** `LauncherCapsule.qml` retains desktop-entry icons — they are launcher icons and should keep following the icon-theme switcher, unlike the tiny workspace glyphs which move to Nerd Font.

### Verification
- **D-20:** Add a `quickshell-doctor` check asserting no `Colours.*` reference survives under `modules/bar/`, extending the structural checks already in `hypr/.config/hypr/scripts/quickshell-doctor` — this converts the failure mode that produced today's bar into a check that fails loudly.
- **D-21:** Diff the `BarRoles` table line-by-line against Athena's `theme.scss`; every row has a named source so this check is mechanical.
- **D-22:** Capture live screenshots of the workspace capsule with a browser, terminal and file manager open — the glyph fix is precisely the kind that passes code review and renders tofu.
- **D-23:** GATE-02 is judged side-by-side by the operator running Athena and the QML bar together, and passes only when the operator says the QML bar is at least as good; 18-20 stays blocked until it passes.

### Claude's Discretion
- Exact QML property/binding style within `BarRoles.qml`, provided every row keeps a named `theme.scss` source and the alpha values from D-04/D-05.
- The mechanism used to implement the hover grace period (Timer, state machine extension, or shared component), provided D-18's explicit `BarReveal` integration holds.
- Task/plan sequencing and wave assignment, provided the diagnose-before-fix ordering in D-11 and the consumer sweep before deletion in D-15 are preserved.

</decisions>

<specifics>
## Specific Ideas

Operator's verdict, verbatim — this is the bar the phase must satisfy:

> "The new bar looks nothing like my Athena waybar. It is so much worse. No colors, big and clunky, nothing expands like Athena that shows my utilities (theme changer, wallpaper picker, etc), the workspace only has icon for terminal (no browser, no pacman icon indicating the selected workspace)"

Complaint-to-finding mapping that constrains what may be changed:

- "No colors" — colour applied as foreground tint, never as fill; `secondary` unused, `tertiary` near-unused; dominant roles are `onSurfaceVariant` (29 uses) and `surfaceVariant` (14), neutral greys.
- "Big and clunky" — **not geometry.** `barHeight: 40` / `barEdgeMargin: 6` / `barSideMargin: 10` are identical to Athena's `height: 40` / `margin-top: 6` / `margin-left|right: 10`. The causes are always-on `4% 36% 7%` text, the extra tray capsule, and flat opaque grey capsules with no colour hierarchy.
- "Nothing expands" — the drawers exist and are complete (8-entry apps launcher; settings drawer with theme, wallpaper, font, icon theme). Nothing is missing; only the trigger changed from hover to click.
- "Only terminal has an icon" — `symbolFontFamily` is Material Symbols Rounded, which carries none of Athena's Nerd Font codepoints; kitty's `󰆍` renders only via fontconfig fallback.
- "No pacman icon" — deliberately dropped in Phase 18; `WorkspaceCapsule.qml:85-93` records the choice and defers to GATE-02's judgment. It did not read as well.

</specifics>

<scope_fence>
## Scope Fence — Out of Scope

- Any change to popout content or the `SectionPopout` framework — not complained about.
- The bar's geometry tokens — measured identical to Athena's, so geometry must not be touched to chase "big and clunky".
- Retiring waybar (18-20), which this work unblocks but does not perform.
- QBAR-11's soak and its verdict.

</scope_fence>

<risk_summary>
## Risk Summary

1. **Hover-reveal vs `BarReveal`.** Two hover systems on one surface — a drawer opening while the bar is mid-reveal, or two grace timers racing. Sharpest integration risk in the design (see D-18).
2. **Deleting `TrayCapsule`.** 30K, the module's largest file. Requires an explicit consumer sweep beyond `BarEntryModel` and `qmldir` before removal (see D-15).
3. **The appId mismatch is inferred, not proven.** Concluded from zen being mapped yet blank; it could instead be purely the font. Diagnose before fixing, or the wrong layer gets changed (see D-11).
4. **Losing the numeral** is a real usability cost against Super+N, accepted deliberately (see D-08).
5. **QBAR-11's soak stays open** regardless — it needs an uninterrupted 4-hour window, and any of this work restarts the shell.

</risk_summary>
