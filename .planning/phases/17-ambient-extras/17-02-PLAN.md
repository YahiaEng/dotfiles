<objective>
Give the live wallpaper a still frame, and give that frame the two jobs `current.jpg` already has: the lock-screen background on every unlock, and the Material You palette source. Then make the state that carries it survive a theme switch, a wiped state directory, a deleted video, and a hostile `last-wallpaper` value.

This is the theme-engine half of AMB-01. 17-01 proved the player; this plan proves the pipeline around it — extraction, coupling, validation, and the gate that notices when any of it is missing.

Purpose: two RESEARCH findings here are trap-shaped and both fail *silently*. Placing `-ss` before `-i` produces zero output for animated WebP while still working perfectly for mp4 and gif, so an mp4-only test passes and the bug ships. And ffmpeg exits 0 with no output file on an out-of-range seek, so an exit-code check reports success for a frame that does not exist. Both traps end in the same place — a lock screen with no background and a palette derived from a stale pointer, with nothing anywhere reporting a failure. This plan turns both into assertions that fail if the trap is reintroduced.

Output: an ffmpeg frame extractor with the verified command shape; `wallpaper-frames/` as a registered engine-owned state directory; `current.jpg` repointed at the frame in every mode with palette coupling still Material-You-only; the T-05-07 last-wallpaper validator widened precisely; the `live/` autoset enumeration pass; the deleted-wallpaper fallback; and a conditional `theme-doctor` gate.

**Precedence note (RESEARCH.md corrects CONTEXT.md).** CONTEXT.md's open question framed the seek step as possibly needing a per-format command split. RESEARCH.md reproduced it locally three times and settled it: one command shape suffices and the fix is positional, not per-format. Do not branch on input type.

**Scope boundary — what this plan deliberately does NOT do.**
- **It does not touch `wallpaper-picker.sh`.** The picker's writer-side guard at `wallpaper-picker.sh:346` (`[[ "$BARE_FILENAME" != */* ]]`) is the mirror of the validator widened here, and it is **17-03's** to widen. Until 17-03 lands, the picker cannot *record* a live choice; this plan's own autoset write-back can, and that is the path exercised here.
- **It does not call `wallpaper-visibility.sh`.** D-21's wiring of theme-apply's wallpaper step to the owner's `reassert` is 17-03's. Adding it here would put two writers on one process lifecycle — the exact bug class D-14 exists to prevent.
- It does not touch the picker preview (D-18), the hover debounce (D-19), the Esc restore (D-20), the suppression states (D-28/D-30/D-31), or the blocking human render-and-look gate — all 17-03.

**Known intermediate state between this plan and 17-03, recorded so it is not mistaken for a regression.** After this plan, selecting a live wallpaper updates the lock screen and the palette input and shows the extracted frame through `awww`, but does not yet start the player. That is exactly the brief static-frame state RESEARCH Pitfall 7 already documents for login, and 17-03 closes it. It is *not* the "silently presents as a static still" failure 17-01 prohibits — that prohibition is about a live wallpaper that cannot play at all, and it stays owned by 17-01.
