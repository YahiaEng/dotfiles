<diagnosis_carried_forward>
Do NOT re-diagnose. These five findings were each established with live evidence in
`.planning/debug/panels-missing-animated-border.md` and are inputs, not questions:

1. **Root cause.** `PanelDialog.qml:157-174`'s background Rectangle declares no border of
   any kind and the file never instantiates `GradientBorder`. `grep -rn GradientBorder`
   over the whole quickshell tree returns exactly one instantiation: `Dashboard.qml:387`.
2. **No geometry coupling.** `GradientBorder` is a bare `Item` whose only geometric inputs
   are its own width/height (via `anchors.fill`) and four independent per-corner radius
   properties. `_ringPath` recomputes from `root.width`/`root.height`. It already renders
   at three different drawer sizes (760x826, 1040x450, 760x514); the panel's 850x620 is
   inside that range.
3. **The Qt6 Shapes constraint is already solved inside the component.**
   `GradientBorder.qml:110-147`'s `_roundedRect(x,y,w,h,tl,tr,br,bl)` builds the SVG path
   in JS with four independent radii and conditionally omits the arc when a radius is 0.
   The panel's corner set (0/0/28/28) is **byte-identical** to the drawer's — the exact
   case that workaround was written for.
4. **The `default property alias body` capture hazard does not bite.** Poison-proven under
   qml6 6.11.1: a child declared in the SAME file as the alias stays a direct child of the
   root; only call-site children are captured. Exit 0 on the honest run, exit 5 on the
   poisoned run. Corroborated in-tree: `background`, `grab`, `content` and `advancedProcess`
   are already bare same-file children of `PanelDialog` and render correctly.
5. **No content collision.** `Design.panelPadding` is 24 and `bodyFlick` uses
   `anchors.margins: panelPadding`; the header's identity Row and the Advanced button both
   use the same margin. A 3px rim clears all panel content by 21px. No reflow, no call-site
   adjustment.
6. **No import change needed.** `PanelDialog.qml` already resolves siblings by bare name
   (`Cascade {}` at :189, `Design.*` at :138-152) with only `import "../"` in scope, and
   `GradientBorder` is registered in the same `modules/dashboard/qmldir` (line 70).
</diagnosis_carried_forward>

<the_open_judgment_call_resolved>
The gap record names exactly one open decision: *"Decide deliberately where `borderWidth`
3 lives — Dashboard.qml:233-239 names it there 'so the parity claim has one home'; a second
copy splits that home, and GradientBorder's own default is already 3."*

**Resolved: hoist it into `Design.qml`.** Not "declare a second copy in PanelDialog"
(splits the home, which is the thing Dashboard's own comment warns against) and not "rely
silently on GradientBorder's default" (the drawer would follow a future Hyprland
`border_size` change and the panels would silently not, drifting apart with nothing to
catch it).

`Design.qml` is already exactly this mechanism, with a documented per-value provenance
convention in its header, and both `Dashboard.qml` (`import "dashboard"`) and
`PanelDialog.qml` (`import "../"` plus same-directory resolution) already read from it. It
is the only location that is genuinely ONE home reachable from BOTH surfaces. Task 1 does
the hoist and proves the drawer's rim is unchanged before Task 2 adds the second consumer.
</the_open_judgment_call_resolved>
