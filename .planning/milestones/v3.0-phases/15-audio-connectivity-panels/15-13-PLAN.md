<objective>
Close gap **G-15-4**: a wrong wifi password opens an external dialog rendered behind the
panel, instead of the row-scoped copy inside it.

Window ownership is **confirmed, not inferred**: nm-applet, PID 1018, the sole registered
NetworkManager secret agent (the only agent-registration line in the whole boot). The full
causal chain was recovered from the actual UAT session's journal — the supplicant reports a
4-way handshake failure, NetworkManager logs `psk mismatch reported by supplicant, asking
for new key`, re-enters `need-auth`, and issues GetSecrets to the registered agent, which
answers with its own GTK dialog. **NetworkManager does not fail an activation on a PSK
mismatch — it re-asks.**

Three hypotheses were eliminated with evidence: the panel *does* supply the passphrase (NM's
audit log records `connection-add-activate` from the live quickshell PID, followed by
`secrets exist. No new secrets needed.`); it is *not* a z-order or styling problem (it is
another process's GTK toplevel, and a layer-shell overlay is unconditionally above every XDG
toplevel in Hyprland, so no QML change could ever win); and no polkit agent is involved.

**A second, independent defect sits underneath the dialog.** `WifiBackend.qml:310-325` maps
"Wrong password" to one failure reason only, but the reason NetworkManager actually emitted
was `no-secrets`, which maps to "Password required" — and `WifiPanel.qml:249` then re-expands
the password row on it. Fixing the dialog alone does not deliver the copy the user asked for.

Purpose: make the panel genuinely self-contained for the most common possible error.

Output: nm-applet's autostarted agent suppressed reproducibly under stow, the failure NM
emits with no agent registered measured rather than guessed, and the row-scoped copy wired
to be reachable for that measured reason.
</objective>

<stow_fold_hazard>
`stow.sh` carries three worked examples of one bug class, each written after it cost real
rework: a package shipping a file under a parent directory that does not yet exist makes
stow fold the ENTIRE parent into a symlink pointing into the cloned repo, after which every
later write by any program lands inside the repo tree. `~/.config/hypr`, `~/.local` and
`~/Pictures` each have a `mkdir -p` guard for exactly this reason, and the file's own audit
note claims every package ships exclusively under `~/.config/<pkg>/` or `~/.local/<pkg>/`.

This plan makes that audit note false — it ships a file under `~/.config/autostart/`, which
does not exist. The guard is not optional and the audit note must be updated in the same
commit, or the next reader trusts a claim that no longer holds. `swaync`'s stowed systemd
drop-in is the in-tree precedent for a package shipping outside its namesake directory with
a matching pre-create.
</stow_fold_hazard>
