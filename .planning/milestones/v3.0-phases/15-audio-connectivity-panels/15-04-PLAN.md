<objective>
Build the audio panel out from 15-02's proven tracer into the panel PANEL-01 and
PANEL-02 actually describe.

Above the fold: a **pinned control block** — master volume and mute, an output
device picker and an input device picker as inline expanding rows, an input level
slider and a mic mute — that never scrolls and is the panel's declared focal
point (D-15-10, UI-SPEC Dimension 2). Below it: the **scrolling per-app mixer
list**, one row per live PipeWire stream, each row icon-as-mute plus application
name plus slider (D-15-13). Around both: the four widget states rendered
honestly, including the two states this panel can reach that no other panel can —
nothing playing, and PipeWire itself unreachable.

Purpose: this is the plan that makes the audio panel worth summoning. After
15-02 a person could change master volume; after this plan they can see what is
making sound, silence one application without silencing the rest, move audio to
another output device and mute a microphone — the whole reason PANEL-01 and
PANEL-02 exist, and the reason pavucontrol stops being a daily-opened app.

Output: two files, both of which already exist and are already registered in
`modules/dashboard/qmldir` by 15-02. No new QML type, no new `qmldir` line, no
new keybind, no new layer rule, no `shell.qml` edit. This plan adds behaviour to
two files and nothing else — which is what keeps it parallel with 15-05, 15-06,
15-07 and 15-08 in wave 4.

**Scope fence — what this plan deliberately does NOT do.**

| Element | Why it is out |
|---|---|
| `PanelDialog.qml` edits | Not in `files_modified`. The frame's contract is 15-02's; anything this panel needs that the frame lacks is composed locally and surfaced, never bolted onto the shared frame from a leaf plan. |
| Per-app peak level meters | Declined by D-15-13 as polish. Re-addable later inside the row's existing structure; not this plan's scope. |
| A second navigation model (tabs, sub-views) inside the panel | Rejected by D-15-10's own reasoning — the drawer already taught swipe-between-views and a second model inside a panel would be a third. |
| Any floating-popup device picker | Banned by D-15-12. The inline expanding row is the idiom, and it is the same one the tiles and the wifi password row use. |
| `quickshell-doctor` extension, waybar rewiring, tile grid | 15-09, 15-08 and 15-07 respectively. |
</objective>

digit boundary, which is exactly the row-reordering PANEL-01's ordering truth

shipped, so nothing is renamed and the ordering has one visible home.

Add `function streamNodeKey(node)` returning that same id as the value delegates
use for row identity. Row identity is the node id and never the application name
— two concurrent streams from one application are two nodes and must render as
