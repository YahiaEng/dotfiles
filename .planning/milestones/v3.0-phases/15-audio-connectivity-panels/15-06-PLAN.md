<objective>
Fill the empty body slot 15-03 deliberately left in the bluetooth panel. At the
end of this plan a person opens the panel, sees at a glance whether their
headset is connected, reconnects it with one press, pairs something new only
when they ask to, and — when a pairing or a connection fails, which is an
ordinary daily event — is told so on the row it happened to, in words, rather
than watching a spinner forever.

That last sentence is the whole engineering problem. `Quickshell.Bluetooth`
exposes **no failure signal at all** — no counterpart to Networking's
`connectionFailed`/`reason` that the wifi panel gets for free. Failure here is
**inferred from property transitions**, and RESEARCH Pitfall 2's recipe is
implemented exactly, including the caveat that distinguishes a genuine failure
from the user's own Cancel, plus the watchdog that keeps a wedged BlueZ from
parking a row on a spinner permanently. The inference lives in the backend, once,
behind one signal — not re-derived per row.

The second thing worth naming up front is a **deliberate asymmetry with the wifi
panel** (D-15-18). Wifi scans continuously for the panel's whole open lifetime;
bluetooth does not discover at all unless the user presses "Add device". That is
not an inconsistency and must not be quietly "fixed" later: a bluetooth inquiry
contends with the same radio that is carrying an A2DP stream, so continuous
discovery can stutter the very audio the panel was opened to manage — and the
daily case, reconnecting known headphones, needs zero discovery to succeed. The
reason is recorded in the backend's own header so the next reader finds it
without archaeology.

Purpose: PANEL-04 — adapter toggle (15-03), list, connect, disconnect, forget —
becomes true end to end.
Output: `BluetoothBackend.qml` gains its device collections, its five verbs, its
discovery lifecycle and its inference machine; `BluetoothPanel.qml` gains the
grouped list, the contextual-verb row, chevron expansion, the pairing spinner
with a real Cancel, the row-scoped failed state and the opt-in discovery section.
</objective>

connected group, paired group, discovery section, discovered group. The connected

must be the first thing on screen without a scroll and without an inquiry. Each
group renders as a quiet heading plus its rows, and **a group whose collection is

heading copy comes from `groupHeadingFor(name)`; the strings themselves are

`Design.fontLabel` in `Colours.onSurfaceVariant`, and raise them at the render

The list renders **whole**. Do not stagger rows into view; D-15-08 rejected that

network list. The only element this file contributes to the frame's entrance is
the focal group, appended to `bodyCascadeBands` so the cascade covers header,

**B. `DeviceRow` — the contextual-verb row (D-15-19).** One inline component,
used by all three groups so a device that changes group does not change shape.
Left to right: the device glyph, the device name, and one trailing action region.

- **Glyph.** `deviceGlyph(device)` maps the BlueZ icon class to a Material
  Symbols Rounded name — headset and headphone classes to their audio glyphs,
  keyboard and mouse and gamepad classes to theirs, phone and computer and
  printer likewise — and returns a generic bluetooth glyph for anything
  unmapped. The device's icon string is used **only as a lookup key and is never

  mitigation and it is two properties, not a mechanism.

  states applies. Fixed width is not cosmetic: it is what makes the "no row state
  changes the list's geometry" truth hold, so a row moving from idle to pending to
  failed never nudges its neighbours or reflows the list under a moving cursor.
  - *Idle* — the label for `backend.contextualVerb(device)`: `Pair` when unpaired,
    `Connect` when paired and disconnected, `Disconnect` when connected. The row's
    press **is** the call to action; there is no separate button. A press anywhere
    on the row outside the chevron calls `backend.pressDevice(device)`.
  - *Pending* — when the backend's pending slot holds this row's address: an
    indeterminate spinner **plus a real Cancel** wired to
    `backend.cancelPair(device)` for a pairing, replacing the verb label. The
    Cancel is the point (D-15-19): this is the one operation whose wait is long
    and user-visible, and a silent watchdog is not an adequate answer to a person
    staring at a spinner. Drive the spinner's rotation from an **existing** Motion
    token — `Motion.borderRotateDuration` is the repo's only rotation period —
    and do not add a token to `motion.json`, which would re-open D-25's semantic
    layer growth policy that D-15-08 was careful to avoid. Gate the rotation on
    `Motion.motionEnabled` so it is static at the `off` setting; the pending state
    stays legible there because it is carried twice, by the spinner glyph's
    presence and by the Cancel replacing the verb.

    pressed again or the panel is dismissed. **No auto-clear timer**: a message
    that vanishes before it is read is exactly the failure the fourth state was
    minted to fix.

  fourth consistent use of the split-affordance idiom and it must read as the same
  affordance the quick-toggle tiles and the device pickers use.

**C. Expansion (D-15-19).** `expandedAddress` is a single slot: expanding one row
collapses any other. Bounded expansion keeps the list from growing under the
cursor and mirrors the player selector's own single-slot `menuOpen`. The expanded
region renders in place, below the row, inside the frame's existing scroll body —
**no popup type of any kind**, here or anywhere in this file. Contents:

- **Battery**, only when the device reports it available. Its absence removes the
  line and nothing else: an ordinary absence, not a degraded row, not a dash, not
  an "unknown" placeholder.
- **Address**, at `Design.fontLabel` in `Colours.onSurfaceVariant`, plain text
  format pinned for the same T-15-08 reason as the name.
- **Forget**, visually separated (see D).

**D. Forget — destructive treatment and the P4 confirm.** Forget sits in its own
sub-region separated from the detail lines by a divider or a full
`Design.spacingMd` gap — **never adjacent to the row's own press action**
(D-15-17's separation requirement). It is `Colours.error`-toned; `Colours.error`
is reserved for exactly this and the failed state, so nothing else in this file
may use it.

Pressing it does **not** forget. It reveals an inline confirm in place, using the
same press-to-reveal idiom the row itself uses: the question naming the device,
a confirming Forget and a Cancel. Only the confirming Forget calls
`backend.forget(device)`. `confirmingForgetAddress` is a single slot for the same
bounded-state reason as `expandedAddress`, and it clears when the row collapses,
when another row's confirm opens, or when Cancel is pressed. **No destructive
action commits on a single press** — that is Prohibition P4, shared with the wifi
panel, and it is the difference between an accidental brush of a trackpad and
re-pairing a headset from scratch.

**E. The discovery section (D-15-18, T-15-04).** One region of **fixed height**,
sitting between the paired group and the discovered group so it reads as the
discovered group's own heading — press it and the section below fills. Two states
inside that one fixed height, so switching between them never moves the rows
above or below:

- *Idle* — a button labelled `Add device`, exactly as the Copywriting Contract
  locks it. Its press is the **only** call site of `backend.startDiscovery()` in

- *Discovering* — an indeterminate progress line in the same treatment D-15-15

**F. The empty case.** When the adapter is present and enabled, no device is
bonded, and discovery has not been started, the list region renders the copy

`Add device` as the only forward path — because it genuinely is the only one.
This branch lives **inside** 15-03's third branch (adapter present and on); it is
not a fourth off-state and must not be composed as one. The distinction matters:
"your adapter is off" and "you have not paired anything yet" are different
sentences and only one of them has an Enable button, which 15-03 already owns.

**G. Failure wiring.** One `Connections` block targeting the backend handling

address and `failedReason` to the reason text. Both are single slots, cleared

most one failure can be current; a map would accumulate stale messages a user
never asked to keep. Record that reasoning inline.

**H. Token discipline, without exception.** Every colour is a role name; every
duration and easing is a Motion token pair; every gap is a `Design.spacing*`
