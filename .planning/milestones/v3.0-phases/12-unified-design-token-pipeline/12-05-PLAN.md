<objective>
Build the eighth rerunnable gate: a deny-by-default motion lint that refuses any surface
hand-rolling its own duration or easing value, refuses any motion token reference that does not
resolve, and proves both refusals against committed poisoned fixtures before it is trusted to
pass anything.

Purpose: D-32 places the lint after the render targets because it needs them to exist — its
definition sets are read from the emitted files. Criterion 3 requires "proven to fail, not
merely observed to pass", and D-28 makes that a permanent, rerunnable property via committed
fixture pairs reached by a path argument, rather than a one-time ceremony of poisoning a real
file.

Output: `hypr/.config/hypr/scripts/motion-lint`, nine committed fixtures, and a
`theme-doctor` fold so the gate runs on every health check rather than only when someone
remembers the standalone script.
</objective>

  <action>
Create `hypr/.config/hypr/scripts/motion-lint`, report-only, never mutating any file, exiting
non-zero if any check FAILs.

**Location decision (Claude's Discretion, recorded):** `hypr/.config/hypr/scripts/` alongside
`waybar-design-lint` and `keybind-doctor`, not `theme-engine/`. The criterion is the one
Phase 11's D-05 set — the gate must stay runnable when the thing it gates has failed. A lint
living inside `theme-engine/` would be reached through the same tree whose render output is
under suspicion, and both the Hyprland and GTK4 surfaces it inspects sit under paths this
directory already has established conventions for reading.

**Header** in `waybar-design-lint`'s banner style, summarising each check in one line and
carrying a `Usage:` block documenting the optional `[target-dir]` path argument. Include
`set -uo pipefail`, `PASS`/`FAIL` counters and the byte-identical `check()` helper shared
across `theme-doctor`, `waybar-design-lint` and `keybind-doctor`.

**Definition sets** — build the resolvable name set once, from the emitted files, never from a
hardcoded list: the `--motion-*` custom-property names declared in `gtk-4.0-motion.css`; the
`semantic` keys in `motion.json`; the `bezier = <name>` curve names and the top-level `$var`
names in `hyprland-motion.conf`. Refuse to proceed with an empty definition set the way
`theme-parity` refuses an empty reference name-set — an empty-versus-empty comparison makes
every subsequent check vacuous, which is the exact false-pass shape this gate exists to
prevent.

**Surface set** — deny-by-default (D-23). Scan every repo-authored file that *could* consume a
motion token: GTK4 stylesheets, Hyprland `.conf` fragments under the hypr config tree, and
`.qml` files under the quickshell config tree. Derive the globs from the target directory (the
path argument) so the same code path serves both the real run and a fixture run. Do not build
an opt-in registry: under an opt-in registry, new surfaces across four remaining phases go
unlinted until someone remembers to register them, and the repo reads compliant while most of
it is not.

**Exemption list** — an associative array near the top of the script mapping a path glob to a
required non-empty reason string, modelled on `waybar-design-lint`'s `AT_RULE_KEYWORDS`
set-literal-near-the-top placement. Two categories of reason exist today and both must appear
verbatim in the entries that need them: "pending Phase 13 retrofit" for the five GTK surfaces
and the 14 Hyprland assignment lines this phase deliberately does not touch, and "GTK3, no
variable mechanism exists" for waybar, swaync and SwayOSD, which have no CSS custom-property
support at all on the installed GTK3. Print one `[EXEMPT]` line per entry with its reason on
**every** run — that visibility is the whole mechanism by which the debt shrinks to zero
rather than becoming invisible, and it hands Phase 13 a checklist. An entry with an empty
reason is itself a FAIL.

Seed the exemptions honestly against the current tree: at the time this task runs, `wleave`'s
stylesheet is still un-retrofitted (plan 12-07 does that) and `animations.conf`'s 14 assignment
lines are hand-authored by D-04's explicit fence. Both need entries with the Phase 13 reason,
and plan 12-07 removes wleave's.

**CHECK A — reference resolution (D-24).** For every non-exempt scanned surface, extract every
motion token reference — a `var(--motion-…)` usage in CSS, a `Motion.<property>` usage in QML,
a curve name in the trailing position of a Hyprland `animation =` line — and diff the set
against the definition set. FAIL on any reference with no matching definition, using UI-SPEC's
dangling-reference message verbatim, citing file and line. This is the half TOKEN-04's own
wording omits and the half that matters most: two of the three targets fail *silently* on a
dangling reference (QML yields undefined, GTK4 drops or falls back); only Hyprland errors
loudly.

**CHECK B — no raw values (D-23).** For every non-exempt scanned surface, strip comments first
(the same discipline `waybar-design-lint` applies before its hex scan), then flag any bare
duration literal — a number immediately followed by a seconds or milliseconds unit — and any
bare timing function, whether a `cubic-bezier(` call or one of the CSS easing keywords. A value
inside a `var(…)` reference is not a raw value; a value inside the emitted definition files is
not either, since those files are definitions rather than surfaces and must be excluded from
the surface set. FAIL with UI-SPEC's raw-value message verbatim, citing file, line and the
matched literal. Take care with the false-positive class D-23 explicitly accepted as a cost:
duration-shaped numbers in comments and in unrelated config keys. Comment-stripping handles the
first; scoping the scan to declaration values rather than whole lines handles most of the
second, and anything left over is an exemption entry with a reason, never a loosened pattern.

**CHECK C — scanned count.** Print the number of surfaces scanned on every run and assert it is
greater than zero, with the UI-SPEC zero-surfaces FAIL text on failure. Deliberately not a fixed
expected count: that would go stale the moment Phase 13 adds surfaces, and a gate that goes
stale gets edited to pass rather than fixed.

**Abort reporting.** If any file in the surface set cannot be read, FAIL naming it and stop
reporting success — do not silently report on the subset that was readable. Failing open is
precisely what criterion 3 requires this gate not to do.

**Output discipline.** One line per check. Paths print in full, never truncated. The summary
line reports `N passed, M failed` with correct singular and plural forms for the failure count,
and the exit code matches.
