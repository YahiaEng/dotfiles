## Wave rationale and file ownership

**Wave 1 — 17-01 alone.** The tracer leads. It is the only plan that proves the architecture end-to-end (owner script → mpvpaper → compositor protocol → pause) before any expansion is built on it, and it is the plan that resolves D-26's shipping-vs-fallback branch. Everything downstream in the AMB-01 track assumes that branch is settled.

**AMB-01 and AMB-02 are independent** — no shared runtime path, no shared source file — with exactly one exception: **`install.sh`**. The tracer must register and install `mpvpaper` to run at all, and 17-04's whole subject is `install.sh`. Same-wave plans must have zero `files_modified` overlap, so 17-04 sits at wave 2 rather than wave 1. From wave 2 onward the two tracks run fully in parallel:

## Cross-cutting obligations for the per-plan planners

- **Precedence:** RESEARCH.md was written after CONTEXT.md and deliberately corrects it — the D-26 mechanism analysis (`-a full` is a protocol path, not the frame-callback hack), the `verify_packages()` canonical-ref citation, `-ss` placement, the MPRIS non-issue, and the third `XCURSOR_THEME` site at `env.lua:9`. Follow RESEARCH.md and note the correction in the plan. Where CONTEXT.md records a *user decision* RESEARCH.md merely has an opinion about, the user decision wins.
- **Every plan** needs `<threat_model>` (ASVS L1, block on high). The concrete surface: the T-05-07 validator widening (17-02), filenames reaching `mpvpaper`/`ffmpeg`/owner argv (17-01/17-02/17-03 — argv-list discipline, never a shell string), and the sudo-scoped hyprpm build from a remote git repo (17-04). `T-{phase}-SC` covers the three audited packages, all `OK`, no `[ASSUMED]`/`[SUS]`/`[SLOP]`.
- **Every plan** needs an "Artifacts this phase produces" section — script names/paths, function names, `install.sh` array entries, `contract.json` keys, Lua module paths, config option names, state-file paths.
- **Spec-less probe fallback:** both AMB-01 and AMB-02 came back `unclassified`/`unresolved` from the edge-coverage probe. Each must be surfaced as an **explicit flagged planner assumption** in the plan that owns that requirement (17-01 for AMB-01, 17-04 for AMB-02) — never auto-resolved with a backstop, never silently dropped. Recalled prohibitions go in `must_haves.prohibitions:` (descriptor-less), not `truths`; the validator widening is canon path-traversal and belongs in `<threat_model>` instead.
- **Reversibility ratings carried from CONTEXT.md:** D-02, D-04, D-14 are **costly**; D-26, D-33 are **reversible**. No decision in this phase is rated `one-way`.
- **`autostart.lua` carries a documented no-new-entries prohibition** (D-15, D-35). Nothing in this phase may add an entry to it.
- **Do not plan MPRIS suppression work** — mpv core has no built-in MPRIS at all, so D-16 is satisfied by omission (`--no-audio` still applies).
- **Deferred, not in scope:** `gaming-mode-toggle.sh` may be silently dead since the 13.1 Lua cutover. It is filed as its own `/gsd-debug`, not folded here — but if confirmed, D-28's gaming-mode suppression must not be built on a broken toggle.
