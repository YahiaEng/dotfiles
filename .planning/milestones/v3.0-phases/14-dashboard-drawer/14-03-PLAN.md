## Scope correction carried by this plan (recorded, not silent)

The outline states that wave-3 parallelism rests on 14-03 creating every
`modules/dashboard/` stub and owning the subdirectory `qmldir` outright, and that a
type 14-03 did not declare is a 14-03 scope correction rather than a wave-3 edit.
Applying that rule honestly forces one addition the outline did not spell out:
**the shared instances and their mount points also belong to this plan.**

D-14 puts the data backends at the shell root. If 14-05 mounted `MediaBackend` in
`shell.qml` and 14-07 mounted `WeatherBackend` in the same file, two wave-3 plans
would collide on `shell.qml` and wave 3 would stop being parallel. The same applies
to the single shared `SystemResources` instance that 14-06's Performance dials and
14-08's resources strip both read, and to the deep-link signal 14-08 emits.

So this plan mounts every shared instance, declares every property and signal the
wave-3 plans consume, and leaves each of those four plans with exactly one file of
its own to fill. This is recorded here rather than discovered at wave 3.
