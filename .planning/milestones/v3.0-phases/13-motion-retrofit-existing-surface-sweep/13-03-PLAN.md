"already installed" guard already provides retry semantics on the next shell.

bootstrap URL at a path that returns 404 on the same host and start a fresh interactive fish

showing it gone.

function's `use` branch errors unconditionally when the requested version is not installed,
and the silent flag suppresses only the success message, not the error path. Guard the
activation on the version directory existing under the nvm data dir, per the review's exact
fish snippet.

*Proof:* move `$nvm_data/$nvm_default_version` aside, start a fresh interactive fish shell

    13-RESEARCH.md established the mechanism difference from the installed package docs: the
    session-manager stop subcommand's documented job is narrowly to stop the compositor's
    systemd unit, after which systemd tears down dependents in reverse with its own stop
    timeout before a hard kill — nothing in that path asks each Wayland client to close first.
    `hyprshutdown` is documented as showing a shutdown UI and explicitly closing apps before
    exiting the compositor. **Whether that difference is observable on this build is
    unverified** and is flagged as assumption A3.

    Wrapping unconditionally would apply a fix of unproven necessity to the one power action
    that exits the compositor by definition, where the wrapper's post-command may be redundant
    or subtly wrong. Documenting an exemption without measuring would invent a reason. So:
    measure first.
