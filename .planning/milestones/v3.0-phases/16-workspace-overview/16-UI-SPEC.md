# Phase 16 — UI Design Contract

> Visual and interaction contract for the workspace overview. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Grounded in `16-CONTEXT.md`'s 24 recorded decisions and the actual Design/Colours/Motion singletons this repo already ships — no new token vocabulary is invented; where a value is genuinely new (tile radius, scratchpad size), it is called out explicitly as a local, non-hoisted constant.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is a native QML/Quickshell desktop shell (Arch + Hyprland), not a React/Next/Vite project. `components.json` does not exist and no shadcn-style registry applies. The shadcn initialization gate is not applicable to this stack. |
| Preset | not applicable |

## Spacing Scale

Declared values — this repo's actual scale (`Design.qml`), **not** the template's default 4/8/16/24/32/48/64 set. `Design.qml` stops at `spacingXl` (32px) plus a separate `panelPadding` (24px); there is no 2xl/3xl token anywhere in this pipeline, and this phase should not invent one.

| Token | Value | Source | Usage in the overview |
|-------|-------|--------|------------------------|
| spacingXs | 4px | `Design.spacingXs` | Icon-to-label gaps inside a tile's denial/empty state |
| spacingSm | 8px | `Design.spacingSm` | Workspace-number inset from a tile's top-left corner; monitor-badge inset from top-right |
| spacingMd | 16px | `Design.spacingMd` | Default internal padding inside a tile's denial-state stack |
| spacingLg | 24px | `Design.spacingLg`/`panelPadding` | Outer margin between the grid block and the screen edge (scrim padding); **and** the column gap, row gap, and 5×2-block→scratchpad gap (see the fit arithmetic below) |
| spacingXl | 32px | `Design.spacingXl` | *No consumer in this surface.* Originally specified for the tile gaps; the fit arithmetic below forced them down to `spacingLg`. Listed only so a future reader does not re-derive 32px gaps and re-break the fit. |

**Grid fit arithmetic (load-bearing — the earlier draft did not close).** At `spacingXl` (32px) gaps the block measured 5×480 + 4×32 = **2528px**, which with a 24px scrim margin per side needed **2576px on a 2560px display** — 16px over per side. Resolved by dropping the tile gaps to `spacingLg` (24px):
- Block width: 5×480 + 4×24 = **2496px**; + 2×24 margin = **2544px** ≤ 2560 ✓ (16px spare)
- Block height: 2×270 + 24 = **564px**; + 24 gap + 169 scratchpad + 2×24 margin = **805px** ≤ 1440 ✓
Any future change to tile width, gap, or border must re-run this arithmetic — it fits with 16px of horizontal slack, not comfortably.

**Exceptions:** two new local constants this phase introduces (not hoisted to `Design.qml` — no other consumer needs them yet, mirroring `QuickToggles.qml`'s own precedent of a locally-scoped `chipRadius`):
- `tileRadius: 12` — a workspace tile's corner radius. Neither existing radius token fits: `PanelDialog.cornerRadius` (28) is tuned for an 850×620 panel, `QuickToggles.chipRadius` (16) for a 72px chip; a 480×270 tile sits between them in proportion, and 12 keeps the radius at roughly the same *visual* weight relative to tile size as the chip's 16 has relative to its own.
- `Design.borderWidth` (3px, already a token — Hyprland's `general:border_size` parity number) is reused verbatim for every tile outline, never a new literal.

## Typography

| Role | Size | Weight | Line Height | Source / Usage |
|------|------|--------|-------------|-----------------|
| Label | 12px | `Font.Normal` (`Design.weightBody`) | 1.2 | `Design.fontLabel`. Per-window denial reason text, monitor badge, keyboard mode-indicator pill, any hover tooltip (`Design.tooltipDelayMs` = 400ms, matching every existing panel/chip). |
| Body | 16px | `Font.Normal` / `Font.DemiBold` (`Design.weightBody`/`weightEmphasis`) | 1.5 | `Design.fontBody`. Per-window denial-state title (the window's real title/appId, always known from `HyprlandToplevel.title` regardless of capture success). |
| Heading | 20px | `Font.DemiBold` (`Design.weightEmphasis`) | 1.2 | `Design.fontHeading`. The workspace number on each tile (D-16-03's number-row identity is the single most load-bearing piece of text in this surface); whole-grid catch heading. |

Exactly 2 distinct weights are exercised this phase: `Font.Normal` (`Design.weightBody`) and `Font.DemiBold` (`Design.weightEmphasis`). `Design.qml` also carries a `fontDisplay`/`weightDisplay` (32px, `Font.Medium`) token — used elsewhere in the shell (`Dashboard.qml`, `WeatherTab.qml`) — but it is **not exercised anywhere in this phase's UI** and is deliberately omitted from the table above rather than declared unused: nothing in the overview needs 32px text, and a third weight would exceed this phase's own 2-weight budget. Do not invent a use for it just to fill a row.

**Workspace number placement (discretion, resolved):** top-left corner of every tile, `spacingSm` (8px) inset, `Design.fontHeading`/`weightEmphasis`, `Colours.onSurface`. Because it sits *on top of* live thumbnail content (unlike an empty tile, where it can float freely), give it a small legibility backing: a pill `Rectangle` at `Colours.surface` with ~0.6 alpha, radius = half its own height, `spacingXs` padding. Same backing idiom reused for the multi-monitor badge (top-right corner, `Colours.surfaceVariant`/`Colours.onSurfaceVariant`, `Design.fontLabel`) — see Color section.

## Color

All colours are `Colours.*` role references (`modules/Colours.qml`) — no hex, matching this repo's own zero-hex invariant.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `Colours.surface` at reduced alpha (recommend **0.55**, not `PanelDialog`'s 0.78) | The full-screen translucent scrim (D-16-06). Lower than the panels' 0.78 deliberately: a panel's job is to read as a solid surface; the overview's job is to show live thumbnails of the real desktop *through* the scrim — the tiles are the content, the scrim is context, not cover. |
| Secondary (30%) | `Colours.surfaceVariant` (unoccupied-tile fill) / `Colours.surface` (occupied-tile backing behind the thumbnail composite) | The eleven tile surfaces themselves. |
| Accent (10%) | `Colours.primary` / `Colours.onPrimary` | **Reserved for exactly these elements, never more broadly:** (1) the drag drop-target highlight (D-16-14 — hovered tile's fill/border shifts to `Colours.primary`, reusing D-26's lit-tile language verbatim, the same treatment `QuickToggles.qml`'s `ToggleChip` uses); (2) nothing else pulses or fills primary in this surface. |
| Secondary accent | `Colours.secondary` | Keyboard tile-selection ring (D-16-16's two-level model) — a **thin outline only**, deliberately not a fill, so it reads as "where the keyboard is" rather than competing with the drag highlight's "drop here" fill. Distinguishing the two colours keeps D-16-13's two-verb grammar (drag = organize, click/keyboard = navigate) visible in the colour language itself, not just the interaction. |
| Tertiary accent | `Colours.tertiary` | Scratchpad tile's steady (non-animated) border — D-16-05's "visually separated, distinct styling" resolved as a colour distinct from both the primary drag-accent and the secondary keyboard-accent, so its identity never collides with either interactive state. |
| Neutral orientation ring | `Colours.outline` | The currently-focused workspace's tile gets a thin `Colours.outline` ring (not an accent colour) purely as an orientation cue — "you are here" — kept neutral so it never competes with the two interaction accents above. |
| State colours (reused from `PanelDialog.stateColour()`, D-16-10 explicitly reuses D-15-09's vocabulary) | `Colours.primary` (pending) / `Colours.onSurfaceVariant` (empty) / `Colours.error` (failed/denied) | Per-window capture state, byte-identical role mapping to `PanelDialog.qml`'s existing `stateColour(state)` function — do not invent a second mapping. |
| Destructive | not applicable | This phase performs no destructive action. Drag-to-move is fully reversible (drag it back) and drop-on-miss cancels for free (D-16-14) — no confirmation dialog anywhere in this surface. |

**Accent reserved for:** the hovered drag-drop-target tile (`Colours.primary`, D-16-14) and nothing else. `Colours.secondary` and `Colours.tertiary` are each reserved for exactly one further meaning (keyboard selection; scratchpad identity) so no colour in this surface ever carries two meanings at once.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **N/A — no button-labeled CTA in this surface.** The whole surface is direct-manipulation (click a tile = focus + close per OVER-02; drag a thumbnail = move per OVER-03). `Super+O` (D-16-18) is the entry keybind, not in-surface copy. |
| Empty state heading | The workspace number itself (e.g. `3`) — an unoccupied tile shows only its number, `Design.fontHeading`, plus a quiet Material Symbol (`apps`, discretion pick — a low-key grid glyph that reads as "workspace," not an error/warning shape). |
| Empty state body | **None.** D-41's vocabulary is explicit: "quiet Material Symbol + workspace number, no invented chrome." Do not add descriptive text to an unoccupied tile. |
| Error state (per-window denial/failure) | Icon `visibility_off` + the window's real title/appId (always known from Hyprland IPC regardless of capture success, `Design.fontBody`) + one line: **"Live preview unavailable"** (`Design.fontLabel`, `Colours.error`). Deliberately does not claim to know *why* — a genuinely blank window and a denied capture are indistinguishable from `ScreencopyView.hasContent` alone, so the copy stays honest rather than overclaiming a diagnosis only `quickshell-doctor` can make. |
| Error state (whole-grid catch, D-16-10) | One surface-level message, not fifteen tile-level repeats. Icon `lock`. Heading: **"Can't show live thumbnails"** (`Design.fontHeading`). Body: **"Screen capture looks blocked for every window — check Hyprland's screencopy permission, then reopen the overview (Super+O)."** (`Design.fontLabel`/`Colours.onSurfaceVariant`). Plain language, matching the standing directive recorded in `16-CONTEXT.md` `<specifics>` — the user asked mid-discussion for jargon re-stated in plain terms ("frame and CPU budget" was initially misread as agent token budget); this copy leads with what the user sees ("can't show thumbnails") and puts the mechanism (screencopy permission) second, as a next step rather than the headline. |
| Destructive confirmation | **N/A** — no destructive action exists in this phase. |
| Hint line (discretion — recommend omitting) | No existing surface in this repo (the drawer, all three panels, the quick-toggle grid) carries a persistent instructional caption. Discoverability there comes entirely from hover-triggered tooltips (`Design.tooltipDelayMs`, 400ms). **Recommendation: omit a persistent hint line entirely**, to match that established idiom rather than introduce a new one this phase alone would carry. If the render gate (D-16-17's checkpoint) finds the interaction model non-obvious without one, add a hover-triggered tooltip over empty grid space with copy `"Click to focus · Drag to move"` — never a permanently-visible caption. |

## Phase-Specific Interaction & Layout Contract

*(Additive section beyond the template's standard dimensions — operationalizes `16-CONTEXT.md`'s "Claude's Discretion" list into concrete, prescriptive numbers so planner/executor never re-derive them. All numbers below are recommendations subject to the human render-and-look gate, standing constraint 1.)*

### Grid geometry (D-16-01/D-16-02/D-16-03)
- Host: single monitor, `DP-1`, 2560×1440 @ 164.999Hz, scale 1.0.
- 10 numbered tiles, fixed 5 columns × 2 rows, always rendered. Tile size **480×270** (16:9, scale 0.1875 relative to the 2560×1440 monitor — `tileWidth / monitorWidth`, per D-16-02).
- Column gap and row gap: `Design.spacingLg` (24px). Grid block: 5×480 + 4×24 = **2496px wide**, 2×270 + 1×24 = **564px tall**. Centered horizontally with a `spacingLg` (24px) scrim margin per side, total **2544px** on the 2560px display — see the Spacing Scale section's fit arithmetic, which this number is load-bearing to. Vertical slack above/below reserved for the workspace-number overlay (drawn inside the tile, per the Typography section — no extra vertical space needed for it) and for the scratchpad tile beneath.
- Scratchpad tile (11th, D-16-05): smaller than the numbered tiles to read as "distinct, lesser" without being illegible — recommend **300×169** (≈0.625× the numbered tile, still 16:9). Centered horizontally below the 5×2 block, `Design.spacingLg` (24px) gap above it.
- **Tile clipping:** every tile sets `clip: true`. D-16-02 renders windows at real `hyprctl clients` geometry, so a window positioned partly offscreen, sized larger than the monitor, or carrying stale coordinates would otherwise paint outside its tile and over its neighbours. Clipping crops it at the tile edge — the geometry stays honest, the grid stays intact.
- Tile corner radius: `tileRadius` = 12 (new local constant, not hoisted — see Spacing section). Tile outline width: `Design.borderWidth` (3px, reused token).

### Backdrop (D-16-06)
Translucent scrim inheriting the `^quickshell-.*` family blur, `Colours.surface` at ~0.55 alpha (see Color section for the rationale versus the panels' 0.78). `WlrLayershell.namespace: "quickshell-overview"` so the existing family blur/`ignore_alpha` layerrules apply automatically with no new Hyprland config, exactly as `PanelDialog.qml`'s three panel instances already do. **Fallback lever #1 (pre-authorized, D-16-06):** a per-namespace `hl.layer_rule` blur override in `windowrules.lua` drops this blur entirely if OVER-04's measurement demands it — no new decision needed to pull that lever.

### Per-window capture states (D-16-10)
Reuse `PanelDialog.qml`'s exact `stateColour()` mapping — do not invent a second state-colour function:
- `populated` → live `ScreencopyView` content, no overlay.
- `pending` → `Colours.primary` tinted loading glyph, ambient pulse on `Motion.ambientDuration`.
- `failed`/denied → `Colours.error`, icon `visibility_off`, real window title, "Live preview unavailable" (see Copywriting Contract).
- Whole-grid catch (all windows fail simultaneously): one centered surface-level message over a slightly darkened scrim, not per-tile repetition.

### Drag visuals (D-16-12/D-16-14)
- Dragged element: a still snapshot (`captureFrame()` at drag start), not the live view — protects the frame budget at the phase's load peak.
- Scale-up on lift: **1.05×** (5% — a subtle "lift" cue, not an exaggerated zoom that would fight the snapshot's own already-small size).
- Shadow: soft drop shadow, ~0.35 opacity black, ~8px blur radius — MD3 elevation-level-3 weight, matching the elevation language implied by `GradientBorder.qml`'s own prior (rejected) `MultiEffect` experiment, applied here to a genuinely appropriate use (a floating dragged element, not a static ring).
- Hover-target highlight: `Colours.primary` fill/border shift on the hovered tile, reusing `QuickToggles.qml`'s `ToggleChip` lit-tile treatment verbatim (D-16-14/D-26).
- Cancel animation: `Motion.standardDuration`/`Motion.standardEasing` (the standard pair, not a bespoke curve) — snaps the snapshot back to its origin tile.

### Keyboard model (D-16-15/D-16-16/D-16-17)
- **Edge behaviour — linear wrap across all 11 tiles (human decision at the UI-consideration gate, 2026-08-02).** Left/Right treat the eleven tiles as one sequence: Right from tile 5 continues to tile 6 (row 2, column 1), Right from tile 10 continues to the scratchpad, Right from the scratchpad returns to tile 1. Left reverses the same cycle. Up/Down keep their 2D, column-preserving meaning as a fast row jump (Down from row 1 → row 2 → scratchpad; Up reverses). ⚠ **Recorded tension:** this was chosen over edge-stop, which is what D-16-03's "the grid teaches itself because it mirrors the number row" argument implies — under linear wrap a single Right keypress can move the selection to a different row, so tile position and travel direction stop agreeing. The decision stands as made; **the render gate (D-16-17) should specifically look at whether the row-crossing jump reads as natural in the hand**, since that is the one place this could feel wrong, and edge-stop is a one-line fallback if it does.
- Tile-level selection ring: `Colours.secondary`, thin outline (2px), never a fill — distinct from the drag highlight's `Colours.primary` fill so the two accents never carry the same meaning.
- Mode indicator (discretion, provisional pending D-16-17's checkpoint): a small pill, `Design.fontLabel`, `Colours.surfaceVariant` background / `Colours.onSurfaceVariant` text, positioned top-center of the grid, reading either `"Tiles"` or `"Workspace {N} windows"` depending on selection depth — reusing the same segmented-pill visual language `QuickToggles.qml`'s `PresetSegment` already establishes (outline + tonal fill), not a new chrome idiom. **If the render gate finds this cluttered or the two levels confusing in the hand, fall back to Esc + number keys per D-16-17 — remove this pill and the window-level selection ring entirely, without a new decision.**

### Entrance motion (D-16-24)
Row-level cascade, not per-tile: Row 1 (workspaces 1–5) at t=0, Row 2 (6–10) at t=`Motion.staggerOffsetDuration` (50ms default, scale-safe), scratchpad tile at t=2×stagger. Each band's own animation uses `Motion.emphasizedInDuration`/`Motion.emphasizedInEasing`, exactly matching `Cascade.qml`'s existing per-band shape (opacity + translate-y together). Layer rule: `fade`, not `slide` — a full-screen surface has no edge to slide in from, unlike the drawer/panels. New `quickshell-overview` `hl.layer_rule` entry required in `windowrules.lua` (D-16-24).
