<objective>
Bring the new `lua-table` generated file under the same contract validation every other render
target already has, and settle what the measured Lua re-read semantics mean for the theme-switch
reload path.

Purpose: `contract.json` gained a `lua-table` entry in plan `13.1-02`, but a format with no handler
in `lib/contract.sh` is a file the parity checker cannot see. This repo has been bitten by exactly
that shape before — an orphaned contract entry red-lighting `theme-doctor`/`theme-parity` for weeks
in v2.0 — so the handler lands before the file accumulates consumers. Separately,
`lib/reload.sh` issues a compositor config re-read on *every* theme switch; plan `13.1-03` measured
what that does under Lua, and this plan acts on the measurement.

Output: `lua-table` handlers in both `contract.sh` dispatch tables, a recorded reload verdict, and
`lua` registered as an explicit install dependency.

This plan touches no file on the Hyprland config load path and shares no file with plan `13.1-04`,
so the two run in the same wave.
</objective>

  <action>
Add a `lua-table)` case arm to **both** `contract_extract_names` and `contract_extract_values` in
`theme-engine/.config/theme-engine/lib/contract.sh`.

Both arms load the file with the `lua` interpreter and walk the returned table, in the same
"parse-in-its-own-runtime, then walk" shape the `toml` branch uses. Do not pattern-match Lua source
text with `grep`/`sed`: the file is a real Lua table with nesting the regex approach cannot follow,
and RESEARCH.md's "Don't Hand-Roll" section is explicit that a bespoke Lua parser is the wrong
build here.

- **Names arm**: emit every key name found at every nesting level, bare and unqualified, sorted and
  de-duplicated — matching the `json` branch's `.. | objects | keys[]` semantics exactly. For the
  real token file that means `colors`, `motion`, `primary`, `on_primary`, …, `enabled`, `speed`,
  `curves`, `standard`, `type`, `points`, and so on.
- **Values arm**: emit one `key<TAB>value` line per **leaf scalar**, with the bare key name,
  matching the `key<TAB>value` shape every other value arm emits. Non-scalar leaves (the `points`
  arrays inside curve specs) should be emitted in a stable, deterministic textual form rather than
  skipped — a skipped value is a value the parity checker cannot compare.

Both arms must be defensive in the same way the sibling arms are: a missing, empty or unloadable
file produces empty output and a non-zero-free path (`2>/dev/null`), never a crash that takes the
whole `theme-doctor` run down.

This makes the theme-engine's verification tooling depend on the `lua` binary at run time. `lua` is
currently present only as a transitive dependency of `hyprland`. Per ROADMAP standing constraint 3
and D-14, add `lua` explicitly to `install.sh`'s `PACMAN_PKGS` array in this same commit, with a
one-line comment naming why (`contract.sh`'s `lua-table` extractor). Do not add either community
converter to `PACMAN_PKGS` or `AUR_PKGS` — they are one-time local authoring aids, never runtime
dependencies, and this phase does not use them.

Prove the branch can fail as well as pass: run the name extractor against a deliberately malformed
copy of the token file and confirm it yields an empty set without crashing, and confirm
`theme-parity` treats an empty extracted name set for a declared contract file as a failure rather
than a pass. If it does not, that is a pre-existing vacuous-pass hole in the parity checker — fix
it here, since this plan is the first to add a format whose extractor can legitimately return
nothing.
