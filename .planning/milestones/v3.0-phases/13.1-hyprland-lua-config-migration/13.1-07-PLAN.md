<objective>
Port the two files the equivalence gate covers least — the 307-line window-rule set and the 121-line
permission grant set — using the empirically established property vocabulary rather than hyprlang
muscle memory.

Purpose: this is where a silent divergence is most likely and least visible. Lua tables tolerate
unknown keys, so a misspelled window-rule property does not error — it registers a rule that never
fires, and nothing complains. Permission grants are worse: they are read once at startup and are
not reachable through `hyprctl getoption` at all, so the phase's automated gate structurally cannot
see them. Both gaps are closed here by different means — the recorded property verdicts for window
rules, and a recorded textual review for grants.

Output: `config/windowrules.lua`, `config/permissions.lua`, and `13.1-PERMISSION-REVIEW.md`.
</objective>

Write `hypr/.config/hypr/config/windowrules.lua`, translating every declaration in
`windowrules.conf` one-for-one, in the same source order, with no consolidation.

**Match criteria.** Hyprland 0.54+'s `match:class = <regex>` / `match:title = <regex>` colon
syntax becomes a nested table: `match = { class = <regex>, title = <regex> }`. Note the two rules
that carry both criteria together (`thunar` + `File Operation Progress`, and `thunar` + `Confirm`)
— those two criteria belong in the **same** `match` table, not in two separate rules, or the rule
stops meaning what it means today. Layer rules use `match = { namespace = <name> }`.

**Regex strings must use Lua long-bracket literals.** Several patterns contain backslash escapes —
`^(org\.gnome\.Calculator)$`, `^(org\.gnome\.Settings)$`, and the picture-in-picture title pattern
with its `[-\s]?` groups. Inside a Lua short string those sequences are not valid escapes and will
either be rejected or silently transformed. Write every regex as a long-bracket literal so the
backslashes reach the compositor exactly as written today. Apply this uniformly to all patterns,
not only the ones that currently contain a backslash, so a later edit that adds one cannot
reintroduce the hazard.

**Properties.** The complete set this file needs, with occurrence counts to check against:
`float` (18 rules), `size` (9), `center` (8), `animation` (6), `workspace` (2), `pin` (1),
`move` (1), `opacity` (8), `no_blur` (2). Layer rules use `blur` (6), `ignore_alpha` (6) and
`animation` (1). Use the exact spelling and value shape recorded in `13.1-LUA-FINDINGS.md` for
each — in particular the two whose shape was genuinely open: how `size` expresses its two
components (including the percentage forms `85% 85%` and `70% 65%`), and how `opacity` expresses
its two floats. Preserve the `move` expression `(monitor_w-490) (monitor_h-280)` exactly; the
vendor example passes such expressions as a plain string.

**Named rules.** The 11 block-form rules each carry a `name`. Keep those names byte-identical —
they are the human-facing identifiers used when reasoning about which rule fired.

**Comments.** Carry across the substantive section comments from `windowrules.conf`. They document
why individual rules exist and several record findings from earlier phases; losing them would
discard institutional knowledge in a phase that is explicitly not allowed to change anything.

Verify what can be verified at runtime. Start `hypr-lua-harness`, launch disposable windows
