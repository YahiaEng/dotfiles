# Phase 13.1 Plan 09: Consumer Retarget Summary

**Retargeted the four live tools that still read a soon-to-be-deleted hyprlang file — `keybind-doctor`, `cheat-sheet-parser.sh`, `gaming-mode-toggle.sh`, `theme-stress-test` — at their Lua/merged-token replacements, with `keybind-doctor` returning to fully green (14/14) through two empirically-confirmed parsing fixes rather than any loosened check.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 2 of 2
- **Files modified:** 5 (4 retargeted tools + 1 new deferred-items.md)

## Accomplishments

- **`keybind-doctor`** now parses `keybinds.lua` directly via a purpose-built quote/bracket-depth-aware tokenizer (needed because Lua bind lines embed literal `--` inside quoted arguments, e.g. `"uwsm app -- walker -m menus:main"`, which a naive comment search would misparse). Re-proven able to fail: a poisoned fixture (one description removed, one chord duplicated against the quickshell manifest) exits non-zero and names both problems; the real config exits 0. Back to fully green (14 checks passed, 0 failed — one MORE check than the pre-cutover baseline's 13, from a new declared-bind parse shape guard) via two correctly-scoped fixes:
  - the declared-vs-registered tuple now matches what a Lua-registered `code:NNN` bind ACTUALLY reports through `hyprctl binds` (the full modifier-prefixed key string, keycode 0) rather than reusing the hyprlang-specific keycode-split — confirmed live, not assumed;
  - the D-03 kill-bind check is split into a source-level half (does `keybinds.lua` declare Super+Escape -> `hl.dsp.exec_cmd("pkill walker")`) and a live half (is that exact chord registered), mirroring `hypr-equivalence-check`'s own established structural/source-level split for the same dispatcher/arg opacity gap.
- **`cheat-sheet-parser.sh`** retargeted with the same tokenizer approach (degrading gracefully — silent skip, not a loud failure — on any unparseable line, matching its display-only purpose). Output proven byte-identical to the pre-migration parser: 80 records, empty diff between the old hyprlang-sourced run and the new Lua-sourced run. The rendered kitty cheat-sheet still reports "80 binds - 21 sections", unchanged.
- **`gaming-mode-toggle.sh`** now reads `~/.local/state/theme/hyprland-tokens.lua` through `lib/contract.sh`'s shared `lua-table` value extractor instead of a hand-rolled hyprlang grep — one implementation of "how to read this format," not a third one. Behaviour unchanged: the four `decoration:*`/`animations:*` restore keys still resolve to nothing (as documented, they've never existed in either the old or new rendered file), so `gaming_mode_off` still correctly falls through to `hyprctl reload`.
- **`theme-stress-test`**'s `REPRESENTATIVE_FILES` swaps `hyprland.conf` for `hyprland-tokens.lua`; no other code change needed since `sentinel_present_in_file`/`contract_extract_values` already dispatch purely off `contract.json`'s format tag. Ran the full 10-switch live reliability sweep to completion: **162 passed, 0 failed, exit 0**, with the sentinel found in `hyprland-tokens.lua` on every one of the 10 switches (catppuccin, materialyou, catppuccin-latte, materialyou-light, dracula, materialyou, ethereal, materialyou-light, everfrost, materialyou).
- **`ai-webapp-launch.sh`**'s two comment references repointed at `config/windowrules.lua` (the finding block they cite exists there byte-identical to the retiring `.conf`).
- Discovered and fixed (Rule 3, blocking issue, narrowly scoped to the two call sites): `theme-stress-test`'s own quickshell-probe dispatch used the classic `hyprctl dispatch global quickshell:probe` string form, which the Lua-config compositor rejects outright (`')' expected near 'quickshell'` — it tries to parse the dispatch line as Lua). This silently aborted the entire stress-test run right after the elephant precondition, before this task's own retargeted sentinel check could ever run. Fixed to the Lua expression form (`hl.dsp.global("quickshell:probe")`) already established and proven correct by `keybinds.lua`'s own bind — confirmed live before and after.
- Discovered and deliberately left unfixed (out of scope — logged in `deferred-items.md`): `hyprctl keyword` is a silent no-op on this Lua-config session (`keyword can't work with non-legacy parsers. Use eval.`, exit 0 regardless). This breaks `gaming-mode-toggle.sh`'s eye-candy on/off mechanism (a different code path from the value read-back this task retargeted), but reproduces identically from a bare, unrelated CLI invocation — a global 13.1-08 cutover consequence, not caused by this task's changes.
- `theme-doctor` (225 passed, 0 failed) and `theme-parity` (2785 passed, 0 failed) both confirmed green on a clean git tree — unchanged from the pre-migration baseline counts recorded in 13.1-08.
- Live compositor confirmed unrestarted throughout (pid 956, unchanged), theme restored to `catppuccin` at the end of this plan.
