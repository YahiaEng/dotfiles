### `hypr/.config/hypr/scripts/hypr-equivalence-check` (NEW)

**Analog:** `hypr/.config/hypr/scripts/waybar-equivalence-check` (302 lines, read in full)

This is the strongest and most load-bearing analog in the phase. Copy its **shape**, not its
resolver internals (Hyprland's resolution is runtime-only, not a static parse).

**Mode-dispatch pattern** (lines 47-63):
```bash
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &>/dev/null && pwd)"
REPO_ROOT="$(git -C "$SCRIPT_DIR" rev-parse --show-toplevel 2>/dev/null || true)"
if [[ -z "$REPO_ROOT" ]]; then
    REPO_ROOT="$(cd -- "$SCRIPT_DIR/../../../.." &>/dev/null && pwd)"
fi

# -> for the new tool: .planning/phases/13.1-hyprland-lua-config-migration/.hypr-baseline

if [[ "${1:-}" == "--snapshot" ]]; then
    MODE="snapshot"
    OUTDIR="${2:?... requires an output directory}"
elif [[ "${1:-}" == "--resolve" ]]; then
    MODE="resolve"
    RESOLVE_PATH="${2:?...}"
else
    MODE="check"
fi
```
D-08 locks the same two-mode contract (`--snapshot`, default = diff). The `--resolve` single-file
helper mode is optional discretion, not required by CONTEXT.md, but is a clean pattern to reuse
for ad-hoc `hyprctl -j getoption <key>` inspection.

**Snapshot mode: capture, never compare** (lines 221-243):
```bash
if [[ "$MODE" == "snapshot" ]]; then
    mkdir -p "$OUTDIR"
    ...
    for f in "${FILES[@]}"; do
        if resolve_layout "$f" > "$OUTDIR/$layout.json"; then
            echo "  [OK] snapshot written: $OUTDIR/$layout.json"
        else
            echo "  [FAIL] snapshot failed for $layout" >&2
            fail=1
        fi
    done
    exit "$fail"
fi
```
For `hypr-equivalence-check --snapshot`, replace the file-glob resolve step with the three
`hyprctl -j` calls D-08 specifies (must run while still on `.conf`, per D-09):
```bash
# Adapted call shape — not from an analog, this is the compositor-specific substitution:
hyprctl -j binds > "$OUTDIR/binds.json"
hyprctl -j animations > "$OUTDIR/animations.json"
for key in $(extract_set_option_keys); do
    hyprctl -j getoption "$key" >> "$OUTDIR/options.jsonl"
done
```
Verified live output shapes (RESEARCH.md, this machine, 2026-07-28):
```json
{"option": "decoration:rounding", "int": 12, "set": true }
{"option": "general:gaps_in", "custom": "5 5 5 5", "set": true }
```

**Default mode: diff against committed baseline, SKIP on no-baseline** (lines 245-301):
```bash
for f in "${FILES[@]}"; do
    baseline_file="$BASELINE_DIR/$layout.json"
    if [[ ! -f "$baseline_file" ]]; then
        echo "  [SKIP] $layout (no baseline — new layout)"
        continue
    fi
    if diff_out="$(diff -u "$baseline_file" "$tmp_resolved")"; then
        echo "  [PASS] $layout: matches baseline"
        PASS=$((PASS + 1))
    else
        echo "  [FAIL] $layout: differs from baseline"
        echo "$diff_out"
        FAIL=$((FAIL + 1))
    fi
done
echo ""
echo "PASS: $PASS  FAIL: $FAIL"
[[ "$FAIL" -eq 0 ]]
exit $?
```
This is the "no baseline yet → SKIP not FAIL" pattern the phase-specific guidance asked to extract
explicitly. **D-10 tightens this for the new tool**: the analog exits 0 on any-SKIP-or-PASS
combination; `hypr-equivalence-check` must exit 0 **only on exact match with every divergence
individually recorded as intended, with a reason** — this is a deliberate deviation from the
analog's looser "SKIP is fine" posture, driven by D-10, not an oversight to copy verbatim.

**Cleanup/temp-file discipline** (lines 258-265):
```bash
TMP_FILES=()
cleanup() {
    local t
    for t in "${TMP_FILES[@]}"; do
        rm -f "$t"
    done
}
trap cleanup EXIT
```

**Report-only / never-mutate discipline**: the analog never invokes `waybar` itself and never
writes to any file outside `$OUTDIR`/baseline dir. The new tool must equally never invoke
`hyprctl reload`, never edit `.lua`/`.conf` files — it only reads via `hyprctl -j` and diffs.

**Structural difference to account for (per phase guidance):** waybar's effective config resolves
**statically** (`resolve_layout` parses JSONC files on disk with no running process involved).
Hyprland's effective config is only observable **at runtime** via `hyprctl -j getoption`/`-j
binds`/`-j animations` against the live compositor — there is no static-parse equivalent. This
means `hypr-equivalence-check` has no `resolve_layout`-shaped pure-parse function; its "resolve"
step is a live `hyprctl` invocation, which also means `--snapshot` mode is meaningfully coupled to
*which config format is currently booted* (must run pre-edit per D-09), unlike waybar's snapshot
mode which could be re-run any time from the same static files.

**D-16 (uncovered options) has no waybar-equivalence-check precedent** — that concern must be
handled net-new: the diff/report output should carry an explicit, documented list of any
`hyprctl getoption` keys that could not be resolved for a given option key set in the config,
distinct from a normal FAIL.

### `theme-engine/.config/theme-engine/lib/contract.sh` (MODIFIED — `lua-table` format)

**Analog:** itself — the existing `contract_extract_names` `case "$fmt"` dispatch (lines 77-186+),
specifically the `hypr-motion` branch (lines 116-126) as the closest sibling (union-of-two-syntax
extraction) and `json` branch (line 164-166) as the simplest structured-data sibling.

**How a format handler is registered** (three touch points per format, extracted from the
`hypr-vars`/`hypr-motion`/`json` handling across the file):
1. `contract_format` (lines 55-61) — reads the `format` field from `contract.json`, no per-format
   code needed here; this is generic and format-agnostic already.
2. `contract_extract_names`'s `case "$fmt"` (lines 83-186+) — **this is where the new `lua-table`
   branch goes.** Nearest-shape sibling, the `json` branch:
   ```bash
   json)
       jq -r '.. | objects | keys[]' "$path" | sort -u
       ;;
   ```
   A `lua-table` branch cannot use `jq` (Lua ≠ JSON) — it needs either a small `lua -e` one-liner
   that `require()`s/`loadfile()`s the table and walks it printing keys (mirrors the `toml` branch's
   `python3 - <<'PYEOF' ... tomllib.load ... walk(...)` pattern at lines 142-163, same
   load-native-format-then-walk-keys shape, just in Lua instead of Python), or a regex extractor
   in the same family as `hypr-motion`'s two-`grep`-then-union approach if a full interpreter call
   is undesirable. The `toml` branch is the stronger structural analog since both are "parse in the
   file's own language runtime, then generically walk the resulting tree for all keys," rather than
   grep-based syntax matching:
   ```bash
   toml)
       python3 - "$path" <<'PYEOF'
   import tomllib, sys
   with open(sys.argv[1], "rb") as f:
       data = tomllib.load(f)
   def walk(node, keys):
       if isinstance(node, dict):
           for k, v in node.items():
               keys.add(k); walk(v, keys)
       elif isinstance(node, list):
           for item in node:
               walk(item, keys)
   found = set(); walk(data, found)
   print("\n".join(sorted(found)))
   PYEOF
       ;;
   ```
3. The equivalent value-comparison branch further down the file (lines 260-350, second `case
   "$fmt"` — value extraction, not just names) also needs a `lua-table)` arm, same pairing
   discipline as every other format (`gtk-css`/`hypr-vars`/`hypr-motion`/`gtk-css-motion` all
   appear twice in the file — once for names, once for values).

## Shared Patterns

### Report-only, never-mutate discipline
**Source:** `hypr/.config/hypr/scripts/waybar-equivalence-check` (whole-file property, never calls
`waybar`/writes outside `$OUTDIR`), `hypr/.config/hypr/scripts/motion-lint` (line 83: "Never runs
theme-apply, never edits anything — pure read-only analysis.")
**Apply to:** `hypr-equivalence-check` (NEW) and the Lua-aware path in `motion-lint` (MODIFIED).
Both new/modified verification tools must be read-only against the config tree; `hypr-equivalence-check`
additionally must never call `hyprctl reload`/`hyprctl keyword` — only `-j getoption`/`-j binds`/`-j
animations` (read-only `hyprctl` verbs).

### Seed-by-invoking-the-real-renderer, never a stub
**Source:** `stow.sh` lines ~156-194 (motion-file seed block, quoted in full above).
**Apply to:** any `stow.sh` change for the new merged `lua-table` file, and implicitly to the new
`hypr/.config/hypr/state/tokens.lua` symlink. Never ship a hand-authored placeholder `.lua`/colour
stub — always seed by sourcing `lib/motion.sh` (or its D-05 successor) and calling its real
