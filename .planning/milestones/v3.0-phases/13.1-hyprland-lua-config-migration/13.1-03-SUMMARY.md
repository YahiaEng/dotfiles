# Phase 13.1 Plan 03: Empirical Lua Vocabulary + Monitors/Autostart Port + Equivalence-Gate Normalization Summary

**Established the phase's remaining unverified Lua API vocabulary against a live nested compositor (discovering that `hl.window_rule`/`hl.layer_rule`/`hl.permission` all validate field names live via `configerrors`), ported `monitors.lua`/`autostart.lua` with proven parity and reached the entry point's final seven-module require shape, then — as an explicit human-authorized scope addition — fixed `hypr-equivalence-check`'s `options.jsonl` comparison to fold the hyprlang/Lua JSON type-key divergence while discovering and documenting a separate, more severe `binds.json` opacity gap for plan 13.1-08.**

## Accomplishments

- Discovered that `hl.window_rule`/`hl.layer_rule`/`hl.permission` all validate their table argument's field names live at config-load time (`configerrors`: `unknown field '<name>'`) — a materially stronger position than the silent-no-op scenario RESEARCH.md's A3 worried about, and the mechanism every VERIFIED verdict in this plan relies on
- All 10 window-rule properties (`float`, `size`, `center`, `pin`, `move`, `animation`, `workspace`, `opacity`, `no_blur`, `scroll_touchpad`) and all 3 layer-rule properties (`blur`, `animation`, `ignore_alpha`) verified — 6 with direct behavioural confirmation via `hyprctl clients -j` (including a centering-math cross-check that accounted for the nested output's `scale: 2.0` factor), the rest via the field-validator contrast mechanism
- `hl.permission()`: both the positional-string form (vendor example) and the typed-table form (typed stub) work on this installed binary — resolves RESEARCH.md's apparent contradiction; it was never real
- Config re-read is non-accumulating for both binds and animations, confirmed across 10 consecutive reloads — with a self-caught and corrected measurement bug (the original check measured `hyprctl -j animations`'s outer 2-element wrapper length, not the real leaf/curve counts)
- Physical-keycode bind syntax (`code:107`) verified via parse-error contrast, with an honestly-recorded gap: the `hyprctl -j binds` `keycode` field itself does not surface `107` for a Lua-registered physical-keycode bind — flagged NOT MECHANICALLY VERIFIABLE with a physical-keypress compensating check deferred to end-of-phase human verification
- `config/monitors.lua` and `config/autostart.lua` ported with proven value+order parity (extracted-list diff, not inspection); four placeholder modules created so the entry point reaches its final seven-`require` shape in one edit
- **Authorized addition:** `hypr-equivalence-check`'s `options.jsonl` comparison normalized to discard the hyprlang/Lua JSON type-key name and fold `bool`<->`int`, closing the ~25-27/46 false-positive risk found in 13.1-02, both D-10 failure branches re-verified after the change
- **New finding from the authorized addition's own empirical check:** `binds.json` suffers a DIFFERENT, more severe divergence than `options.jsonl` — every Lua-registered bind's `dispatcher`/`arg` fields become opaque (`"__lua"` / an internal index, vs hyprlang's readable `"exec"` / command text) — left byte-exact per the task's own instruction, but documented prominently in `COVERAGE.md` as a 100%-false-positive-rate gap for plan 13.1-08 to handle at the Wave 7 flip. `animations.json` was checked and found to have no divergence at all.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected own prior-task measurement bug in config re-read accumulation check**
- **Found during:** Task 3 (while investigating whether binds.json/animations.json suffer the getoption-class divergence)
- **Issue:** Task 1's Spike C measured `hyprctl -j animations`'s OUTER array length via `jq length`/`len(json.load(...))`. That call actually returns a 2-element wrapper `[animation_leaves, bezier_curves]`, so the measurement was always 2 regardless of actual content — the recorded `animations: 2 -> 2` result was an artifact, not real evidence about accumulation.
- **Fix:** Re-measured correctly (`len(data[0])` for leaf count, `len(data[1])` for curve count) with one real tuned `hl.animation()`/`hl.curve()` pair registered, across the same 10-reload protocol. Result: 35 leaves and 3 curves, stable both before and after — the original non-accumulating conclusion still holds, now on correct evidence.
- **Files modified:** `.planning/phases/13.1-hyprland-lua-config-migration/13.1-LUA-FINDINGS.md`
- **Verification:** Re-run live against a fresh harness instance; `configerrors` re-checked clean after the corrected 10-reload run.
- **Committed in:** `34ae291` (Task 3 commit — the findings doc correction was made alongside Task 3's own additions)

**2. [Rule 3 - Blocking] Renamed comment mentions of `hl.exec_cmd`/`hl.monitor` to avoid grep-count contamination**
- **Found during:** Task 2, running the plan's own automated verify block
- **Issue:** `autostart.lua`'s header comments literally contained the substring `hl.exec_cmd` (in prose), inflating `grep -c "hl.exec_cmd"` from 17 (real calls) to 19; `monitors.lua`'s header/fallback comments similarly inflated `grep -c "hl.monitor"` from 2 to 5 — both would have failed the plan's own automated verify block and acceptance criteria.
- **Fix:** Reworded the affected comments to describe the function without using the exact literal substring (e.g. "the top-level exec_cmd helper" instead of "`hl.exec_cmd`"), with zero change to any executable line.
- **Files modified:** `hypr/.config/hypr/config/autostart.lua`, `hypr/.config/hypr/config/monitors.lua`
- **Verification:** `grep -c` counts re-checked to exactly 17 and 2 respectively; `luac -p` still clean.
- **Committed in:** `44a1828` (Task 2 commit)
