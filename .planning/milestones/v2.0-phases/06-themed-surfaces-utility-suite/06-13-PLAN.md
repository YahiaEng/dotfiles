<objective>
Close the one remaining blocker from 06-VERIFICATION.md (status: gaps_found, 9/10) — OSD-01 / Truth #3: SwayOSD is functionally broken on a fresh install. This phase rebound all four audio keys from working `wpctl` commands to `swayosd-client`, but `swayosd-server` — the process that performs the actual volume change AND renders the themed OSD pill — is never launched anywhere in the repo, and install.sh enables the caps-lock backend on the wrong (user) systemd bus. Both defects are silenced, so they never surface as errors. Result: on a fresh install, pressing any volume/mute key does nothing at all, and the themed pill (the whole point of OSD-01/D-24) never appears.

This is a three-file, mechanical correction — no new packages, no new render targets, no behavior redesign — that restores Success Criterion #2 ("Volume/…/caps-lock changes show a themed SwayOSD indicator bound to the media keys, re-themed by the pipeline"):
1. Launch `swayosd-server` at session start (autostart.conf).
2. Enable `swayosd-libinput-backend.service` on the system bus with sudo, non-silenced (install.sh:329).
3. Correct reload.sh's theme-switch restart to target `swayosd-server` (the user-owned CSS-rendering process) instead of the system-bus libinput backend (06-REVIEW.md WR-01 fix shape).

Source coverage (gap-closure scope): this plan covers exactly one requirement — OSD-01 — the only BLOCKED item in 06-VERIFICATION.md's Requirements Coverage. All other Phase 6 requirement IDs are already SATISFIED and are out of scope for this round. The remaining ⚠️ warnings (gtk.sh icon-variant fallback, emoji "typed" claim, font-switcher tofu filter, stow.sh keybind text, clipboard-wipe.sh silent abort) touch different files and different requirements (UTIL-01/03/04/05); they do not fit naturally inside the OSD-01 concern and are intentionally excluded to keep this gap closure cohesive and tightly scoped.

Purpose: swayosd-client (already bound in keybinds.conf) is a thin D-Bus client with nothing to talk to until the server runs; and the packaged Arch `swayosd` unit is system-bus-only (root service with polkit/udev rules), so the current `systemctl --user enable` silently fails.
Output: swayosd-server launched at login, the libinput backend enabled on the correct bus, and a theme-switch that actually re-themes the pill.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| install.sh privileged enable (sudo -> system bus) | `sudo systemctl enable --now swayosd-libinput-backend.service` activates a root-owned, package-provided system unit; the unit name is a fixed literal, not user-controlled |
| swayosd-server session process | Launched via `uwsm app --` scope isolation from autostart and from reload.sh's detached relaunch; runs in the user session, renders the OSD pill from state-dir CSS |
| libinput backend -> hardware key events | The root system service listens to libinput device events (volume/brightness/caps-lock) directly; it is the packaged unit with its own polkit policy + udev rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-13-01 | Elevation of Privilege | install.sh `sudo systemctl enable` of swayosd-libinput-backend.service | low | accept | The unit is the packaged extra/swayosd root system service (its own polkit policy + udev rules, authored upstream, not by this repo); install.sh enables it by fixed literal name (no interpolation) and already runs privileged pacman steps — enabling one additional package-provided unit does not widen the trust surface, and a failure now surfaces to stderr instead of being swallowed |
| T-06-13-02 | Denial of Service | reload.sh swayosd-server restart during theme-apply | low | mitigate | Restart is gated by `pgrep -x swayosd-server` (no-op when absent, preserving the headless/container gate) and uses a bounded exit poll plus a detached `setsid uwsm app -- swayosd-server … & disown` relaunch (mirroring the proven walker idiom, set -e-safe increments) so a missing or stuck server can never hang or abort the theme switch |
| T-06-13-03 | Tampering | autostart `exec-once = uwsm app -- swayosd-server` | low | accept | Launches a fixed, package-provided binary name via the same `uwsm app --` scope isolation as every other autostart daemon; no path or argument is user-controlled |
| T-06-13-SC | Tampering | package installs (npm/pip/cargo/pacman) | low | accept | This plan adds NO new packages — swayosd is already declared and package-legitimacy-gated in Phase 6 (06-01); the plan only launches / enables / restarts the already-installed component, so no install task and no legitimacy checkpoint is triggered |
