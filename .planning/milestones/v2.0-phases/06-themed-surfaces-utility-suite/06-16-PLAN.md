<locked_decision_deviation>
## D-09 hover-label: deliberately dropped (NOT a silent scope cut)

D-09 specifies "label on hover/focus". D-10 specifies "icons are Nerd Font glyphs rendered as button text". **These two are mutually exclusive on this stack**, for a structural reason:

- wlogout gives each button exactly **one** text slot (the `text` field in `layout`, rendered as a single GTK label).
- GTK3 has **no** generated-content mechanism (no `::after`, no `content`) — this is precisely what CR-01 proves, empirically, on this machine.

So there is no second text slot in which to put a hover label. One of D-09's label or D-10's glyph must occupy `text`.

**Resolution (user-locked this session): glyph-only.** D-10 is the load-bearing decision — glyphs are sharp at any scale, get light/dark for free from the palette, and add zero new render targets. 06-CONTEXT.md already places *"wlogout hover-label mechanics"* under **Claude's Discretion**, so adjusting them is within granted scope.

**Affordance is preserved without the hover label** via three surviving mechanisms, all already in the codebase:
1. Per-action accent borders (`#lock` primary, `#shutdown` error, etc. — lines 79-133, currently inert only because the sheet is discarded).
2. Hover/focus colour inversion (`button:hover` / `button:focus`).
3. wlogout's own `keybind` letters, already set per action: l / e / u / h / s / r.

The verifier must treat this as an **explicit, deliberate deviation with a documented structural cause** — not a dropped requirement.
</locked_decision_deviation>
