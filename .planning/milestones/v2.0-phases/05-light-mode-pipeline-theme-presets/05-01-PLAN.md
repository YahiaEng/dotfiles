<objective>
Thread a first-class light/dark mode concept through the theme pipeline (THM-01): add a `materialyou-light` entry (D-05), auto-detect mode from palette lightness with a JSON override escape hatch (D-06), make both dark-hardcoded chokepoints mode-aware — `lib/gtk.sh` gsettings literals and `gtk-3.0/settings.ini` (D-07/D-08) — and convert settings.ini into a rendered state-dir contract target with a stow-seeded symlink (D-08). Also close the third dark hardcode discovered during planning: `uwsm/.config/uwsm/env` exports `GTK_THEME=adw-gtk3-dark`, which would force GTK3 apps dark regardless of gsettings under light mode.

Purpose: without this, light presets (Plan 05-02) render light colors but the desktop chrome stays dark — the exact failure mode the phase exists to fix.
Output: mode-aware pipeline core; every later plan in this phase builds on the `mode` marker and the extended contract.
</objective>
