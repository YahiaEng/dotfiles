STEP 1 — Create the stow package `wleave/.config/wleave/` with the layout config, using the filename 09-01 recorded (RESEARCH proposes layout.json). Use the wleave 0.7.1 wrapped schema: a single top-level JSON object containing a `buttons` array, not the legacy one-object-per-line form, because only the wrapped form can declare top-level options in the file rather than as CLI flags on every invocation. Top-level keys: `buttons-per-row` set to 6 using the value type 09-01 recorded (RESEARCH's verified example passes it as a string); `close-on-lost-focus` false, because D-18/D-20 forbid focus loss becoming a third dismissal path; `show-keybinds` false, because D-19 keeps the letters functional but never rendered. Leave `delay-command-ms` at its 100ms default and do NOT raise it — that delay exists so the compositor can tear the layer-shell surface down before a power transition, and D-10's final clause forbids letting any exit-animation ambition delay the action.

Six button objects in exactly this order (the D-05 severity gradient — note this puts reboot AHEAD of shutdown, swapping the retired layout's last two): lock, logout, suspend, hibernate, reboot, shutdown. Each object carries `label` (the lowercase action name — wleave uses this as the GTK widget name, which is what makes the id selectors `#lock`, `#logout`, `#suspend`, `#hibernate`, `#reboot`, `#shutdown` valid in 09-03), `action`, `text`, `keybind`, and `height` set to 0.5.

`height` is mandatory on every one of the six. It is an alignment fraction, not a pixel size: wleave positions an icon-less label via an Overlay at a vertical alignment read from this field, defaulting to 0.9 — near the bottom of the button. Omitting it reproduces Phase 6's exact visual symptom (glyph crowding the lower border) through a completely different mechanism. There is no per-button defaults-merge block at 0.7.1, so the field must be repeated on each button.

The six action strings carry over byte-identically (D-17). In the D-05 order above they are: `uwsm app -- hyprlock`; then `cliphist wipe; uwsm stop`; then `systemctl suspend`; then `systemctl hibernate`; then `cliphist wipe; hyprshutdown --post-cmd 'systemctl reboot'`; then `cliphist wipe; hyprshutdown --post-cmd 'systemctl poweroff'`. The clipboard-wipe prefix is joined with a semicolon and never with a logical AND — a wipe failure must not be able to block a shutdown (Phase 06-09 decision). Keybinds in the same order: l, e, u, h, r, s.

The six `text` glyphs are the codepoints 09-01 verified: lock U+F023, logout U+F08B, suspend U+F186, hibernate U+F2DC, reboot U+F021, shutdown U+F011. These are Private Use Area codepoints, and 08-16's durable finding is that PUA characters typed through the edit tool are silently stored as EMPTY strings. Do not type or paste the rendered characters. Generate the file so the codepoints land as real UTF-8 bytes — write the JSON from a python3 heredoc using escape sequences plus a non-ASCII-preserving dump, or write printf output into the file — then prove the bytes landed with the codepoint assertion in this task's verify block.

STEP 2 — Create `wleave/.config/wleave/style.css`, structural styling only. First line: a relative import of the state-dir render target, mirroring the retired sheet's idiom, so the deployed symlink at `~/.config/wleave/style.css` resolves it to `~/.local/state/theme/wleave.css`.

Then the transparent-window-plus-scoped-scrim split. A `window` rule setting `background-color: transparent` and `font-family: "FiraCode Nerd Font"`. GTK4 windows paint an opaque libadwaita window background by default, which silently defeats a blur layerrule by leaving nothing translucent to frost — the 10-06 durable finding, and the AGS stylesheet you read carries the same rule with the same rationale. Then a `window > box` rule setting `background-color: rgba(0, 0, 0, 0.40)` as the scrim. The direct-child combinator is load-bearing: wleave's content wrapper is a GtkCenterBox, which shares the CSS node name `box` with the nested buttons-row GtkBox, so a bare `box` selector would tint the capsule row the same colour as the backdrop. The 0.40 alpha literal is a deliberate, documented exception to the zero-literal-colour convention: it means the dim survives a total palette-resolution failure. Write a comment saying so.

Then the capsule geometry. GTK applies min-width and min-height to the CONTENT box and adds padding and border on top, so the 96px outer target is derived, not hardcoded: 62px content plus two times 16px padding plus two times 1px border equals 96px. Write a `button` rule with `min-width: 62px`, `min-height: 62px`, `padding: 16px`, `border: 1px solid @outline`, `border-radius: 24px`, `background-color: alpha(@surface, 0.35)`, `box-shadow: none`, `text-shadow: none`. Put the derivation in a comment naming its three inputs so a later padding change forces a recompute instead of silently clipping — the same discipline the retired wrapper script's own comment established for the outer-window case.

For the 24px inter-capsule gap (D-02): if 09-01 recorded a native inter-button spacing config key, use it in the layout config and add NO CSS margin. If it recorded none, add `margin: 12px` to the `button` rule (12px on each of two adjacent capsules composes to 24px) and add NO config key. Apply exactly one mechanism — applying both is Phase 6's double-gap bug reappearing in a new engine. Record which mechanism you used.

Then a `button label` rule with `font-family: "FiraCode Nerd Font"`, `font-size: 36px` (the retired surface's 28px-glyph-in-72px-button ratio of about 0.39, applied to 96px) and `color: @on_surface`. Do NOT add margin-bottom to the label: that was a GTK3 optical correction with no equivalent effect here, and vertical centring on this engine comes from the layout config's alignment field instead.

STEP 5 — Create `hypr/.config/hypr/scripts/wleave.sh` and delete `hypr/.config/hypr/scripts/wlogout.sh`. Open-only semantics (D-18): no pgrep, no pkill, no toggle branch. Shape: a bash shebang, `set -euo pipefail`, a `command -v wleave` guard that fires `notify-send "Power menu" "wleave is not installed" -u critical` and exits 1, then spawn wleave in the background, capture its PID, sleep about 0.3s, and use a `kill -0` liveness check whose failure branch fires `notify-send "Power menu" "wleave failed to launch" -u critical` and exits 1 (D-23). In any comment in this file, describe the retired engine's geometry problem WITHOUT naming the retired tool — Task 3's sweep negative-greps that name across the whole repo.
