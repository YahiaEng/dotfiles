# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Domain note:** Not a web/component-library UI. This phase is almost entirely an **interaction/copywriting contract**, not a new visual surface. Per `07-CONTEXT.md` D-08, the walker menu **reuses the existing `walker-style.css`** (contract target #18 since Phase 5/6) verbatim — **zero new CSS, zero new spacing tokens, zero new color mappings, zero new parity fixtures.** The only genuinely new visual surfaces this phase touches are two **kitty-hosted picker/table windows** (`nmtui` in floating kitty, the cheat-sheet's "View all" table), which follow the exact fzf-in-floating-kitty pattern already proven in Phases 5/6 — no new template either (they inherit `fzf-colors.conf`, contract target #13, and kitty's own themed profile).

What this phase **does** contribute that a checker must validate:
1. A complete **menu tree** (6 root entries → submenus → leaf actions) with exact wording and Nerd Font glyphs, each glyph verified present in the installed font (see Typography).
2. A **copywriting contract** for every notification, confirmation prompt, and empty/defensive state this phase's new scripts produce (gaming-mode toggle, AI workspace launch, cheat-sheet, kill-bind safety).
3. An **interaction contract** for navigation (drill-down, breadcrumb, cancel semantics) and for the walker→kitty picker handoff (D-16).

## Color

No new palette work, no new color mappings, no new render target. The menu is 100% covered by the existing `walker-style.css` 60/30/10 mapping locked in `05-UI-SPEC.md`/`06-UI-SPEC.md`:

| Role | Palette key | Usage (existing, unchanged) |
|---|---|---|
| Dominant (60%) | `background` / `on_surface` | `.box-wrapper` fill, unselected item text |
| Secondary (30%) | `surface_variant` / `on_surface_variant` | `.input` fill, `.item-subtext` |
| Accent (10%) | `primary` | **Reserved for:** selected-row background (`row:selected .item-box`/`child:selected .item-box`), input focus border, prompt/pointer glyphs. Never repurposed for a Phase-7 addition — every new menu entry above is plain `.item-text`, not an accent-colored element. |

Gaming-mode's `hyprctl keyword` runtime overrides (D-26) touch Hyprland's blur/animation/shadow/rounding keywords directly — this is **not** a color change and has no palette mapping; it is out of the Color contract's scope by definition (no hex values involved).

The two kitty-hosted surfaces (nmtui, cheat-sheet table) inherit kitty's active theme + `fzf-colors.conf`'s locked slot mapping (FG/BG/BG_PLUS/HEADER/etc., documented in `05-UI-SPEC.md` §3) verbatim — no new fzf color usage introduced (nmtui is not fzf-driven; it's ncurses and stays unthemed, matching D-17's explicit "kitty-themed, not nmtui-themed" scope).

## Copywriting Contract

Notification convention (established, reused verbatim from Phase 6): `notify-send -a "<App Label>" "<Title>" "<Body>" -i <freedesktop-icon-name> -t <ms>`. Standard timeout: 2000–3000ms; error timeout: 6000ms.

| Element | Copy |
|---------|------|
| Breadcrumb (in-menu placeholder or header) | `Menu › {Submenu}` — e.g. `Menu › Utilities`, `Menu › Utilities › Screenshot` (two-level max given the tree depth) |
| Root menu placeholder (input hint) | `Search or select...` |
| Kill-bind (D-03, tested in isolation first) | No user-facing copy — `pkill walker` fires silently; this is an escape hatch, not a feature |
| Gaming mode toggle notification (ON) | `notify-send -a "Gaming Mode" "Gaming Mode: ON" "Eye-candy disabled, idle-lock inhibited" -i input-gaming -t 2500` |
| Gaming mode toggle notification (OFF) | `notify-send -a "Gaming Mode" "Gaming Mode: OFF" "Desktop restored to theme defaults" -i input-gaming -t 2500` |
| Gaming mode menu entry (state-reflecting label, D-27) | `Gaming mode: ON` / `Gaming mode: OFF` — label text itself carries state, not just the glyph (accessibility: never rely on glyph swap alone) |
| AI Workspace launch (idempotent, D-24) | No notification on success (the workspace switch IS the feedback, matching the SwayOSD "the pill is the feedback" precedent from `06-UI-SPEC.md`); if a launch fails, `notify-send -a "AI Workspace" "Launch Failed" "{app} did not start" -i dialog-error -t 4000` |
| Ollama model missing (D-23, if a "pull a model" entry is included) | `notify-send -a "Local Models" "No Model Installed" "Run: ollama pull <model>" -i dialog-information -t 4000` — defensive/informational, not an error |
| Keybind cheat-sheet — walker searchable list header | `Search keybinds...` (placeholder) |
| Keybind cheat-sheet — walker list row format | `{Chord} — {Description}` e.g. `Super+Z — Emoji picker` (reuses the exact `keybinds.conf` trailing-comment text verbatim, per D-30 — never paraphrased, so the two surfaces can never diverge from the source file) |
| Keybind cheat-sheet — "View all" entry (opens kitty table) | `View all keybinds ›` |
| Keybind cheat-sheet — kitty table format | Column-aligned, section-grouped (mirrors `keybinds.conf`'s own `# ── Section ──` comment banners as group headers); columns: `CHORD` \| `DESCRIPTION`, left-aligned, header row bolded via kitty escape codes, section headers using the fzf `HEADER` color slot equivalent (kitty theme's `color3`/accent, not a new mapping) |
| Keybind with no description (defensive fallback — should not occur post D-30 backfill) | `(no description)` — never blank, never crash the parser |
| Missing/unbindable action (defensive, e.g. a script that no longer exists) | Entry omitted from both surfaces silently; logged non-fatally (matches Phase 6's Zen self-heal "silent, logged non-fatally" precedent, `06-UI-SPEC.md`) |
| Regression-sweep gate failure (D-04, scripted checker) | Non-interactive — prints a diff of declared-vs-registered binds and any shadowing conflicts to stdout/exit-nonzero; no `notify-send` (this is a dev-time gate, not a runtime user surface) |
| nmtui window title (D-17) | Kitty window `--title "Network"`, `--class "network-manager"` — follows `icon-theme-switch.sh`'s exact `--class`/`--title` launcher-shim convention |
| Cancel (Esc/click-outside) anywhere in the menu | Silent — walker's own exit-130 convention, no notification (matches Phase 5's `theme-switch.sh` cancel pattern, reused verbatim by every submenu, not just leaf pickers) |

**Destructive actions in this phase:** none introduced directly — Power delegates entirely to the existing `wlogout.sh` (D-19), which already owns its own confirmation-free-but-deliberate action model (unchanged, Phase 4/6 audited). Gaming mode's toggle is reversible and session-scoped (D-28), not destructive. The clipboard wipe entry (`Super+Shift+C`) is pre-existing (Phase 6 D-15) and its confirmation copy is already locked in `06-UI-SPEC.md` — not re-specified here.

## Interaction Contract

### Navigation (D-06)

- **Drill-down in place**: selecting a root entry swaps the same walker window's list to that submenu's entries. Esc or Backspace goes back exactly one level (root → submenu → back to root; sub-submenu, i.e. Screenshot, → back to Utilities → back to root).
- **Breadcrumb** shown per the Copywriting Contract row above; exact placement (input placeholder vs. a header slot) depends on what the D-05 `menus` provider spike actually exposes — both candidate implementations use existing unstyled rules, so no new CSS decision blocks this.
- **Global cross-submenu search is explicitly NOT required** (D-06) — bonus only if the walker matcher provides it for free at zero implementation cost. Do not hand-roll it.
- **Esc from the root level** closes the menu entirely (walker's existing `close_when_open`/`click_to_close` behavior, unchanged).

### Menu engine decision gate (D-05 — binding on the plan, not this file)

This UI-SPEC describes the **target interaction shape** (drill-down, breadcrumb, entry format) independent of which engine renders it. The plan/executor must still run the D-05 spike (prove walker 2.16.2's `menus` elephant provider actually expresses submenus + actions + icons) before committing. If the spike fails, the **bash + `walker --dmenu` chain** (Phase 5's exit-130-cancel pattern, reused verbatim) delivers the identical interaction contract above — same tree, same wording, same glyphs, same breadcrumb text — just via chained script invocations instead of a declarative provider. This UI-SPEC's contract does not change based on that engine choice; only the implementation does.

### Launch convention (D-09)

Every GUI-launching entry uses `uwsm app -- <app>` (or `<app>.desktop` where an existing keybind already established that form, e.g. `kitty.desktop`). Shell scripts (all Phase 6 utility scripts, `theme-switch.sh`, etc.) are invoked bare, matching `keybinds.conf`'s existing convention exactly — the menu introduces no second launch pattern.

### Picker handoff (D-16)

Selecting a Settings entry that targets a kitty-graphics-preview picker (Wallpaper, Icon theme, Font) or a rich table (nmtui, cheat-sheet "View all") **closes the walker menu first**, then opens the floating kitty window — identical to what pressing the entry's existing keybind does today. This is an intentional surface transition, not a bug: the kitty-graphics previews these pickers render (wallpaper thumbnails, live font specimens, icon grids, column-aligned tables) are not expressible inside walker's list view. **The menu is a launcher for the pickers, not a replacement for them** — do not attempt to rebuild picker previews as walker submenu items.

### Tap-only safety (D-02/D-03 — binding on the plan)

Before any Super-tap bind experiment lands: (a) the kill-bind (exact chord Claude's discretion, e.g. `Super+Escape` → `pkill walker`) must be bound and tested in isolation FIRST, verified to never be shadowed by any existing `$mainMod`-prefixed bind in `keybinds.conf`; (b) a second TTY must be logged in with the Phase 4-style recovery procedure open before touching `keybinds.conf`. This UI-SPEC does not prescribe the exact tap-only mechanism (release-bind, submap, or an input-layer tool) — that is D-02's research question — but any mechanism chosen must preserve every existing `$mainMod+key` combo verbatim, provable by the D-04 scripted regression sweep (`hyprctl binds` cross-check) plus a human pass.
