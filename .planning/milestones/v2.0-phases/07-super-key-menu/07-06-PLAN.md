<objective>
Build the AI dashboard (MENU-03): a submenu of AI launchers plus the dedicated, idempotent Hyprland AI workspace.

Purpose: This is greenfield — nothing AI-related is installed today. Two things make it non-trivial rather than a list of `exec` lines: (1) Zen collapses every window to one WM_CLASS, so D-21's per-app windowrule classes are not achievable as written and need a verified fallback; (2) D-24's idempotency is a real engineering requirement — a naive "launch everything" entry doubles your windows on the second pick.
Output: A 7-entry AI submenu, an idempotent workspace launcher, and windowrules that actually discriminate the AI web-app windows from the user's regular browser.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ollama daemon ↔ aichat (localhost:11434) | A local inference API on a TCP port. Unauthenticated by design; the control is that it binds loopback only. |
| Zen web-app windows → remote AI services | The AI web-apps load remote third-party sites. This is a browser doing what a browser does — the browser's own sandbox is the trust boundary, not this phase's code. |
| windowrules → window placement | A mis-scoped rule grabs windows it should not, including the user's regular browsing window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-09 | Information Disclosure | ollama listening on a network port | medium | mitigate | Inherited from 07-03: ollama binds 127.0.0.1:11434 by default and `OLLAMA_HOST` is never set, so the inference API is not reachable off-host. aichat connects to that loopback endpoint. D-23's no-auto-pull also means the daemon serves nothing until the user deliberately pulls a model. |
| T-07-18 | Spoofing / unintended action | a class-only windowrule grabbing the user's regular Zen browsing window | medium | mitigate | Zen's single-WM_CLASS behaviour is verified live (RESEARCH Pitfall 4). Task 1 empirically determines a working discriminator BEFORE authoring rules, and an explicit regression test launches a normal Zen window and asserts it is untouched. A class-only placement rule is forbidden by acceptance criteria. |
| T-07-19 | Denial of Service | AI Workspace duplicating windows on repeated picks | medium | mitigate | D-24's idempotency, asserted by measured window-count equality across two consecutive invocations. The script fails CLOSED when it cannot query compositor state (switches workspace, launches nothing) rather than launching blind. |
| T-07-20 | Information Disclosure | AI web-apps loading remote third-party services | low | accept | The user is deliberately opening claude.ai / chatgpt.com / gemini / perplexity in their own browser — identical to typing the URL. Zen's sandbox is the control. D-21 explicitly chose Zen web-app windows OVER AUR electron wrappers precisely to avoid adding an unaudited supply-chain dependency for something a browser tab already does. |
