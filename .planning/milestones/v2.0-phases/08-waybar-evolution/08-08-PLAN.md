Tunable constants at the top of the file, each on its own line with an explanatory comment:
  - `ANCHOR_MODE` — `cursor` or `fixed`, default `cursor`. **This is D-23's pre-authorised fallback switch.** Flipping this one constant to `fixed` takes the fixed-position path with zero other edits anywhere in the repo.
  - `POPUP_W` / `POPUP_H` — the popup's declared size. The comment must state the invariant: these MUST equal the `:width` / `:height` in 08-07's `defwindow media-popup` `:geometry`. UI-SPEC fixes the width at 300px; take the height from what 08-07 actually shipped, never from a guess.

  - `CURSOR_GAP` — vertical offset from the cursor to the popup's top edge.
  - `WINDOW_NAME` — the eww window name exactly as 08-07 declared it.

Behavior, in order:

1. **Guards.** If `eww` is not on PATH, exit 0 **silently**. The UI-SPEC's Copywriting Contract makes this an explicit silent no-op — a missing eww is a build/packaging concern, never a user-facing toast, and an error notification on every click is worse than nothing. Guard `hyprctl` and `jq` the same way, but on their absence fall through to the fixed path rather than exiting, since the fixed path needs far less of them.

2. **Single-flight guard.** Take a non-blocking `flock` on a lockfile under `$XDG_RUNTIME_DIR` (falling back to `~/.cache` when that is unset) and exit 0 if the lock is already held. A burst of clicks on the segment must not spawn racing open/close calls that leave the popup in an indeterminate state.

3. **`cursor` mode — read the pointer.** `hyprctl cursorpos` is verified live to emit a single line of the form `<int>, <int>` (observed: `1352, 941`). Parse it with a strict ANCHORED regex accepting only optional-minus integers. If the line does not match that shape, do NOT use it — fall through to the fixed path. An unvalidated string never reaches an `eww` argument.

4. **Select the monitor by CONTAINMENT, not by `focused`.** Read `hyprctl monitors -j` — verified live to carry `name`, `x`, `y`, `width`, `height`, `scale`, `focused` — and choose the monitor whose logical rectangle contains the cursor point. Logical width is `width / scale` and logical height is `height / scale`: `x`/`y` are already logical layout coordinates while `width`/`height` are the mode's PHYSICAL pixels, so a fractional-scale display would otherwise be sized wrong and the clamp computed against the wrong rectangle. Use `jq` to compute and emit the chosen monitor's `name x y logical_w logical_h` as one whitespace-separated line, and validate every field against the same integer regex before use. If no monitor contains the point (should be impossible), fall back to the `focused` monitor; if that also yields nothing usable, exit 0 silently.

5. **Compute and clamp.** Centre the popup horizontally on the cursor (`x = cursor_x - POPUP_W / 2`) and place it below by `CURSOR_GAP` (`y = cursor_y + CURSOR_GAP`). Then CLAMP both axes into `[mon_x + EDGE_MARGIN, mon_x + mon_w - POPUP_W - EDGE_MARGIN]` and `[mon_y + EDGE_MARGIN, mon_y + mon_h - POPUP_H - EDGE_MARGIN]`.

   The clamp is what makes ONE code path work identically from every layout, which is precisely what D-23's fallback clause demands of any solution: from the top-anchored bars the cursor sits near y≈20 so the popup drops cleanly below it; from the vertical/left column the cursor sits at x≈24 so the centred x goes negative and clamps flush to the left edge, opening beside the column instead of off-screen; near the right or bottom edge it clamps flush inside. The clamp is ALSO the monitor-seam guard — because both axes are clamped inside ONE monitor's rectangle, the popup can never straddle two displays. If `POPUP_W + 2 * EDGE_MARGIN` exceeds the monitor's logical width (a pathological tiny display), clamp to `mon_x + EDGE_MARGIN` and let the popup overflow, rather than computing an inverted range and producing garbage coordinates.

6. **`fixed` mode — D-23's pre-authorised fallback.** Skip the cursor read entirely. Place the popup at the `focused` monitor's top-right: `x = mon_x + mon_w - POPUP_W - 10`, `y = mon_y + 10`, mirroring where swaync's control centre opens (the UI-SPEC's own wording for this fallback). This path runs the identical clamp and the identical eww invocation — only the source of the raw point differs — which is what makes ANCHOR_MODE a genuine one-constant flip rather than a second implementation.

7. **Invoke eww in ARRAY FORM.** Every value quoted; no `eval`, no `sh -c`, no unquoted command substitution in an argument position. Pass, using the Step-A-pinned spellings: the toggle flag, `WINDOW_NAME`, the x arg, the y arg, and the monitor selector if 08-07's window definition needs one. Convert to the coordinate space Step B proved before passing. Guard the invocation with `2>/dev/null || true` so a transient eww failure can never propagate a nonzero exit back into waybar's click handler.

8. `chmod +x`.

**Hard boundary:** nothing in this script may send waybar SIGUSR1 or SIGUSR2. 08-03 is the sole owner of waybar visibility (outline note 2), and D-08 makes overlays explicitly not a visibility intent — opening the popup leaves the bar's state untouched in both directions. There is no interaction to write here, only one to NOT write.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| waybar `on-click` string → `/bin/sh -c` | waybar executes every `on-click` value through a shell. Whatever string sits in that config field IS a shell command. |
| `hyprctl` (compositor IPC) → `media-popup-open.sh` shell variables → `eww` argv | Coordinates and monitor geometry are parsed out of subprocess output and then used to build a command line. This is the only external data this plan's script consumes. |

| mpris player metadata → **NOT crossed by this plan** | Track/artist/album/artUrl strings are player-supplied and untrusted, but they never enter this plan's script (see T-08-83). That boundary is owned entirely by 08-07's hardened `media-*.sh` helpers. |
