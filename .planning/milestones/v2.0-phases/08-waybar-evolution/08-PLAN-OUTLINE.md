## Notes for per-plan authors

Contracts a planner writing ONE of these in isolation would otherwise miss:

1. **Everything goes through 08-01's shared-include mechanism.** `modules.jsonc` holds one canonical definition per module key and **zero** bar-level or `modules-*` keys. Each `config-<layout>.jsonc` declares `include`, its own bar keys, its own `modules-left/-center/-right`, and — where it genuinely diverges — a **full redefinition** of the module key. waybar's `include` is **whole-key, first-defined-wins, NOT a deep merge** (verified against `waybar.5.gz`). Never partial-patch a module. Never copy-paste a module into four config files.

2. **08-03 is the single owner of waybar visibility.** `on-sigusr1` is reconfigured to the FIXED action `hide` (never `toggle`) in `bar-common.jsonc`; `on-sigusr2` stays `reload`. **Nothing in 08-05..08-10 may send waybar a raw SIGUSR1/SIGUSR2 toggle.** Any new actor declares an intent via `waybar-visibility.sh <source> <hide|show>`, and the `<source>` allowlist (`idle|fullscreen|gaming`) is load-bearing security — adding a source means extending that allowlist inside the owner, not bypassing it. 08-10 in particular must respect D-09 kill-criterion #3: if pixel-shift jitter needs to coordinate with the owner beyond "don't jitter while hidden", **kill the feature**.

3. **`waybar-equivalence-check` (08-01) is a live drift detector, not a one-shot.** Any plan that changes a waybar config's *effective* resolved output (08-05 adding `custom/gaming-mode` to `modules.jsonc` and the bell to floating; 08-08 re-pointing `mpris`'s `on-click`) will make the gate diff. The required move is: run the gate, **review the printed diff and confirm it contains ONLY the intended change**, then re-snapshot the baseline (`--snapshot .planning/phases/08-waybar-evolution/.waybar-config-baseline/`). Never edit the baseline by hand. 08-03 already established this pattern.

4. **08-02 already made layout discovery dynamic.** `config-vertical.jsonc` + `style-vertical.css` become selectable and launchable with **zero script edits** — do not add a "vertical" case anywhere. `full` remains the hardcoded *fallback constant* (D-16); that is not a hardcoded list. The picker label is derived from the filename; do not author a "Vertical" string.

5. **eww is the phase's ONLY new render target (D-19).** It must be a first-class theme-pipeline citizen, not a hardcoded stylesheet: a new `matugen/.config/matugen/templates/eww-colors.scss` (all 19 palette keys in SCSS `$var:` syntax), a new `[templates.eww]` block in `matugen/config.toml` (3 lines, **no `post_hook`** — reload is owned exclusively by `theme-engine/lib/reload.sh`), a new `contract.json` entry (`{ "name": "eww.scss", "format": "scss-kv" }`, files 17→18), and a **new `scss-kv` branch in `lib/contract.sh`'s two `case "$fmt"` dispatchers** — an unknown format tag is designed to be loud, so omitting the parser branch fails `theme-parity` across all 22 palettes. `theme-parity` must go green (light + dark) before eww is considered landed.

6. **eww is AUR-only and therefore blocking-human-gated (D-36).** 08-06 MUST contain a `<task type="checkpoint:human-verify" gate="blocking-human">` before the install, per RESEARCH's Package Legitimacy Audit (`eww` is `[ASSUMED]`; `eww-git` is NOT to be installed). This checkpoint is never auto-approvable, so **08-06 is `autonomous: false`.** eww is a compiled Rust binary — the unattended container gate (`verify/container-run.sh`) must stay green and its wall-clock/timeout budget must be checked, not assumed. Also: `eww` joins `stow.sh`'s `PACKAGES` array (currently 19 entries).

7. **Verify eww's CLI against the installed binary before writing any wrapper (RESEARCH Pitfall 4).** `eww open --toggle`, `--arg`, `:onlostfocus`, `:onkeypressed` are all MEDIUM/LOW-confidence WebSearch findings. The first eww task after install must run `eww --help` / `eww open --help` and pin the real flag spellings. 08-08's anchoring uses `hyprctl cursorpos` (verified live) + `hyprctl monitors -j` clamping, with the **fixed-position fallback pre-authorised by D-23** — take the fallback without debate if the cursor approach jitters.

8. **mpris metadata is untrusted input (security contribution, ASVS L1, block on `high`).** Track/artist/album strings and `mpris:artUrl` come from arbitrary third-party players and can contain shell metacharacters, newlines, and Pango-breaking characters. Every plan touching them (08-07 primarily, 08-08 secondarily) needs `<threat_model>` entries for command injection: quote everything, **no `eval`**, array-form/argv invocation only, validate `artUrl`'s scheme (`file://` passthrough vs `http(s)://` download) before acting, `curl -sL --` with a `--` guard, and hash-key the album-art cache filename under `~/.cache/eww-media-art/` rather than using a predictable path. Zen/Firefox already exposes a local `file://` artUrl (verified live); Spotify's remote-URL branch is Assumption A2.

9. **D-28 is a HARD anti-drift constraint on 08-09.** Every `buttons-grid` toggle must call the SAME script and read the SAME state file as the Super-key menu: gaming → `gaming-mode-toggle.sh` (bare call; it is already idempotent-toggle-shaped) + `~/.cache/gaming-mode`; DND → `swaync-client -dn/-df` + `-D`; theme → `theme-switch.sh` + the theme-engine's existing state (`~/.local/state/theme/mode`, already declared in `contract.json`'s `state_metadata_files`). **No second copy of any toggle's logic, no independently-derived state.** Note theme-switch.sh is a *picker*, not a boolean — its toggle's `active` state must reflect real read-back state (light/dark), and that semantic must be recorded in the SUMMARY.

10. **Glyphs must be cmap-verified against the installed FiraCode Nerd Font before use** (Phase 6/7 discipline — never copy an unverified codepoint). This binds 08-05 (gaming-mode indicator ON/OFF glyphs) and 08-09 (gaming + theme toggle labels). The DND glyph `󰂛` is already live in `config-full.jsonc` and needs no re-verification.

11. **D-17's "full module re-test" is a rerunnable gate, not a checklist.** Fold it into `theme-doctor` (which already hardcodes a 3-file `GTK3_CSS_SHEETS` list at lines 194-201 — `style-vertical.css` is a 4th entry there, itself an instance of the copy-paste drift D-31 exists to kill). The gate asserts every module named in every layout's `modules-*` arrays has a reachable CSS rule and that every colour token those rules reference is `@define-color`'d in the rendered `~/.local/state/theme/waybar.css`. An unresolved colour is a hard FAIL (this is the exact Phase-1 battery/backlight silent-unstyled bug class). Plus a human pass under one light and one dark preset.

12. **BAR-02 may legitimately fail — but only loudly (D-10).** 08-10's descope is *real, verifiable work*: a written evidence artifact recording what was attempted (2px jitter / 15-min interval per UI-SPEC), which kill criterion fired, measurement method, and the explicit evaluation of the standing hypothesis ("D-01's auto-hide + D-06's luminance trim may already remove most of the exposure" — must be *demonstrated*, not asserted). The artifact must be copy-paste-ready as a `## BAR-02` section of `08-VERIFICATION.md`. A silent drop is a plan failure.

13. **Housekeeping conventions every plan inherits:** stow-package layout (never host-only state); `set -euo pipefail` + boxed header + atomic `tmp`+`mv` state writes + `2>/dev/null || true` on best-effort external calls (see `gaming-mode-toggle.sh`); `exec-once = uwsm app -- <script>` for any daemon; `bind = <mod>, <key>, exec, <script> # <description>` with a **mandatory** trailing description (MENU-07's cheat-sheet parses it literally); no `font-family` literal in any waybar stylesheet (Phase 6 CR-01 — `waybar-font.css` owns it); zero hex-literal colours in any pipeline stylesheet.
