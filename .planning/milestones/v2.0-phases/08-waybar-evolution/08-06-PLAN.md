<critical_findings>
**Read before touching anything.**

1. **`eww` is AUR-only and tagged `[ASSUMED]`** in RESEARCH's Package Legitimacy Audit. `pacman -Ss eww` finds nothing in `core`/`extra`; `paru -Si eww` resolves (0.6.0-1, 42 votes, maintainer `eclairevoyant`, upstream `github.com/elkowar/eww`, last modified 2024-08-12). **Registry lookup succeeding does NOT waive the human gate** — D-36's text mandates it, and RESEARCH says so explicitly. The git-suffixed AUR variant is **refused** (lower adoption, worse reproducibility).

2. **eww is GTK3 + `gtk-layer-shell`** (verified via `paru -Si` dependency list — NOT GTK4/libadwaita). This is what makes D-18's whole bet valid: GTK3 is the toolkit tier this repo's PROJECT.md documents as fully themeable via named colours. eww genuinely CAN follow the palette; a GTK4 popover could not.

3. **`contract.json`'s two dispatchers are designed to be LOUD.** `contract_extract_names()` and `contract_extract_values()` in `lib/contract.sh` each end in a `*)` catch-all that prints `unknown format '$fmt'` to stderr and `return 1` (CR-01). Adding `{"name":"eww.scss","format":"scss-kv"}` to `contract.json` **without** adding a `scss-kv` branch to BOTH dispatchers fails `theme-parity` across all 22 targets, instantly and noisily. That is by design. Add the entry and the two branches in the same task.

4. **matugen's config.toml carries NO `post_hook` lines, by contract.** Its own header states reload is owned solely by `theme-engine/lib/reload.sh` (PIPE-02/D-04). The eww reload therefore lands in `reload.sh`, not in matugen.

5. **eww's CLI is MEDIUM/LOW confidence** (RESEARCH Pitfall 4). `eww open --toggle`, `--arg`, `:onlostfocus`, `:onkeypressed` all come from WebSearch, not from a binary anyone has run. Task 3 pins them. 08-07 and 08-08 are already written against the interface `eww open media-popup --arg x=<int> --arg y=<int>` and the window name `media-popup` — if the installed binary spells something differently, **record the real spelling in the SUMMARY** so the downstream plans correct against it rather than silently no-op'ing.

6. **`~/.config/eww` does not exist yet** (verified). Once the `eww/` stow package lands, stow will *fold* the directory (symlink `~/.config/eww` -> the repo dir) unless it is pre-created as a real directory — exactly the fish/gtk-3.0/gtk-4.0 precedent in `stow.sh`. This matters for how eww's SCSS `@import` of the rendered palette resolves; Task 5 verifies it empirically instead of assuming.
</critical_findings>
