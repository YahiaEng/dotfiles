waybar `include` is **whole-key, first-defined-wins** — NOT a deep merge (verified against the installed `waybar.5.gz`: *"In case of duplicate options, the first defined value takes precedence, i.e. including file -> first included file -> etc."*). Therefore:

- `modules.jsonc` holds ONE canonical definition per module key.
- Any layout whose current definition differs from the canonical one must **fully redefine that key in its own file** (not partially patch it) — as the including file, its definition wins in its entirety.
- **Do NOT "unify" divergent definitions.** Unifying floating's `cpu` onto full's `cpu` is a behavior change and D-33 forbids it. The equivalence gate in Task 1 exists precisely to catch that.

The refactor's payoff is not "every module is now shared" — it is "every module this phase ADDS or CHANGES cross-cuttingly is defined once." That is the entire scope guard (D-31).

It must NOT be a preprocessor waybar runs — waybar still resolves its own `include` at runtime; this script only *proves* the resolution is equivalent.

Behavior:
1. `resolve_layout <config-path>` — emit the normalized effective config as JSON on stdout:
   - Strip JSONC comments (`//` line comments and `/* */` block comments). This mirrors waybar's documented precedence exactly.
   - Drop the `include` key itself from the output (it is a directive, not effective config).
   - Emit recursively key-sorted JSON so the diff is order-insensitive.
2. `--snapshot <outdir>` mode — write `<outdir>/{layout}.json` for every `waybar/.config/waybar/config-*.jsonc` found (glob, never a hardcoded list — the same disk-truth principle as D-32).
3. Default (check) mode — resolve every current `config-*.jsonc` and `diff` it against `.planning/phases/08-waybar-evolution/.waybar-config-baseline/{layout}.json`. Print a unified diff for any mismatch. Exit 0 only if every layout that has a baseline matches it byte-for-byte. A layout with NO baseline (i.e. `vertical`, added later in this phase) is reported as `SKIP (no baseline — new layout)` and does **not** fail the gate.
4. Accept an optional explicit waybar-dir argument (default `$HOME/.config/waybar`) so the gate can be pointed at a throwaway copy for a self-test — a gate that cannot fail is not a gate (keybind-doctor's own header convention).
5. `set -uo pipefail` (not `-e` — a gate must survive an individual check failing and still report), PASS/FAIL counters, a final `PASS: n  FAIL: n` line, exit 1 when FAIL > 0.

Then, **before any refactor edit lands**, run `waybar-equivalence-check --snapshot .planning/phases/08-waybar-evolution/.waybar-config-baseline/` against the CURRENT standalone configs and commit the three resulting baseline JSON files. Make the script executable (`chmod +x`). It lives in the `hypr` stow package so it deploys to `~/.config/hypr/scripts/` with everything else.
