The UI-SPEC currently states the waybar work is a "styling *trim*, not a new visual identity" and
specifies the OLED deltas that produced the failure — an `alpha(@background, 0.90)` window
background and a transparent-underline active workspace. The user's explicit redesign directive
superseded that contract. Leaving the spec describing a design that no longer exists guarantees a
future phase "restores" the bug.

Update it to describe the shipped design:
- Replace the "No redesign — this is a styling trim" framing with the translucent-island design
  system. State plainly that the OLED-trim approach was tried, shipped, rejected by the user on
  sight, and replaced.
- Replace the "OLED Styling Deltas" table with the design system's rules: transparent window,
  surface on the inner box (or on .modules-* for floating), ONE neutral surface derived via
  `alpha()` from a real palette token, chroma reserved exclusively for state, the 14/10/6 radius
  scale, `min-height: 0`, the workspace-button min-width floor, and per-role font sizes.
- Correct the palette section. The spec's Color section must state the 19 real token names and
  must record that there is NO surface-container token — this is the single most dangerous
  misconception in the phase's artifacts (08-UAT.md's design_direction prescribes one, and using
  it makes GTK3 discard the entire stylesheet). Add the semantic alias layer (theme.css) as the
  documented indirection, and state the rule that palette token names appear in exactly one file.
  <!-- planner-discipline-allow: surface-container -->
- Record the glyph-verification discipline as binding: a codepoint must be verified by its GLYPH
  NAME in the installed font's cmap, not merely by presence. Cite the concrete burn (U+F04FE is
  present but is `md-target`, not a controller) so the next author cannot dismiss it as pedantry.
- Update the vertical layout's column width to the value actually observed in plan 14, and note
  that waybar's `width` key is advisory — the column sizes to its widest child, so width is
  controlled by content, not config.
- Set the Checker Sign-Off status and `status:` frontmatter to reflect the shipped state.

Keep the eww and swaync sections intact — this redesign did not touch those surfaces.
