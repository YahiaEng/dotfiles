<objective>
Replace the hardcoded three-item layout lists in `waybar-switch.sh` and `waybar-launch.sh` with disk enumeration over `config-*.jsonc` (D-32).

Purpose: this is the **identical fix Phase 5 already applied to palettes** (`palettes/*.json` dynamic enumeration), which PROJECT.md records as closing that pitfall permanently. The same hardcoded-list pattern is sitting in these two scripts right now, and the vertical layout (plan 08-05) is about to prove it: without this, adding `config-vertical.jsonc` silently produces a layout that exists on disk, is invisible in the picker, and gets reset to `full` by the launcher's enum validation.

Output: two scripts that treat the filesystem as the source of truth for "what layouts exist."
</objective>

  <action>
Rewrite the layout-discovery half of `waybar-switch.sh`. Keep everything else byte-identical — in particular the walker-dmenu exit-code-130 cancel pattern (`rc=0; SELECTED=$(... ) || rc=$?; if (( rc == 130 )) then exit 0`), the `pkill waybar` + `sleep 0.3` + `uwsm app -- waybar -c … -s …` relaunch, the `~/.cache/current-waybar-layout` state write, and the `notify-send -a "Waybar Switcher"` confirmation. Those are load-bearing and out of scope.

Replace:
1. **The hardcoded `LAYOUT_LIST` string** with a list built by globbing `"$WAYBAR_DIR"/config-*.jsonc`, taking each file's basename, stripping the `config-` prefix and the `.jsonc` suffix, and rendering one menu line per layout. Sort the results so the menu order is stable across runs (`sort`), rather than depending on glob/locale ordering.
2. **The hardcoded `case "$SELECTED" in *"Minimal"*) …` mapping** with a direct mapping from the selected menu line back to its layout slug. Do not re-parse a decorated label with glob patterns — carry the slug through. The simplest correct shape: build a parallel array of slugs in the same order as the menu lines, or emit the menu line in a form whose slug is mechanically recoverable (e.g. the layout slug is the last whitespace-separated token, or the line is `<Title>` and the slug is `${title,,}`).

**Menu label copy (UI-SPEC, binding):** the label is *derived from the filename* — title-cased from the slug (`vertical` → `Vertical`, `minimal` → `Minimal`). Do NOT hardcode a per-layout description string (the current emoji + em-dash descriptions like `📊 Full — System stats, media, tray` are hardcoded copy that a 4th layout would have no entry for, which is exactly the drift D-32 kills). If a decorative prefix is kept, it must be uniform across all entries or derived, never a per-layout literal lookup table.

**Guards:**
- If the glob matches zero files, `notify-send` an error (`-a "Waybar Switcher"`, `-i dialog-error`, following the existing error-notify shape) and exit 1 — never silently fall through to an empty walker menu.
- Validate that the chosen layout has BOTH a `config-<slug>.jsonc` AND a `style-<slug>.css` before relaunching waybar. A config without a matching stylesheet would launch an unstyled bar; fail loudly instead.
- Keep `set -euo pipefail`.

  <action>
Rewrite the validation in `waybar-launch.sh`. Preserve its contract exactly: read `~/.cache/current-waybar-layout`, fall back to `full` when absent or invalid, then `exec waybar -c "$WAYBAR_DIR/config-${LAYOUT}.jsonc" -s "$WAYBAR_DIR/style-${LAYOUT}.css"`.

Replace the hardcoded `case "$LAYOUT" in minimal|full|floating) ;; *) LAYOUT="full" ;; esac` enum with a **disk-truth existence check**: the saved layout is valid if and only if BOTH `"$WAYBAR_DIR/config-${LAYOUT}.jsonc"` and `"$WAYBAR_DIR/style-${LAYOUT}.css"` exist as files. Otherwise fall back to `full`. Same disk-truth principle as Task 1 — the filesystem, not an enum a human must remember to update.

**D-16 is binding: `full` remains the hardcoded fallback default.** This is not a hardcoded *list* (which D-32 kills) — it is a single fallback constant, and it is deliberate: a fresh install and the unattended container/VM gate must keep landing on `full`, not on whatever layout happens to sort first on disk. Do not "improve" this into "first layout found."

**Path-traversal guard (the state file is host-side and user-writable):** `$LAYOUT` is read from `~/.cache/current-waybar-layout` and then interpolated into two file paths. Validate it against a strict slug pattern (`^[A-Za-z0-9_-]+$`) before using it in any path — a state file containing `../../evil` must fall back to `full`, not construct a path outside `$WAYBAR_DIR`. The existence check alone is not sufficient, because a traversal path could resolve to a real file elsewhere.

Add `set -uo pipefail` (the script currently has no strict-mode line at all). Do NOT add `-e`: this script ends in `exec`, and an `-e` abort on a transient `cat` failure would leave the session with no bar. The fallback path must always be reachable.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `~/.cache/current-waybar-layout` → `waybar-launch.sh` | A host-side, user-writable state file whose contents are interpolated into two filesystem paths at session start. This is the only untrusted-ish input in this plan. |
| walker dmenu stdout → `waybar-switch.sh` | The user's own menu selection; walker is a trusted local process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-13 | Tampering | `waybar-launch.sh` `$LAYOUT` → path interpolation | medium | mitigate | Validate `$LAYOUT` against `^[A-Za-z0-9_-]+$` before it is interpolated into `config-${LAYOUT}.jsonc` / `style-${LAYOUT}.css`. A traversal value (`../../…`) falls back to `full`. Quote every path expansion. |
| T-08-14 | Tampering | `waybar-switch.sh` layout slug → `waybar -c` argument | low | mitigate | Slugs are derived from `basename` of a `config-*.jsonc` glob, so they cannot contain `/`. Pass paths as separate quoted argv to `uwsm app -- waybar`, never through `sh -c` string interpolation. |
| T-08-15 | Denial of Service | zero-layout glob | low | mitigate | An empty glob must produce a loud error + nonzero exit, not an empty walker menu or an `exec waybar -c ''` that leaves the session barless. |
| T-08-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan installs no packages. |
