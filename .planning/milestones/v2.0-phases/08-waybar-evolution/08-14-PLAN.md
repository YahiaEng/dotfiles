<inherited_design>
The design system is defined in 08-12-PLAN.md's `<design_system>` block and was approved by the
user at plan 12's checkpoint. Read it there and follow it.

Vertical's structural divergences from the horizontal layouts:
- The island goes on `window#waybar > box` (same as full/minimal) but is a narrow vertical strip.
- Glyph size is 18px (the column is glyph-only; the horizontal bars' 16px glyph size is tuned to
  sit beside 13px text, which does not exist here).
- The column's width is NOT set by config. waybar's `width` key is advisory and the column sizes
  to its widest child, which is why 08-05 got a live warning that 48px was refused in favour of
  66px. Width is therefore controlled by CONTENT: shrink the content and the column narrows on
  its own. Do not fight it with the `width` key. Whatever width the content settles at is the
  answer to the deferred UAT Test 2 question — record it in the SUMMARY.
</inherited_design>

<task type="auto">
  <name>Task 1: Strip config-vertical.jsonc to icon-only formats with detail in tooltips</name>
  <files>waybar/.config/waybar/config-vertical.jsonc</files>
  <action>
Plan 11 already repaired this file's hardcoded calendar hex and promoted its glyph set upstream
into modules.jsonc. What remains is to make the column genuinely icon-only, which is what lets
it narrow and stop reading as a stack of boxes.

The column currently stacks a glyph plus a `<small>`-wrapped value inside each of cpu, memory and
temperature (e.g. a microchip glyph, a newline, then `<small>{usage}%</small>`). Two stacked
lines per module is what forces the column wide and makes each module a tall box. Go icon-only:
each of cpu, memory, temperature, pulseaudio, network and battery renders ONLY its glyph, and the
numeric detail moves into `tooltip-format` where it belongs. This is the layout's own stated
premise — anything that needs a text label to be useful does not belong in the column.

Keep the clock as the ONE exception: it stays as stacked text (`{:%H\n%M}`, hours over minutes,
stacked with a newline rather than rotated). A bare clock glyph would be useless, and a rotated
label is unreadable — stacking is the correct answer and it is already implemented that way.

For every module whose detail you move out of the column, ensure `tooltip-format` actually carries
that detail (cpu usage %, memory used/total, temperature °C, volume %, network essid/ip, battery
capacity + time remaining). A tooltip that says nothing is worse than no tooltip. Do not use
`tooltip: false` on any module that just lost its inline text.

Leave `custom/notification` alone — it is a `return-type: json` module whose exec already emits a
live tooltip field, and flipping tooltip to true was a deliberate prior decision.

Do not touch module ordering, on-click actions, or exec commands.
  </action>
  <verify>
    <automated>~/.config/hypr/scripts/waybar-design-lint 2>&1 | grep "CHECK E" && python3 -c "
import json,re
s=re.sub(r'^\s*//.*$','',open('waybar/.config/waybar/config-vertical.jsonc').read(),flags=re.M)
d=json.loads(s)
for m in ['cpu','memory','temperature']:
    f=d[m].get('format','')
    assert '<small>' not in f and '\n' not in f, f'{m} still stacks text in the column: {f!r}'
    assert any(k.startswith('tooltip') for k in d[m]), f'{m} lost its detail with no tooltip to carry it'
assert '\n' in d['clock']['format'], 'clock should stay stacked'
print('vertical config is icon-only with tooltip detail preserved')
"</automated>
  </verify>
  <done>cpu, memory, temperature, pulseaudio, network and battery render a glyph only; each carries a tooltip with the detail that left the column; the clock remains stacked text; CHECK E stays green.</done>
</task>

<task type="auto">
  <name>Task 2: Rewrite style-vertical.css as a bare-glyph column</name>
  <files>waybar/.config/waybar/style-vertical.css</files>
  <action>
Rewrite this sheet wholesale against the approved design system.

Import chain: `theme.css`, `waybar-font.css`, `waybar-modules.css`, then LAST
`../../.local/state/theme/waybar-visibility.css`.

The `*` reset: `min-height: 0; border: none; border-radius: 0;` and font-size 13px. Do NOT put
`font-size: 20px` in the `*` rule — that global rule is the root of the "big button boxes",
because it inflates every element including padding-sensitive containers, not just the glyphs.
Set the glyph size on the modules themselves instead (18px), which is the design system's Rule 7
applied to this column.

`window#waybar` gets `background: transparent;` and `color: @fg;` and nothing that paints. Delete
the `alpha(@background, 0.90)` background AND the `border-right: 1px solid alpha(@primary, 0.4)`
edge — that border is chroma on a non-state element and violates the design system's Rule 3.
Keep `transition: opacity 0.3s ease;`.

`window#waybar > box` gets `background: @bar-surface;` at the 14px radius with a 6px margin, so
the column reads as a narrow floating island down the left edge rather than a slab welded to the
screen.

Now delete the box treatment. The current grouped rule gives EVERY module
`min-width: 24px; padding: 4px 12px` — that is the oversized-box bug. Replace it: modules get
`padding: 6px 0;` (vertical breathing room only — horizontal padding is what widens the column),
NO min-width, NO background, NO border. They are bare glyphs on the island. Set `font-size: 18px`
on the glyph modules.

Delete every `border-left` accent rule. The current sheet rotates the horizontal layout's
per-module bottom-border rainbow into a left-border rainbow (@tertiary cpu, @secondary memory,
@primary temperature, @tertiary pulseaudio, @secondary network) — five coloured stripes running
down a narrow column, which is precisely the "terrible colour scheme" the user reported. All of it
goes. Module colour is `@fg`. Chroma appears only on the state rules already defined in the shared
sheet.

Workspaces become bare coloured glyphs with no box at all. Override the shared sheet here:
`#workspaces button` gets `background: transparent; border: none; padding: 4px 0;` and colour
`@fg-dim`. `#workspaces button.active` gets `color: @accent;` and NO background fill — in a narrow
column an accent-filled pill is a heavy blob, so the active state is carried by glyph colour alone.
This is a deliberate, documented divergence from the horizontal layouts' filled-pill active state;
note it in the SUMMARY as such. Keep the shared 14px min-width floor (it is harmless here and
guards against the same collapse), but do NOT reintroduce padding: 0.

Clock: it is the only text in the column. Give it `font-size: 14px;` (small enough that two stacked
digit rows fit a narrow column without forcing it wide) and centre it.

Every colour reference must be a theme.css role name (CHECK B).

Then LOOK at it: `echo vertical > ~/.cache/current-waybar-layout && ~/.config/hypr/scripts/waybar-launch.sh`,
`theme-apply tokyonight`, `grim /tmp/bar-vertical-tokyonight.png`; then `theme-apply catppuccin-latte`,
`grim /tmp/bar-vertical-catppuccin-latte.png`. Inspect both yourself: is the column a clean glyph
strip rather than a stack of boxes? Is there exactly one accent element? Measure the resulting
column width from the screenshot and record it in the SUMMARY — that closes the deferred UAT Test 2
width question with an observed value rather than a config guess.
  </action>
  <verify>
