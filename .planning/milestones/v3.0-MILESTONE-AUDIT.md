## Cross-Phase Integration

**Result: clean. 0 orphaned exports, 0 missing connections, no silent
assumptions.** Every file one phase exports for another to consume is actually
imported and read. The six seams checked:

**1. Phase 12 token pipeline → Phases 13/14/15/16/17 consumers — WIRED.**
`Motion.qml` and `Colours.qml` are both declared `singleton` in
`quickshell/modules/qmldir` and both use `FileView` with `watchChanges: true`.
`motion.json` and `palette.json` are actively read with file-watch; consumers
span 9+ QML modules (Dashboard, DashboardTab, MediaTab, WeatherTab, QuickToggles,
Overview and its WindowThumbnail/DragGhost children, and all three panels).
Outside QML, the pipeline feeds `gtk-4.0-motion.css`, `gtk-4.0-colors.css`,
`waybar-*.css` and `swaync.css`. No surface was found hardcoding a colour or
duration in place of a token.

**2. Phase 13.1 Lua migration → Phases 14/15/16 keybinds — WIRED end to end.**
All three later-phase binds trace cleanly through three layers: `keybinds.lua`
(`Super+D` → `quickshell:dashboard`, `Super+A` → `quickshell:audio-panel`,
`Super+O` → `quickshell:overview`), the `shortcuts.json` registry, and the
`GlobalShortcut` handlers in `shell.qml` that drive the corresponding loaders.
The Phase 13.1 contract collapse also holds — `contract.json` is down to one
`lua-table` format entry, matugen's `[templates.hyprland]` block is retired, and
`hyprland-tokens.lua` is the sole Hyprland output.

**3. Dropped QS-03 → Phase 16's overview — correct by design, not a regression.**
The concern was that Phase 16's full-screen overview inherits a shell root that
cannot fan out per-screen. It does not paper over this: `Overview.qml` is a
single full-screen `PanelWindow` with no `Variants` declaration anywhere in it or
its children, and carries an explicit comment (lines 36-40) recording that the
per-screen fan-out lives entirely inside `modules/Probe.qml`. This is the
documented D-13 design, applied deliberately.

**4. DASH-07 shared state — no duplicate ownership.** The backends
(`MediaBackendInstance`, `WeatherBackendInstance`, `SystemResourcesInstance`,
plus the panel-gated Audio/Wifi/Bluetooth instances) are each mounted once at the
`shell.qml` root and passed to both the dashboard's quick-toggle grid and the
panels. Quick-toggles read swaync state as truth rather than holding a second
copy. The state-drift bug class Phase 8 fixed has not been reintroduced.

**5. PANEL-06 single shared component — confirmed.** All three panels import and
instantiate `PanelDialog.qml`; no forked copy exists.

**6. `contract.json` completeness — verified, including one suspected miss that
turned out moot.** Phase 13's deferred items flagged `motion-curves` as written
by the engine but absent from `engine_owned_files`, which would make
`commit.sh`'s `rsync --delete` destroy it on every apply. Checked directly at
audit time: that entire mechanism was removed as planned by 13-07 — there is no
`--curves` flag in `motion-switch.sh`, no `theme_engine_read_motion_curves`, no
`curve_sets` key, and no `motion-curves` file in the live state dir. The missing
entry now protects nothing. The deferred item resolved itself by removal and can
be struck rather than carried into v4.0.

### Integration finding: GradientBorder reuse omission (14 → 15)

The one genuine cross-phase gap, and it is a design-reuse gap rather than a
wiring break — which is why the wiring-oriented pass above reads clean.

`GradientBorder` (DASH-10, Phase 14) is instantiated at exactly one call site:
`Dashboard.qml:387`. `PanelDialog.qml:157-174` — the single shared frame all
three Phase 15 panels are constructed from — declares a background `Rectangle`
with radius and colour only: no `border.width`, no `border.color`, no `Shape`,
no rim. So the animated border the drawer carries is structurally absent from
every panel.

Confirmed by the `panels-missing-animated-border` debug session (2026-08-02,
status `diagnosed`, bug class Bohrbug — 100% reproducible) via three independent
methods: a repo-wide grep returning exactly one instantiation, direct source read
of `PanelDialog.qml`, and a live A/B screenshot at identical 200% zoom on the
same corner region showing the drawer's gradient rim and the wifi panel's bare
surface. It was left unfixed deliberately — the session ran in diagnose-only mode
at the user's direction.

The user's own framing when raising it: *"this is important for all panels not
just wifi, they need to have the same animated colored border as the rest of
dashboard."* That is a stated expectation the milestone does not currently meet.

## E2E Flows

**Theme change — traced end to end, complete.**
`theme-apply <name>` → `lib/generate.sh:108` calls `theme_engine_render_motion_files`
→ `motion.sh` emits `motion.json`; matugen emits `palette.json`,
`gtk-4.0-motion.css`, `gtk-4.0-colors.css` → `Motion.qml`/`Colours.qml`
`onFileChanged` fire via `watchChanges` → bound properties update → every QML
surface re-renders in place. No Quickshell reload is required, which is the
deliberate D-18 choice (a reload would rebuild the `PanelWindow` and destroy the
crossfade).

**Fresh install — traced end to end, complete.** `install.sh` installs
`quickshell` from the official `extra` repo plus the AUR set including
`mpvpaper`; `stow.sh` pre-creates `~/.config/quickshell`, `~/.config/hypr` and
`~/.local/state/theme`, stows every package, seeds `motion.json` and
`palette.json` directly, and runs `theme-apply` at the end to populate the state
dir. No host-only state is required, satisfying the project's standing
reproducibility constraint.

**Dashboard live data and overview drag-between-workspaces** are wiring-verified
(backends mounted, shortcuts bound, dispatch confirmed) rather than re-traced
here; their behavioural evidence sits in the Phase 14 and Phase 16 summaries and
in `16-OVER04-MEASUREMENT.md`.
