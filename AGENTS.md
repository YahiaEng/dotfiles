## Where changes belong

- GNU Stow packages live under each app directory, usually at `<package>/.config/<app>/`. Edit the repo sources. On this machine Hyprland, Quickshell and Fastfetch resolve back to them. Fish's plugin directories contain individual symlinks and host-local plugin files, so a new Fish function needs its own link or a restow.
- Hyprland uses `hypr/.config/hypr/hyprland.lua` and `config/*.lua`. Use the current Lua dispatchers via `hyprctl eval` for live tests. Some legacy dispatch commands used by older examples fail on this build.
- Quickshell's root is `quickshell/.config/quickshell/shell.qml`. Its user service is `quickshell.service`. The launcher, bar, settings and lock each have their own components and IPC handlers. Use `systemctl --user restart quickshell.service` when a restart is needed.
- Matugen templates live in `matugen/.config/matugen/templates/`. The theme engine generates and commits files under `~/.local/state/theme/`. Change the template or generator for durable fixes. To validate or deploy one template in isolation, stage a render with `theme_engine_generate` from `theme-engine/.config/theme-engine/lib/generate.sh` and inspect the staged file before installing it.
- `install.sh` and `stow.sh` are the shared onboarding entry points. The [installation guide](README.md#installation) documents both launch paths.

## Weaselway and display layout

- `wsl/custom-weaselway-session` is installed at `/usr/local/bin/custom-weaselway-session`. It selects the dxgdrm device and drops inherited and ambient capabilities before Hyprland starts. Those capabilities previously caused Bubblewrap failures in GTK image loaders. The Hyprland WSL overrides use `AQ_DRM_DEVICES=/dev/dri/by-path/platform-dxgdrm-card` as their guard.
- `fish/.config/fish/conf.d/weaselway.fish` opens the desktop for an interactive local WSL login. Set `ARCH_WSL_TERMINAL=1` for a terminal-only WSL session. The launcher is `wsl/launch-desktop` and its Windows helper is `wsl/windows-viewer.ps1`.
- Keep the viewer borderless at the native size of each selected monitor. The earlier exclusive fullscreen approach produced dark displays. `Ctrl+Alt+H` switches between Arch and Windows. The Windows Start menu contains **Arch Linux - Display settings**, also reachable from Quickshell under **Setup → Display**. It lets the user identify displays, assign them to Arch, and select the Linux main display.
- A cold WSL launch could outlast Windows window discovery and leave the viewer at 800×500. Single-display launches start at the selected display's dimensions when they fit within the initial RDP size limits. Larger modes resize after connection. `wsl/windows-viewer.ps1` gives discovery and placement separate timeouts. Startup failure cancels the pending viewer, releases the launcher locks, and records the error in the viewer log. A relaunch with a 13-second startup delay filled the 1920×1200 panel, and the user verified the fix.
- `wsl/weaselwayd-hyprland.conf` installs the `20-hyprland-socket.conf` drop-in. The daemon sees the live Hyprland Wayland socket through `$XDG_RUNTIME_DIR/weaselway-hyprland/wayland-hyprland`. This keeps WSLg from supplying the wrong pointer geometry. The drop-in keeps PipeWire on the normal user runtime socket. The viewer log is `$XDG_RUNTIME_DIR/arch-hyprland-viewer.log`.
- Cross-display dragging was tested. In multi-display mode the launcher disables SDL mouse auto-capture and keeps click-through on focus. The Windows helper delivers a missed left-button release to the originating viewer window when the drag ends on another display. Quickshell mounts a bar, workspace icons and rails on every assigned display. Notifications and default dialogs use the main display.

### Per-display scaling

An unavailable saved scale falls back to automatic until the mode supports it again.

## Fixes and verification

- **Touch input.** The stock viewer sent screen contacts and touchpad gestures through the same RDPEI channel, and the daemon treated them as touchpad input. The patches in `wsl/weaselway-viewer-touch.patch` and `wsl/weaselway-daemon-touch.patch` route native Windows touchscreen messages to direct Linux touch devices bound to the corresponding `Virtual-N` output. The synthetic touchpad path retains its own device. `wsl/install-touch` builds the pinned viewer and daemon from source and installs the pair under `~/.local/share/weaselway/touch/`. The daemon runs via `30-native-touch.conf`. The launcher prefers the patched viewer when the inherited setting points to the stock binary. The installer was exercised end to end. Injected taps and swipes worked on both displays without moving the mouse pointer, and a tap opened Quickshell's Updates card. The user then confirmed physical touchscreen and touchpad operation.
- **Kitty tiling.** Hyprland could transfer a maximized window's mode to the new terminal. `hypr/.config/hypr/config/windowrules.lua` gives ordinary Kitty windows an initial `fullscreen_state = "0 0"`. The standard `uwsm app -- kitty.desktop` launch was verified to tile beside an existing maximized window. Purpose-built Kitty surfaces use their own classes and rules.
- **Edge bar popouts.** `modules/Bar.qml`, `modules/bar/PopoutController.qml`, `PopoutTrigger.qml` and `SectionPopout.qml` own the geometry. The trigger selects the bar on its own output. Continuous bars expose the straight span where the complete popout, including both flares, can attach. Resources and Updates were verified to fit with the app drawer collapsed on the horizontal Continuous bar. Use actual layer geometry or a screenshot when checking another style or orientation.
- **Desktop lock recovery.** `modules/lock/Lock.qml` owns the session lock and unlock timer. It keeps lock state under the current Hyprland runtime directory and reattaches a PAM-backed lock client when a real output returns. WSL tests covered simulated output removal, DPMS off/on and recovery after forcing a Quickshell restart. The user confirmed recovery and password unlock on the physical desktop.
- **Themes, wallpaper and keybinds.** The user confirmed readable text and per-theme wallpaper changes. The wallpaper picker and theme engine accept Stow-linked images. **Style → Wallpaper** opens the same in-launcher carousel as the shortcut. Relevant files are the launcher components, `hypr/.config/hypr/config/keybinds.lua`, `scripts/wallpaper-{picker,switch}.sh` and `theme-engine/.config/theme-engine/lib/wallpaper.sh`. IPC shortcuts invoke explicit launcher routes so the menu stays in the intended mode.
- **Starship.** Fish reads the generated `~/.local/state/theme/starship-prompt.toml` unless `STARSHIP_CONFIG` is already set. `theme-engine/.config/theme-engine/lib/generate.sh` assembles it from the stowed base and the Matugen theme fragment. Change the base for prompt structure and the template for colors.
- **Fastfetch.** The old 54-column box overflowed on long values and was missing icons. The module labels and colors come from the Matugen `fastfetch.jsonc` template. `fastfetch/.config/fastfetch/render.py` sizes the box and logo for the viewport and preserves the logo picker and Kitty sprites. At smaller sizes it stacks the art or uses a compact logo and elides long values. Fish's `__fastfetch_setup_greeting.fish` makes the text greeting part of the first prompt so it can redraw on resize. The first command clears the greeting from scrollback and restores the ordinary Starship prompt. Running `fastfetch` in Fish uses the same layout. - **Steam and audio in WSL.** The user signed in and played Vampire Survivors. The old Steam launcher forced llvmpipe on games. `wsl/install-steam-launcher` lets 64-bit games use the GPU and 32-bit Steam use Mesa's software fallback, keeps `-cef-disable-gpu` for the web UI, and raises the Mesa shader-cache cap to 8 GB. Vampire Survivors reported D3D12 on Intel Arc 140V. The user confirmed sound after the muted `weaselway_rdp_sink` was unmuted. ## Quick checks

Run these in Bash from WSL to select the live Hyprland instance and check the desktop.

```bash
export HYPRLAND_INSTANCE_SIGNATURE="$(hyprctl instances -j | jq -er '.[0].instance')"
export WAYLAND_DISPLAY="$(hyprctl instances -j | jq -er '.[0].wl_socket')"
hyprctl configerrors
hyprctl monitors -j
systemctl --user is-active weaselwayd.service quickshell.service
qs ipc --pid "$(systemctl --user show -p MainPID --value quickshell.service)" show
```

`hyprctl layers -j` gives layer-surface coordinates by output. Use the Quickshell `popout` IPC target with `open resources`, `open updates`, `open wifi`, or `open bluetooth` to verify a card, then call `close`. `upower -i /org/freedesktop/UPower/devices/DisplayDevice` shows the battery state and charge. Repo diagnostic entry points include `hypr/.config/hypr/scripts/keybind-doctor`, `quickshell-doctor` in the same directory, and `theme-engine/.config/theme-engine/theme-doctor`.
